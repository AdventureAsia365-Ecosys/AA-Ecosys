# Docs lint tools (AA-888)

The checks behind [`.github/workflows/docs-lint.yml`](../../.github/workflows/docs-lint.yml). The rules they enforce
are in [`docs/STYLE.md`](../../docs/STYLE.md).

| Tool | Checks | Level in root |
|---|---|---|
| `check_frontmatter.py` | Front-matter of every `docs/**/*.md` page that has one validates against `docs/templates/frontmatter.schema.json`; catalog IDs are unique (templates excluded); a translation `<name>.vi.md` shares the ID of its English page, needs `lang: vi` and a `translation_of` that names that page (docs/STYLE.md, Language). `--freshness-report` writes the weekly report. | error (freshness: warning) |
| `check_adr_index.py` | Each `docs/adr/NNNN-*.md` states a status (Proposed, Accepted, Deprecated, Superseded, Rejected) and is linked from `docs/adr/README.md`. | error |
| `check_docs_text.py aws-multiline` | No `aws ...` command continued with a backslash in `docs/`, `skill/`, `.kiro/steering/`, `.claude/` (journals excluded). | error |
| `check_docs_text.py resource-ids` | No `sg-`/`subnet-`/`vpc-` IDs, standalone 12-digit account IDs, ARNs with an account, user-pool IDs or API Gateway hosts in `docs/` prose (journals, `docs/onboarding.md` and generated pages excluded). | warning (`--mode error` for public repos) |
| `check_prd_refs.py` | PRDs under `docs/product/` (not its `README.md`) carry `linear` (AA keys) and the path lists `adrs`, `contracts`, `erd`, `migrations`, plus a `## Acceptance criteria` list of unique `**AC-<n>**` items; on every docs page those path lists point to files that exist (a path into another workspace repo is checked only where that repo is checked out, a warning in CI). Rules: [`docs/product/README.md`](../../docs/product/README.md). Root only, not vendored. | error |
| `check_alarm_runbooks.py` | Every alarm row of `docs/generated/alarms.md` (generated by AA-CIS-Infra `docs-gen.yml`, AA-893) has a runbook link that resolves to a file under `docs/` here. No page yet: passes. | error |
| `gen_llm_routes.py` | Not a lint: renders `docs/generated/llm-routes.md` (APP-06-routes, AA-900) from the snapshot `docs/generated/llm-routes.snapshot.json`; `dump` runs in a CIS container (read-only, as `cis_app`) and `import` turns its ECS exec output into the snapshot and the page. `test_llm_routes.py` fails when the committed page is not the render of the committed snapshot, or the snapshot holds an account ID or ARN. Root only, not vendored. | error (unit test) |
| `build_docs_reader.py` | Not a lint: builds the `/admin/docs` reader bundle (manifest + redacted pages) for [`.github/workflows/docs-sync.yml`](../../.github/workflows/docs-sync.yml) (AA-898). Publication rule v1 in its header (rule 8: translations, with `lang` / `translation_of` / `translations` per manifest entry; rule 9: checked SVG images such as the architecture diagrams, published under `assets/`) and in [`docs/README.md`](../../docs/README.md#admin-docs-page-allowlist-aa-898); the redaction guard fails the build when an account or resource ID is left. Tests: `test_docs_reader.py`. Root only, not vendored. | error (guard) |
| `report_registry.py` | `check`: the report registry [`docs/reports/catalog.yaml`](../../docs/reports/catalog.yaml) and [`kpis.yaml`](../../docs/reports/kpis.yaml) (AA-1003): required fields and allowed values, unique IDs, every KPI a report lists exists and each KPI's `used_by` matches, template paths exist, every KPI source table is in `docs/architecture/db-schema-reference.md` or in `planned_sources` (a planned source that is live now only warns). `--copy DIR` also compares with the CIS vendored copy. `import --force` rebuilds both files from the AA-1001 advisory JSON (one-off; it overwrites hand edits). Tests: `test_report_registry.py`. Root only, not vendored. | error |
| `lychee.toml` | Internal links, offline. | error |
| `.markdownlint-cli2.jsonc` (repo root) | Markdown style of catalog pages (journals, `docs/archive/`, generated pages ignored). | error |

Journals keep their history as written and are out of scope: `docs/sessions/`, `docs/audits/`,
`docs/implementation-notes/`, `docs/backlog/`, `docs/research/`, `docs/calib/`. To skip one line on purpose, put
`docs-lint: ignore` on it (an HTML comment works).

## Run locally

From the repo root:

```bash
python3 -m pip install -r tools/docs/requirements.txt
python3 -m unittest discover -s tools/docs -p 'test_*.py'
python3 tools/docs/check_frontmatter.py
python3 tools/docs/check_adr_index.py docs/adr
python3 tools/docs/check_docs_text.py aws-multiline
python3 tools/docs/check_docs_text.py resource-ids --mode warn
python3 tools/docs/check_alarm_runbooks.py
python3 tools/docs/check_prd_refs.py
python3 tools/docs/report_registry.py check
python3 tools/docs/build_docs_reader.py --check
python3 tools/docs/check_frontmatter.py --freshness-report .tmp-session/freshness.md
```

Link check, with a [lychee](https://github.com/lycheeverse/lychee) binary on the PATH:

```bash
lychee --config tools/docs/lychee.toml 'docs/**/*.md'
```

Markdown style, with Node (the version the pinned workflow action uses):

```bash
npx markdownlint-cli2@0.23.2 'docs/**/*.md'
```

The other repos can run `check_adr_index.py` and `check_docs_text.py` with `--root <repo>`: both are stdlib only.

## Copies in AA-Booking, AA-TripPlanner-Web and AA-CIS-Infra

AA-Booking, AA-TripPlanner-Web and AA-CIS-Infra vendor these files in their own `tools/docs/` (public / separate
repos cannot read this private one from CI). `docslib.py`, `check_docs_text.py`, `check_adr_index.py`,
`check_frontmatter.py`, `test_docs_tools.py`, `lychee.toml` and `requirements.txt` must stay byte-identical in all
four repos; only each README is repo-specific. The app repos and Infra also copy `docs/templates/frontmatter.schema.json`. Options used only by those repos, harmless here:

- `check_docs_text.py ... --all` scans every tracked Markdown file (minus journals) instead of the default scope.
- `check_docs_text.py resource-ids --mode warn --block vpc,apigw` keeps the listed kinds failing in warn mode
  (kinds: `vpc`, `arn`, `user-pool`, `apigw`, `account`).
- `check_frontmatter.py` also validates a `CONTEXT.md` at the repo root; this repo has none.

Change a rule here first, then copy the seven files to the three other repos in the same session, and check from the
workspace root:

```bash
for f in docslib.py check_docs_text.py check_adr_index.py check_frontmatter.py test_docs_tools.py lychee.toml requirements.txt; do for r in apps/AA-Booking apps/AA-TripPlanner-Web infra/AA-CIS-Infra; do cmp tools/docs/$f $r/tools/docs/$f; done; done
```
