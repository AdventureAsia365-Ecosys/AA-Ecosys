# Ops calendar

Every dated or recurring ops duty lives in one file, [`calendar.yaml`](calendar.yaml): billing and account steps,
periodic reviews, credit and programme expiries, privacy and AI law dates, security scan follow-ups and the scheduled
jobs that run by themselves. Before this page, the same dates sat in the backlog, the tracker, agent notes and the
session-start routine, and nothing turned red when one passed.

## How it works

- **Source:** [`calendar.yaml`](calendar.yaml). Edit that file, never the table below or the `.ics` feed. The header
  of the file lists every field.
- **Kinds:** `recurring` (a cadence; the newest matching audit folder dates the last run, or a compliance check
  grades it against its admin age setting: access review, restore drill, monthly security review),
  `deadline` (a due date, or a "not before" window), `trigger` (due a number of days after an event) and `automated`
  (a job or workflow with its own alarm, listed so the calendar is complete).
- **Dates read, not copied:** secret rotations and certificate or domain expiries come from the rotation blocks of the
  [secrets register](../security/secrets-register.md), go-live gate due dates from the
  [go-live checklist](go-live/README.md), and exception expiries from the vulnerability exception register.
- **States:** a line is overdue (red) once its due date passes and it is not done; due soon (amber) inside its own
  `warn_days`; open (amber) once a "not before" window opens.
- **Red by itself:** the daily compliance collector publishes the check `ops_calendar_overdue`. It is red on CIS
  Platform › Compliance readiness the day a line is overdue, and green again once the line is done (`done:`) or
  re-dated. The Calendar tab there lists every line with its state.
- **Guard:** the workflow "Ops calendar" runs on a pull request that changes the calendar or its registers (overdue
  lines are warnings there) and every Monday (overdue lines fail the run, so the session-start guard run list shows it).
  It also fails when the table below or the `.ics` feed is stale.
- **Session start:** `python3 tools/ops/ops_calendar.py status` prints the overdue, due-soon and open lines.

## Subscribe on a phone

The feed [`calendar.ics`](calendar.ics) is generated from the YAML (`python3 tools/ops/ops_calendar.py ics --write`;
the same commit as the YAML change). In Google Calendar: **Other calendars › From URL**, paste the raw URL of
`docs/ops/calendar.ics` on the default branch of the public repository, **Add calendar**. Google refreshes a
subscribed feed every few hours to a day. Each dated line is an all-day event and each recurring line repeats from
its anchor. The feed depends on `calendar.yaml` alone: the lines that read their dates from a register (secrets,
go-live checklist, vulnerability exceptions) have no event, so editing a register never makes the feed stale. Their
dates are on the CIS Calendar tab and in `status`.

## Change a line

1. Edit `calendar.yaml`: set `done: <date>` when a deadline is met, or move its `date` with a note why.
2. `python3 tools/ops/ops_calendar.py render --write && python3 tools/ops/ops_calendar.py ics --write`.
3. `python3 tools/ops/ops_calendar.py check --warn-overdue` before the pull request.

Titles and notes show on the CIS tab and in a public repository: generic words, roles instead of names, no issue ids
(those go in `source`), no account ID, ARN or e-mail address (the guard refuses them).
