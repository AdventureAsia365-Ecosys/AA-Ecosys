# Go-live gate

Prod opens to real users only when every line below is met, and the first real agency data lands in any app only when
every line marked "pilot data" is met. The list is the single gate: the eight items of the
[ADR 0012](../../adr/0012-environment-model.md) go-live gate (decision 11), plus the proofs a first real agency needs
that the S282 ecosystem audit found spread over many issues (price coverage, the Booking restore drill, a load test,
edge rate limits, a capacity baseline, the enforce_admins plan, no real personal data before the DPA, the AI caps at
prod), the pilot items of the November 2026 security review (deletion paths, on-demand capacity for the agency-facing
web service, written recovery targets), and two gate dates: the go-live date and the pilot data date.

## How the gate works

- **Source:** [`checklist.yaml`](checklist.yaml) in this folder. Edit that file, never the table below.
- **A line is met** when it links a proof: a repo path (optionally with a `#heading` or `#L<line>` anchor) or an https
  URL. Evidence that exists but does not prove the line (a Dev drill for a prod item, a method to copy) goes under
  "Evidence so far" and does not count.
- **An open line** names an owner role (tech lead, business owner or engineer on duty) and an ISO due date.
- **Two gate dates.** The go-live date is the day prod opens to real users. The pilot data date is the day the first
  real agency data lands in any app (the pilot runs on Dev, so it can come before prod). Each line says which one it
  must be met before (column "Before"; `gate_date` in the file, go-live by default). A "pilot data" line is needed
  before the go-live date too, so both dates bound it.
- **The gate date lines** may stay unset only with an owner. Once a date is set, every open line bound to it must be
  due on or before it, the gate fails if the date arrives with those lines still open, and the pilot data date may not
  fall after the go-live date.
- **The guard** is `tools/ops/golive_gate.py check`, run by the Go-live gate workflow on every pull request that
  changes the checklist or the tool, and weekly on Monday. It fails on a dead proof path or anchor, an unknown owner
  role, an open line past its due date, a missing owner or due date, a line due after a set gate date it is bound to,
  and a table below that no longer matches the checklist. `check --golive YYYY-MM-DD --pilot-data YYYY-MM-DD` shows
  what a proposed pair of dates would fail, without changing the file.
- **After an edit:** `python3 tools/ops/golive_gate.py render --write` rewrites the table, then
  `python3 tools/ops/golive_gate.py check` must pass.

The due dates were set on 2026-11-25 as planning dates while no gate date exists, and the lines due 2026-12-15 were
re-dated on 2026-11-28 (each says why in its note). Neither gate date is set: no go-live date or pilot data date is
written in the repo by the tech lead or the business owner. When the business owner sets a date, re-date every open
line bound to it in the same pull request.
