Generated by a 6-agent workflow on main @ 20a2387. Sections: 1 pipeline · 2 failure & retry stats (real DB data, S233a + S234 r1–r4) · 3 chị Thư repo comparison · 4 Jev audit. The plan is in 09-next-step-plan.md.

## 1. How T9 writes a piece (code as deployed)

T9 writing pipeline on `main` @ 20a2387: this traces the code as it runs today. Paths are relative to `apps/AA-CIS-App/` unless noted. I didn't edit any repo files and wrote nothing to scratch.

## Plain summary for the product owner

The tenant picks a topic (a Slate card) and chooses one of three angles. They press "Write", get an immediate placeholder, and a background job does the rest:

1. It collects the facts the writer may use: the tour moment(s), place background, platform facts and the brand pack.
2. A Sonnet call writes the post.
3. Code cleans the post up without any model: it removes duplicates, leaks and stock phrases and fixes the CTA. For blogs, two cheap Haiku calls fix the SEO title/meta and the FAQ. For LinkedIn, one cheap call shortens a long first line.
4. About 20 checks ("gates") run. Two of them are AI judges (structure and fact/CTA); the rest are code rules.
5. If a blocking check fails, the post gets up to two more tries:
   - Usually only the flagged sentences are rewritten.
   - The whole post is rewritten only when a failure can't be fixed sentence by sentence.
   - The third try is always sentence-only. If a try makes things worse, the system keeps the earlier version.
6. The post is saved as **approved** or **held**. Since AA-770 the tenant gets the text either way and can publish either. "Held" plus every gate detail is visible only to the admin.

## Ordered flow, request to stored piece

**A. Before T9 (upstream)**
1. **Slate pick:** `POST /v1/subjects/{subject_id}/pick` (`api/routers/v1_planning.py:105`) runs `slate.pick_subject` (`services/acp_shared/slate.py:641`).
   - It creates the `acp_shared.angle_gate_request` with `atom_id`, `trip_id` and `channel`.
   - A route/blog pick also stores `route_segment_ids`.
2. **T8 goal and angles:** `POST /v1/angle-gate/requests/{id}/goal` (`v1_angle_gate.py:56`) starts a `t8_angles` job. Stage `t8_angle_gen` is Sonnet, max_tokens 2048 (`services/acp_angle_gate/generate.py:128`). It produces 3 angles.
3. **T8 choose:** `POST .../choose` (`v1_angle_gate.py:87`) sets one angle as chosen and the request to `approved`.

**B. HTTP pre-flight: `start_write` (`services/acp_content_writing/service.py:796-962`), no LLM**
4. `POST /v1/content-writing/requests/{id}/write` (`api/routers/v1_content_writing.py:46-58`).
5. Guards, in order:
   - status must be `approved` (`:812`)
   - channel must be set (`:817`)
   - a chosen angle must exist (`:828`)
   - a CTA must exist (`:838-844`). Fallback order: `req.cta`, then `cta_override` from the request body, then the brand's `default_cta`.
6. **Seed:**
   - Route pick: `_fetch_route_segments` (`:175-230`). It sorts moments by day, skips segments whose ranking excluded them, and merges same-place moments.
   - Otherwise: `_fetch_atom_text`, which calls `atom_seed_text` (`:107-120`).
7. **Scope and keyword:**
   - SCOPE line from `_scope_line` (`:239-261`).
   - Places outside the scope come from `_trip_places_outside` (`:279-293`).
   - Brand pack (with fallback brand name from `shared.tenants.name`, `:884-888`), trip name and destination (`:890-896`), brand rubric (`:898-899`).
   - Sibling openers, non-blog only (`:778-793`).
   - Keyword from `choose_keyword` (`:323-362`), using `dfs_paa_snapshot.related_keywords`.
8. Inserts a placeholder `content_piece` with status `processing` and marks the subject `used` (`:965-1019`). The context dict is built at `:942-961`.
9. The router enqueues a durable `t9_write` job (`v1_content_writing.py:84-86`), handled in `services/jobs/t9_write_job.py`.

**C. `run_write_background` (`service.py:1074-1573`)**

10. `resolve_facts` (`:1041-1060`):
    - Re-reads the seed so place cards built since step 6 are included. T9 never drafts a card itself.
    - Loads facts for the trip's country.
    - **No Jev call here.** The comment at `:1085` saying "Jev fact-select runs here" is stale, and `facts.select_relevant_facts` (`facts.py:81`) has no caller.
11. `_add_date_spans` (`:1063-1071`) turns "served … until 1955" plus a start year into a stated span line.
12. Builds the per-job context:
    - `channel_spec` (LinkedIn only)
    - `HygieneContext` (scope lexicon)
    - `TripFactContext`
    - brief texts
    - `writer_trip` = scoped trip name with duration and out-of-scope places removed (`:1126`)
    - `grounding_text` = seed + facts + BRAND / CORE IDEA / AUDIENCE / TRIP / DESTINATION lines (`:405-425`)
    - `sibling_texts`: last 5 pieces of the same request (`:716`)
    - `taken_titles`: this brand's last 50 blog titles (`:739`)
13. **Attempt loop, `MAX_ATTEMPTS = 3` (`:74`, `:1179`):**
    - **Attempt 1:** `write_content`, stage `t9_write` (`:1181-1188`).
    - **Attempts 2 and 3:** `sentence_repair.plan(content, ledger)` (`:1202`) decides:
      - **Items found:** `repair_sentences` with the ±2 neighbouring sentences and only the cited moment/fact as source (`_repair_source`, `:550-575`). Stage is `t9_repair` (Haiku) only when every blocking failure is in `CHEAP_REPAIR_GATES` (F15, F13_repeat, F17, F18; `quality_gates.py:1388`, `service.py:611-618`). Otherwise it is `t9_write` (Sonnet). The result is spliced with `splice_checked`, which reverts any repair that creates a new repeat or a dangling pronoun (`:1227-1244`).
      - **`[]` (only title/meta failures):** no text change; `repair_mode = "seo_fields"` (`:1219-1223`).
      - **Attempt 3, repair call failed:** the flagged sentences are deleted in code (`delete_flagged`, `:1245-1251`).
      - **Attempt 3, nothing repairable:** attempt 2 is kept and the loop stops (`:1252-1260`). Attempt 3 never does a full rewrite (AA-770).
      - **Otherwise, attempt 2 only:** a full rewrite with every blocking violation as feedback (`rewrite_with_feedback`, `:1262-1271`; feedback built at `:754-762`).
    - **Blog only:** `_fit_seo_meta` (`:456-543`). If the title or meta is out of band, names an out-of-scope place, sells an unsupported product, makes a "remains/today" claim or duplicates a taken title, it makes 1–2 `t9_repair` calls. If that still fails, it falls back to adding " | Brand" to the title.
    - **Embedding** (`compute_embedding`, Cohere on Bedrock) and a cross-tenant similarity lookup feed F10 (`:1287-1314`).
    - **Deterministic fixes, in order:**
      1. `hygiene.autofix` (`hygiene.py:1944`)
      2. `ensure_cta` (`:1321`)
      3. `add_family_caveats` (`:1325`)
      4. Blog: `drop_restated_faq` and `drop_unanswerable_faq`, then `_enforce_faq_contract`. This is one `t9_repair` FAQ regeneration if there are fewer than 3 pairs, run on fresh text, or once more if a repair dropped the FAQ below 3 (`:1327-1344`, `:621-663`).
      5. `_fix_first_line`: one `t9_repair` call if the LinkedIn hook is over 140 chars (`:1346-1350`, `:666-704`).
      6. `trip_facts.fix_trip_facts`: thin-moment heading/coda, a played-down hazard, a background place written as the trip's base (`:1356`).
      7. `text_integrity.final_pass`: one CTA, dedupe, broken fragments, normalisation (`:1357`).
    - **Gates:** `run_quality_gates` (`:1360-1372`). Then the `F7_faq_autofix` and `F13_autofix` log flags are added (`:1375-1382`).
    - **Jev:** `observe_t10` on stage `t10_gates`. Observe-only, allow-listed tenants only, never changes an outcome (`:1384-1388`).
    - **Pass:** status `approved`, stop (`:1390-1392`).
    - **Fail:** a `repair_log` entry is written (`:1395-1400`). Then the **regression guard** (AA-528, `:1418-1455`): if this attempt newly fails a gate that used to pass and doesn't have fewer blocking failures overall, the previous attempt is restored and this one goes to `discarded_attempt`.
    - **Stop rule** (`:1458-1472`): stop when `first_failure` isn't repairable, OR at attempt 3, OR at attempt 2 when `plan()` returns None. On stop, `_hold_or_ship` (`:369-377`) sets `held` on the first failed product-truth gate. A piece whose only remaining failure is F15_voice ships as `approved`, with the failure added as a flag.
14. **After the loop:**
    - All `[R:]` and `[F:]` tags are stripped from the text, ledger, repair log, flags and held reason (`:1483-1488`).
    - `_final_integrity` runs `final_pass` again. Any F13_repeat residue replaces the ledger entry and **turns approved into held**, with no further repair (`:1492-1493`, `:578-595`).
    - `discarded_attempts` is filled (`:1499-1509`).
    - `within_tenant_reuse` flag at cosine ≥ 0.92 against a different atom (`:1518-1535`).
    - `_waive_style_only` (`:1537`, `:598-608`).
    - `_finalize_piece` (`:1539-1550`, `:1598-1663`) plus an audit log entry.
    - Any exception in the job sets status `failed` with an empty text (`:1558-1573`).

## (5) Output and who sees what

**`content_piece` columns written** (`service.py:1630-1636`):
- `attempt_number`
- `content_text` (tags stripped)
- `status`: `approved` / `held` / `failed`
- `held_reason` (`"<gate>: v1; v2; v3"`, `:365-366`)
- `gate_ledger` (every gate's `{gate, passed, violations, repairable, blocking[, waived]}`)
- `repair_log`, with entries `{attempt, gate_targeted, violations, repairable, feedback, repair_mode (sentences / seo_fields / sentences_cut), sentences_repaired, repeat_guard_deletes, integrity_reverts …}` and any `gate_regression_guard` entries
- `seo_title`, `meta_description`, `slug` (blog only)
- `flags`
- `content_summary`
- `content_embedding`
- `discarded_attempts`
- `writer_input` (`writer_input_snapshot`, `:1576-1595`): seed, route moments, facts, scope, brand pack, rubric, angle, goal, channel, keyword, CTA, trip, writer_trip, trip_places

**Tenant view** (`_tenant_safe_piece`, `:1678-1699`): `ready_state` (approved or held shows as "ready"), text, SEO fields, route hub/count, created_at. No status, gates, flags or held reason. Publish accepts both approved and held (`api/routers/v1_publish.py:284-291`).

**Admin view** (`api/routers/admin_content_quality.py`): list/detail at `:122` and `:308` with the full ledger, flags, repair log, discarded attempts and writer_input. Also sentence suggest/apply on `t9_repair` (`:345`, `:415`) and regenerate-angles (`:516`).

## Code findings and r4 statistics

1. **An F4_seo_surface failure on its own forces a full Sonnet rewrite.** I confirmed this by calling `plan()` directly: it returns `None` for an F4-only ledger. The comment at `sentence_repair.py:114-116` says it "never forces a full rewrite". F4 plus a title-only F12 returns `[]` as intended.
2. **Most sentence repairs still run on Sonnet.** `t9_repair` (Haiku) is used only when every blocking failure is in F15/F13_repeat/F17/F18. Repairs for F1, F9, leak and brand failures go to `t9_write` Sonnet (`service.py:1209`).
3. **F12_scope is warn-only**, so out-of-scope body sentences are never repaired (r4: 1 blog warning).
4. **The final integrity pass can turn an approved piece into a held one** after all attempts are used, with no further repair (`service.py:1492`).
5. **Stale comments and dead code:**
   - `service.py:1085` says Jev fact-select runs there; it doesn't.
   - `facts.select_relevant_facts` / `T9_STAGE = "t9_facts"` (`facts.py:76-81`) have no caller.
   - The `rewrite_with_feedback` docstring (`generate.py:242`) still says "the only retry, cap of 2"; `MAX_ATTEMPTS` is 3.
6. **r4 outcomes:**

   | | Approved | Held | Attempts |

## 1. Her pipeline in brief

**Inputs**

  7. The journey.

### 0. How the switch works (applies to every use)

- **Per-question mode.** The only per-question switch is `shared.decision_question.mode`, which is `off`, `shadow` or `enforce`. It is cached for 20 s (`shared/llm_client/decide.py:196-220`).
- **The mode belongs to the question, not the stage.** One question key used in two stages cannot be switched off for only one of them (`decide.py:518-533`).
- **Only enforced, confident verdicts change anything.** A stage acts only when the question is in enforce mode and the zone is accept or reject (`decide.py:123-147`).
- **No floors means always grey.** With NULL floors, `zone_for` can only return `grey` (`decide.py:160-181`). Every T-native question has NULL floors.
- **Failures leave the stage on its own rule.** A missing config, an HTTP error or the 402 breaker produces zone `error`, and the stage keeps its existing rule (`decide.py:510-605`). `decide()` never raises (`decide.py:672-690`).
- **Tenant guard (DPA).** On a stage named `t<digit>…`, content goes out only for tenants in `shared.jev_tenant_allowlist`. A missing tenant fails closed (`decide.py:223-239`, `525-531`).
  - The allow-list holds 4 AA-owned test tenants: atlas-hearth, terra-family, trail-pulse and wildkind-travel. They were added 12/10 by kiro:s229.
  - Real tenants are already `skipped`: since 12/10 no T-stage row has a non-allow-listed tenant. The only exceptions are 9/30 pilot rows for test-1 and wanderlux.
- **There is no env var or feature flag** per stage. The admin route is `PUT /admin/decisions/questions/{key}` (`api/routers/admin_decisions.py:395-419`). `off` needs no calibration; `enforce` needs `calibration_ref` (`admin_decisions.py:382-392`).
- **There is no admin UI to edit the allow-list.** The decisions page reads it (`admin_decisions.py:124`), and rows are deleted only when a tenant is offboarded (`api/routers/admin.py:1127`).
