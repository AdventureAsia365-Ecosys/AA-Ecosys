# Critic review: AA-784 place-card model eval (S252)

Read-only review of `design.md` and `cardeval_run.py`, checked against CIS `main` 900f2463 (`place_cards.py`, `shared/llm_client/client.py`, catalog migrations 169/170/259, `db-schema-reference.md` verified 2026-10-25). Fixes applied in place. Offline harness: real `place_cards` + real `LLMClient.generate` wrapper, fake provider, DB and S3. Scenarios: design tokens, every call at full `max_tokens`, and a crash then `resume`. `flake8` is clean apart from line length.

## Verified OK (no change)
- **Arms differ only by model.** `draft_card` / `check_card` / `_clean_facts` / `_clean_aliases` / `_representative` / `place_key` / `find_card_for_draft` are imported. `pc.LLMClient` is swapped at module level, so the real prompts and parsers run. `model_tier` gives a one-key chain: no route fallback and no shadow (`client._generate`). The context variable carries through `asyncio.to_thread`. In the harness every call reached the intended key.
- **Logging.** The gateway does not log successful calls, so `place_cards._log` → `record_call_with_pool` writes exactly one row per successful call (`stage=adhoc_aa784_cardeval`, roles writer/validate, both allowed by `llm_call_log_role_check`). Billed unusable replies are logged by the gateway under the same stage because the request already carries it. No double counting.
- **Model keys exist** in the catalog migrations, with prices. `opus-5-5` was enabled by 170 at list price. `gpt-6-luna` was inserted disabled by 170 but is live-routed by 212/213, so it is enabled now. The dry run drops any disabled key anyway.
- **Tables, columns and grants** used by every query exist, and `cis_app` has SELECT (and INSERT on `llm_call_log`). The only writes are `llm_call_log` rows. `_would_link` is read-only.
- **Blind packet.** It contains no model key, arm id, verdict or "planted" marker (checked in the harness). Ids are opaque hashes in shuffled order.

## Blocking issues found and fixed
1. **The cost cap was not hard.** Each call reserved 1.5× an estimate, but a 5.5 or Opus call with a 4,000-token floor can cost about 6× that, so 6 concurrent calls could overshoot by about $0.5. Each call now reserves its worst case (2,000 prompt tokens plus its full `max_tokens`) under an `asyncio.Condition`. Near the cap a call waits for in-flight calls to settle, and it is skipped only when nothing is in flight. Harness, all calls at full `max_tokens`: spend stopped at $2.998.
2. **A tier skip did not stop the run.** After a skipped tier, cheaper later tiers still ran. In the harness, tier D (Opus on live drafts) was skipped while the less useful D4×Opus ran. Now the run stops at the first tier that does not fit.
3. **Opus (C4) could never qualify.** C4 had no planted cards, so its identity recall would have n < 10 and gate 6 could not be measured. Tiers were rebuilt so each checker gets its planted cards together with its natural cells: A, then B (C1/C2 planted, $0.05), C (C3 + planted), D (C4 on D1#1 + planted), E (C4 on D4#1), F (optional Sonnet 4.6). Estimate for A–E: $2.85, 682 calls. Gate 6 now says outright that n < 10 means not eligible.
4. **Tenant text could leak.** `v_active_tour_atoms` keeps `owner_scope`, and the `tour_atoms` RLS shows tenant-scoped atoms exist. `cis_app` bypasses RLS. The sample now uses `owner_scope = 'platform'` only, and `ORDER BY atom_id` makes the representative atom deterministic.
5. **A dead task meant paying again.** The S234 lesson: an api task replaced mid-run loses everything. Results are now checkpointed every 15 calls. `paid` refuses to start if `results.json` exists. `resume` skips finished calls and sets spent to the larger of the saved figure and the `llm_call_log` sum since the first start. Harness: crash, then resume, gave 677 provider calls against 682 for a clean run (only in-flight calls repeat).
6. **A crash in `json.dump(results)`.** `TOKEN_FLOOR` has tuple keys. Its keys are now stringified in the output.
7. **An unfair token limit.** The floor was given only to the 5.5 models. gpt-6-luna (S246: empty replies) and Luna as a checker also reason inside `max_tokens`. All challengers now get the floor; the live arms keep production limits so the incumbent is measured as it runs. `max_tokens` is recorded per call.
8. **A truncated check looked like a strict check.** `check_card` maps an unparseable reply to identity rejected with nothing kept. Production behaviour is kept, but the runner now sets `unusable` (checks) and `parse_ok` (drafts) for gate 5. The summary excludes rows where the legacy Sonnet fell back to Haiku.
9. **The decision rule could be gamed.** A checker that keeps nothing wins on FK. New gate 8: U ≥ 2.5, or ≥ 80% of the live pair's U.
10. **Panel rules.** Citations are now required: a supported or contradicted label without a URL and quote becomes unverifiable, and the adjudicator checks quotes. Planted recall now counts fabricated plants and mutations of supported facts as known false; before, only "contradicted" counted, which drops most fabricated plants. The panel's isolation is enforced on disk: no `results.json`, `panel_key.json` or design files in its reach. The design must be committed and hashed before the paid run.
11. **Sample class bug.** The `variant` class missed its own example: Burang/Purang scores 0.833, below the 0.85 threshold. The threshold is now 0.8 for names of up to 8 letters.
12. **The dry run did not check its assumptions.** It now prints the live `llm_role_config` route of both stages, with a warning if the incumbent is no longer Luna + Haiku, and the observed 30-day average and p90 output tokens for each eval key.

## Remaining risk (not fixed)
- **Prices.** The Bedrock prices for Opus 5.5 and the 5.5 Haiku/Sonnet are list prices that have not been verified. The cap uses the same catalog prices that `llm_call_log` records, so real spend could be above $3.00 if Bedrock charges more than list.
- **Output tokens are assumed.** If the 5.5 models or Opus think more than about 600–1,000 tokens, tiers D and E get cut. C4 then fails gate 6 by rule, not on merit. Read `CALIB_MODEL` in the dry run before paying.
- **n = 30.** Only large differences can be detected; the tie band and Wilson intervals are in §7.
- **No cross-border class.** This was the S232 failure mode. It is only partly covered by the homonym and variant classes; the panel's `country` field still measures it.
- **Linked drafts.** When a draft would link to an existing card, production keeps the existing card's facts. The eval scores the draft's own facts, and `would_link` lets the analysis split these cases out.
- **Long run inside the api task.** Merge or hold any pending CIS backend PR first. `nohup` survived in S234; a SIGKILL from a deploy is covered by `resume`.
- **Role on gateway-logged unusable rows.** These rows carry role `writer` for checks too, because the adhoc stage has no `llm_role_config` row. This affects cost attribution only.
- **The panel is agents, not humans.** An optional human spot-check of 20 labels is recommended before the result decides a route migration.
