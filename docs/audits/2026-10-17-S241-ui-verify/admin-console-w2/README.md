# S241 UI verify: admin console W2 on Dev (17/10/2026)

This is a read-only check of the admin console wave 2 on Dev:

- **CIS** `main` c2f9e919 (PR #794: AA-882 GĐ3 staff policy, AA-883 Platform / CIS Content sections and the read-only Staff directory) at https://aa-cis.lumiguides.it.com. CI, Deploy Dev and Vercel Deploy for c2f9e919 all show success.
- **Booking admin** `main` 26da312 (PR #30: "CIS console" topbar link) at https://aa-booking-admin.vercel.app. Its Vercel Deploy run for 26da312 shows success.

The build was confirmed by behaviour: the section headers, `/admin/platform/staff` and the `topbar-cis-console` link are all new in those commits.

- **Tooling.** Headless Playwright Chromium on node 22, with a fresh context for each width and theme. Scripts are in the session scratchpad (`uiv/w2/w2.mjs`, `uiv/w2/w2sup.mjs`, `uiv/w2/api_roles.py`), not in the repo. Raw measurements are in `results.json` here (`ui`, `ui_supplement`, `api_roles`).
- **Accounts.** The UI admin was `e2e-claude-code` (`aa-cis/dev/e2e-test-admin`). `aa-cis/dev/e2e-test-admin-2` is `e2e-claude-code-2`, which is **also role `admin`**. The Staff directory has no active reviewer or content *test* account: `trang` is a real reviewer, and `s226_rev_ui` is a reviewer but inactive. So the reviewer and content checks ran **at API level**. Each call sent `aa-cis/dev/admin-secret` to https://api-cis.lumiguides.it.com with `x-admin-role: reviewer | content | admin` or with no role (machine). Secrets were read into process memory only and were never printed or saved. The saved JSON was scanned afterwards for the password and the admin secret, with 0 hits.
- **Writes.** The UI runs aborted every non-GET request except the login POSTs: 3 CIS logins and 3 Booking logins through Booking's own form, which uses the CIS account. `blocked_writes` is empty in every run. The API run sent GETs plus 4 × `PATCH /admin/llm-config/t9_write` with an **invalid body** (`model_id` missing). The `t9_write` row was the same before and after (`sonnet` / `acc3`, `updated_at` 2026-09-02, `updated_by` `system-seed-aa518`). Nothing was clicked that saves anything: no lifecycle, Save, New, DOCX or route buttons.
- **Leak scan.** Before every screenshot, the page text was checked for the password, Mapbox `pk.eyJ…` tokens and JWTs. There were 0 hits, and every screenshot was written.
- **Themes.** Light and dark come from `colorScheme` emulation plus `localStorage.cis_theme`. Widths are 1440×900 and 390×844.

## Observations (not failures)

1. **No reviewer/content UI test account.** The UI side of role hiding (the sidebar showing only CIS Content with no section headers, the BottomNav without Overview/Jobs, the Settings tabs, Master Content buttons, brand read-only) was checked in code, not rendered. The backend half was checked live (3a–3f). An e2e reviewer account (design §7 GĐ4 `smoke-reviewer`) would close this gap.
2. **Staff table has no `id` column.** The id is in the drawer ("Account id") and in the deep-link URL. The columns are Username / Role / Status / Created / Updated / Booking.
3. **Settings breadcrumb reads "Admin / Settings".** Settings is the standalone footer entry outside both sections (design GĐ6 splits it later), so it has no section root.
4. **Notification count scoping is untestable on current data**, because there are 0 unread rows for every role (3e). The list scoping is proven.
5. **The Booking 390 topbar shows the CIS console link as an icon only.** This is intended by the `.aa-topbar-cis-label` media rule; it keeps its `aria-label` "Open the CIS console (new tab)".
6. Opening Booking admin from the CIS sidebar without a Booking session lands on Booking `/login`. This is expected until Cognito SSO (the link tooltip says so).
