# AA-Ecosys documentation

AA-Ecosys is the Adventure Asia platform: four apps on one AWS account (acc2) - **AA-CIS** (content and catalog),
**AA-TripPlanner-Web** (traveller front door), **AA-Booking** (customers, trip cases, pricing, payments) and
**AA-Partner** (partner agencies' CRM and the tenant portal) - plus the Terraform repo **AA-CIS-Infra**. Model calls run on Amazon Bedrock in acc3; acc1 is no longer part of the
ecosystem (AA-998). Today there is only a **Dev** environment, holding **test data only** (D-01).
Prod will be a separate RDS instance in its own AWS account, `aa-prod` (ADR 0018, C7.2a, D-17), dated when go-live is set (AA-880).

This page is the doc catalog (AA-887). Git is the only source. Google Drive holds PDF exports for the business owner.
The admin docs page `/admin/docs` (AA-898, live) shows the catalog pages and ADRs of this repo
([publication rule](#admin-docs-page-allowlist-aa-898)). How to write a page: [STYLE](STYLE.md).
Templates: [`templates/`](templates/). Terms: [glossary](glossary.md).

## How to read the catalog

- **ID**: stable key used in front-matter `id` (a page under an entry adds a suffix, e.g. `OPS-02-cis`).
- **Type** (Diátaxis): Tut = tutorial, How = how-to, Ref = reference, Exp = explanation, Rep = report.
- **Mode**: H = hand-written, G = generated by a workflow, H+G = hand-written prose with generated tables.
- **Owner**: `nghiep` (the tech lead) approves, Claude Code drafts and updates, unless stated. Generated pages are changed only by
  their generator's PR.
- **Review**: the `review_every_days` value (days) or the event that forces a review.
- **Audience**: O = owner (the business owner, CEO), E = engineer, D = DevOps, CT = CTO, CI = CIO, P = PM, A = agent. It is a
  navigation filter, not access control.
- **Repo**: root = AA-Ecosys, INF = AA-CIS-Infra, CIS / BK / TP / Partner = app repos. The app repos are
  **public** (public-safe content only, see [where a page may live](STYLE.md#where-a-page-may-live-sec-06)); root and
  Infra are public too since 22/10/2026 until the coding phase ends ([ADR 0014](adr/0014-repo-visibility-and-github-plan.md)
  amendment), so every new commit there follows the public-repo no-secret rule for now.
- **Language**: every page is English. A Vietnamese translation sits next to its page as `<name>.vi.md`, with the
  same ID, `lang: vi` and `translation_of` ([STYLE, Language](STYLE.md#language)). The catalog lists the English page
  only; translations today: [engineering handbook](engineering-handbook.vi.md), [glossary](glossary.vi.md),
  [CEO guide](guides/ceo.vi.md), [legal readiness packet](legal/readiness-packet.vi.md).
- **People**: company docs name roles, not people: the tech lead, the business owner (CEO), the engineer on duty.
- **Status**: `exists` = page is in the repo (front-matter added or not); `planned` = page not written yet, with
  the issue that writes it. S241 roadmap items (U-xx) are named so nothing is built twice.

## Outside the catalog (journals)

## Admin docs page allowlist (AA-898)

The CIS admin docs reader (`/admin/docs`, Platform › Developer › Docs, admin only) shows a bundle that
[`docs-sync.yml`](../.github/workflows/docs-sync.yml) builds **from a CI checkout** of `master` (tracked files only,
never a laptop) with [`tools/docs/build_docs_reader.py`](../tools/docs/build_docs_reader.py) and uploads to the bronze
bucket prefix `docs-reader/`. Publication rule v1 (the script header is the source):

| Rule | What it means |
|---|---|
| Catalog pages and ADRs only | A page is published when it has catalog front-matter (`id`, `title`, `type`) or is an ADR (`docs/adr/NNNN-*.md`); everything else is a draft or a journal |
| Never published | `docs/sessions/`, `docs/audits/`, `docs/implementation-notes/`, `docs/backlog/`, `docs/research/`, `docs/calib/`, `docs/backups/`, `docs/security/`, `docs/templates/`, `docs/archive/`, `docs/linear-export/`, and any page with `status: archived` |
| Owner only (N-3) | Catalog IDs `SEC-*` outside `docs/security/` (privacy, legal, secret rotation) and the generated infrastructure maps `ARCH-02` (network), `ARCH-03` (inventory), `ARCH-04` (IAM roles): the API lists and serves them only to a staff member with the owner flag on a verified Cognito session |
| Redacted | 12-digit account IDs (also inside bucket names and ARNs), VPC resource IDs, Cognito user-pool IDs, API Gateway host IDs and AWS access key IDs become `[redacted-…]`; a guard re-scans the bundle and fails the build if one is left |
| Navigation only | `audience` filters the list; it is never an access control |
| SVG images (AA-697) | A tracked `docs/**/*.svg` outside the never-published folders is published byte for byte under `assets/` when it is safe (no script, `foreignObject`, event handler or outside reference; only fragment links and inline PNG icons) and its text has no account or resource ID; an unsafe SVG fails the build. Assets are staff tier, so an SVG never carries owner-only content |
| Translations (S255) | A `<name>.vi.md` page is published only when its English page is, with the same ID and access tier. Each manifest entry carries `lang` (`en` or `vi`); an English entry lists its `translations` (`lang`, `path`, `key`, `title`) and a translation names its English page in `translation_of`, so the reader lists English pages and offers an EN/VI toggle |

v1 is stricter than the S243 wording for security and audit pages: they are not synced at all (security reports and
audit evidence stay in git). Only this repo is published for now; Infra pages can be added as a second `repo` in the
manifest later. The prefix lives in the existing bronze bucket (`App=cis`, SSE-S3, Block Public Access), so there is
no new bucket; cost under 0.10 USD a month (AA-CIS-Infra `accounts/aa365/docs_reader.tf`).
