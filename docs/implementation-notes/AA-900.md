# AA-900 — LLM operations: generated route table and pointers (root part)

The CIS part (prompt register, eval runbook, `--stage adhoc_aa900` on the R2 runner, PR template section) is the
AA-CIS-App PR of the same issue; its note is `AA-CIS-App/docs/implementation-notes/AA-900.md`.

## Decisions

- **Route table lives in the root repo** (`docs/generated/llm-routes.md`), as the catalog row APP-06 already planned:
  the gateway tables are shared by CIS and TripPlanner (`tp_*` stages), so the table is ecosystem-wide.
- **Input = a committed snapshot, not the migrations.** About 34 CIS migrations write `shared.llm_role_config` and 15
  write `shared.llm_model_catalog`, and the admin edits both at runtime in CIS Settings, so a replay of migration seeds
  would not be the live state. The generator reads the two tables read-only (as `cis_app` inside a CIS container) and
  prints a snapshot; `import` turns the exec output into `docs/generated/llm-routes.snapshot.json` and the page.
- **The check runs in the existing docs-lint step**, with no workflow change: `tools/docs/test_llm_routes.py` holds a
  test that `check()` is clean on the committed pair (page == render(snapshot), snapshot normalised, no account ID or
  ARN), and the "Unit tests of the lint tools" step runs every `tools/docs/test_*.py`.
- **Public-repo safety:** `bedrock_profile_ids` is reduced to its account keys (the values can be ARNs), `updated_by`
  (a person) is never read, and any 12-digit number or ARN left in text is replaced at dump time and refused by
  `check`.
- **First commit carries an empty snapshot.** This lane cannot read the database (no ECS exec for subagents), so the
  page says "No snapshot yet". The orchestrator captures the live snapshot (live step in the lane result) and commits
  the pair on this branch before pushing.
- **Handbook §5.7** now names the register, the route table and the runbook, and drops the "AA-900 is to be narrowed"
  note (it is narrowed). The Vietnamese translation is updated in the same PR. `skill/aa-ship` gets the pointer in the
  pre-merge checklist and a verify-live step 8.

## Tradeoffs

- A snapshot goes stale when someone changes a route in admin Settings and does not re-capture. The page shows the
  capture time and `review_every_days: 30`; the runbook and aa-ship ask for a re-capture after a route change. An
  automatic capture (for example inside the nightly DB Schema Dump task of AA-CIS-Infra) would remove the manual step
  but is an Infra workflow change, left for later.
