# AA-871 — Implementation notes (root repo: secrets register)

## Decisions
- Three new register rows, status `planned` (flip to `keep` once each exists): `booking/dev/sentry-dsn` and
  `tripplanner/dev/sentry-dsn` (Secrets Manager shells from AA-CIS-Infra `feat/aa871-sentry-secrets-uptime`), and
  Vercel `aa-tripplanner` `SENTRY_DSN` (server-only, read by `frontend/lib/sentryLite.ts`). The Sentry vendor row lists
  the new consumers. md and yaml rows stay twins.

## Changed
- Nothing beyond the register; the Terraform and the TripPlanner reader are in their own repos.

## Tradeoffs
- `planned` (not `keep`) so the drift check does not report MISSING before the apply; after the apply it reports
  PLANNED-NOW-PRESENT until flipped.

## Should know
- DSNs are low sensitivity (ingest-only) but follow the same rule as other credentials: no value in a repo, the Lambda
  env or Terraform state. TripPlanner Lambdas read theirs by name at cold start; Booking maps its into the task only
  when `booking_sentry_enabled = true` (after the value exists).
