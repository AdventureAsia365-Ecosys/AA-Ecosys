# AA-893 — Generated alarm catalog and infra tables (root side)

Full notes: AA-CIS-Infra `docs/implementation-notes/AA-893.md` (generator, workflow, IAM, plan).

## Decisions

- The four generated pages live here, in `docs/generated/` (`alarms.md` OPS-07, `network.md`
  ARCH-02-tables, `inventory.md` ARCH-03, `iam-roles.md` ARCH-04-tables), written by AA-CIS-Infra
  `docs-gen.yml` through a bot PR (branch `bot/generated-infra-docs`), like the DB schema reference. The
  catalog said `INF docs/generated/...`; the Linear issue said "bot PR into root". Root wins because the
  runbooks are here (relative links checked by this repo's lint) and a bot PR into Infra could not pass
  its required checks. Catalog rows OPS-07, ARCH-02, ARCH-03, ARCH-04 updated.
- New lint `tools/docs/check_alarm_runbooks.py` (docs-lint step "Alarm runbook links"): every alarm row
  has a runbook link to an existing file under `docs/`. It fires on the bot PR (bad Terraform link) and
  on any docs PR that renames or deletes a runbook an alarm points to.

## Changed

- `docs/generated/*.md`: first render, from the read-only plan JSON of the Infra branch (state after
  its apply), not hand-edited. The bot PR replaces them from the state.
- `.github/workflows/docs-lint.yml`, `tools/docs/README.md`, `docs/README.md`.

## Tradeoffs

- The pages hold resource IDs, ARNs and Cognito client IDs. Fine in this private repo (generated pages
  are exempt from the resource-ID lint); never copy them into an app repo.
