# AA-1132 — Docs sync engine (slices A1, A2, A4)

Lane l11-aa1132, S284 (Claude Code). Advisory: `docs/audits/2026-11-17-S283-docs-advisory/README.md` sections 2 and
4.2; tech lead choices S283: one central doc map in the root, docs-impact warns only, no DVC.

## Decisions

- **A1 builds on AA-1133.** Rule 11 already fetched the whole history (blobless) and wrote `last_changed`. A1 turns
  that one `git log` walk into `git_history()`: each entry gets `history` (newest 10 commits: sha, date, subject, PR)
  and `last_changed` stays `{sha, date}` of the first item, so the CIS reader keeps working unchanged.
- **Commit subjects are cleaned before a reader sees them:** the "(#123)" suffix becomes `pr`, issue keys
  (AA / KAN / CON / PR) are removed (no internal issue id in UI), IDs are redacted, and the subjects go through the same
  guard as the bodies.
- **"What changed in docs" is a generated bundle page, not a file in git** (`docs/generated/docs-changes.md`, id
  `CAT-00-docs-changes`). A committed page would need a bot PR on every docs merge; the bundle is rebuilt on every
  docs merge anyway. It lists hand-written pages only (the nightly ERD / schema regenerations would fill it), links
  staff-tier English pages and counts owner-tier pages without naming them, and is left out of the search index.
  A tracked file at that path fails the build.
- **A2 facts come from files already in this repo, never from AWS in CI.** `platform.yaml` holds the human
  decisions (account roles by label, LLM provider order, App tag -> repo); the ECS services come from
  `docs/generated/inventory.md`, which AA-CIS-Infra Docs Gen already renders from the Terraform state and commits
  here. `gen_sections.py` collects both into `docs/generated/facts.snapshot.json`; every block renders from the
  snapshot only, so `--check` is deterministic.
- **A snapshot behind the inventory warns, behind `platform.yaml` fails.** The nightly Infra Docs Gen PR changes the
  inventory and must stay green to merge itself; a human PR that edits `platform.yaml` can always run `--write`.
- **Block markers are HTML comments** (`<!-- gen:name -->` … `<!-- /gen -->`): GitHub and the CIS reader hide them,
  the rendered Markdown reads normally; a marker inside fenced code is text (so docs can show the syntax).
- **First blocks:** `accounts` and `llm-route-order` in `docs/ecosystem-architecture.md` (replacing the hand table and
  the route sentence), `ecs-services` and `llm-route-order` in `docs/guides/devops.md` (the hand list missed the two
  staff admin services and the TripPlanner web, and still said chat models run on acc3).
- **A4 map seeding:** 85 audit rows cite code paths as evidence. Seeded once by a lane script (not committed): a
  historical migration file became its topic glob (`*_llm_*.sql`), doc-to-doc citations, ADR and template pages were
  dropped (dated records / examples), and three globs that match nearly every PR (`web/app/**`, TripPlanner
  `backend/**`, Infra `accounts/**`) were dropped. 19 hand entries carry the audit's eight drift groups (ECS services,
  account roots, migration flow, LLM gateway, job kinds x4, deploy workflows x4, root tools) plus one per app repo for
  its own caller workflow, so each caller PR shows the warning once (the live proof).
- **A4 check:** `doc_impact.py github-pr` lists the PR files through `gh api` (no checkout of the app repo), posts one
  sticky comment (marker `<!-- docs-impact -->`; created on the first open entry, updated afterwards, set to "no docs
  impact left" when resolved), prints `::warning` annotations (`::notice` once the PR body has a `Docs-impact:` line)
  and writes the run summary. It exits 0 on every path; the step is also `continue-on-error`.
- **Reusable workflow** `.github/workflows/docs-impact.yml` (`workflow_call` + this repo's own `pull_request`): the
  job runs only on `pull_request`, so the callers' `merge_group` runs skip it; never a required check. Map and tool
  come from root master (one current map), or from the PR head on a root PR.

## Changed

- `manifest.previous.json` (advisory A1 item 5) is not done: the docs-sync role has Put/Delete but no Get on
  `docs-reader/`, so an S3 copy of the old manifest needs an Infra IAM change first (follow-up).
- Advisory L2 said the nightly catalogue job writes the snapshot through a bot PR; not built here. `--write` is run
  in docs PRs; the inventory drift warning tells when. A nightly bot PR is a follow-up (A3).
- Advisory L3 asked for a `Docs-impact:` line in every PR body and a required check after two weeks; the tech lead
  chose warn only (A8 out). The line is optional: it only turns warnings into notices.

## Tradeoffs

- `HISTORY_MAX`, `CHANGES_MAX`, `SUBJECT_MAX` are build-output sizes of a CI tool in the root repo, which has no admin
  settings store; they are constants with a comment, not runtime policy.
- No `--follow`: a renamed page starts a new history (cheap single walk; renames are rare).
- The map is read from root master by every repo: a map change takes effect for app PRs on merge, no re-pin.
  The caller workflows pin the reusable workflow file to a root commit (WL6); only a change of the workflow file
  itself needs a re-pin in the five callers.
- `infra-ecs-services` maps all of Infra `modules/environment/**`: broad, but it is the largest drift group (69
  stale sentences). Narrow it if the warning turns into noise.
- PyYAML is installed without a pip cache in the reusable job (one small wheel, seconds; a cache would be saved per
  caller repo and the WL4 rules make it default-branch only anyway).

## Should know

- The CIS reader does not show `history` or the changes page links yet (reader slice B5); the changes page already
  shows up as an ordinary page in the reference group.
- Generated blocks: never edit by hand; `python tools/docs/gen_sections.py --write` after changing
  `platform.yaml` or when the docs lint warns that the inventory moved on.
- The caller PRs in the five app repos pin the root commit of the reusable workflow; after the root PR squash-merges
  they must be re-pinned to the master merge commit before they ship (see their PR bodies).
- Settings rule (S279): no new runtime threshold here; `HISTORY_MAX` / `CHANGES_MAX` / `SUBJECT_MAX` and the
  three-file display limit of the PR comment are output sizes of root CI tools, and the root repo has no admin
  settings store.
