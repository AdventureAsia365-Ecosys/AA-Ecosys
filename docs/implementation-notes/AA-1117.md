# AA-1117 — One dated go-live gate (S294, lane l5-golive-gate)

## Decisions

- **Where the list lives:** `docs/ops/go-live/checklist.yaml` (source) and `docs/ops/go-live/README.md` (catalog page
  `PROD-01-go-live-gate`, the rendered table between `golive-gate:begin` / `golive-gate:end` markers). The markers are
  not `gen:` blocks: `tools/docs/gen_sections.py` renders only from its facts snapshot, and this table renders from
  the checklist, so it has its own tool and its own sync check.
- **The S260 OPS-17 report is a dated snapshot, so it is linked, not rewritten.** OPS-17's channel is a new
  `docs/audits/<date>-S<nnn>-go-live-readiness/` folder per run (`docs/reports/catalog.yaml`), and the docs tools treat
  `docs/audits/` as journals. The report (and its `.vi.md`) gets one dated note in section 3 pointing at the live gate.
- **proof vs refs:** `proof` is evidence that the line is met (non-empty = met); `refs` is evidence so far or the
  method to copy (a Dev drill for a prod item). Derived status, no separate `status` field to drift.
- **Owner roles:** tech lead, business owner, engineer on duty (the language convention's roles). A name fails.
- **Anchors are checked:** `#heading` against GitHub-style slugs of the Markdown headings (fenced code skipped,
  duplicates `-1`), `#L<n>` against the line count. A renamed heading turns the gate red, like a deleted file.
- **Go-live date line:** one `kind: date` line; `value` may stay null only with an owner. Once a date is set, an open
  line due after it fails, and reaching the date with open lines fails. If the date line gets a `due` and it passes
  while the value is still null, that fails too (left without a `due` today: no agent-made deadline on the business
  owner).
- **Due dates** are planning dates set on 2026-11-25: decisions and Dev proofs mid/late December, build items
  2027-01-15 with a `due_note` (build week N). The checklist header says to re-date every open line in the PR that
  sets the go-live date.
- **Stdlib only:** a small YAML-subset parser (block mappings and sequences, plain/quoted scalars, `[]` flow lists,
  comments); anything else is an error with a line number. A unit test compares it with PyYAML on the committed file
  when PyYAML is installed (docs-lint has it), so the subset never silently misreads.
- **Workflow:** PRs touching `docs/ops/go-live/**`, the tool, its test or the workflow, plus Monday 02:17 UTC and
  `workflow_dispatch`. No secrets, no AWS, `contents: read`, checkout pinned by SHA like the other root workflows.

## Changed

- Scope asked for "~16 lines": the file has 17 gate lines + 1 date line. Added GL-10 (the one-tenant restore drills
  that already passed on Dev: CIS, TripPlanner, the CRM pilot agency) as the one met line, so the three existing drill
  proofs are linked as proof; the Booking per-partner drill (GL-11) and the prod drill (GL-04) stay open and cite them
  as method.
- The edge rate-limit line (GL-13) records that the S286 D10 decision already exists (regional rate rule now, a
  CloudFront web ACL when prod starts); what is open is the prod ACL with its cost in the reconciled prod figure.
- `docs/ops/README.md` (Prod section) and the `docs/README.md` catalog row PROD-01 link the new page.

## Tradeoffs

- A fixed ISO due date on build items that really depend on an unset go-live date: the issue asks for owner + ISO
  date on every open line, and a red weekly run when the date passes is the point (it forces a re-date). Relative dates
  ("go-live minus 7 days") were rejected: they never go red while the date is unset.
- The PR trigger is path-filtered, so deleting a proof file elsewhere is caught by the weekly run, and also by the
  docs-lint unit-test step (`tools/ops` tests run there, and `test_committed_checklist_is_valid_as_of_its_update`
  checks every link). Past-due lines are deliberately not part of that unit test (evaluated on the `updated` date), so
  an overdue line never reddens unrelated docs PRs.
