# AA-1132 — Docs sync engine, slices A3, A5, A6, A7, A9 (lane l14, S284)

Follows root PR #875 (A1, A2, A4; notes in `AA-1132.md`). Advisory: `docs/audits/2026-11-17-S283-docs-advisory/README.md`
sections 2 and 4.2. The CIS docs reader UI (showing `needs_review`) is another lane; this lane only writes the data.

## Decisions

- **A3 facts from other repos are collected, then stored.** `tools/docs/repo_facts.py` reads app versions
  (`.release-please-manifest.json`), job kinds, backup days and workflow names statically (Python `ast` with a small
  cross-module constant resolver, an HCL regex), from a folder or a git ref (`--repos-ref origin/main`, so a dirty or
  stale local checkout is never read). `gen_sections.py --write --repos-root <ws> [--github]` stores them in
  `facts.snapshot.json` (schema `aa1132-facts/2`); without the options `--write` keeps the stored values, so a docs PR
  never needs the other repos. Required checks come from `gh api` (classic protection + rulesets, read only).
- **Latest migration per owner comes from the live schema dump** (`db-schema-reference.md` "Verified" line), not from
  the migration files: docs should say what is applied on Dev. It refreshes through the schema dump bot PR (drift =
  warning, like the inventory).
- **CIS job kinds:** every `@job_kind(...)` under `services/jobs/` (top level only), flags resolved through module
  constants and imports, defaults read from the `JobKind` dataclass. The retention kinds (registered in a loop over a
  registry) are read from the registry's `kind="..."` keywords. A registration it cannot resolve is shown as a note
  under the table, never a failure. Today: 65 CIS kinds, 0 unresolved.
- **`docs/ops/job-kinds.md`:** the kind lists became generated blocks per owner; the hand tables kept only the notes
  (paid calls, switches). Rows for kinds that no longer exist (the B2C Booking kinds) left the notes; "planned" was
  removed where the kind is now registered (CIS `tenant_erasure_saga`, Booking `bk_tenant_erase`, CRM
  `crm_tenant_erase`, TripPlanner erase / backup).
- **Blocks wired:** `latest-migrations`, `app-versions`, `required-checks`, `backup-days` in `docs/guides/devops.md`;
  `required-checks` in `docs/ops/README.md`; `backup-days` in `docs/ops/runbooks/restore-schema.md`. The stale
  "7-day PITR" sentences on those pages now point at the block (Dev keeps 14 days since Infra #694).
- **A5 needs_review is computed from git only.** A page needs review when a commit in the repo of one of its doc-map
  entries touched the entry's code after the page's own last commit (a commit that touches both does not count).
  Docs sync clones the five other repos bare and blobless (commits + trees, a few MB, seconds) for their history; a
  repo without history is listed under `repos_not_checked`, never guessed. Manifest: per-page `needs_review` and a
  top-level `freshness` summary (rule 15 of `build_docs_reader.py`); a failure there never fails the build.
- **`doc-owners.yaml`** registers the files without front-matter (root agent rules, skills, steering, every repo's
  `CONTEXT.md` and `.claude/CLAUDE.md`), with globs for root files. `last_reviewed` is optional (default: the file's
  last commit), so no invented review dates were written.
- **A7 rules:** only `tf-address` is an error in docs lint (0 findings after the two runbook fixes, no false positive
  found); paths, services, job kinds, settings keys, migration numbers and workflow names warn (87 warnings today,
  mostly true staleness, some app-repo paths without a repo name nearby). Lines whose prose says a name is gone
  ("retired", "deleted", "was" ...) skip the name rules.
- **A9:** a new image under `docs/audits/` must be WebP or PNG and at most 300 KB (the reader's screenshot cap, the
  same constant); JPEG / GIF / BMP / TIFF are refused with "convert to WebP". Files already in git are never re-checked.
- **A6:** the rules live where agents read them: `skill/aa-ship` (Docs item), `tools/workflows/lane.js` `COMMON` (the
  lane brief; `parallel-lanes.md` points at it), `.claude/skills/kiro-delegate/brief-template.md`, the session close
  step in `skill/aa-session` (refresh the facts, freshness report, scoped docs review of the session's merges), and a
  warn-only `docs-impact` step in `scripts/pre-push.sh`.

- **Review fixes (same lane, after the independent review):**
  - The nightly catalogue job's CIS sparse checkout now includes `api/services`: two CIS job modules take their kind
    name from there, and without it the sparse read dropped two kinds and always warned. `repo_facts.READ_PATHS` lists
    what the readers open per repo; `test_repo_facts.py` checks the workflow cone against it and, when the local
    workspace is there, compares a sparse read with a full read of `origin/main` (skipped in CI).
  - `--write` keeps a repo's stored `collected_from` head when that repo's facts did not change
    (`repo_facts.keep_heads`), so a heads-only move rewrites neither the snapshot nor a page (no no-op docs commit that
    would also clear `needs_review`). A repo whose facts changed gets its new head; the others keep theirs.
  - `doc_impact.py check` gains `--repo-dir` (the checkout to diff) and `--head` (diff `base...head`); a failed
    `git diff` is a warning, not a traceback. The session close step takes its base from the first main commit of the
    session (`git rev-list -1 --before=<session start> origin/main`) and diffs it to `origin/main` in that repo's
    checkout, so the checkout need not be reset first.

## Changed

- The advisory's critique (section 6) proposed merging `doc-owners.yaml` into `doc-map.yaml` and dropping the
  `Verified:` rule and most of A7; the lane brief asked for all three, so they are built, warn-only where the critique
  feared noise.
- The `Verified:` rule warns (never fails): a PR that raises `last_reviewed` (front-matter or a `doc-owners.yaml` row)
  without a `Verified:` line in its body gets a warning in docs lint.
- `manifest.previous.json`: the Docs sync upload keeps the manifest it replaces (download + upload). It needs the
  Infra grant (`s3:GetObject` on `docs-reader/manifest.json`, separate Infra PR); until it is applied the step only
  prints a notice.
- Runbook fixes found by the new check: `crm-keys.md` and `secret-rotation.md` targeted addresses that moved into
  `module.environment` (AA-1004).

## Tradeoffs

- The repo facts refresh at session close (and the nightly Catalogue run warns on drift), not through a nightly bot
  PR: a bot PR needs the `aa-ci-bot` token and an auto-merge path in the root repo; follow-up if drift stays common.
  The nightly check does not read GitHub required checks (the default token may not see another repo's protection);
  the session close step does, with the tech lead's `gh`.
- `CHANGES_SHOWN` (5) and `DEFAULT_REVIEW_DAYS` (90) are output sizes / the front-matter default of root CI tools; the
  root repo has no admin settings store (S279 rule), so they are constants.
- A page's own commit resets its flag, even a regeneration of its `gen:` blocks; precise "reviewed" signals need the
  `Verified:` line or the session-close review.
