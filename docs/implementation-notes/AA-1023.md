# AA-1023 — Implementation notes (root repo, lane l14: rollback runbook, game day plan, helpers)

The AA-CIS-Infra part (job-idle gate in `terraform-apply.yml`) keeps its own `docs/implementation-notes/AA-1023.md`
in that repo.

## Decisions

- **One parameterised runbook, app pages kept.** `docs/ops/runbooks/rollback-ecs.md` (OPS-02-ecs) holds the shared
  procedure and a per-service table (image tag form, images kept, health URL and the field that carries the commit,
  job table). `rollback-cis.md` and `rollback-booking.md` stay for their app facts (CIS: two services on one image) and
  link to it. CRM api/web/portal had no runbook; they now point at `rollback-ecs.md`.
- **Helper `tools/ops/ecs_rollback.sh`, dry run by default.** It reads the service, resolves the target
  (`--previous`, `--to <rev>`, `--to-sha <sha>`), checks it (ACTIVE, a real build, image still in ECR, configuration
  names), and prints the one-line `update-service`, wait, verify and way-back commands. Only `--apply` writes; it then
  waits for services-stable, checks the service is on the target with rollout COMPLETED and reads the health endpoint
  until it reports the target SHA. Bash + jq + AWS CLI like `tools/ecs/ecsx.sh`, so it runs where the runbooks run.
- **Terraform template revisions are never a target.** A live read-only `--list` on 2026-11-02 showed
  `aa-booking-dev-api:92` and `aa-crm-dev-api:116` with image tag `bootstrap` between real builds (registered by
  Terraform applies). A plain "current minus one" would have rolled Booking onto the template. `--previous` skips them
  and `--to` refuses a placeholder tag.
- **Configuration difference blocks `--apply` unless `--allow-config-diff`.** It prints only names (env names, secret
  names), never values or ARNs. Live: every older Booking build lacks `ALERTS_TOPIC_ARN` (added by a later Terraform
  apply), so the Booking drill needs the flag; the game-day plan says why that is acceptable on Dev.
- **Game day seed for the gate proof:** `tools/ops/gameday_seed_job.py` inserts one `noop_sleep` row (the Dev-only test
  kind, `deploy_gate_exempt`, touches no data) tagged `created_by = aa1023-gameday`, run through `tools/ecs/ecsx.sh`
  as `cis_app`. It touches only its own rows and refuses a second open row. The row ends by itself after
  `SLEEP_SECONDS` (default 900) only when the worker runs with `JOB_TEST_KINDS=1` (the kind is registered only then);
  on the normal Dev config it stays queued and blocks the idle gates until `ACTION=clear`, so the game day makes the
  clear + `OPEN_COUNT 0` a mandatory step and evidence line, and the seed watches the row for `CLAIM_WAIT_SECONDS`
  (default 15) and prints `CLAIMED` or `UNCLAIMED` (review fix). Columns from `docs/architecture/db-schema-reference.md` (`shared.job`), defaults from
  CIS migration 174. `SLEEP_SECONDS`, not `SECONDS` (a bash special variable).
- **Vercel drill target `aa-booking-admin`, Lambda drill target `aa-tripplanner-dev-browse` only:** the least-used
  production frontend, and one function is what the issue asks for (path B on one function; both functions are
  independent zips).

## Changed (vs. the issue text)

- The issue's `environment: prod` -> `dev` rename (N15) is not in this lane: the environment name is part of the OIDC
  subject the bootstrap apply role trusts (local MFA apply) and the environment holds the secrets. Follow-up.
- Root CI: `docs-lint.yml` now also runs `tools/ops` tests and triggers on `tools/ops/**`.

## Tradeoffs

- A helper in bash rather than Python: matches `ecsx.sh` and the AWS CLI one-liners the runbooks print; tests drive it
  with a scripted `aws` and `curl` on PATH (no AWS, no network).
- The helper verifies the commit through the public health endpoint; the CIS worker has none, so it only checks the
  rollout (the runbook adds the `job_worker_started` log line).
