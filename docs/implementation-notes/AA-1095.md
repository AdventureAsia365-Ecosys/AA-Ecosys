# AA-1095 — Implementation notes (root repo: ADR note, docs, the route switch run-script)

The CIS (`docs/implementation-notes/AA-1095.md`: migration 406, registry-driven account directory, the pure
per-family order `api/services/llm_family_order.py`) and AA-CIS-Infra (`accounts/acc1-bedrock`, the assume grant,
env `BEDROCK_ACCT_PAYER`) lanes keep their own notes.

## Decisions

- **ADR 0001a gets a Note S278**, not a new ADR: the reversal is narrow (Bedrock chat serving only) and temporary
  (until acc3's AWS case is solved); the note states scope, evidence, route order and the reversal steps.
- **The route switch is a root run-script** (`tools/llm/aa1095_acc1_route_order.py`), run in the CIS api container
  by `tools/ecs/ecsx.sh`: CIS `tests/unit/test_aa998_no_acc1_runtime.py` refuses the `acc1` key in CIS `scripts/`,
  and the switch is a one-off ops action. The order itself comes from CIS (`llm_family_order.family_provider_order`).
- **DRY RUN by default**; `APPLY=1` switches connection `acc1` on (audited `set_enabled`), then saves ONE
  route-control version (`llm_route_control.apply(action="save", order_mode="model_first", provider_order=...,
  break_glass_reason=...)`). A refused save switches the connection back off (unless it was on before).
- **Enable first, then save**, as decided by the orchestrator: the save's preview then sees the new serving model
  per stage, so the break-glass evidence is recorded on every writer / judge stage whose first model@connection moves.

- **GPT order recorded as it behaves (review fix pass).** The decision said "GPT: acc1, then the OpenAI API, then
  acc3 behind or disabled". A Bedrock GPT model has no OpenAI API deployment (an OpenAI connection serves only
  OpenAI catalog rows); its OpenAI API path is a twin model behind it on the chain, so the model-first walk is
  gpt@acc1 > gpt@acc3 > twin@openai-direct. While acc3 refuses the calls are the decided ones; a recovered acc3 is
  tried before the OpenAI API. Chosen: correct the record (ADR note, architecture page, run-script docstring) and ask
  the tech lead's OK in the PR body, instead of switching the acc3 GPT deployments off: no audited per-deployment
  switch exists (only connection switches and route-control versions), a raw UPDATE would skip the audit and the
  one-click revert. Follow-up if he wants "disabled".
- **Account map consistency (review fix pass):** `docs/onboarding.md` (account map intro + History line) and ADR 0001
  (Amended-by pointer + Update 2026-10-28) now say acc1 serves Bedrock chat models through one role since
  2026-11-12. The acc1 ID stays out of the Infra repo (secret `BEDROCK_ACCT_PAYER_ID`), so
  `docs/security/baseline.md` needs no exception.

## Tradeoffs

- The chain print is computed in the script (deployment rows and connection state), not by the gateway resolver;
  the resolver's answer ("first" per stage) is printed after the save from `llm_route_control.serving`.
- Between the enable and the save (well under a second) a Claude stage could pick acc1 before the Anthropic API.
