# AA-805 (S245): closing evidence for TripPlanner AI Phase 0 (root repo part)

Files: `docs/audits/2026-10-20-S245-tp-ai-phase0/` (evidence, runners, raw outputs). The DB script is in AA-CIS-Infra
(`db/scripts/aa805_ai_guards_read.py`, notes `docs/implementation-notes/AA-805-s245.md` there).

## Decisions

- The throttle was probed straight at the HTTP API without the edge key. Probes that pass API Gateway die at the edge
  check (401) with no DB or model work, so the run cost $0 and created nothing.
- The cache and ownership checks go through the public BFF with one cookie jar per client, like a browser. The runner
  (`aa805_cache_run.py`) stops after the first narration when the source is not cacheable. A master narration costs
  nothing, so retrying with other components was free. It retries a 429 up to 3 times, because a lone call was
  throttled once.
- The 30-query search set was re-run, not reused, because the search code changed after 14/10 (AA-712, AA-856). The
  runner now records `ranking`: all 30 queries were semantic, so the inactive-tour rule to check is the embedded-component
  rule.
- After 5 trips (33 components, 10 countries) were all `source: master`, the lane stopped guessing. It added a
  candidate query to the read-only DB script instead.

## Changed

- Against the S237 plan: the cache line could not be closed over HTTP in this lane. The 30-query results file is new
  (725 destinations; S237 had 724).

## Tradeoffs

- More random trips might have found a non-master day eventually. But each try leaves a guest trip on Dev, and the
  catalog evidently has master text for almost every component. A DB-derived candidate list is cheaper and certain.

## Should know

- Findings beyond the Done-when line: API Gateway's per-route throttle on `/narrate` is approximate (about 4.9 rps
  passed against 2 rps). The assembly Lambda's reserved concurrency of 5 answers 503 to bursts. The frontend narrate
  call does not retry 429 or 503.
- Test trips left on Dev are listed at the end of the evidence file.
