# AA-880 — ADR 0012 environment model (draft S256, accepted S257)

Scope of this slice: the ADR 0012 draft only (status Proposed). The L9 prod blueprint (Terraform, cost approval,
apply) stays for the go-live date, as the issue says.

## Decisions

- **Prod on acc2 with per-environment isolation (option B)**, not a separate prod account. Follows ADR 0001 (S235)
  and D-17; the separate account (option A) is the documented upgrade path with explicit reopen triggers
  (decision 12). AA-864 (consolidation) is not a precondition; the ADR names "the infrastructure account" in its
  rules so it survives a later account move.
- **Terraform layout (D-16, three incompatible proposals in S241):** keep `accounts/aa365` (account-wide layer + Dev,
  same state key), extract the environment-scoped resources into one module (`modules/platform-env`, working name)
  with `moved` blocks and a zero-change Dev plan as the gate, add a new root `accounts/aa365-prod` with its own state
  bucket. This keeps Infra `CONTEXT.md` (AA-841: new env = `accounts/<name>/`), takes the "one code path" idea of the
  review's `stacks/platform`, and amends C7.2c (`envs/prod/`) on acceptance.
- **GitHub environment rename:** `prod` (applies Dev today) becomes `dev` before any prod role exists, with a
  four-step order so the OIDC subject `environment:prod` is never trusted by two roles. The review's `dev-apply`
  name was not used: `dev` / `prod` match every other environment name.
- **Release flow:** backends promote the same image by digest (Dev ECR -> prod ECR, read-only from the prod side);
  frontends are rebuilt per environment in separate Vercel prod projects (Next.js bakes public config at build).
- **Data:** personal data never leaves prod; a one-time allow-listed content seed Dev -> prod at go-live; after
  go-live prod is the content system of record, with only allow-listed non-personal refreshes to Dev.
- **Cross-region backup region:** us-west-2 (C7.2b left the region to this ADR).
- **Separate acc3 invoker role for prod** (own ExternalId) so prod LLM access can be cut apart from Dev.
- **Go-live trigger:** the business owner sets a date (D-16); real personal data, the first paying tenant or real
  payments force the question. Lead time stated as about three to four weeks.

## Tradeoffs

- Same account is cheaper and simpler for one engineer, but isolation rests on IAM/tags/key policies; mitigated by
  explicit Denies, per-environment boundaries, KMS key policies, a separate state bucket, detection alerts and the
  management-account review (decision 4).
- Module refactor before prod costs effort and carries state-move risk, but avoids two hand-copied roots drifting;
  the zero-change plan makes the refactor verifiable.
- Dev stays in `accounts/aa365` (no cross-state move) at the cost of a root that is "account + Dev" rather than a
  clean account layer.
