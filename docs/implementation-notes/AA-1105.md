# AA-1105 — AA Academy part 2: implementation notes (root repo)

Slice S1 (root prerequisites). The app and Infra slices keep their own notes file in their repos.

## Decisions

- **Design ERD tables.** Nine tables: `learner`, `enrollment`, `statement`, `lesson_progress`, `quiz_attempt`,
  `review_card`, `lab_run`, `certificate`, `content_review_item`. Composite keys for `lesson_progress`
  `(learner_id, lesson_id)` and `review_card` `(learner_id, item_id)`; every other table has a uuid key.
- **`tenant_id` on every learner-data table**, NULL for staff, soft key to `shared.tenants` (no FK, no tenant edge),
  so the CIS RLS template applies per table and P7 adds no table rewrite. `content_review_item` has no tenant column.
- **`learner.admin_user_id` FK to `shared.admin_users` with `ON DELETE SET NULL`**: a staff row is deactivated, not
  deleted; when it disappears the retention job treats the learner as inactive instead of losing the record at once.
- **`learner.inactive_since`** starts the 365-day retention clock (D11). The job sets it when the staff account is
  inactive or gone and clears it when the account is active again.
- **Expired certificates are computed** (`expires_at < now()`), not stored; stored statuses are `valid`,
  `renewal_due`, `revoked`.
- **Certificate code**: 128-bit random, 22 URL-safe base64 characters, stored only as SHA-256. Because the code is not
  stored, it is shown once (in the graded result that completes the path) and the learner can rotate it (new code,
  old code stops verifying): `POST /learn/v1/certificates/{id}/code`.
- **Contract field policy** for `learn.http.v1`: forbids `answer`/`answers`, e-mail, `iss`/`sub`, `code_sha256`,
  tokens, password, `admin_user_id`; allows only `x-pii: name`. The graded result names `correct_choices`, never
  `answer`. Required negative samples: `answer`, `email`, `code_sha256`.
- **Video field**: `video: {key, captions}`; key pattern `learn-media/<module id>/<NN>-<slug>.(mp4|webm)`; caption
  files `<stem>.<lang>.vtt`; `en` caption required. `check_learn.py` checks folder = module id, file starts with the
  lesson number, unique key, guard patterns. The bundle passes `video` through as an additive manifest field and never
  uploads a video.
- **ADR number** 0022 (next free on master 14/11/2026; no other S280 worktree used it).

## Learn allowlist: partner grants at section level (S280 follow-up)

The AA Academy allowlist granted agency (partner tier) modules whole catalog pages through `partner_pages`
(`GUIDE-12-content-studio`, `GUIDE-12-crm`). The CRM runbook mixes agency sections with Adventure Asia staff sections
(the staff console, the CIS admin agency page, internal escalation), so a whole-page grant published staff-only text
to agency learners.

### Decisions

- **One list.** `partner_pages` is gone. A partner grant is a `sections` entry with a `doc:<catalog id>#<anchor>` ref
  and `tier: partner`, next to the skill, steering and `CONTEXT.md` entries, with its own reason. One entry is one
  section, as for the other kinds; a whole page is never granted (the schema already requires an anchor).
- **A `doc:` entry is a partner grant only.** Catalog pages are readable by every staff role without the allowlist, so
  a `doc:` entry with `tier: staff` is an error: it would only add noise to an access review.
- **Exact match.** A partner module cites exactly a granted section. A grant does not cover the subsections of the
  granted section, and a grant of a subsection does not cover its parent. Each line of the allowlist is then exactly
  one published section, which is what a reviewer reads.
- **Staff-only marker.** The English page marks a section that is not for agency learners with the HTML comment
  `<!-- learn-tier: staff -->` below its heading. The check refuses a partner grant whose section text holds the marker,
  so a grant of the marked section, or of any section around it, fails. The docs reader drops raw HTML (`skipHtml` in
  `MarkdownView`), so the marker is invisible to readers. Only the English page carries it: the check and the bundle read
  the English page; translations are not cited.
- **What is marked.** Sections that hold Adventure Asia internal procedure or staff surfaces, including mixed sections
  that cannot be split without rewriting the page: CRM §2 Addresses, "A new agency (Adventure Asia)", "Adventure Asia
  staff console", both "Adventure Asia staff" subsections, §5 Roles (staff groups paragraph), §8 (staff rows and
  internal escalation), §9 Dev-phase caveats, Sources; Content studio §3 Get an account (steps 1 and 2 are internal), §8,
  §9, Sources.
- **What is granted.** Only sections written for agency users. CRM: joining an agency, the owner invites the team, the
  agency team's sign-in, travellers, the agency menu, and the seven agency day-to-day subsections. Content studio:
  address, sign in and out, roles, the menu, and the four day-to-day subsections. Each reason names the agency module
  of the research (A1 to A7, GUIDE-13-lms §agency path) that will teach from the section. §1 "Who uses it" of both pages is
  neither granted nor marked: it is an overview for every group, not written for agency users.

### Changed

- `docs/learn/allowlist.yaml`: `partner_pages` replaced by 20 `doc:` section grants of tier partner.
- `docs/learn/schema/allowlist.schema.json`: `doc:` refs allowed in `sections`; `partner_pages` removed.
- `tools/docs/check_learn.py`: `Ref.canonical` (a bare `GUIDE-12-crm#x` and `doc:GUIDE-12-crm#x` are one section),
  allowlist entries of kind `doc` (tier partner, published, not owner only), the staff-only marker check, and a
  partner module's `doc:` source must be a granted section.
- `tools/docs/build_learn_bundle.py`: a section's tier comes from the allowlist by canonical ref only.
- CRM and Content studio runbooks (English): staff-only markers.
- `docs/learn/README.md` + `.vi.md`, `tools/docs/README.md`: the grant and the marker.
- Tests: `test_check_learn.py` (grant to a marked section fails, grant around a marked subsection fails, a partner
  module citing an ungranted section of a granted page fails, a staff-tier `doc:` entry fails, a bare ref matches the
  `doc:` grant), `test_learn_bundle.py` (tier partner in the manifest; the committed allowlist grants no marked
  section).

### Tradeoffs

- A marker in the source page instead of a list of staff anchors in the allowlist: the marker moves with the section
  when a page is edited, and the writer of the page sees it; a list in the allowlist would drift silently.
- Mixed sections are marked, not split. Splitting CRM §5 (agency roles vs. AA staff groups) would let an agency module
  teach roles from the runbook; that is a page edit for the runbook owner, with the `.vi.md` in step.

## Contract 1.1: the per-visitor verify limit header (S281 academy web review)

- **Decisions.** The academy web calls the public verify route from its server, so every visitor reaches CIS from the
  web's one NAT address and CIS's per-address limit is a cap for the whole web host. The web must limit each visitor
  from a real, editable value lower than that cap. CIS sends it on every verify answer as `X-Learn-Visitor-Limit`
  (setting `cis.learn.verify_visitor_requests_per_minute`, CIS 429, default 6; clamped by CIS to the per-address
  limit minus one). A dedicated header, not `X-RateLimit-Limit`: that name already means CIS's own limit of the
  response (the `/v1/*` tenant middleware), and a caller reading it as the per-visitor value would hand one visitor
  the whole host budget.
- **Changed.** `learn.http.v1` 1.0 -> 1.1, additive: `components/headers/VisitorLimit`, the header on the verify 200,
  404 and 429 answers, `Retry-After` on the 429, and a "Rate limits" paragraph in the operation description. The
  404 / 429 answers now spell out the Problem body inline (a `$ref` response cannot add headers).
- **Should know.** Merge this before the CIS code PR that copies the file byte for byte (its sha256 pin) and sends the
  header; the CRM web reads the header name from its own constant.
