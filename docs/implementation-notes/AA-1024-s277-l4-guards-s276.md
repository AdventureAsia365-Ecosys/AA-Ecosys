# AA-1024 — S277 lane l4: S276 lessons become guards (root part)

Four S276 lesson lines had `Guard: pending AA-1024`. This PR adds the two root guards and updates the four lines;
the CIS PR of the same lane adds the pre-push pins check and the parametrize determinism lint.

## Decisions

- **RAM-1, deterministic part** (`.claude/hooks/aa_shell_guard.py`, `lane_pytest_check`): in a lane worktree
  (`.tmp-session/wt/**`) a pytest run is refused whatever the free memory when it asks for more than 2 xdist workers
  (`-n N` / `-nN` / `-n=N` / `--numprocesses N|=N` with N > 2, `-n auto|logical`) or collects a whole test directory
  (no test path, `.`, `tests`, `tests/unit`, `tests/integration`, `backend/tests`, …). "In a lane" is the directory
  after `cd` / `pushd` / `env -C` (tracked like WT-1 / TF-1), a `--rootdir`, or an absolute test path there. The
  memory-based part of RAM-1 is unchanged; the same FIX text and the same `AA_RAM_OVERRIDE=1` prefix (logged) apply.
- pytest is recognised as `pytest`, `py.test`, `python -m pytest` (also with `-I` / `-X dev`), `.venv/bin/…`,
  `uv|poetry|pipenv|pdm|hatch|rye run pytest` and `coverage run -m pytest`. Options that take a value (`-k`, `-m`,
  `-p`, `--deselect`, …) are not read as test paths.
- A test path known only at run time (`$(git diff …)`, `$FILES`, a quoted path) counts as unreadable and passes: the
  replay over the last 62 transcripts (38,973 commands) found two such lane commands, both file lists.
- Replay result after the change: 17 commands refused whatever the memory, all real whole-directory runs in lane
  worktrees (`tests/unit -k …`, `tests/unit tests/acp`). `replay_shell_guard.py` now prints that count.
- **Linear export gitleaks gate** (`tools/linear/linear_export.py`): the files a run writes (issue pages and the
  index) are copied into one temporary tree and scanned once with `gitleaks dir`, the root `.gitleaks.toml`,
  `--redact` and a JSON report, after writing and before the summary line or any archive / rescue call.
  Binary: `GITLEAKS_BIN` or `gitleaks` on PATH. No binary: exit 2 with a loud message, unless `--no-gitleaks`
  (then a warning). A finding or a gitleaks error: exit 3 with `file:line rule`, values redacted, nothing archived.
  `main()` now takes `argv` and returns an exit code (tests call it).
- **Review fix: scan the run's files, not only the changed ones.** The gate scans the export file of every issue in
  the run plus the index (with `--only`: the named issues' files), changed or not. Scanning only rewritten files let
  the retry path pass: a run stopped by a missing binary (exit 2) or a finding (exit 3) leaves its files on disk, the
  re-run rewrites nothing, scans only the index and archives. The whole current export (695 files) scans clean in
  about 3.5 s with gitleaks 8.30.1, so a full scan costs nothing worth saving.
- **Review fix: rewrite only path-shaped secret names.** The colon is dropped only when the backticked token looks
  like an ecosystem secret name: lower-case, `[a-z0-9][a-z0-9._-]*` segments joined by at least one `/`
  (`<app>/<env>/<name>`; the secrets register has no other shape). Any other token after a secret label (a pasted
  value such as a 16-character random string, an upper-case or base64-looking token, a bare word) is left as
  written, colon included, so generic-api-key still fires on it in the gate and in the CI secret scan. Checked with
  the real binary: the S276 name shape is cleared, a pasted value after "Secret" + ":" still fires after render.

## Changed

- The brief asked to strip the backticks around secret names after "Secrets:". Checked with the real gitleaks
  v8.30.1 and the root config on the S276 shape (invented name): with or without backticks the generic-api-key rule
  fires; what it reads as an assignment is the colon after the label. So the export drops the colon instead
  (`Secrets: `name`` becomes `Secrets — `name``) and keeps the backticks: on a name list (`a_key`, `b_name`) the
  backticks are what stop the rule; without them `key, b_name` reads as key=value. The S276 hand fix used the same
  idea ("Secret named …"). The rewrite applies to issue descriptions and comments.
- Lessons: the parametrize and the Linear export lines moved to `guards.md` (their guard blocks the whole class,
  `SKILL.md` section 4); the lane pytest line (TP pre-push split still a practice, not a guard) and the CIS pins line
  (only fastapi / pydantic are compared) stay in `lessons.md`, shortened, with their `Guard:`.

## Tradeoffs

- Name vs value: a lower-case path-shaped token is treated as a name, so a value of that exact shape would be
  rewritten and missed by generic-api-key. Random keys are mixed case or have no `/`, and provider rules still fire
  on known formats; the two non-path tokens after a secret label already in the export (a service name, a brace
  list) stay as written and scan clean today. A red gate on such text is the safe direction (edit in Linear).
- The lane rule is static: a pytest started inside a script the command runs is not seen (the memory check still
  covers it when memory is low). Reading scripts would make every lane command slower for a rare case.
- A sub-package (`tests/unit/llm_gateway`) is allowed: it is small, and the brief names the whole-suite directories.
