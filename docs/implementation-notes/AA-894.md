# AA-894 scopes 3 and 4 (root): design ERD `crm` and PRD as code

Branch `docs/erd-design-prd-as-code`, S247 (2026-10-22). Agent: Claude Code. Part 1 (generated ERD) is live;
scope 2 (admin view) and scope 5 (env-config register) are other branches. The drift checker and the gen_erd
keyword fix are in the AA-CIS-Infra branch `feat/erd-design-drift-check` (notes in Infra
`docs/implementation-notes/AA-894.md`).

## Decisions

- **Design page format = the generated pages' Mermaid**, plus three conventions the drift check reads: one marker
  comment (`<!-- erd-design schema=crm enforce=false implied-fk=tenant_id:tenant -->`), the relationship label is the
  child's FK column list (not a constraint name), and one attribute block per table (a bare name elsewhere is a
  reference). Rules written once in `docs/architecture/erd/design/README.md`.
- **Thirteen diagrams of at most ~15 boxes** (STYLE.md: fifteen nodes per diagram) instead of one 89-box diagram:
  overview, A, B+C (vault and pseudonymous profile side by side, to show there is no FK between them), D pipeline,
  D intake/metrics, E builder, E client access/agreements, F, G messages, G campaigns/calendar, H, I, J.
- **Table set = the 88 `crm.*` names of the DM-7 rows plus the `insight_fact` view** (design v3 §3.3 lists the same
  89; DM-7's old `crm.contact` row from v1.0 is not a planned table). Checked by script: design set == DM-7 set.
- **Keys from the lane §2 names** (`tenant_id`, `member_id`, `traveler_token`, `grant_id`, `rule_id`, ...); PK
  `<table>_id` where the lane is silent, natural keys where the lane gives one, template `id` for `job`, `outbox`,
  `inbox_events` (ADR 0003a, like `booking.job`). Every choice the sources do not make is in the page's
  "Open points for the migration PRs" table with the issue that decides it.
- **Tenant FK implied, not drawn** (~80 lines). FK form (single-column vs composite with `tenant_id`) left to
  AA-933 (`crm-001` base template).
- **Not drawn:** soft keys to other apps (DM-4.2) and the Booking-owned `b2b_*`/`departure` objects (Booking design).
- **Errata additions** (data-request log, owner acknowledgement) are not drawn: no table name and no DM-7 row yet
  (DM-7.1 says the row comes first).
- **PRD catalog ID `APP-10`** (index) and `APP-10-<feature>`: under "Apps, delivery and API", no new ID prefix in
  the shared schema. `PROD-` is the production blueprint, not product.
- **PRD fields added to `docs/templates/frontmatter.schema.json`** as optional properties (`linear`, `adrs`,
  `contracts`, `erd`, `migrations`): the schema has `additionalProperties: false`. Requiredness on PRDs is the job of
  `check_prd_refs.py`, so the schema stays one file for all pages.
- **New tool `tools/docs/check_prd_refs.py`** instead of extending `check_frontmatter.py`: the latter is one of the
  seven files that must stay byte-identical in four repos; PRDs exist only here. Path lists are checked on every
  docs page that has them (journals excluded), the PRD-only rules (required fields, `AA-<n>` keys, acceptance list
  with unique `**AC-<n>**`) on `docs/product/**` except its README.
- **Other-repo paths** (`infra/AA-CIS-Infra/...`, `apps/<repo>/...`) are checked when that repo is checked out next
  to the root (the workspace) and are a warning in root CI, which has only this repo. `crm` migrations will live in
  AA-Partner and the Infra byte copy, so the PRD's `migrations` will hold Infra paths.
- **Acceptance criteria** = numbered `AC-<n>` items in the PRD; Linear Done-when points to them ("PRD partner-crm
  AC-1"). Taken from the final design's milestone criteria (§7.4), issue-card refusal/edge cases and the privacy
  rules (§5.5, DM-6.8), not new requirements.

## Tradeoffs

- Keys only in the design boxes (plus the state column and DM-6.1 tags of the PII columns shown): the lane §2 keeps
  the full column lists; copying ~700 columns would duplicate a source that is still moving.
- `linear` lists all 53 CRM issues plus AA-821: long front matter, but it is the machine-readable link from the PRD
  to the work; the check rejects anything that is not an `AA-<n>` key.
- The schema copies in AA-Booking and AA-TripPlanner-Web are now a subset of the root schema (Infra is synced in its
  branch). They hold no PRD, so nothing fails; sync them at the next tools/docs copy.
