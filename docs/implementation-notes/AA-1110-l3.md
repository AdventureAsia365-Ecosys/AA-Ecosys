# AA-1110: continuity pack, documentation part (lane l3 of S283)

Root repo part of AA-1110: the "run without the agent" page, the security tabletop script, the access register
template and the drill index. The second alert channel is a separate AA-CIS-Infra PR (same lane). Naming the second
key-holder, testing their access and running the drills need people; they stay open.

## Decisions

- **`docs/ops/run-without-agent.md` (`OPS-01-no-agent`) adds no procedure.** It is a short path over the existing
  runbooks (rollback-cis, rollback-ecs, rollback-booking, rollback-tp-lambda, rollback-vercel (superseded),
  rollback-terraform, db-migrate, break-glass) with the GitHub web UI steps an agent normally hides (merge queue vs
  squash, the deploy workflow per repo, Run workflow on `main`). Status `draft` with the UNTESTED banner.
- **Two kinds of tested state.** "Agent-run" (an agent ran it, often with a helper) vs "runbook-only" (a person alone).
  The issue's point is the second kind, and none exists yet, so every path says "never" there.
- **The S264 rollback game day is recorded as agent-run, not hidden.** The lane brief said rollback-ecs, rollback-booking
  and rollback-tp-lambda were never drilled. The evidence folder `docs/audits/2026-11-02-S264-rollback-game-day/`
  shows the agent ran rollback-ecs (Booking API, CRM API) and rollback-tp-lambda path B on 02/11 (5/5 pass), but the
  drill index and the runbooks' tested logs were never updated. The pages say exactly that: agent-run once, never
  runbook-only, runbook status still `draft`. rollback-booking itself was never run beyond its read-only steps.
- **Tabletop Part C rotates the `db_migrator` password.** Only the short migration tasks log in with it, so no
  running service restarts; it has a scripted path (DB Migrate `set-password`) that never prints the value, and a
  one-line rollback (move `AWSCURRENT` back, run `set-password` again).
- **CRM data-key rotation is a talk-through, not a run.** `KeyProvider.rotate` exists in AA-Partner but no route, job
  kind or admin page calls it; the step list names what an operator entry point must do and verify. Column names come
  from `docs/architecture/db-schema-reference.md` (`crm.tenant_key`, `crm.audit_event`, `crm.tenant.is_synthetic`).
- **Access register (`SEC-05-access-register`) is a template by role.** Rows for the GitHub organization, the GitHub
  Apps, the management account, acc2, the LLM accounts, root users, both domains (registrar, auto-renew, lock,
  expiry) and break-glass. No account ID, no e-mail address, no name.

## Tradeoffs

- One page links the runbooks instead of copying them: a copy would drift. The cost is that a person needs two pages
  open for a rollback.
- The register does not record who the second key-holder is today: nobody is named yet, and inventing a row would be
  a false claim.
