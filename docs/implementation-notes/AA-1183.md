# AA-1183 — Secrets register v2 with rotation dates (part 1, S296)

Part 1 of AA-1183: the register v2 (root) and the ACM expiry warning (AA-CIS-Infra). Part 2 (S297) is the weekly
`rotation_check.py`, its read-only metadata permission, the CI bot key consolidation and the register drift check
failing on unknown names.

## Decisions

- **The rotation block replaces the `rotation` string** of each YAML row (no second field): `class`, `interval_days`,
  `owner_role`, `method`, `last_rotated`, `next_due`, optional `expires`, `events`, `copy_of`, `how`. The old free text
  moved into `how` when it said something. `register_check.py` (AA-CIS-Infra) reads only name, store and status, so
  it keeps working unchanged.
- **Five classes**: `scheduled`, `auto`, `on-incident`, `identifier`, `retired`. The issue's classes map onto them:
  180/365/730/90-day rows are `scheduled` with their `interval_days`; AWS-managed KMS/ACM/RDS CA and registrar
  domains are `auto`; "event only" is `on-incident`; identifiers are their own class so the check never reports
  them; gone rows are `retired` (status deleted/removed/orphan-delete/pending-removal ⇔ class retired).
- **LLM vendor keys are `on-incident`** (tech lead S295 N1). A unit test pins `aa-cis/dev/openai-key` and
  `aa-llm/dev/anthropic-direct` to that class.
- **`next_due` is written, not only computed**, so a reader sees it in the YAML; the validator refuses a `next_due`
  later than `last_rotated + interval_days` (earlier is allowed: a key ceremony or a "now" revoke comes first).
- **Copies point at their primary** (`copy_of: "<store> <name>"`) and take its class, interval and next due date;
  each copy keeps its own `last_rotated` (the day that copy was set). A copy older than its primary is stale; part 2
  reports it. The six CI bot key copies point at the `vendor:github GitHub App aa-ecosys-ci-bot` row.
- **New documentation-only stores** for what the weekly check reads beyond Secrets Manager and GitHub: `cognito:`,
  `kms:`, `acm:<region>`, `rds:`, `iam:`, `domain:<registrar>`, `local:agent-machine`. `register_check.py` lists them
  as "not checked" (its checkable-store pattern does not match), so the drift check is unaffected.
- **The Markdown view is rendered**: `secrets_register.py md --write` fills a generated "Rotation" schedule block and
  sets the Rotation and Status cells of every table row; `md --check` also fails when a YAML row has no table row or
  the other way round. Markers are `rotation-schedule:begin/end`, not `gen:` (those belong to `gen_sections.py`).
- **Account ID removed** from the YAML (`account_acc2`) and the Markdown heading (public repo); nothing read it.

## Tradeoffs

- **Hand-written `last_rotated`** instead of AWS dates: the Secrets Manager `LastChangedDate` moves on tag edits and
  the AWSCURRENT date moves on the AA-829 host-only DSN rewrite (23/10), so both overstate freshness. Dates come from
  the S295 secrets calendar (version history read with the verifier). Cost: a person must update the YAML after each
  rotation (the runbook says so; part 2's check compares it with live metadata).
- **One sentence per Vercel row** instead of a separate Vercel section rewrite: the Vercel projects are gone (S272),
  so the 8 remaining orphan-delete variables became deleted with a note.
- **E2EPORTAL* not linked by `copy_of`** to `crm/dev/e2e-test-studio/viewer`: the dates match (29/10) but the link is
  not proven, so the `how` text says "probably its copy, to confirm".
