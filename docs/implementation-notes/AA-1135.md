# AA-1135 — Platform › Delivery v2 (root repo part: the collector)

Lane l8-aa1135, S284. The CIS part (custom-range endpoint, settings, page) is in AA-CIS-App
`docs/implementation-notes/AA-1135.md`.

## Decisions

- **One computation, two callers.** The metrics code moved out of `tools/delivery/delivery_metrics.py` into
  `tools/delivery/delivery_engine.py` (pure, stdlib only). The collector keeps GitHub reading, the store files and the
  CLI and re-exports the engine names it used to define (tests and older callers keep `dm.<name>`). CIS computes a custom
  range with a **byte copy** of the engine, so a custom range and a preset of the same window cannot diverge.
- **Guard against drift at runtime, not by convention.** `summary.json` carries `definitions.engine_sha256` (sha256 of
  the engine file) and `config` (the apps.json the summary was computed with). CIS compares its copy's sha256 with the
  published one and refuses a custom range while they differ; presets keep working. `tools/delivery/sync_engine.py
  --cis <checkout>` writes the copy and its lock file; `--check` exits 1 when they differ.
- **`range_block`** is the single windowed function: dora, lead-time segments (now with p95), CI, merge-queue block,
  flaky jobs, verify, the deploys and failed deploys of the window, change counts, the merge-queue section and the git
  activity of the window. The presets (`ranges.d7|d28|d90` per app, `range_presets` in apps.json) and the CIS custom
  range both call it. The existing top-level (28-day headline) keys are unchanged: format 1 stays, new keys only.
- **Deterministic event order.** `Store.of` returns events in (time, id) order. Before, the order was the dict
  insertion order, which differs between the cached store and a store rebuilt from day files; a tie in
  `classify_entries` (`run_url` of the first run) then picked another run (seen on live data: one Partner queue entry).
- **Day files can hold an older copy of an event** (a run that moved to a later day when it finished keeps its first
  copy in the earlier file). `load_events` keeps the copy with the newest time per id, as the store does; the custom
  range prunes events before `store_from` like the collector.
- Merge-queue charts: `wait_histogram` (bins `queue_wait_bins_h` in apps.json) and `weekly` (merged / ejected / removed
  and the ejection rate per ISO week of the window) in the queue section.

## Changed

- `DEFINITIONS_VERSION` 2026-11-18 (event order; new keys). No metric definition changed.
- `summary.json` grows from about 0.7 MB to about 1.9 MB on live data (three range blocks per app); the CIS reader cap
  is 5 MB.

## Tradeoffs

- A collector change that touches the engine pauses CIS custom ranges until the CIS copy is synced (one CIS PR running
  `sync_engine.py`). Accepted: a short pause is better than custom numbers that silently disagree with the presets.
- Range thresholds of the root collector (presets, histogram bins) stay in apps.json: the root repo has no settings
  registry (same as AA-1108). The CIS-side cap and cache size are CIS settings.
