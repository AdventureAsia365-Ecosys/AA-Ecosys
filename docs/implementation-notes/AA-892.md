## Decisions

- **File names follow the catalog, not the task list**: `restore-rds-pitr.md` and `restore-schema.md` (catalog OPS-03)
  instead of `restore-pitr.md` / `restore-single-schema.md`, because the catalog and the guides lane already link the
  catalog names.
- **Secret rotation lives in `docs/ops/runbooks/secret-rotation.md`** (as the task asked), one section per class. The
  catalog row SEC-02 said `docs/security/rotation/*.md`; its status text now points to the runbook. One page is enough
  while every rotation is manual.
- **IDs**: sub-pages use catalog IDs with suffixes (`OPS-02-cis`, `OPS-04-5xx-spike`, `OPS-05-ecs-exec`,
  `OPS-06-legacy-login`, `OPS-10-deploy-gate`, `SEC-02-rotation`, `OPS-03-drills`).
- **Status**: only `rollback-cis` is `active` (content moved from the approved `skill/aa-ship` §5 and drilled in S241).
  Every other page is `draft` because STYLE says an agent-written page stays draft until Nghiệp reads it. Pages whose
  steps did run on Dev (ECS exec, DB Migrate, PITR restore, isolation probe) carry `last_tested` / `tested_evidence`
  and no UNTESTED banner; the rest carry the banner.
- **Added beyond the task list** because the catalog assigns them to AA-892: `break-glass.md` (OPS-10),
  `isolation-probe.md` (OPS-11), `job-kinds.md` (APP-09), `drills/README.md` (OPS-03 index).
- **Evidence** of today's read-only checks is in `docs/audits/2026-10-19-S243-ops-runbooks/readonly-checks.md`
  (DM-8.10). The drill index only links evidence (reconciliation §5.1 item 5); the S241 drill stays where it is.
- **ECS exec canonical copy**: the runbook reads the container's own `DATABASE_URL` and documents the X1 S18/S19 table.
  The skill quick reference gets a pointer appended at the end (not rewritten) so it does not conflict with the open
  branch `docs/x1-s19-ecs-exec`, which rewrites the top of the same file.
- **Underscore variable names** appear only as names in the flag register and the legacy-login runbook; no command
  sets them. Values are Nghiệp's hand edits (global rule).

## Tradeoffs

- **Hand-written CI/CD matrix and job-kind register** (catalog mode H): cheap now, can drift. Both say where the live
  truth is (`.github/workflows/`, `/admin/job-runner/summary`).
- **Single-schema restore**: two zero-cost options (a reviewed asyncpg copy script through DB Migrate run-script, or a
  one-off `pg_dump` task). The first is preferred because it adds no infrastructure; neither is tested (AA-829).
- **TripPlanner Lambda rollback by S3 object version** instead of downloading old code: zips are close to the 50 MB
  direct-upload limit, and the artifacts bucket is versioned. The alias `live` (U-54) would be simpler; not built.

## Should know

- **Gaps found** (not fixed here, worth issues):
  1. The SES feedback topic `aa-email-dev-feedback` has no subscriber, so bounce/complaint details are lost; only rates
     and the suppression list remain (AA-811 scope 3).
  2. No per-kind pause switch for jobs; stopping a runaway kind means cancelling rows or scaling the worker to 0 (and
     the worker's autoscaling minimum is 1).
  3. The ECS exec drill-compare script reads the master secret; after X1 S19 the PITR comparison must move to a
     reviewed read-only `run-script` (written as UNTESTED in the runbook).
  4. `/aws/apigateway/welcome` log group has no retention (tiny, default group).
  5. Booking ECR keeps only the last 10 images, so Booking rollback depth is 10 deploys.
- `TP_DAILY_SPEND_CAP_USD` is not set on the Lambdas, so the 5 USD code placeholder is the live cap (open question for
  Nghiệp in TripPlanner's config).
- 11 new links in this branch point at the AA-897 page `onboarding.md#account-map` and resolve once that PR merges; the
