# AA-1021 — Architecture video pipeline, public-content gate and the Ep1 pilot

Slice of the S262 plan (`docs/audits/2026-11-01-S262-arch-video-plan/README.md`, steps 6-9) built in S264 lane l8.
Code only in this repo (`tools/uat/arch/`); the label profile, the deny-list, the episode script, the blog draft and
every render stay outside git.

## Decisions

- **Post-process the rendered SVG instead of re-rendering the diagram sources.** `labels.py` maps the `<text>` of the
  committed `docs/architecture/diagrams/*.svg` through the private profile (exact map, null = drop, regex rewrites),
  strips `<title>`/`<desc>`/comments/links, and keeps only neutral Graphviz node keys (`s14`, `s14-t`) as `data-k` /
  `data-from` / `data-to` so the stage can reveal a group with its edges. No Graphviz install is needed, and the
  internal sources keep their real names (plan principle).
- **Vendor logos become plain shapes.** The profile's `neutral_icons` swaps the icon of a labelled node or group for a
  rounded square: the frontend-hosting vendor's logo would otherwise reach the frames, and no text layer can see a
  logo.
- **Keyframes, not screen recording.** `capture.cjs` shoots each distinct visual once per aspect at deviceScaleFactor 2
  and `video.py` joins them with cross-fades; labels stay sharp and the encode is crf 19.
- **Camera frames the revealed core.** With `reveal`, the view zooms to the revealed groups and nodes (not their
  enclosing account / VPC frames); `focus` overrides it. Without it a 2900-pt diagram is unreadable at 1080p.
- **One voice per sentence**, defaulting to scene-by-scene alternation (F first in odd episodes), only `af_heart` and
  `am_michael` accepted; each clip is loudness-normalised in two passes (-16 LUFS, linear gain) and cached by a hash
  of voice + text.
- **Gate layer 1 runs before any TTS**, so a failing script costs nothing. N-gram size 5 with 2+ content words: size 4
  flagged common English idioms found in unrelated audit JSON; size 5 kept the real echoes (the plan's own episode
  titles, a sentence of an ADR).
- **Label-set check (new, not in the plan).** One public file holding 4+ of the multi-word public labels is a hit. The
  plan page itself was the only such file: it listed the public labels and the episode outlines, so the combination
  on screen would have led back to this repo.
- **Plan page redacted in this PR** (separate commit): the episode list, scene outlines and the label mapping example
  were replaced by a pointer; the full original is kept with the private series files.
- **Gate logs and REVIEW.md sit beside the publish folder** (`<slug>-gate/`), not in it: they are for the team, are not
  scanned by layer 4, and a checklist naming risk words would otherwise trip the deny-list.
- **Chapters**: `-map_metadata -1` also blanks chapter titles in ffmpeg 6.1, so a master with chapters takes its
  (empty) global block from the ffmetadata file instead; the only tag set is the neutral title either way.
- **OCR**: tesseract 5.3.4 unpacked from the Ubuntu archive with `apt-get download` + `dpkg -x` (no root), run with
  `--psm 11`; layer 3 reports SKIPPED with a warning when it is missing.
- **CI**: the stdlib gate tests run in Docs lint (path filter `tools/uat/arch/**`); TTS, browser, ffmpeg and OCR stay
  local.

## Changed

- The series and episode titles differ from the plan's: the plan's wording is public in this repo (and in its history),
  so the n-gram layer rejected it.
- The X cut is about 1:55 and the LinkedIn cut about 1:17 (4:5); the plan's targets were about 2:00 and 1:30.
- Ep1 builds from the ecosystem view only; the other views still carry internal labels (the gate rejects them until
  their profile entries exist), which is the work of the next episodes.

## Tradeoffs

- The n-gram corpus is every tracked text file of the root repo and the four app repos plus Infra (about 9 s per run).
  It reads the local checkouts, which can lag origin; run it after a pull.
- Fuzzy OCR matching (edit distance 1) applies to deny terms of 6+ letters only; short terms are matched exactly to keep
  OCR noise from failing builds.
- Text removed from the plan page remains in git history; the redaction lowers discoverability, it does not erase it.
