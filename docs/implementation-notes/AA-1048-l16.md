# AA-1048 lane l16 (S281): ship deploy wait per service, ECS exec guard before a CIS backend merge

## Decisions

- New read-only module `tools/github/ship_deploy.py` holds both guards, so the merge path (`ship_merge.merge_one`,
  used by the wave, the train and the merge CLI) and the deploy wait (`ship_wave.wait_deploys`) read one table.
- `SERVICES` lists every Dev service a repo merge deploys, with the deploy workflow's `on.push.paths` copied in order
  and the health URL that reports the running commit. Beyond the Partner api/web split the issue asked for, it also
  covers the CIS admin and the Booking admin (ECS, `deploy-admin-dev.yml`, `/api/healthz` reporting `sha`): a
  frontend-only merge in those repos used to wait on the API and time out the same way (lesson S277, Booking #222).
- Path matching follows GitHub semantics (patterns in order, a later `!pattern` clears an earlier match; `**/`,
  `**`, `*`, `?`). A drift test compares the table with `origin/main` of the local app clones (skipped in CI where
  the clones are absent), so a changed workflow filter shows as a red test on the orchestrator workstation.
- A PR touching no deploy path logs "no deploy expected" and is not waited on. An unreadable file list waits on every
  service of the repo (conservative: a false timeout is louder than a silent skip).
- The exec guard runs in `merge_one` after the gate and before the merge call, only for AA-CIS-App PRs whose files
  touch the api/worker deploy paths. It lists the top level of `scripts/out/` (one `aws s3api list-objects-v2
  --delimiter /`, profile `ECSX_PROFILE` default `aa365-admin`), and applies the CIS deploy gate's rule (heartbeat
  `.running` younger than 120 s and no `.done`). The bucket comes from `ECSX_BUCKET` or the default written in
  `tools/ecs/ecsx.sh` (one source, no second copy of the bucket name).
- Fail closed: an unreadable listing (expired MFA) refuses with the renew command; an unreadable file list counts as a
  backend PR. `--allow-running-exec` (ship_merge and ship_wave) turns either refusal into a WARN line plus a JSON line
  in `.tmp-session/ship-overrides.jsonl`.

## Changed

- `ship_wave.DEPLOY_URL` removed; `wait_deploys` now builds a per-service plan (`deploy_plan`) and names the service,
  URL and workflow on a timeout. The old message "a docs-only merge does not deploy" is replaced by the explicit
  "no deploy expected" line before the wait.
- `tools/ecs/ecsx.sh`: usage says ECSX_SCRIPT_TIMEOUT goes after the script path (with an example next to
  ECSX_TIMEOUT), and the env-form refusal says "AFTER the script path as a VAR=value pair"; new test in `test_ecsx.py`.

## Tradeoffs

- The 120 s freshness mirrors `shared/jobs/exec_heartbeat.FRESH_S` and the runner's 30 s heartbeat cap. It is an
  orchestrator-tool constant, not an app setting: the root tools have no admin settings store. Follow-up if wanted:
  read it from the CIS deploy-gate answer instead of a copy.
- Booking and CRM runs use the ecsx local mode: output stays in the container's `/tmp`, nothing is written outside,
  so no tool can see a running script. Documented as a gap (README, runbook, ecsx usage) rather than inventing a local
  marker that would only be seen on one workstation and would go stale when the local side dies.
- `ship_train.py` gets the guard through `merge_one` with the default (no override flag on that CLI); a refused train
  step stops the train, which is what a running script should do.

## Should know

- The CIS CI deploy guard still blocks the roll on the same heartbeat; this guard only keeps `main` from getting ahead
  of what can deploy (S280: a merge during a paid exec run left Deploy Dev red until a re-dispatch).
- Tests: `tools/github/test_ship_deploy.py` (paths, listing, guard, merge_one ordering, drift),
  `tools/github/test_ship_wave.py` (web-only waits on web, api-only on api, both on both, docs-only none, unreadable
  list, wave refusal of the CIS api PR only, override), `tools/ecs/test_ecsx.py` (env-form refusal text).
- Review fix: `test_ship_deploy.py` runs real `git -C <clone>` in the drift test, so it carries the same import-time
  scrub of `git rev-parse --local-env-vars` as `ship_fakes.py`; without it the static guard
  `test_git_env_isolation.py` fails, and under a pre-push hook the drift test would read the root repo and skip.
