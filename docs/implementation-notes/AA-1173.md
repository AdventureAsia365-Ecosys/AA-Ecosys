## Decisions

- **The root collector seals first, then still writes the docs-reader copy.** The CIS reader takes the sealed bundle
  first and names its object on the row; the docs-reader copy is the phase 1 path, kept until the sealed path is
  proven live (then a small follow-up drops the docs-reader upload and the Docs sync grant on `docs-reader/compliance/`).
  While both exist, the CIS reader ignores a docs-reader file once the sealed `root_daily` is current, accepts only
  source `root_daily` from it, and its "latest per check" read prefers a sealed row (object_key set) over an unsealed
  one for every sealed source, so the mutable copy can never override sealed evidence (AA-CIS-App notes).
- **One shared writer** (`tools/compliance/seal.py`) in two repos, pinned by SHA-256 in both test suites: the root
  workflow and the Infra workflow write the same layout and the same hash-chained manifest, and the CIS reader checks
  one layout.
- **The GitHub alert checks (Dependabot, secret scanning, code scanning) wait for the read-only GitHub App** (S287 Q5,
  a tech-lead step, below). Nothing in this wave asks for an App token; the collector gains those checks in a follow-up
  once the App exists.
- **acc4 / acc1 scans are a follow-up**: they need a read-only role in acc4 (another Terraform root, applied locally)
  and a cross-account trust; this wave covers acc2.
- **Every threshold and validity window is a CIS setting** (Platform › Settings, area compliance): the validity of
  each source (`cis.compliance.validity_hours.<source>`), the Prowler critical / high tolerance, the longest exception,
  the age of the newest monthly review. The bucket retention is a Terraform variable (an infrastructure setting whose
  change the plan guard refuses without the tech lead).

## Tradeoffs

- Keeping the docs-reader copy for a while costs two S3 PUT a day and keeps a mutable copy around; it avoids a gap on
  the page if the first sealed runs fail.
- GOVERNANCE + deny-bypass instead of COMPLIANCE mode: an auditor gets the same "nobody can delete or shorten" result
  from the bucket policy, and the tech lead can still undo a wrong setup on Dev through a reviewed Terraform change.

1. Open <https://github.com/organizations/AdventureAsia365-Ecosys/settings/apps/new>.

   `gh variable set COMPLIANCE_READER_APP_ID --repo AdventureAsia365-Ecosys/AA-Ecosys --body <app-id>`; then delete

## S294 follow-up: the docs-reader upload is dropped (lane l6-sec-hygiene)

### Decisions

- **The root collector no longer writes the phase 1 copy under `docs-reader/compliance/`.** The sealed path was proven
  live on 24/11/2026 (root run 45364700766, Infra run 45364721985, delete / overwrite refused, both sealed sources
  read by the CIS page: `docs/audits/2026-11-24-S290-session/live/aa-1173/evidence.md`). The Docs sync role steps,
  `PREFIX`, `HAS_AWS` and the two `aws s3 cp` are gone from `.github/workflows/compliance-evidence.yml`.
- **A seal failure now fails the run at its own step.** The `continue-on-error` on the three seal steps and the last
  "Seal outcome" step existed only so a failed seal could not block the docs-reader upload; with one output they are
  removed. On master, missing `COMPLIANCE_EVIDENCE_*` secrets fail the run ("Seal not configured") instead of a
  notice: without them no evidence is written at all, and a red run is seen sooner than a stale page.
- **The CIS reader fallback stays** (`api/services/compliance_store.py` in AA-CIS-App still accepts a docs-reader
  `root_daily` file when no sealed bundle is current). Out of scope here; with no writer it simply finds no newer
  file.

### Changed

- `.github/workflows/compliance-evidence.yml`: header rewritten (seal is the only output; proof of 24/11), docs-reader
  steps removed, seal steps without `continue-on-error`, "Seal not configured" fails.
- `tools/compliance/test_seal.py`: `SealWorkflowTest` checks no Docs sync role, no docs-reader path, no
  `continue-on-error`, the seal as the last step and the missing-secrets step failing.
- `tools/compliance/test_collect.py` (`test_workflow_shape`) and the `collect.py` docstring follow.

### Should know
