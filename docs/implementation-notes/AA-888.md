# AA-888 — Docs lint and ADR indexes (root part)

Branch `ci/aa888-docs-lint`, based on `docs/aa887-docs-standard` (AA-887 foundation). The ADR indexes of
CIS, Booking, TripPlanner and Infra ship in each repo's `chore/aa890-pr-template` branch, with their own note.

## Decisions

- **One job per PR, one job a week.** GitHub bills each job rounded up to a minute, so all PR checks are steps of
  one `lint` job (each step runs even when an earlier one failed). The `freshness` job runs only on the weekly
  schedule and on manual dispatch. The PR trigger is limited to docs-related paths.
- **Python tools in `tools/docs/`, stdlib except the front-matter check** (PyYAML + jsonschema, pinned in
  `requirements.txt`). The text and ADR checks can be reused in the public repos without installing anything.
- **Unit tests run in CI** (`test_docs_tools.py`): each check has a passing and a failing fixture, which pins the
  AA-888 Done-when ("a PR adding an `sg-` ID or a backslash-continued `aws` command fails").
- **Resource-ID check is warn-only in root** (task brief; root is private). STYLE.md said "fails"; it now says
  warn in root and Infra, fail in the public repos once their docs job lands.
- **Journals are out of scope** for the text checks (sessions, audits, implementation notes, backlog, research,
  calib): they are records of what happened. The one multi-line AWS command in a session log stays as written.
- **AWS multi-line check covers `docs/`, `skill/`, `.kiro/steering/`, `.claude/`** because agents copy commands
  from skills and steering; today there are no violations there.
- **ADR status lint added** (proposal §2.6 lists it under AA-888): status must start with Proposed, Accepted,
  Deprecated, Superseded or Rejected and the ADR must be linked from `docs/adr/README.md`. Root passes (12 ADRs).
- **gitleaks on the PR's added lines** with the same pinned image as Infra `secret-scan.yml`, default rules.
  Scans every file the PR's commits touch, not only `docs/`: stricter and simpler than a pathspec.
- **All actions pinned by commit SHA** with the tag in a comment (checkout v7.0.1, setup-python v7.0.0,
  upload-artifact v7.0.1, lychee-action v2.9.0). upload-artifact v7.0.2 was skipped: released 2026-10-07, under
  the two-week age rule.
- **markdownlint warn-only** (`.markdownlint-cli2.jsonc` at the root, the AA-887 settings including
  `MD025 front_matter_title: ""`, journals and the generated schema reference ignored). 94 findings exist today in
  older pages (`t-series-audit-and-plan`, data standards part A, stray root docs); the step uses
  `continue-on-error` until they are cleaned up, then the flag goes.
- **Lychee does not check heading anchors** yet (`include_fragments` off): GitHub's slugs for Vietnamese headings
  differ from lychee's and would give false failures.

  `--profile aa365-admin --region us-west-1`. Without this the new check fails on master. The page itself is a

## Tradeoffs

- Freshness report as a run artifact, not `docs/generated/freshness.md` committed by a bot: no write token in the
  root repo and no bot PRs. The session-start ritual reads the latest artifact (Actions tab) instead of a file.
- Warn-only ID check means the 20 current findings (data standards, ADRs 0001/0004b/0006/0006a/0008,
  ecosystem-architecture, schema-ownership, two stray docs) do not block. Clearing them is AA-889 with data
  standards v1.1.

## Follow-up: markdownlint scope and clean-up (S245, branch `ci/docs-lint-markdown-scope`)

- **Measured first** (markdownlint-cli2 0.23.2, the version the pinned `markdownlint-cli2-action` v24.2.0 runs):
  10,921 findings in 506 of 588 files. 8,084 were in `docs/linear-export/` and 314 in `docs/generated/` (both
  generated), 472 in `docs/archive/`, and 3,580 were MD060 (table-column-style, new in markdownlint 0.39, arrived
  with the action bump). Outside generated/archive pages, 1,991 of the 2,051 findings were MD060.
- **Decision: fix, not changed-files-only.** With MD060 off and generated/archive pages ignored, 60 findings were
  left in 11 files; they are fixed and the step lost `continue-on-error` (the plan in the first section: "then the
  flag goes"). A changed-files filter would have kept 60 known findings and made every edit of one of those pages
  red for reasons the author did not cause. The full run takes a few seconds, so no scheduled split is needed.
- **MD060 off:** the house table style `| a | b |` over `|---|---|` fails every MD060 style (`any`, `compact`,
  `tight`, `aligned` were each tried on a sample table). Turning the rule off keeps thousands of tables as written.
- **Ignored:** `docs/archive/**` (frozen old pages, like journals), `docs/generated/**` (AA-CIS-Infra
  `docs-gen.yml`), `docs/linear-export/**` (Linear export tool), next to the existing journals and
  `db-schema-reference.md`.
- **Changed (pages):** `markdownlint-cli2 --fix` for blank lines around lists, headings, fences and tables and the
  bare AUP URL; three auto-fixes were wrong and were redone by hand: a wrapped line starting `+ switch + drop` (data
  standards Part A MIG-7) and `+ monthly rollup` (Part C C5.4) — both also rendered as stray list items on GitHub —
  and `#664` at a line start (t-series plan), which `--fix` turned into an H1; each is reflowed instead. ADR 0005
  keeps its decision numbering 8–10 (cited elsewhere as "decision 8") inside an MD029 disable/enable pair. Bold
  labels used as headings: `####` headings in ADR 0006 (WORKFORCE / EXTERNAL) and the 2026-09 ecosystem review;
  a trailing colon on the data-standards checklist labels (they are pasted into PR descriptions); the retention
  table caption bolds only "Retention table". Two fences got `text`.
- **Also:** `tools/docs/README.md` lists the markdownlint step and the AA-TripPlanner-Web copy (the `cmp` loop now
  covers the three vendored copies).
- **Should know:** after this merges, a docs PR whose catalog pages break a markdownlint rule is red on "Docs lint".
  Local check: `npx markdownlint-cli2@0.23.2 'docs/**/*.md'` → 0 issues in 80 files on this branch.
