# AA-783 — Human calibration of the T9 commercial panel (label data + agreement tooling)

S248 lane `aa783-label-data` (Claude Code). Scope of this lane: the data side only. Export the 40 pieces,
define the label scheme, and ship the agreement script. The orchestrator runs the export (ECS exec,
read-only) and builds the click-to-label page; Nghiệp labels; the agreement report is written afterwards.

## Decisions

- **Which 40 pieces: the S234 label pack, by fixed piece id (default `--set s234`).** The issue's Scope
  names `label-pack/S234-label-40.xlsx` (16 blog: A&H 8, Terra 8; 24 LinkedIn: 6 per tenant; 26 approved /
  14 held). These are the only T9 pieces with stored 4-lens panel votes, so they are the only pieces on which
  "human vs panel" kappa can be computed. The S239 Linear comment ("~40 current T9 pieces") is supported as
  `--set current`, which draws the same quotas from the newest pieces but has no panel key: a panel round
  would have to be run on them first (no cost estimate here, as the panel is local Claude Code agents).
- **The panel key lives inside the export script** (`PANEL_KEY`, generated by `build_panel_key.py` from the
  S234 scratch data), so the export JSON carries text and keys in one file. The text block never contains the
  key: the label page reads `pieces[]` only, and the agreement script reads `key`.
- **Per-lens dimensions available: verdict, overall, fidelity, ai_tells** (all four rounds kept these in the
  synth scripts). The rubric also scored brand_voice, channel_fit, hook, clarity and commercial_value, but
  those per-lens numbers were never saved, so the voice and format columns are compared with gates only.
- **Label keys = the admin Label API keys** (`fact`, `voice`, `format`, `ai_phrasing`; `none/light/heavy`;
  `as_is/light/heavy/reject`). `labels.json` can therefore be posted to `content_piece_label` later through
  the AA-791 API without a mapping step.
- **Gate to defect-column map is a constant in `agree.py`** (`GATE_COLUMN`), from report 12 §1.2 "What it
  checks". Gates not in the map are reported under `other`, never dropped.
- **Panel majority rule = the S234 rule**: as-is needs ≥3 as-is votes; light-or-better needs ≥3 of 4; a 2–2
  tie takes the stricter label (heavy). Reproduced in `build_panel_key.py` and checked against the
  committed per-piece tables (the stored verdict wins if they differ, and the difference is printed).
- **Output transport**: stdout between `AA783-BEGIN`/`AA783-END` as asked; `--gzip` shrinks ~630 KB of JSON to
  ~145 KB of base64 (tested on the S234 texts), and `--s3 s3://…` (opt-in) puts the same output in the scripts
  bucket because the runbook warns that `execute-command` output can hang. A sha256 line lets `agree.py decode`
  prove the output was not truncated.
- **Text drift**: AA-769 admin sentence rewrites can change a stored text after the panel scored it. The export
  flags `text_changed_since_panel`; `agree.py page --pack` then shows the panel-era text from the xlsx, so the
  human labels the same text the panel scored.
- **Label page data carries the definitions** (EN + VI, from `HUONG-DAN-CHAM.md`) and never the key: `page`
  asserts that no key field leaks into the page JSON.

## Changed

- Nothing in app code. Tooling only (root repo, `label-pack/agreement/`) plus the scratch handoff. The issue's
  "agreement report committed next to the label pack" is still to come (after the labels).
- The S234 README lists the new folder.

## Tradeoffs

- Fixed ids vs a fresh draw: fixed ids keep panel comparability; the price is that the texts are from
  S234 writers (pre AA-779/AA-800/AA-819). Gate decisions from this set describe the S234 gate set; the
  gate ledger exported is the stored one for those pieces, not a re-run of today's gates.
- Unweighted and quadratic-weighted kappa are both reported: the verdict scale is ordinal, and n=40 makes
  unweighted kappa jumpy; bootstrap 95% CIs (seeded) show the noise.
