# AA-901 — GitHub App for agents and release-please, two root ADRs, CODEOWNERS (U-25)

S247, 22/10/2026, Claude Code (subagent lane). The Apps themselves are not created here: Nghiệp creates and installs
them in the browser with the guide `docs/security/github-apps.md`.

## Decisions

- **ADR numbers.** The issue text says "ADR 0010/0011"; 0010 went to AA-Partner (AA-928). The index lists 0011 and
  0014 as the next free numbers, so: **0011 = agent and bot identity on GitHub + merge rights per risk tier** (the
  issue's "ADR 0010"), **0014 = repo visibility and GitHub plan, D-14 Free** (the issue's "ADR 0011"). The release-please
  token is a consumer of the 0011 identity, not a separate decision, so it is a section of 0011. Next free after this
  PR: 0015 (computed by `tools/adr/check_adr_numbers.py`: no gap left below 0014).
- **Two Apps, not one.** `aa-agent` (interactive agent sessions: push, PR, merge, dispatch workflows, edit workflow
  files) and `aa-ci-bot` (release-please in the app repos, root docs PRs from AA-CIS-Infra). A key leaked from a CI
  secret then cannot push workflow files or dispatch workflows; the audit trail tells agent from bot. Both are free.
  The issue names only `aa-agent`; the split is recorded here and in ADR 0011 for Nghiệp to accept or fold back.
- **No `Administration`, `Secrets` or `Environments` permission on either App.** Branch protection, secrets and
  environments stay with Nghiệp's personal login. A leaked App key cannot weaken the gates.
- **Key storage.** `aa-agent` key in Secrets Manager acc2 (`aa-ecosys/github/aa-agent-app-key`, same `aa-ecosys/*`
  prefix as the Linear key), read on demand by a helper that never prints the token. `aa-ci-bot` key as a GitHub
  secret per consuming repo, in an environment limited to `main` where the repo's plan allows it (lesson S241 AA-866:
  repo-level secrets are readable from old branches).
- **Helper `tools/github/as-app.sh`.** Runs one command with a fresh installation token in `GH_TOKEN`; the token is
  never echoed. Uses only `aws`, `openssl`, `curl`, `python3` (JSON). Written for the guide's test step; untested
  until the App exists.
- **CODEOWNERS owner = `@pqnghiep1354`.** The org has two admins (`pqnghiep1354`, `adventure365`, both org `admin`
  role, checked read-only with `gh api` on 22/10). Only the engineer's account is an owner; whether `adventure365`
  should be a second owner is a question for Nghiệp.
- **No catch-all `*` rule.** Only sensitive paths are owned, so the future "require code owner review" gate bites only
  where D-13 wants a human (Terraform/IAM, migrations, auth, CI/workflows, agent rules).

  renumbering.

## Tradeoffs

- One App would be one key and fewer clicks; rejected for blast radius (see Decisions). Cost of two: a few minutes
  of browser setup.
- Secrets Manager for the agent key costs about 0.40 USD/month (one secret) against a `.pem` on the laptop; chosen
  for CloudTrail on every read and no file on disk.
- CODEOWNERS in the two private repos (root, Infra) does nothing on GitHub Free (code owners need Pro/Team for
  private repos). Kept anyway: the file is ready and documents ownership; ADR 0014 says what happens at the prod
  trigger.
- In the public repos CODEOWNERS auto-requests a review from `@pqnghiep1354` on PRs authored by the App that touch
  owned paths. That is notification noise only; nothing blocks while branch protection does not require code owner
  review (checked 22/10: `required_pull_request_reviews` is null on all three public repos).

## Should know

- Branch protection is **not** changed by this issue. Turning on "Require review from Code Owners" is a prod-trigger
  step (AA-880), listed in ADR 0011 decision 4 and ADR 0014.
- The subagent hook blocks `gh pr create/merge` for subagents whatever token they hold; the App does not change that.
- The child-repo CODEOWNERS branches are `chore/codeowners` in AA-CIS-App, AA-Booking, AA-TripPlanner-Web and
  AA-CIS-Infra; each carries its own short notes file.
- Done-when items still open after merge: the App test PR, the first release-please PR with the bot token (AA-891),
  ADRs accepted, register rows. All need the Apps to exist first.
