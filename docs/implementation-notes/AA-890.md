# AA-890 — PR template (root part)

The app and infra parts (PR templates, PR-title check in Booking and TripPlanner, Infra `.bak` cleanup) are in
each repo's `chore/aa890-pr-template` branch, each with its own note. This root branch carries the root PR
template together with the AA-888 docs lint.

## Decisions

- `.github/pull_request_template.md` for the root repo: What / Why (`Refs AA-xxx`), Risk and rollback, Cost,
  Docs checklist and Verification. Because this repo is docs, skills and steering, the checklist is about the docs
  standard: valid front-matter, `last_reviewed` moved only after a real check, runbooks marked tested only with
  evidence, ADR index, no secret values or real data, account IDs only in the onboarding account map, single-line
  AWS CLI, backlog and session log.
- No PR-title workflow in root: root PRs are merged by hand by the main session and the S243 plan limits the title
  check to Booking and TripPlanner. Actions minutes on this private repo go to docs-lint.

## Changed

- Nothing else in root for AA-890.

## Tradeoffs

- One template per repo instead of an org-level `.github` repository (S241 U-48 suggests one): each repo's
  verification lines differ (CI job names, migration owner folder, deploy checks), and an org repo is one more repo
  to keep. Revisit with U-48 when a second contributor joins.

## Should know

- Repo settings (squash-only, `delete_branch_on_merge`, squash commit title from the PR title) are not changed by
  any branch; the main session applies them with `gh api` (listed in the lane report).
- U-11 also asks to remove `/v1/webhooks` from the API Playground; that part of AA-890 is not in this lane.
