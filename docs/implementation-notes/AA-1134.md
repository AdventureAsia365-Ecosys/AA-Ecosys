# AA-1134 — Docs-audit code follow-ups (root repo part, slice A)

Lane l5-docs-audit-fixes, S285. The S283 docs audit (`docs/audits/2026-11-17-S283-docs-audit/README.md` section 4.1)
listed 19 places where the docs are right and the code is wrong. This PR holds the root items 1, 3, 5, 7 and 17. The
Booking, Infra and CIS items are in each repo's `docs/implementation-notes/AA-1134.md`; the vendored docs-tool copies
are re-synced in AA-Booking, AA-Partner, AA-TripPlanner-Web and AA-CIS-Infra in the same wave.

## Decisions

- **Rollback helper (item 1).** `aa-cis-dev-admin` and `aa-booking-dev-admin` join the service list. Their health is
  the public `/api/healthz` of each staff host, which answers `{status, app, sha}`; the helper reads the field `sha`
  (not `git_sha` like the APIs). Image tags: `dev-<sha>` for CIS, `<sha>` for Booking, so `is_build` and `--to-sha`
  work unchanged. No api/worker same-image note for the CIS admin (separate image and ECR repo).
- **acc1 cost line (item 3).** acc1 serves Bedrock first since S278 (AA-1095); the report called it "retired". The
  CIS Cost Explorer client reads acc2 and acc3 only and the CIS task role may only invoke Bedrock on acc1, so the
  collector cannot read acc1's bill (DM-10.4: no new Cost Explorer client). Split:
  - `collect_month.py` gives every month an `llm_satellites.acc1` line: the gateway estimate (cost_by_app's own when it
    has one, else the sum of the month's ledger rows with account `acc1`), `ce_bedrock_usd` null and a `ce_source` note.
  - `monthly_cost_report.py` always shows acc1 and acc3 (route order: acc1 first), takes `--acc1-usd` /
    `--acc1-prev-usd` from a one-line Cost Explorer read on acc1 (profile `pqnghiep-admin`, documented in
    `docs/ops/cost/README.md` step 3), and adds an "acc1 Bedrock (gateway estimate)" month-over-month row.
  - The totals do not change: acc1 calls are already in the LLM spend by app (billed outside acc2), as for acc3.
- **Vendored test file (item 5).** The AI gateway names test moved to `tools/docs/test_check_ai_gateway_names.py`
  (root only, own small `TempRepo`), so `test_docs_tools.py` tests only vendored scripts and is byte-identical again in
  all five repos. AA-Partner's copies were older (no translation helpers in `docslib.py` / `check_frontmatter.py`);
  they are re-synced with the rest. `docs/templates/frontmatter.schema.json` is synced too (additive `nav`,
  `nav_order`, `known_issue` fields).
- **project-template (item 7).** The repository exists in the org (public, not archived; read-only org listing). It is
  added to a new `KNOWN_PUBLIC` set (REPOS plus public repos meant to stay) that only the org check reads, so the
  "unknown public repo" finding clears. It is NOT added to `REPOS` (review fix): the ci-bot token in
  `ci-hygiene.yml` is scoped to the six repos of `REPOS`, so scanning a seventh repo would read its caches with a 403
  and open a standing "needs-permission" issue every day. A test keeps the workflow's `env.REPOS` equal to `REPOS`.
  Scanning project-template too means adding it to both and installing the ci-bot App on it (follow-up, not here).
- **Retired phrases (item 17).** A new `check_docs_text.py retired-phrases` check (vendored, so every repo can run it).
  Each entry pairs a pattern with the live truth the message prints. A line with a history word (retired, removed, no
  longer, was, ...) passes; journals, ADRs, exported Linear issues, archived pages, dated postmortems, the dated
  ecosystem review and the generated schema reference are skipped. Root CI runs it warn-only (40 warnings today, all
  real stale claims the AA-1118 rewrite fixes); switch to `--mode error` once that lands.

## Tradeoffs

- History words are a coarse filter: a stale line that happens to contain "was" passes. Accepted for a warn-only
  check; the precise fix is the page rewrite, the check only stops the phrases from coming back.
- `portal/` is matched only as a code span or after a repo name (`AA-Partner/portal/`), not bare, because route
  segments such as `/portal/...` in the CRM web are live.
