## Decisions

- **ADR numbers.** Used before this PR: 0001–0008 (+ 0003a, 0004a, 0004b, 0006a). Reserved before: 0009 (AI platform,
  AA-804). This PR adds:
  - `0005a` (ADR 0005 amendment: decision 9 warn-not-block, no subscription line, VND),
  - `0006b` (ADR 0006 amendment: partner pool with required MFA, M2M pool; 0006a already exists, so `b`),
  - `0008a` (ADR 0008 amendment: CRM as a separate app, step 8 traveller OTP exception, step 9 own LLM gateway),
  - `0010` (new AA-Partner ADR; 0010 is the next free number after the 0009 reservation).
- **Reservations recorded in the index.** The engineering handbook, the guides and `docs/README.md` already cite
  ADR **0012** (prod blueprint / environment model, AA-880) and ADR **0013** (HTTP API conventions, AA-899) by
  number. An exact index has to list them, otherwise the next-free line would offer 0012 to the next author. They are
  now reserved in the index with their issue. **Nothing is reserved for AA-901** (GitHub App identity,
  release-please): as instructed by the orchestrator, AA-901 takes the next free numbers when its ADRs are written.
  The handbook / backlog text that said "ADR 0010/0011" for AA-901 now says "two root ADRs, numbers from the index".
  Next free after this PR: **0011, 0014**.
- **ADR-number check is a new tool, not a change to `tools/docs/check_adr_index.py`.** The docs-lint tools must stay
  byte-identical in four repos (tools/docs/README.md). The new `tools/adr/check_adr_numbers.py` runs only in root.
- **Reserved-number claim rule.** A new ADR may use a reserved number only when its header cites the reserving issue
  (e.g. `AA-804` for 0009) and the same PR removes the reservation row. That lets AA-804 take 0009 without a manual
  override and still rejects anyone else.
- **New base ADRs must take a next-free number of the base branch** (no skipping ahead), and a new amendment must take
  the next letter of its base ADR (0006a exists → 0006b). Renaming an ADR's slug is allowed (same number disappears
  from the base list).
- **Contracts format.** The four HTTP contracts are OpenAPI 3.1 in YAML (`docs/contracts/<name>.openapi.yaml`):
  OpenAPI 3.1 schema objects are JSON Schema 2020-12, so the same `jsonschema` library validates them and the
  samples. The lane draft named `booking.b2b.v1.yaml`; the `.openapi.yaml` suffix keeps them apart from the JSON
  Schema event contracts in the same folder.
- **Forbidden-key policy lives in the checker** (`tools/contracts/check_contracts.py`, `POLICY`), not inside the
  contract files, so loosening it is a visible change to reviewed code rather than an edit next to the schema it
  guards. Two layers catch a forbidden key: the schemas (`additionalProperties: false` everywhere) and an independent
  recursive key scan of every schema and sample. Required negative samples (trip_count, revenue, `pii:`,
  supplier_net) are listed in the checker; deleting one fails CI.
- **crm.ops.v1 carries no PII at all**, including the first-owner invite: the request names a CIS membership
  invitation id (`membership_invitation_id`), never an email. CIS owns invitations and the mail (ADR 0006 decision 3,
  AA-978); the CRM only learns "this invitation becomes the first owner".
- **tenant.membership.v1** carries `(iss, sub)` tagged `x-pii: online_id` (AA-813 S238 addendum) and the Content
  studio role only (`content_studio_role` owner/editor/viewer). No CRM role, no email or display name; the checker
  forbids `crm_role`, `role`, `email`, `display_name` there.
- **Path prefixes** (`/booking/b2b/v1`, `/catalog/v1`, `/tenant/membership/v1`, `/crm/ops/v1`) are written as in the
  design; the Booking and CIS ones are marked provisional until ADR 0013 (AA-899) sets HTTP conventions. The contract
  name and major do not change with the prefix.
- **Spec errata** go into the spec itself as a new last section (bilingual EN–VI, the convention for pages meant for
  Ms. Thư), so the original text stays readable and the correction sits next to it.
- **v2.2 copy:** already done in S246 (`docs/audits/2026-10-21-S246-crm-design-v3/inputs/`, byte-identical to
  `.tmp-session/s245-r2/r4/`, checked with `diff -q`). Nothing to copy; the ADRs cite it (D8).

## Tradeoffs

- **OpenAPI structure check is home-made** (operationId unique, local `$ref` resolve, path parameters declared,
  component schemas valid 2020-12) instead of `openapi-spec-validator`. Reason: no new dependency beyond the two pins
  docs-lint already uses (`jsonschema==4.23.0`, `PyYAML==6.0.2`); the full meta-schema check can be added later if
  contracts multiply.
- **Reserving 0012/0013** goes slightly beyond "next free numbers"; not reserving them would make the index wrong
  against five other pages that already cite those numbers.
- **PII key-name deny list** for no-PII contracts (email, phone, dob, passport, …) is a heuristic on top of the
  `x-pii` / `pii:` markers. It can false-positive on a future harmless field; the fix is an explicit, reviewed
  exception in `POLICY`.
