# AA-697 — Architecture diagrams with official AWS icons (root repo)

Session S256 (2026-10-28), lane AA-697. Companion CIS branch: `feat/aa-697-docs-reader-svg` (the docs reader shows the
SVGs). Plan source: the S255 Linear comment and `docs/audits/2026-10-28-S255-aa697-aws-icons/`.

## Decisions

- **Python `diagrams` 0.25.1 is the tool**, not Mermaid `architecture-beta`: official AWS icons including Bedrock,
  Graphviz layout with clusters for accounts / VPC / groups. Graphviz is not installed system-wide and there is no
  sudo; `apt-get download` + `dpkg -x` into `.tmp-session/S256/aa697/gv` works (graphviz 2.42, `dot -c` once, then
  `PATH`, `LD_LIBRARY_PATH`, `GVBINDIR`). The README documents this.
- **Six views**: ecosystem, AA-CIS-Infra, AA-CIS-App, AA-Booking, AA-TripPlanner-Web, AA-Partner. Deployment views only;
  the A/T pipeline and other non-AWS flows stay Mermaid in the prose (as the S204 tooling plan says).
- **Self-contained SVG**: `diagrams` writes `<image xlink:href="/abs/path/icon.png">`. `_common.finalize_svg` inlines
  each icon as a PNG data URI (downscaled to 96 px with Pillow: 180-370 KB per view instead of about 2x that), strips
  every Graphviz comment and renumbers the random uuid4 node ids (`n1`, `n2`, ...) so an unchanged view renders to
  the identical file and no random digit run looks like an account ID.
- **Curved splines, not ortho**: Graphviz cannot place edge labels on orthogonal edges (they drifted far from their
  lines in the first render). The infra view is top-to-bottom (left-to-right made it 2 x 4.5 k px); the others are
  left-to-right.
- **One safety rule, two places**: rule 9 of `tools/docs/build_docs_reader.py` (`svg_problems`) is the check; the
  diagram renderer imports it. SVGs are published byte for byte (never redacted, a marker inside base64 would break
  the PNG); an unsafe SVG or one with an ID in its text fails the build instead.
- **Digits inside inline PNGs are not text**: the guard runs on the SVG with the base64 payloads removed.
- **Assets are staff tier**: no owner-only SVG exists; the rule says an SVG must not carry owner-only content.
- **Upload**: `docs-sync.yml` syncs `assets/AA-Ecosys/` with `image/svg+xml` before the manifest and deletes stale
  ones after it, same order as pages. The existing `aa-cis-dev-docs-sync` role already allows `docs-reader/*`, so no
  Infra change.
- **ecosystem-architecture.md** keeps its Mermaid flowchart as the text version under the new image.

## Tradeoffs

- Rendered SVGs are committed (not rendered in CI): Graphviz output differs between versions, a CI render would need
  Graphviz in the runner and would make every docs merge rewrite the images. The cost is that a `.py` edit without a
  re-render goes unnoticed; the README says to commit both together.
- Inline PNG icons instead of vector icons: `diagrams` ships PNG only. 96 px keeps them sharp at the drawn size.
- No Terraform drift check (TerraVision) yet; the infra view was drawn from CONTEXT.md and the ecosystem doc.

## Should know

- Done-when items still open on the issue: tech lead review of the pilot view, TerraVision drift check, `CONTEXT.md`
  links in the five repos (each is a public repo PR).
- A reader that predates rule 9 ignores `assets`; the CIS branch adds `GET /admin/docs/asset` and image rendering.
- Independent review (S256): rule 9 now also parses the SVG (`svg_tree_problems`): SVG-namespace elements from a fixed
  allowlist only, no namespaced attribute except `xlink:href`/`xlink:title`/`xml:space`, no `on*`, every href a
  fragment or an inline PNG, no decoded value with `url()`/`javascript:`/`@import`/`image-set`/backslash, no
  processing instruction. The regexes alone missed namespace prefixes and character references. A new diagram that
  needs another element type (for example `<style>`) must extend the allowlist on both sides.
- Byte-identical re-renders assume the same `diagrams`, Pillow and Graphviz versions; the README does not pin them.
