# AA-1064 — Guides show screenshots (root side)

Session S275 (2026-11-10), lane l6. The CIS side (route, BFF, reader) is in AA-CIS-App
`docs/implementation-notes/AA-1064.md`.

## Decisions

- **Rule 10 of the bundle builder**: a tracked PNG / WebP under `docs/` is published only when a published page links
  it. Rule 9 publishes every SVG, but `docs/AAA/figma_AAA/` alone holds 120 design PNGs (with spaces in the names) that
  must not leave git by accident; "linked from a published page" is the intent of a guide screenshot.
- **Fail the build, not skip**, on a linked image that is over 300 KB, has a wrong signature or an account / resource ID
  in its text metadata (PNG tEXt / iTXt / zTXt / eXIf, WebP EXIF / XMP): same stance as an unsafe SVG. The lint catches
  it in the PR first. A missing linked image is not a build failure (the page shows alt text); the lint fails on it.
- **Access tier** of a screenshot = the most open tier of the pages that link it.
- **One parser for lint and bundle**: `check_images.py` imports `image_links`, `resolve_image`, `raster_problems`,
  `svg_problems`, `is_never` from the builder, so they cannot drift. `resolve_image` mirrors the CIS reader's
  `resolveImage` (relative to the page folder, `/` from the repo root, query and fragment dropped, percent-decoded),
  and so does the CIS API's `docs_reader.linked_images` (which bundle images the AI gateway Guide page links).
- **Lint scope**: every tracked `docs/**/*.md` outside the never-published folders; fenced code, inline code and
  `docs-lint: ignore` lines are skipped. Remote and `data:` images are errors (the reader never loads them).
- **Proof**: `docs/guides/images/cis-admin-docs-reader.png` is a copy of an existing S255 Dev screenshot of the Docs page
  (`docs/audits/2026-10-28-S255-aa898-docs-reader/docs-list-1440-light.png`, 88 KB, no ID visible, no metadata),
  linked from `docs/guides/cis-admin-runbook.md` and its `.vi.md`, section 6. It is not cropped (no image tool on the
  lane machine); a fresh cropped capture can replace it in place.

## Changed

- `tools/docs/build_docs_reader.py` (rule 10), `tools/docs/check_images.py` (new), tests `test_docs_reader.py`
  (ScreenshotAssets) and `test_check_images.py` (new).
- `.github/workflows/docs-sync.yml`: one `aws s3 sync` per type (svg, png, webp) for upload and for `--delete`.
- `.github/workflows/docs-lint.yml`: step "Docs images".
- `docs/STYLE.md`, `docs/README.md` (publication rule table), `tools/docs/README.md`.

## Tradeoffs

- Pixels cannot be checked for IDs; STYLE asks the author to crop. Metadata is checked.
- The builder imports nothing new; `check_images.py` is root only (not vendored to the other repos).

## Should know

- The Docs sync role writes anywhere under `docs-reader/`, so the new object types need no Infra change.
- Merge order with the CIS PR is free (see the CIS note).
- Where screenshots show: the CIS admin docs reader (`/admin/docs`, admin only) and, for its own page only
  (`docs/architecture/ai-gateway.md` and `.vi.md`), the AI gateway Guide tab (admin, finance, ai_ops), which serves
  the images that page links through its own route. No other page renders bundle images.
