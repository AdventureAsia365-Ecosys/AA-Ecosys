# AA-1022 — SEC-01 correction (root slice)

The Terraform and CI work of AA-1022 (and the AA-873 N17 alert) is in AA-CIS-Infra `docs/implementation-notes/AA-1022.md`;
the Dependabot change is AA-CIS-App `docs/implementation-notes/AA-1022-cis.md`. This root PR corrects SEC-01
(`docs/security/baseline.md`) to the control set that runs today (S261 architecture review F6 / N17).

## Decisions

- **No SoA-lite.** The page states that it is a control list, not a Statement of Applicability, maps to no ISO 27001
  Annex A control or SOC 2 criterion and claims no certification; the mapping waits for trigger T-QUESTIONNAIRE (the
  tech lead's S263 decision on the S262 follow-up table).
- **Every changed row re-read live on 2026-11-01** (read-only AWS CLI with the MFA profile, GitHub API): GuardDuty
  (no detector: by decision), Access Analyzer active, account S3 BPA 4/4, trail multi-region + KMS + validation,
  Redis AUTH/TLS/at-rest all on, five `aa-sec-dev-*` rules (the two Identity Center rules come with the apply), rulesets per repo, `security_and_analysis` on six repos,
  `dependabot.yml` ecosystems per repo, `docs/backups/` empty. Issue states (AA-875, AA-829 Done) from the Linear
  export.
- Rows that depend on the AA-1022 Infra apply (S3 gateway endpoint, Identity Center admin alert, `ref` pins on the
  Booking/CRM roles) say "after the AA-1022 apply": this PR merges after that apply is verified.
- `docs/security/README.md` no longer says the security pages live in a private repo (the root is public until the
  coding phase ends, ADR 0014 amendment); it states what the pages may and may not hold instead.

## Changed

- `docs/security/baseline.md`: summary, edge rows (SSRF in place, new S3 endpoint row), CI trust row, merge-rights row
  (DM-11.5 v1.1 wording), data rows (Redis, laptop dumps), detection rows (CloudTrail, GuardDuty by decision, Access
