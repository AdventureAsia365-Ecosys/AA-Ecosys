# AA-1087 — Dev-only write-capable E2E staff identities (root half)

Decision record: ADR 0006a A10b-3 (CIS) and A10e (Booking). Code: AA-CIS-App (A10b-3 + migration 401), AA-Booking
(`backend/app/auth/e2e_staff.py`), AA-CIS-Infra (trigger map, mailbox, user tool); each repo keeps its own
`docs/implementation-notes/AA-1087*.md` with the threat note for the independent review.

## Decisions
- CIS keeps one E2E admin (A10b) and gains one synthetic-only write (Compliance release of a held piece). The Review
  Queue approve is never given to an E2E identity: it publishes AA master content, which has no synthetic records.
- Booking gets three new Dev-only addresses (staff; finance maker / checker) in the MFA-admin-only mailbox prefix,
  not a wider A10a (CI-readable codes).
- "Synthetic" is CIS's one rule (`is_canary IS TRUE AND NOT is_pilot`), served to Booking as
  `catalog.v_tenant_account_v1.is_synthetic` (CIS 401, tenant.entitlements.v1 1.6).

## Changed (this repo)
- `docs/adr/0006a-identity-phase1-amendments.md`: A10b-3, A10e, the header summary and the removal list.
- `docs/contracts/tenant.entitlements.v1.openapi.yaml` 1.6 (byte copy pinned by CIS) and `docs/contracts/README.md`.

## Tradeoffs
- No new secrets: sign-in is the email code (secrets register unchanged).
