# AA-877 implementation notes (root repo: RoPA column inventory from the pii tags)

Scope: AA-877 scope item 3 (a RoPA table built from the DM-6.1 column tags), root repo part. The tags themselves are
set by AA-Booking bk-018 and AA-TripPlanner-Web tp-016; AA-CIS-Infra (`db/schema_dump.py`,
`db/gen_schema_reference.py`) carries them into `docs/architecture/db-schema-reference.md`, section *Personal and
confidential data tags (DM-6.1)*. Refs AA-877, AA-886.

## Decisions

- **One RoPA, in `docs/legal/register.md` section (a)** (SEC-04, written by the AA-886 lane). No `docs/legal/ropa.md`.
  The tool writes a generated block "Column inventory (from pii tags)" between markers inside section (a), before
  "How to regenerate this table" (or before section (b) if that heading is gone). The hand-written RoPA rows (purpose,
  subjects, retention, recipients, transfer, legal basis `[to be confirmed]`) stay hand-written.
- **`tools/data/gen_pii_inventory.py`**, standard library only, reads the *Tagged columns* table of the reference for
  every schema (CIS `shared.*` tags of migrations 247 / 251 included). `conf:commercial` is business data and is left
  out of the inventory; `pii:*` and `conf:credential` are in.
- **`--check`** exits 1 when the block is stale or a tagged column is named by no RoPA row (a new processing line).
  Tagging gaps (a booking / tripplanner column named in a row, present in the reference, without a tag) are printed;
  they fail only with `--strict`, because consent flags, pseudonymous refs and business data are untagged on purpose
  (DM-6.1) and are still worth naming in the RoPA.
- A RoPA cell names columns as `` `schema.relation.column` `` or `` `schema.relation` (`col`, `col`) ``. Plain words
  ("dates, pax") are not parsed: PR-5 rewrites those cells with backticked column names so the check can see them.

## Changed

- `tools/data/gen_pii_inventory.py`, `tools/data/test_gen_pii_inventory.py` (13 tests, fixture reference + register).

## Tradeoffs

- The tool parses the rendered Markdown, not `schema.json`: the JSON is a workflow artifact the root repo does not
  keep, and the Markdown table is generated with a fixed shape (AA-CIS-Infra `render_pii_tags`). A shape change there
  breaks the parse loudly (exit 2), not silently.
- Not wired into the root docs-lint workflow yet (it runs `tools/docs` tests only); a one-line workflow change can add
  `tools/data` later.
