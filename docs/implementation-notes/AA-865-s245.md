# AA-865 (S245) — pooled F9_cta_fact re-flag rate: implementation notes

Lane `f9pool`, Claude Code, 20/10/2026. Scope of this lane: the $0 read-only pooling script and the audit
folder skeleton. The fix is NOT in this lane: it waits for the data.

## Decisions

- **Script location.** `.tmp-session/s245_f9_pool.py` (workspace scratch, gitignored) is the runnable copy, as the
  lane brief asks. A copy goes into the audit folder (`script/s245_f9_pool.py`) once it has run, so the report
  cites the exact code that produced the numbers. The root repo is private, so the bucket name in the script is
  allowed there.
- **DB login.** The script reads `DATABASE_URL` from the api container (role `cis_app`), `ssl="require"`, one
  read-only transaction. It does not read `aa-cis/dev/rds`: since X1 S18/S19 the CIS task role is denied that
  secret, so the S239 readouts (which did) can no longer run unchanged.
- **Metric definition copied, not re-invented.** `reconstruct()` and the "retry added a blocking fail" rule are
  copied from `.tmp-session/s239/aa777_r7_readout.py` (itself a port of S234 `fr_analyze.py`). The pooled numbers
  must therefore reproduce the committed per-round readouts (r5 1/26, r6 4/26, r7 3/23, aa768 sets 1/9, 0/8, 1/8);
  the script carries those as `expected` and reports any mismatch instead of hiding it.
- **Piece sets.** S235_r5 / S239_aa768_pre761 / S234_r4 ids are the `BASE_SETS` of the r7 readout. The r6 and r7
  ids (main set and AA-768 set) are taken from the `pieces` arrays of the committed
  `docs/audits/2026-10-16-S239-in-progress-audit/aa777-r{6,7}/readout_stdout.json`, so no S3 state file is needed.
- **Pools reported.** `primary_r5_r7` (the issue title: r5 + r6 + r7, n = 75 retries), `extended_with_aa768`
  (adds the three AA-768 sets, n = 100), `current_code_r7` (r7 + r7 AA-768, code after #767), `natural_post_r7`
  (T9 pieces created after 2026-10-16T08:12Z that are in no set: real traffic on current code) and
  `reference_S234_r4` (pre-sticky, never pooled). Each pool reports both the issue's headline metric (any blocking
  fail added) and the title's metric (F9_cta_fact added), each with a Wilson 95% interval, plus the same two on the
  sentence-repair family only, plus a variant that ignores F17 adds (the r6 F17 adds were fixed by #767).
- **Case dump.** Every retry that added a blocking fail is dumped (not only F9), because the Done-when asks to
  classify every retry-added fail. Per case: piece id, set, channel, attempt k, repair mode, gates added, the
  attempt k-1 repair targets (gate + quoted sentence), and for each F9_cta_fact claim at attempt k: the claim, the
  judge's reason (`why_not_in_source`), the located sentence, how many sentences the quote spans, whether that
  sentence is present unchanged in the attempt k-1 text, whether its sticky key (current `_f9_key`) changed, and the
  content words the repair added. A `suggested_class` (C1 real new fault / C2 F9 re-judging / C3 two-sentence quote)
  is a heuristic hint only; the class in the report is set by reading the case.

## Changed

## Tradeoffs

- **Attempt texts.** `content_piece` keeps only the final text and one `discarded_attempts` entry. A 2-attempt
  piece has both texts; a 3-attempt piece has attempt 2 and 3 only, so for its k = 2 case the attempt-1 text is
  missing and "unchanged" falls back to "was the sentence one of the k-1 repair targets" (a sentence repair edits
  only its items). The case says which method was used (`location_method`).
- **Post-loop edits.** The final text can differ from the last attempt's text (LinkedIn F9 truth cut, aup cut,
  final integrity pass). Cases on a post-loop-edited final text are marked `final_text_post_loop_edits`.
- **Sticky replay is an approximation.** The earlier verdict's flagged set is rebuilt from its F9 violation quotes;
  loose note quotes and the "verdict was whole" condition are not stored in the DB (`F9_sticky_pass_skipped` is a
  CloudWatch line only), so `would_be_sticky_now` is a hint, not a replay.
- **Output size.** Full JSON goes to S3 (`scripts/out/s245_aa865_pool.json`); stdout is a short summary, because
  the SSM session truncates long stdout (lessons, S237).
