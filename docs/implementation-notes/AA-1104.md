# AA-1104 — Implementation notes (root repo: gap pages and the lesson format)

Source: the AA Academy research `docs/research/lms/README.md` (GUIDE-13-lms; gap table §2, pipeline §6, rollout §8;
decisions approved in S279). This file covers the root repo. The app and Infra repos keep their own notes for the
run-it-locally sections (G7) when those land.

## Decisions

- **Two writers, one commit owner.** Two S280 agents wrote this tree at the same time. The fix-round agent commits the
  whole tree and re-runs every check on that commit; results from before the commit do not count.
- **Dead links removed, not stubbed.** The handbook §2.4 (EN and VI) linked a G6 page `guides/working-rules/sessions.md`
  that was never written. The link is removed; §2.4 points at `skill/aa-session/SKILL.md` only. G6 stays open.
- **Testing strategy links the existing local-run section.** ARCH-10 points at `new-engineer.md#first-local-run-per-repo`
  until G7 writes a run-it-locally section per `CONTEXT.md`.
- **ARCH-10 gets its catalog row** in `docs/README.md` (decision D12: the catalog is the only index). Its `related`
  names `GUIDE-13-lms`, the id the research page really has (no page has the bare id `GUIDE-13`).
- **Dates stay strings.** `check_learn.py` loads YAML with a SafeLoader subclass that drops the timestamp rule, so an
  unquoted `last_reviewed: 2026-11-14` (the repo habit in front-matter) passes the schema. This keeps keys and nested
  values untouched, unlike stringifying after the load.
- **`--pin` edits by YAML meaning, not by line shape.** It collects the wanted hash per ref from the parsed module, then
  walks the block-style list items: the `ref` value is read as a YAML scalar (quotes removed), the `sha` key is found in
  any order inside the item, and a missing `sha` is inserted after `ref`. A source it cannot rewrite (flow style
  `{ref: ..., sha: ...}`) is printed with its hash so the owner sets it by hand, instead of failing silently.
- **All-digit hashes are quoted** when pinned: PyYAML loads `0000...` as an int, and YAML 1.2 readers load any
  all-digit hash as a number.
- **G13 Infra roots.** `skill/aa-ecosys-repos` now lists the four Infra roots on `origin/main` (aa365, acc1-bedrock,
  acc3-bedrock, management).

## Changed

- Gap pages: G2 `docs/architecture/testing-strategy.md` (ARCH-10, draft); G5 handbook §2.4 + §10.4 (EN and VI); G13
  fact fixes in data standards (v1.14), FinOps, onboarding and five skills.
- P2 groundwork: `docs/learn/schema/{module,quiz,path,allowlist}.schema.json`, `tools/docs/check_learn.py`, and its unit
  tests `tools/docs/test_check_learn.py` (picked up by the existing `unittest discover -s tools/docs` step of docs lint).

## Tradeoffs

- Removing the G6 link loses a pointer the research wanted, but a dead link fails the offline lychee step; the page
  comes with G6.
- `--pin` still does not round-trip flow-style YAML. A YAML round-trip library would, but it adds a dependency to the
  docs lint for a style the format does not use.

## Should know

- Not done yet (still in AA-1104 scope): G6 rule pages, G7 run-it-locally sections, `docs/learn/README.md` (the
  schemas point at it), `allowlist.yaml`, a sample path and module with a quiz, the `check_learn.py` step in
  `docs-lint.yml`, the GUIDE-13 catalog row switch, and the Docs sync learn manifest (CI/workflow change, needs review).
- `check_frontmatter.py` reads `git ls-files`, so it skips untracked pages; run it after the commit, not before.
- A hand-written all-digit `sha` that loads as a number fails the schema, and `--pin` skips modules that fail the
  schema; quote it or delete the line and re-pin.

## Slice 2 (S280, branch docs/aa1104-part1-rest): G6, G7 patches, P2 format and bundle

### Decisions

- **G6 as three rule pages plus an index** under `docs/guides/working-rules/` (catalog `GUIDE-15`, `-sessions`,
  `-planning`, `-stakeholders`), matching the three lesson groups the research names (L3 sessions, L4 planning and
  issues, L6 stakeholders). The page holds the rule, the skill keeps the procedure; when they disagree the stricter
  one applies until one PR fixes both. The three skills got a one-line pointer to their page.
- **GUIDE-15 is a new catalog ID** (GUIDE-14 is the playbook); the earlier slice's dead link
  `guides/working-rules/sessions.md` now exists and handbook §2.4 links it again (EN and VI, change history rows).
- **Vendor wording.** The source rule says to call the business owner "sếp mình" to vendors; the English page says
  "our management", the `.vi.md` keeps "sếp mình".
- **G7 is not in this branch.** Five patches (one `## Run it locally` section per `CONTEXT.md`, AA-CIS-App, AA-Booking,
  AA-TripPlanner-Web, AA-Partner, AA-CIS-Infra) against each repo's origin/main, written from the README, `package.json`,
  `scripts/pre-push.sh` and a boot test: Booking and Partner APIs answer `/health` locally with no database; the CIS
  API refuses to start without `DATABASE_URL` (pool at start) and `JWT_SECRET`; the TripPlanner fixtures server answers
  `/browse/countries` with no database. GUIDE-10 names the new sections without linking them (app repos are external).
- **Sample module F3 "How work flows"** (Fundamentals): two reading lessons citing handbook §2.2 / §2.4 and the new
  rule pages, a six-item quiz. Prerequisite F2 is planned in `paths/fundamentals.yaml`.
- **Allowlist starts with five `context:` sections** (each repo's role section, English, public repos) for F2/E1, and
  `partner_pages` with the Content studio and CRM runbooks for the agency path. Verified with
  `check_learn.py --ext-root <workspace> --strict-external`.
- **Separate bundle builder** `tools/docs/build_learn_bundle.py` (imports `check_learn.py`) instead of extending
  `build_docs_reader.py`: its own output folder (`_site/learn`), so a course problem can never touch the pages build.
- **Drift publishes as stale on master.** A changed root section fails docs lint on the PR, but in Docs sync it only
  marks lessons stale and suspends the quiz items citing it (research §6.4); any other course error fails the learn
  build. External `CONTEXT.md` problems are always stale marks.
- **Quiz answers live in `quizzes/<module>.json`**, never in the manifest, so the API can keep them server side.
- **Docs sync order:** pages build and upload unchanged; then the five sparse `CONTEXT.md` checkouts
  (`continue-on-error`), the learn build (`continue-on-error`), the learn upload (only on success), and a last step that
  turns the run red when the learn build failed. Same IAM role (Put/Delete on `docs-reader/*` covers `learn/`).
