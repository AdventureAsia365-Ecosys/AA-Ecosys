# AA-886 (S245) — root repo: DM-6.5 consent capture query

Part A of the issue. The pages ship in AA-TripPlanner-Web (`feat/draft-legal-pages`) and AA-CIS-App
(`feat/portal-draft-legal-pages`); each repo has its own `docs/implementation-notes/AA-886-s245.md`. The legal
packet (part B: register, retention log, DPA template, RoPA, GDrive upload, Jira draft) stays open.

## Decisions

- **Page:** `docs/legal/consent-capture-query.md`, catalog ID `SEC-04-consent-query` (sub-page of SEC-04, the
  compliance and privacy register this issue owns). `type: how-to`, `status: draft` with the UNTESTED banner
  until it has run on Dev.
- **Runs through DB Migrate `mode=run-script`**, not ECS exec: it reads `booking.*` and `tripplanner.*`, which
  since X1 only the master can read. The page carries the ready Python file for AA-CIS-Infra
  (`db/scripts/dm65_consent_capture.py`, `READ_ONLY = True`); it is not added to Infra in this lane.
- **No personal data in the output:** the script prints ids, booleans, timestamps and counts only (the run-script
  contract forbids customer row values in the task log). The test inquiry is found by a LIKE pattern on a
  dedicated test address (`aa886-consent-test%@example.com`), never by printing emails.
- **Chain join on `booking.customers.external_ref = tripplanner.customers.id::text`** (AA-Booking
  `inquiry/contract.py`: `external_ref` = TripPlanner `customer_id`), so the TripPlanner record and the Booking
  master are compared without comparing contact data.
- **No schema change.** Value + time exist in both tables and the source is `booking.customers.source`
  (`tripplanner_lead`), which DM-6.5 names as the master. A `tp-016` consent-source column was not needed.

## Changed

- New `docs/legal/consent-capture-query.md`.
- `docs/README.md`: SEC-04 row links the page.

## Tradeoffs

- One script with four queries (coverage, integrity, chain, test inquiry) instead of only the test-inquiry
  lookup: the extra three are aggregates, cost nothing, and turn the one-off evidence into a check that can be
  re-run before prod.
- The test email is a constant in the script (run-script takes no parameters). A new test run needs a new
  address that still matches the pattern.
