# AA-1110: continuity pack, the parts an agent can prepare (lane l8 of S297)

Root repo side. The Infra side (the Slack chat alert channel in Terraform) is
`infra/AA-CIS-Infra/docs/implementation-notes/AA-1110-l8-chat-alert-channel.md`.

## Decisions

- **Extend `docs/ops/run-without-agent.md`, do not add `run-without-the-agent.md`.** The page already existed
  (OPS-01-no-agent, S283) and is linked from the drill index, the tabletop, the access register and the ops index. A
  second page with the same job would split the reader. Added the missing paths: rotate a key, handle an incident,
  who calls whom, and rows for them in the tested-state table.
- **Drill target: the Booking admin (`aa-booking-dev-admin`), not the CRM web.** Staff-only audience, stateless, no
  job table or migration, healthz names the build, its deploy workflow reuses the image on a rerun of the same commit,
  and its ECS path was never drilled (the game day drilled it on Vercel, since retired). The CRM web fronts the tenant
  portal host and the CRM sign-in, so a bad minute reaches agency users.
- **The drill uses no helper script.** `tools/ops/ecs_rollback.sh` was proven by the agent-run game day; a person
  without the agent must succeed with plain AWS CLI lines, so the drill page spells them out (list revisions, ECR
  check, configuration names diff, update-service, wait, verify).
- **Deploy by Run workflow, not by a merge.** A redeploy of `main` exercises the same pipeline (build or reuse, register,
  update, wait, verify, smoke, auto-rollback on red) without needing a code change in the drill window.
- **Tabletop re-centred on the business owner** (second on-call person and second key-holder, sec-Q16): who calls
  whom (a card), a real break-glass sign-in by the business owner with the tech lead watching, the CRM key rotation
  walk-through in plain words, a short leaked-secret talk-through. The cross-agency scenario and the real
  `db_migrator` rotation moved to an optional 30-minute extra part (kept, not dropped).
- **Second key-holder checklist as its own page** (`docs/security/second-key-holder-checklist.md`), with an evidence
  field per check; the access register stays the record and links to it.
- **Second alert channel runbook** (`docs/ops/runbooks/chat-alert-channel.md`): Slack through Amazon Q Developer in chat
  applications (piece A), the existing e-mail fallback (piece B, built S283) and the business owner's page-alert
  subscription on the CIS admin page (piece C). Cost 0 USD, cited from the AWS documentation page on the service rename
  (Pricing section), read 28/11/2026.

## Tradeoffs

- Slack shows only the AWS notifications Amazon Q Developer understands; plain-text messages on the alerts topic (CIS
  in-app checks, `[aa-sec]` sentences) stay e-mail only. The runbook says so and keeps e-mail as the fallback.
- The break-glass test puts the TOTP seed on a second phone for the test; whether the business owner keeps a copy of
  the rotated seed is left to the tech lead and recorded in the access register.
- The drill index carries two "to fill" rows. They are labelled, so nobody reads them as results.

  the commands), the tabletop with the business owner, and the hand steps of the chat channel runbook.
