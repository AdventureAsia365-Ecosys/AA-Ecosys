## Decisions

- **Hook = static reading of the SQL an agent is about to send** (`.claude/hooks/pilot_pii_guard.py`, Bash
  PreToolUse, orchestrator and subagents). It triggers only on commands that reach the database: an `aws s3 cp <file>
  s3://` upload (the S3-mediated ECS exec pattern), the ECS exec wrapper with a script file, an inline `--command` /
  `psql -c` / `psql -f`, and a DB Migrate run-script dispatch (it reads the Infra file DB Migrate would run, from
  `origin/main`). Every other command costs one regex check.
- **Same rule in both guards:** the protected columns are the DM-6.1 `pii:` tags (the hook reads them from
  `docs/architecture/db-schema-reference.md`, the Infra guard from the live catalogue) in crm, booking, tripplanner and
  the shared tables that have `tenant_id`, minus the AA staff directory `booking.staff_users`. A statement may count
  (`count(...)`, `count(DISTINCT ...)`, `FILTER`) and test `IS [NOT] NULL`, and may use the column in WHERE / JOIN /
  GROUP BY / ORDER BY; it may not return the value or a whole row.
- **Always on, not only while a pilot exists.** No agent or run-script needs a person's row values; a per-column rule
  cannot be fooled by a query that "should" only hit synthetic tenants, and it is tested before the pilot starts.
- **The hook is a heuristic, the Infra guard is precise.** The hook parses text (subqueries' select lists count, so
  `SELECT count(*) FROM (SELECT email …) s` is refused: write `count(DISTINCT email)`); the run-script guard plans each
  statement on the live database and follows aliases, views, CTEs and subplans.
- **Restore drill into a throwaway schema = temporary tables** of the drill's own transaction (`pg_temp`, dropped at
  commit), as `crm_app` inside the CRM API container (it holds the KMS key and the bucket). Runbook
  `docs/ops/runbooks/pilot-tenant-restore-drill.md`.
- **Retention of the nightly export:** the `crm.export_job` row of DM-7.1 already covers the files (`exports/` prefix,
  7 days by the bucket rule); its text now names the nightly pilot backup. No new table, so no new row.

## Tradeoffs

- The hook refuses some harmless forms (an inner select list that only feeds a count, `email IN (SELECT email …)`).
  Rewriting them as counts is cheap; a false pass would put a traveller's data in an agent transcript.
- Static scan of today's scripts: none of `tools/**/*.py` is refused; in AA-CIS-Infra `db/scripts/`, the past one-off
  AA-682 live checks, the `aa990_*` TripPlanner backfill / checks and `dm65_consent_capture` read tagged columns and
  would now be refused if re-run (history; the re-runnable seeds pass because the staff directory is out of scope).
- Columns without a `pii:` tag are not protected (the DM-6.1 census lists 52 untagged candidates).
