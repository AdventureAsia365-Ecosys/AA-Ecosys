# AA-1118 — Docs back to reality, with drift lints (S291 lane c-docs-drift)

Source: S282 ecosystem audit (R12, R19, R20, R21, R24, R26), AA-1118 scope (a)–(h). Cost 0 USD. Root PR + one CIS PR
(CONTEXT split); no Infra PR (see (c)).

## Decisions

- **(a) Runbooks.** `last_tested` is a date or the word `untested` on every page under `docs/ops/runbooks/`; `null` or a
  missing key fails `check_frontmatter.py` (the existing "Front-matter schema" step of the Docs lint, so no new
  workflow step). A date also needs `tested_where` and `tested_evidence`. A read-only check of the first steps is not
  a test: rollback-booking, rollback-terraform and ses-bounce stay `untested` and keep their read-only rows in the
  tested log. Templates keep `null` allowed by the schema (they sit outside the runbook folder); the runbook template
  now starts at `untested`.
- Dates come only from recorded evidence: rollback-ecs / rollback-tp-lambda / rollback-vercel from the S264 game day
  (D1/D2, D4, D3), secret-rotation from S242 (class 4 only), the two ECS cut-overs from S271–S272. Status stays
  `draft` (STYLE: active only after the tech lead read the page); the banners now say what ran.
- The drill index lists the S269, S279 and S281 one-tenant restore drills it missed (audit R12).
- **(b) Stale phrases.** Extended the existing `retired-phrases` check (AA-1134) instead of a new tool: entries are
  `RetiredPhrase(pattern, truth, history_ok, allow)`. New: Bedrock / "the LLM account" on acc3 alone, acc1 "removed from
  the ecosystem" without its S278 role (also when the sentence wraps), `develop` branch, `:latest` image tags. Phrases
  whose own words read like history (acc1 removed) pass only when the line or the next 3 lines state today's fact.
  Struck-through lines (`~~`) count as history. The 7-day backup phrase now needs "PITR", "automated backups" or "RDS
  backups" (tenant export prefixes really are kept 7 days).
- The Docs lint runs it as an **error on `docs/`** (every hit fixed here) and a **warning on agent files** (skills,
  steering, `.claude`): agent files are owned by their sessions; their 21 hits are listed as follow-ups.
- **(c) alarms.md IDs.** Already done in Infra by AA-1171 (Infra #968, `tools/docs/aws_mask.py` ELB_ID_RE, the
  generated page shows `{masked}`). Not redone. The audit's second half — "add the ALB/TG pattern to the root resource-ID
  lint" — is done here: kind `elb`, blocked (`--block elb`) in the root Docs lint even though other kinds only warn.
- **(d) Free tier.** Always-free amounts only, each with its AWS page and the as-of date 2026-11-24 (read through the
  AWS documentation tool). The section says up front that the free tier is shared by the whole organization
  (consolidated billing), so acc2 inside its reseller's organization may get none of it.
- **(e) Catalogue.** `proven: {date, evidence}` (key `date`, not `on`: YAML 1.1 reads `on` as `true`); evidence is a repo
  file, `uat:<id>` or a run / pull-request link of the org's repos. Planned rows need `milestone` (a plan.json milestone
  or `later`) and own no surface. Five planned rows from open plan issues; three proven pointers from recorded drills.
  The CIS bundle reader ignores unknown fields, so `proven` / `milestone` reach the bundle without a CIS change.
- **(f) plan.json drift.** Inside `plan_sync.py --validate` (already a Docs lint step): errors only where plan.json
  contradicts itself (done with an open criterion, all criteria done but not done, an open issue slotted to a done
  milestone). "Criterion names only closed issues" is a warning: a criterion can wait on a date (M1b's ≥01/12 checks).
- **(h) Postmortems.** `detected_at` / `resolved_at` in the schema (date or date-time with offset) and the template;
  the one record gets `detected_at` 2026-10-29 (minute not recorded) and `resolved_at` 2026-11-12 (acc1 serves
  Bedrock, S278), its index row moves to `mitigated`. `check_frontmatter.py` now keeps a YAML date-time's time and
  offset (it used to cut every date-time to the day).

## Changed

- (c) needed no Infra PR (done by AA-1171). (f) adds no new CLI mode: `--validate` is the check mode the Docs lint
  already runs.
- Docs fixed for the stale phrases: README, STYLE, onboarding, glossary, ops README, FinOps, database operations,
  restore-rds-pitr, rollback-terraform (the acc1 root exists again since S278), llm-cost-spike, CIO guide, legal register,
  DPA outline and template (14-day backups, `backup_retention_period = 14` in Infra `modules/rds/main.tf`), security
  baseline, secrets register, AI use register, diagrams README, contracts README, ecosystem architecture, 03-scaling
  (dropped the retired inquiry-pull row).

- The vendored copies (`check_docs_text.py`, `check_frontmatter.py`, `test_docs_tools.py`, the schema) are synced
  byte-identical to AA-Booking, AA-Partner, AA-TripPlanner-Web and AA-CIS-Infra in one small PR each (tools/docs
  README rule). The two loops were split so the copies pass the Booking / Partner code-health limit (complexity 10).

## Tradeoffs

- Warning, not error, for agent files and for criteria naming closed issues: both have false positives an author
  must judge; failing CI on them would push people to `docs-lint: ignore`.
- `ALLOW_WINDOW = 3` lines: wide enough for a wrapped sentence, small enough that a far paragraph does not clear a
  stale line. A lint window, not a policy threshold, so it stays a code constant.
