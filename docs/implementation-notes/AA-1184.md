## Decisions

- **Shared parser, imported, not extracted.** The calendar uses `golive_gate.parse_yaml` by import. Lane l7-golive edits
  `golive_gate.py` in the same wave (gate dates), so moving the parser into a new module now would make two root PRs
  touch the same lines. Follow-up: extract `tools/ops/yaml_subset.py` once both are merged.
- **Dates read, not copied**: three `dates_from` lines read the secrets register rotation blocks (via
  `tools/security/secrets_register.py`, PyYAML), the open go-live gate lines and the vulnerability exception register.
  The line is due on the earliest date and overdue when any date passed. These dates are live state only: the `.ics`
  has no event for a `dates_from` line (review fix, see Changed).
- **Four kinds as the issue names them**, plus a "not before" window on a deadline (`window_from` without `date`): the
  backlog's "≥ date" checks have no due date, so they turn amber (`open`) and never red.
- **Recurring due date = last record + one period** (weekly 7 days, monthly/quarterly/yearly by calendar month, clamped
  to the month end). It matches the skill's weekly rule; monthly is a little later than "first session of the month".
  `evidence: check:<id>` lines are graded by CIS (the tab shows that check's state); `evidence: none` lines are
  reminders that never go red. A duty that a compliance check already grades against an admin age setting (access
  review `cis.compliance.access_review_max_age_days`, restore drill, monthly security review) is always a
  `check:<id>` line with no `warn_days`, so the duty has one limit and one evidence source (test
  `test_a_duty_a_compliance_check_grades_is_watched_never_graded_by_a_glob`).
- **No threshold literal**: `warn_days` is a per-line field, required on every line that can be overdue (no default in
  code). Overdue = past the due date, a definition, not a tunable threshold. The collector publishes pass/fail itself;
  no CIS setting was added (no migration).
- **Pull requests warn, Mondays fail.** On a PR the workflow reports overdue lines as warnings (an unrelated edit is
  never blocked); the Monday run and a dispatch fail, so `guard_runs.py` shows it at session start. The daily red comes
  from the compliance collector, so no GitHub cron runs more often than daily.
- **Detail under 8 KiB**: rows are `id|kind|state|due|last|owner|title|check|extra|note` strings with kind and owner
  codes; notes only on lines that need attention. The real calendar is about 7 kB; a fallback shortens calm titles,
  then drops automated lines, then keeps only attention lines (`truncated`). `|` is refused in titles and notes.
- **Live drill without editing the calendar**: workflow input `drill_overdue` adds one past-due line (OC-999) for one
  run; the detail says `drill: true`.
- **plan.json untouched**: the tracker's `checks` stay as they are (the orchestrator edits plan.json at session close).
  Follow-up: generate the tracker's checks from the calendar.
- **GuardDuty line is a trigger** (first real pilot data day), following the S295 decision in the waiting list, not the
  older "≥ 01/12" row of backlog §1.

## Changed vs the issue

- The secret rotation dates are a `dates_from` line, not one line per secret (94 dated rows would crowd the tab).
- Done-time items of backlog §1 (struck through) were not moved; tasks without a date (next-session hand steps) stay
  in backlog §2.
- Review fix (S297): the committed `.ics` first carried one event per register date. Any edit of the secrets register,
  the go-live checklist or the vulnerability exceptions then made it stale and turned Docs lint and the Ops calendar
  check red on unrelated pull requests (two lanes of the same wave edit those registers). The feed is now a pure
  function of `calendar.yaml`; register dates show on the CIS tab and in `status` only.
- Review fix (S297): OC-004 (quarterly access review) was graded by its own glob and `warn_days: 14`, a second limit
  next to the admin setting the Overview check uses. It is now `evidence: check:last_access_review`.

## Tradeoffs

- One line per register instead of one per row keeps the tab readable, but the tab shows only "3 past due of 94";
  the register page has the names.
- The `.ics` depends only on the YAML (never on today or a register), so it is reproducible in CI and no register
  edit can make it stale; the price is no phone event for a rotation or exception expiry (the tab and `status` show
  them). Recurring lines repeat from their anchor, not from the last record.
