## Decisions

- **Copies are "transform copies", not raw byte copies.** A source keeps AA pointers (overlay links, issue keys, ADR
  numbers) that must not reach a public template. Rather than fork the text, a source marks those lines:
  `kit:skip` blocks, `kit:drop` lines, and `kit:only` lines that appear only in the copy
  (`tools/project-kit/kit_transform.py`, header has the grammar). The template repo checks
  `copy == kit_transform(source)` byte for byte, so the guard is still exact: a hand edit of a copy turns its CI red.
  The markers are HTML or `#` comments, so the root pages render and run unchanged (YAML front matter included: a
  `# kit:drop` after a value is a YAML comment).
- **Tooling lives in `tools/project-kit/`, not `tools/kit/`.** `tools/kit/` already holds the UI kit sync of
  ADR 0016; one folder per kit avoids mixing the two "kits".
- **The list of copied files is `tools/project-kit/kit-sources.txt`** (`<source> <dest>` pairs); the template repo
  carries a copy of the list and of the transform, both checked like any other copy.
- **The denylist stays in the root repo** (`kit-denylist.txt`: AA names, issue keys, people, hosts, account-number
  shapes). The template repo reads the same list from an Actions variable (`LEAK_DENYLIST`), so the public template
  never carries a list of AA names. Root Docs lint runs the check on every PR that touches a kit source.
- **Generic skills read their values from the "Project parameters" section of `AGENTS.md`** (tracker, key prefix,
  repos, health URLs, deploy and merge commands); a skill names a parameter, never a value.
- **AA skills become the overlay** with a one-line pointer to the generic skill at the top; the AA text stays as it is
  (no big-bang rewrite, D12).
- **Hooks:** the shell guard is split into `shell_guard_core.py` (generic rules PKILL-1, ZSH-1, ENV-1, BG-1, WT-1,
  TF-1, RAM-1) and `aa_shell_guard.py` (imports the core, adds SHIP-1 and the AA rules). The subagent guardrail reads
  its patterns from `subagent-guardrails.d/*.txt`: `00-generic.txt` (kit) and `50-aa.txt` (AA). The MCP guardrail is
  generic already and gains a red-team test (`test_subagent_mcp_guardrails.sh`), so its "red-teamed by hand"
  exemption in `test_settings_hooks.py` goes.
- **Owner field** of the copied playbook pages and the templates index is the role `tech-lead`, not a person.

## Should know

- The template is public: the leak scan reads `LEAK_DENYLIST` (an Actions variable the orchestrator sets from
  `tools/project-kit/kit-denylist.txt`) and the copy guard reads `KIT_SOURCE_REPO`. Both must be set before the first
  CI run, or those jobs fail closed.
- **Commit identity of the public template.** The lane's two local commits carried the engineer's name and private
  e-mail; file scans and gitleaks cannot see commit metadata. Fix pass: the history is one commit authored and
  committed as `aa-agent[bot]` with its GitHub noreply address, no issue key in the message, old objects pruned. Kit
  CI gains "Denylist scan of the commit metadata" (`tools/kit_copies.py scan-history`: author, committer and message
  of every commit, full fetch depth), so a later PR commit under a personal identity turns CI red. Only commits made
  through the App (squash merges) should reach `main`.
- `.kit-source-ref` records the root commit the copies came from. The root PR squash-merges into a new commit, so after
  the merge the orchestrator re-syncs (`tools/kit_copies.py sync --source <root master checkout>`): the copies stay
  byte-identical, only the ref changes.
- Not in v1.0.0: the full list against design 5.4 is the table under Changed, with its one follow-up issue.
  Infra budget alert percentages (80 / 100) are Terraform values, not admin settings (same follow-up).

## Course on the learning site (R6, S283)

The playbook becomes module **L8 "New-project playbook"** of AA Academy (format: `docs/learn/README.md`, GUIDE-13).

### Decisions

- **Where:** `docs/learn/modules/L8-new-project-playbook/` (module.yaml, five reading lessons, quiz.yaml with ten
  items), listed as a required module of a new path `docs/learn/paths/tech-lead.yaml` (research GUIDE-13-lms §3.4).
  The other tech-lead modules L1 to L7 and L9 are `planned` there, so L8's prerequisites (L1 to L7, research §3.4)
  resolve without inventing modules.
- **Status `draft`, version 0.1.0.** The tech lead approves it (maker-checker, README "Status"); until then only a
  staff learner with the `learn.preview` capability sees it, marked draft, and it counts toward no certificate.
  Approval sets `status: active` and `version: 1.0.0`.
- **Cite, never copy.** Every lesson names the playbook sections it teaches from by heading anchor (`doc:GUIDE-14#...`,
  `doc:GUIDE-14-discovery#gate-g1-go--no-go` and so on, all nine phase pages plus the README and the adoption page),
  with hashes written by `check_learn.py --pin` after the sections were read. A lesson body holds only the objective,
  a short framing, the list of sections and three "check yourself" questions.
- **Gates are the spine.** One lesson per two or three phases, each built around the phase gates G1 to G8 and the
  common-mistakes sections, because the gates are what a tech lead runs; the quiz items each cite one gate, path,
  flow-rule or trigger section.
- **No allowlist row.** The module is staff tier and cites catalog pages only (`doc:`); the allowlist is needed only
  for skill, steering and `CONTEXT.md` sections or agency grants.

  templates (§3.10). Neither is built here: most of that path's modules are not written yet, and labs wait for the lab

- Prerequisites name L1 to L7 although none is written. The CIS learning API never blocks on a prerequisite that is
  only planned (`services/learn/academy.py`), so the module opens; listing them now keeps the research order and

## v1.1.0: the first four missing parts (S293)

Lane `d-kit-v11`, S293 (2026-11-25), Claude Code. Template branch `feat/kit-v1.1` on a fresh clone of the public
template repo (`.tmp-session/wt/s293-d-kit-v11-template`), commits as the App identity with no issue key (the
denylist scans commit metadata). Ships rows 1 to 4 of the table above as one minor release; rows 5 to 9 stay for a
later minor release (template `CHANGELOG.md` "Not in this release", `README.md` "Not in 1.1.0").

### Decisions

- **Template-owned files, not kit copies.** The four parts are written in the template repo, not copied from the
  root: the AA stop hook reads AA plan files and the AA PII guard is AA data shapes (both stay as they are), and no
  root file is generic enough to be the source. So `tools/project-kit/kit-sources.txt` and `kit_transform.py` do not
  change. If the AA hooks later move onto a generic core (as the shell guard did), the core becomes a kit source then.
- **Four Copier questions, each optional:** `stop_hook` (default on unless the team is engineers only), `pii_guard`
  (on), `api_contract` (on; asked only for a Python API), `ui_smoke` (on; asked only for Next.js web). Derived flags
  `has_api_contract` / `has_ui_smoke` gate the files. `.claude/settings.json` became `settings.json.jinja` so each hook
  is registered only when its question is on.
- **Stop hook:** reads the newest open-work file (`.tmp-session/S*-checklist.md`, the project-session skill's live
  checklist) changed within 24 h; refuses the stop once when it has `- [ ]` items without a blocked marker and the last
  message asks the user nothing (a real question or approval / cost / decision words let it through; an offer to go on
  or to stop does not). `stop_hook_active` lets the second stop through. Settings: `.claude/hooks/stop-open-work.json`.
- **PII guard:** PreToolUse on Bash. Reads the SQL a database command carries (client words, heredocs, `-f` / `<` /
  `*.sql` files, `bash -c` bodies, Python scripts or `-c` code that import a driver, dollar-quoted bodies) and refuses
  a select list or RETURNING that names a personal column, a star, a whole row, a run-time select list, an XML export
  function, a table COPY or a data dump. Conservative default: a list of common personal column names, and star /
  whole-row reads refused on every table (`star_reads: "any"`); the project lists its own tables and columns in
  `.claude/hooks/pii-guard.json` (day-1 step 9). Fails closed on an unreadable script of a database command.
- **API contract:** the workflow exports the OpenAPI document of the base (a worktree of the merge commit's first
  parent) and of the PR with `.github/scripts/openapi_export.py`, so no committed document and no staleness test (an
  updated project would otherwise fail a stale-document check: a major-release change). oasdiff 1.33.0 pinned by
  sha256 (checked against the release `checksums.txt`); gate script generalised from the AA one; `/admin/` paths warn
  only; label `api-breaking` or a `type!:` title accepts a break. The job is skipped in a merge queue (a skipped
  required check passes), and it is added to the branch-protection payload.
- **UI smoke:** `workflow_dispatch` and `workflow_call` only (a PR has no deployment); Playwright 1.64.1 (the pin the
  live apps run); routes and the per-route timeout in `web/e2e/smoke-routes.json`, validated by `lib/smokeRoutes.ts`
  with a node unit test; runner pinned to `ubuntu-24.04`.
- **Release bookkeeping:** `CHANGELOG.md` 1.1.0 written by hand and `.release-please-manifest.json` set to 1.1.0,
  because release-please is off until its App variable is set (the workflow says maintainers tag by hand); the
  orchestrator tags `v1.1.0` after the merge.
- **Kit copies re-synced** in a separate commit: two root templates (postmortem, runbook) had changed since v1.0.0 and
  `.kit-source-ref` pointed at a pre-squash commit that is not on root `master`; it now records `8a01baf5` (root
  `master`).

### Changed

- Render matrix: a fifth variant (`web-off`: web only, UI smoke and stop hook off); every variant checks that each
  optional file exists exactly when its question is on and that `settings.json` registers exactly the hooks present;
  the new hook and gate tests run per variant; `--oasdiff` runs the gate with the real tool (same document passes, a
  removed route fails); `--update-from v1.0.0` generates the defaults from the tag, commits and runs `copier update`
  to the tree (0 `.rej`, 0 conflict markers). Kit CI installs oasdiff (pinned) and passes both options.
- Generated CI "Fast checks" and `scripts/pre-push.sh` run the new tests; `AGENTS.md` gains the open-work file,
  personal-data list, API contract and smoke-route parameters; `day-1.md` steps 8 and 9 name the smoke run and the
  personal-data list.

### Tradeoffs

- `VERSIONING.md` says a minor release's new question keeps today's output by default. The four defaults are on, so
  `copier update --defaults` adds the files to an existing project. Chosen because design 5.4 puts these parts in
  every new project; nothing fails on a project that passed before (the contract check passes until a PR breaks the
  API, the smoke never runs on a PR, the hooks are agent-side), and the changelog's upgrade note says to answer no to
  keep today's output. The tech lead may prefer the strict reading (defaults off for updates): a patch release can
  flip them.
- The PII guard is static reading, so a heuristic: SQL assembled from separate variables or read at run time is not
  seen, and a CTE whose select list names a personal column is refused even when the outer query only counts. The
  database grants and review stay the real controls; the docstring lists the limits.
- Exporting the base document at run time imports the base branch's app with the PR's requirements; when that fails,
  the job fails unless the PR carries the breaking label.
