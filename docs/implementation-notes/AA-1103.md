## Decisions

- **Copies are "transform copies", not raw byte copies.** A source keeps AA pointers (overlay links, issue keys, ADR
  numbers) that must not reach a public template. Rather than fork the text, a source marks those lines:
  `kit:skip` blocks, `kit:drop` lines, and `kit:only` lines that appear only in the copy
  (`tools/project-kit/kit_transform.py`, header has the grammar). The template repo checks
  `copy == kit_transform(source)` byte for byte, so the guard is still exact: a hand edit of a copy turns its CI red.
  The markers are HTML or `#` comments, so the root pages render and run unchanged (YAML front matter included: a
  `# kit:drop` after a value is a YAML comment).
- **Tooling lives in `tools/project-kit/`, not `tools/kit/`.** `tools/kit/` already holds the UI kit sync of
  ADR 0016; one folder per kit avoids mixing the two "kits".
- **The list of copied files is `tools/project-kit/kit-sources.txt`** (`<source> <dest>` pairs); the template repo
  carries a copy of the list and of the transform, both checked like any other copy.
- **The denylist stays in the root repo** (`kit-denylist.txt`: AA names, issue keys, people, hosts, account-number
  shapes). The template repo reads the same list from an Actions variable (`LEAK_DENYLIST`), so the public template
  never carries a list of AA names. Root Docs lint runs the check on every PR that touches a kit source.
- **Generic skills read their values from the "Project parameters" section of `AGENTS.md`** (tracker, key prefix,
  repos, health URLs, deploy and merge commands); a skill names a parameter, never a value.
- **AA skills become the overlay** with a one-line pointer to the generic skill at the top; the AA text stays as it is
  (no big-bang rewrite, D12).
- **Hooks:** the shell guard is split into `shell_guard_core.py` (generic rules PKILL-1, ZSH-1, ENV-1, BG-1, WT-1,
  TF-1, RAM-1) and `aa_shell_guard.py` (imports the core, adds SHIP-1 and the AA rules). The subagent guardrail reads
  its patterns from `subagent-guardrails.d/*.txt`: `00-generic.txt` (kit) and `50-aa.txt` (AA). The MCP guardrail is
  generic already and gains a red-team test (`test_subagent_mcp_guardrails.sh`), so its "red-teamed by hand"
  exemption in `test_settings_hooks.py` goes.
- **Owner field** of the copied playbook pages and the templates index is the role `tech-lead`, not a person.

## Course on the learning site (R6, S283)

The playbook becomes module **L8 "New-project playbook"** of AA Academy (format: `docs/learn/README.md`, GUIDE-13).

### Decisions

- **Where:** `docs/learn/modules/L8-new-project-playbook/` (module.yaml, five reading lessons, quiz.yaml with ten
  items), listed as a required module of a new path `docs/learn/paths/tech-lead.yaml` (research GUIDE-13-lms §3.4).
  The other tech-lead modules L1 to L7 and L9 are `planned` there, so L8's prerequisites (L1 to L7, research §3.4)

- **Status `draft`, version 0.1.0.** The tech lead approves it (maker-checker, README "Status"); until then only a

  Approval sets `status: active` and `version: 1.0.0`.

  with hashes written by `check_learn.py --pin` after the sections were read. A lesson body holds only the objective,
  a short framing, the list of sections and three "check yourself" questions.
- **Gates are the spine.** One lesson per two or three phases, each built around the phase gates G1 to G8 and the
  common-mistakes sections, because the gates are what a tech lead runs; the quiz items each cite one gate, path,
  flow-rule or trigger section.

### Decisions

- **Template-owned files, not kit copies.** The four parts are written in the template repo, not copied from the
  root: the AA stop hook reads AA plan files and the AA PII guard is AA data shapes (both stay as they are), and no
  root file is generic enough to be the source. So `tools/project-kit/kit-sources.txt` and `kit_transform.py` do not
  change. If the AA hooks later move onto a generic core (as the shell guard did), the core becomes a kit source then.
- **Four Copier questions, each optional:** `stop_hook` (default on unless the team is engineers only), `pii_guard`
  (on), `api_contract` (on; asked only for a Python API), `ui_smoke` (on; asked only for Next.js web). Derived flags
  `has_api_contract` / `has_ui_smoke` gate the files. `.claude/settings.json` became `settings.json.jinja` so each hook
  is registered only when its question is on.
- **Stop hook:** reads the newest open-work file (`.tmp-session/S*-checklist.md`, the project-session skill's live
  checklist) changed within 24 h; refuses the stop once when it has `- [ ]` items without a blocked marker and the last
  message asks the user nothing (a real question or approval / cost / decision words let it through; an offer to go on
  or to stop does not). `stop_hook_active` lets the second stop through. Settings: `.claude/hooks/stop-open-work.json`.
- **PII guard:** PreToolUse on Bash. Reads the SQL a database command carries (client words, heredocs, `-f` / `<` /
  `*.sql` files, `bash -c` bodies, Python scripts or `-c` code that import a driver, dollar-quoted bodies) and refuses
  a select list or RETURNING that names a personal column, a star, a whole row, a run-time select list, an XML export
  function, a table COPY or a data dump. Conservative default: a list of common personal column names, and star /
  whole-row reads refused on every table (`star_reads: "any"`); the project lists its own tables and columns in
  `.claude/hooks/pii-guard.json` (day-1 step 9). Fails closed on an unreadable script of a database command.
- **API contract:** the workflow exports the OpenAPI document of the base (a worktree of the merge commit's first
  parent) and of the PR with `.github/scripts/openapi_export.py`, so no committed document and no staleness test (an
  updated project would otherwise fail a stale-document check: a major-release change). oasdiff 1.33.0 pinned by
  sha256 (checked against the release `checksums.txt`); gate script generalised from the AA one; `/admin/` paths warn
  only; label `api-breaking` or a `type!:` title accepts a break. The job is skipped in a merge queue (a skipped
  required check passes), and it is added to the branch-protection payload.
- **UI smoke:** `workflow_dispatch` and `workflow_call` only (a PR has no deployment); Playwright 1.64.1 (the pin the
  live apps run); routes and the per-route timeout in `web/e2e/smoke-routes.json`, validated by `lib/smokeRoutes.ts`
  with a node unit test; runner pinned to `ubuntu-24.04`.
- **Release bookkeeping:** `CHANGELOG.md` 1.1.0 written by hand and `.release-please-manifest.json` set to 1.1.0,
  because release-please is off until its App variable is set (the workflow says maintainers tag by hand); the
  orchestrator tags `v1.1.0` after the merge.
- **Kit copies re-synced** in a separate commit: two root templates (postmortem, runbook) had changed since v1.0.0 and
  `.kit-source-ref` pointed at a pre-squash commit that is not on root `master`; it now records `8a01baf5` (root
  `master`).

### Review fix pass (S293)

- The personal-data guard reads a Python script only when the script imports a driver (`import` / `from ... import`
  of a `driver_markers` module, `from mysql import connector` included, or `importlib.import_module` / `__import__`
  of one, found with `ast`). Before, any driver name in the file text counted, so the hook refused its own test
  (`python3 .claude/hooks/test_pii_guard.py`) and its `--check` mode, both of which name drivers in fixtures and
  defaults. A file that does not parse still counts on its text (fails closed). New red-team cases: a driver only
  named in a comment passes; from-imports, submodule imports, dynamic imports and unparsable files are refused; the
  guard's own commands pass.
- The projects edit `pii-guard.json` (day 1: personal_tables) and `stop-open-work.json` (checklist path, age,
  markers), so the generated tests no longer require them to equal the code defaults: they check the shape (same
  keys and types, valid table map, `star_reads` in {any, listed}, sizes > 0, every pattern compiles). The behaviour
  tests and the wrapper tests run on a copy of the hook with the code defaults, so a tuned file cannot break them.
  The "fresh project's files equal the code defaults" check moved to the kit's render matrix (every variant).
- Checked: render matrix 5 variants 0 failures; in a rendered project, both hook suites pass after a day-1 style edit
  of both JSON files (personal_tables filled, `star_reads` listed, another checklist path, 48 h), and the guard's
  wrapper lets `python3 .claude/hooks/test_pii_guard.py` and `pii_guard.py --check q.sql` through while still
  refusing `psql -c 'select email ...'`.

### Decisions

  schemas; the design table (inventory T27) said "vendors the gateway core under a sync guard", but no AA file is
  generic enough to be a byte-copy source. The template writes small generic versions; `kit-sources.txt` does not
  change.
- **Synchronous psycopg 3 (`psycopg[binary]` 3.3.8, `psycopg-pool` 3.3.3), not asyncpg.** The interfaces the stores
  had to keep (`JobStore`, `SettingsStore`, `run_once`, the sync FastAPI routes) are synchronous; an async driver
  would have changed every interface. `asyncpg` stays in `requirements.txt` for projects that already use it.
- **Same interfaces, keyword extensions.** `enqueue(..., idempotency_key=, run_after=, tenant_id=)`,
  `claim(..., per_tenant_limit=)`, `finish(..., run_after=)` and a new `purge_finished(before)`; all new arguments
  default to today's behaviour. The memory stores implement the same semantics and stay for tests.
- **Migration `<prefix>-002`, expand.** 001 is already applied in projects generated from 1.0 / 1.1, so the new
  columns (`idempotency_key`, `run_after NOT NULL DEFAULT now()`, `finished_at`, multi-tenant `tenant_id` with a FK to
  `tenant`) and indexes (partial unique key, finished, tenant-running, ledger month) go in a new file. Adding a
  column with a stable default is metadata-only in Postgres 11+; `lock_timeout` 5 s.
- **Claim time is the caller's `now`, not the database clock.** Both stores take the same `now`, so lease expiry,
  `run_after` and the fair-share count are testable without sleeping and behave the same in memory and on Postgres.
- **Fair-share claims are serialised by a transaction-scoped advisory lock** (`pg_advisory_xact_lock(hashtext(
  '<schema>.job.claim'))`), then one `UPDATE ... WHERE id = (SELECT ... FOR UPDATE SKIP LOCKED)` that skips tenants
  at the limit. Without the lock two workers can both read "one slot left". A claim is one short statement, so the
  serialisation costs little at template scale; the plain claim (single-tenant) stays lock-free.
- **Tenant jobs are not row-level-security tables.** The worker claims across tenants; a tenant job's handler gets
  `payload["tenant_id"]` and opens its own `TenantScopedPool.transaction(tenant_id)`.
- **`TenantScopedPool`** hands out a connection only inside `transaction(tenant_id)` (one transaction, `SET LOCAL
  ROLE` when given, `set_config('app.tenant_id', ..., true)`); a missing or non-UUID tenant raises `NoTenantError`
  before a connection is taken.
- **Gateway caps:** a total cap `ai.monthly_cap_usd` (default 20) and one `ai.monthly_cap_usd.<provider>` per provider
  (`provider_cap(name)`, default 10, 0 turns a provider off), all settings. The gateway refuses to start when a routed
  provider has no cap setting. Before each attempt: month-to-date spend from the ledger + the provider's estimate;
  over the provider cap falls back to the next target, over the total cap refuses the call (`CapExceeded`); a ledger
  read error makes no call. One ledger row per attempt (ok, error, refused) with `**billed_fields(resp)`. Only
  `FakeProvider` ships: a real provider is a project adapter that reads its key from the secret store.
- **Pool size is psycopg_pool's default, not a setting.** The settings registry lives behind the pool, so the pool
  cannot read its own size from it; sizing is deploy configuration next to the database's connection limit (comment
  in `wiring.py`). No new environment variable was added for it.
- **CI:** the generated API job gains a Postgres 16 service, applies every migration, and runs pytest with
  `TEST_DATABASE_URL`, so coverage counts the database stores. Kit CI's render job gets the same service; the render
  matrix (`--pg-dsn`) creates one database per variant, applies every migration twice, runs the isolation probe and
  the API tests against it. `UPDATE_FROM` moves to v1.1.0.

### Changed

- New settings: `jobs.retry_delay_seconds` (all API projects), `jobs.max_running_per_tenant` (multi-tenant),
  `ai.monthly_cap_usd` (AI). Every setting the code reads is joined in `api/app/wiring.py` (`ALL_SETTINGS`).
- `run_once` now waits `jobs.retry_delay_seconds` before a retry (before: the job was claimable at once). The memory
  test of retries moved its second call past the delay.
- `create_app(pool=...)` opens and closes the pool in the FastAPI lifespan and adds the `db` readiness check;
  `app = create_app(pool=pool_from_env())`. The worker (`python -m app.jobs`) uses the same wiring and purges
  finished jobs older than `jobs.retention_days` once an hour.
- Docs in the template: `README.md` questionnaire rows and "Not in 1.2.0", `copier.yml` help of `multi_tenant` and
  `ai_features`, generated `README.md`, `CONTEXT.md` (worker, tenancy, AI rules), `AGENTS.md` (settings, gateway
  parameters), `day-1.md` step 7 (both migrations, `DATABASE_URL` in the secret store), `docs/ai/README.md` (gateway
  rules), `CHANGELOG.md` 1.2.0 with an upgrade note; release-please manifest 1.2.0.

### Tradeoffs

- A global claim lock in multi-tenant projects trades claim throughput for an exact per-tenant limit. A project with
  hundreds of workers can switch to a per-tenant lock with a re-check; the tests pin the behaviour either way.
- Parallel model calls each check the cap before they run, so together they can pass it by at most their own
  estimates; a reservation row would close that gap at the cost of a second write per call.
- Jobs finished before migration 002 have no `finished_at` and are never purged by the new clean-up; they are few
  in a young project and can be removed by hand.

### Review fix pass (S293, v1.2.0)

Four findings of the independent review, all confirmed against the code and fixed in a second template commit:

- **Idempotency keys leaked across tenants** (two findings, one fix). With one key column in the unique index, tenant
  B enqueueing a key tenant A used got A's job (payload and tenant) back and B's job was never added. Multi-tenant
  projects now index `(coalesce(tenant_id, <all-f sentinel uuid>), idempotency_key) WHERE idempotency_key IS NOT
  NULL`; `ON CONFLICT` names the same expression, the look-up adds `tenant_id IS NOT DISTINCT FROM`, and the memory
  store compares the pair. A coalesce sentinel rather than `NULLS NOT DISTINCT` keeps the file valid below Postgres 15;
  the sentinel is all `f`, since an all-zero uuid matches the leak scan's twelve-digit pattern. A key reused for
  another kind now raises `IdempotencyConflict` instead of returning the other job. Migration 002 is not released yet,
  so the index changes in place (no new migration).
- **A stale worker could close a job another worker had taken again.** `finish` now updates only
  `WHERE status = 'running' AND attempts = <the caller's attempts>` (attempts is bumped on every claim, so it is the
  fencing token) and returns False when nothing matched; `run_once` logs "lease lost" and drops the result. The memory
  store now hands out copies, like the database, so the same check works there (tests compare jobs by `id`).
- **Model routes were a code literal.** Routes are now data: `RouteStore` (`MemoryRouteStore`, `PostgresRouteStore`
  on the new `model_route` and `model_route_audit` tables of migration 002, AI projects only), read by
  `Gateway.generate` on every call. `/admin/model-routes` (administrator only) lists the routes and the registered
  providers (the picker) and replaces a role's ordered targets; a save naming an unregistered provider, an empty
  model, a repeated target or no target is refused (422), and every save writes an audit row (who, when, old, new)
  in the same transaction, under a per-role advisory lock. Providers are registered in `wiring.py`
  (`MODEL_PROVIDERS` + `model_providers()`), which also adds each one's cap setting; the gateway refuses to start when
  a registered provider has no cap. No seed rows: a fresh project registers no provider. A stored target whose
  provider is no longer registered is skipped without a ledger row (it is not an attempt).
- Checks: render matrix 5 variants + `copier update` from v1.1.0, 0 failures, with Postgres 16 (`--pg-dsn`), real
  actionlint (shellcheck 0.10.0), oasdiff and markdownlint; API tests 75 / 31 / 33 passed in all-on / app / defaults,
  integration tests included (new: per-tenant keys on Postgres, stale-worker finish on Postgres and memory, route
  store with audit on Postgres, admin endpoint and role check). Template unit tests 15 OK, resource-ID lint 0,
  denylist scan of files and commit metadata 0, gitleaks 8.30.1 over both commits: no leaks.

### Decisions

- **Behind the existing `has_web` flag, no new question.** Both parts are files of a Next.js web project (the harness
  plays scenarios against the web app), so they appear exactly when the stacks answer includes the web; root and
  API-only app repos get neither. A new question would only add a way to have a web app without its design system.
- **Kit path `web/app/_kit/`** (the `AGENTS.md` "UI kit path" parameter now has this value). A Next.js private folder
  (underscore), so it is never a route; the same `app/_kit` layout as the source project's kit, but written fresh and
  generic: no component, token or name of the source kit is copied. `kit-sources.txt` does not change.
- **Plain CSS with tokens, no Tailwind or CSS-in-JS.** The skeleton has no CSS toolchain; `tokens.css` holds neutral
  light and dark values (system setting, or `<html data-theme>` to force one) and `kit.css` the component classes,
  imported once in `app/layout.tsx`. A brand is one edit of the token file.
- **Components:** `Button` / `ButtonLink`, `Table` with server paging (page from `?page=`, pure helpers `parsePage`,
  `pageInfo`, `pageOffset`, `pageHref`, `pageSummary` in `paging.ts` with node tests), `EmptyState`, `Drawer` (client:
  Escape, overlay click, focus in and back, its focus effect independent of the `onClose` identity), `ToastProvider` +
  `useToast` (polite live region; a danger toast stays until dismissed), `PageHeader`, link `Tabs` (the open tab is in
  the URL) and a status `Badge` (five tones). Every component that renders an element forwards the remaining HTML
  attributes to it, so `data-testid` reaches the DOM (source lesson: test ids on kit components were dropped);
  `ToastProvider` renders none of its own. Since TypeScript accepts any hyphenated JSX attribute, a dropped one still
  compiles: `_kit/attributes.test.ts` reads each component's source for `...rest` taken and spread, and the gallery
  sets test ids on the header, tabs, table, drawer and empty state that the example scenario checks in a browser.
- **Kit lint as a node test, not ESLint.** The skeleton ships no ESLint; `web/lib/kitLint.ts` scans `app/` and
  `components/` outside `app/_kit/` for inline styles, a stylesheet of a page's own, non-`kit-` class literals, raw
  `<button>` / `<table>` / `<dialog>`, and a `page.tsx` that imports nothing from the kit. Its test lints the whole
  tree, so `npm test` (CI web job, pre-push) fails on a finding; an exception carries `kit-lint: ignore <rule>` with
  a reason on the line.
- **Kit lint baseline, so 1.3.0 stays a minor release.** VERSIONING.md calls "a new check that fails on a project
  that passed before" major. `web/kit-lint-baseline.json` counts accepted findings per file and rule (line numbers
  shift, counts do not); the lint fails on a finding beyond a count and on a count above what it finds (the list only
  shrinks, as the code-health baseline). A fresh copy writes it empty, so a new project enforces from day one.
  `copier.yml` `_exclude` drops the file when `_copier_operation == 'update'`, so `copier update` from an earlier
  release never adds it: without the file the lint only reports (test diagnostics) until the project runs
  `npm run kit-lint -- --write-baseline`. A later update leaves the file alone (both sides of the update exclude it).
  `_copier_operation` in `_exclude` exists from Copier 9.6, so `_min_copier_version` goes from 9.4.0 to 9.6.0 (CI
  pins 9.19.1). Rejected: a major 2.0.0 with a migration (a migration task needs `--trust` and node at update time),
  and a new Copier question (its default cannot see the operation).
- **Gallery at `/kit`** with invented rows (47 sample items, five statuses), used by the UI smoke route list and the
  UAT example scenario; `robots: noindex`. The README says to keep it or put it behind the staff sign-in.
- **UAT scenarios are JSON, not `.spec.ts`.** A declarative format (title, viewport, `step_timeout_ms`, optional
  `allow_console_errors`, `step_hold_ms`, `color_scheme`, steps with a caption, an optional action and at least one
  expectation) is validated before the browser starts, with the failing row's path in the message, and can be written
  without Playwright knowledge. Targets by role and name first (also text, label, test id, css).
- **A custom runner on the `playwright` library, not `@playwright/test`.** The harness needs per-step verdicts,
  skipped steps after a failure, captions timed per step and a take folder per scenario; the test runner reports per
  test. Every wait is capped by `step_timeout_ms` (source lesson: unbounded waits), `goto` waits for `load`, never
  `networkidle`; a page or console error fails the step. Pin 1.64.1, the same as the UI smoke (a kit test checks the
  two pins and the kit CI's `PLAYWRIGHT_VERSION` agree).
- **Take output:** `out/<yyyymmdd-hhmmss>-<scenario>/` with `result.json` (verdict, build commit from
  `/api/health`, per-step verdict, timing, error, screenshot), `captions.vtt` (a cue per step until the next step
  starts, so cues never overlap), a viewport screenshot per step and `video.webm` with `--video`; `out/index.html`
  lists every take newest first with FAIL marked. Exit 0 all pass, 1 a failing take, 2 a bad file or argument.
- **No narration engine ships.** The captions file is what a free local text-to-speech engine reads; the README
  says so, and no paid service is named or wired.
- **`uat.yml`**, `workflow_dispatch` only (a URL, an optional scenario name checked against `^[0-9]{2}-[a-z0-9-]+$`,
  a video switch), uploads `tools/uat/out/` as an artifact (14 days, as the UI smoke). Not added to branch protection
  (it never runs on a PR).
- **Secrets never sit in a scenario.** A `fill` or `select` takes `value_env: "UAT_<NAME>"` instead of `value`; only
  `UAT_*` names, so a scenario cannot read the runner's other variables. All values are read before the browser starts
  and an unset or empty one exits 2. A `value_env` step is secret, and `"secret": true` marks a literal one (a code in
  a plain field). For a secret step the runner masks the field (`page.screenshot` `mask`) in that and every later
  screenshot, sets `-webkit-text-security: disc` on a filled field before typing so the video shows dots, and redacts
  every secret value from the kept error and console text (`keptStep` in `lib/report.ts`, so `result.json`, captions,
  the step log and the index never hold it). A secret `select` shows its option in a video, so `--video` refuses a
  scenario with one (exit 2). `uat.yml` maps the optional repository secrets `UAT_USERNAME` and `UAT_PASSWORD` into
  the play step only.

### Tradeoffs

- The kit lint is a line-based scan, not a parser: a style object built in a variable and spread, or a class name
  computed at run time, passes. It catches the common drift (inline style, utility classes, raw elements) at no
  toolchain cost; ESLint with a custom rule would be stricter but adds a dependency tree to every project.
- The toast duration (`durationMs`, default 5 s) is a presentation default of the provider, not a business threshold
  or a setting; the step timeout and hold of a scenario are values in the scenario file (data), not code literals.
- An updated project's kit lint stays report-only until the project writes its baseline, so a team can ignore it.
  Chosen over failing the update PR (a major change) or a forced migration; the changelog upgrade note says how to turn
  it on, and a deleted baseline file also falls back to report-only.
- The pass-through test reads source text (`...rest` taken and spread), not rendered markup: the fast web unit tests
  run without `npm install`, so React's server renderer is not available there. The browser check is the example
  scenario's test ids in the web e2e job.
- Secret masking covers what the runner typed. A page that prints the secret elsewhere (a "your code is" banner) is
  not masked; the harness README says to keep such a page out of a recorded walk.
