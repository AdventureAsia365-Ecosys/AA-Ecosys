## Decisions

- **Copies are "transform copies", not raw byte copies.** A source keeps AA pointers (overlay links, issue keys, ADR
  numbers) that must not reach a public template. Rather than fork the text, a source marks those lines:
  `kit:skip` blocks, `kit:drop` lines, and `kit:only` lines that appear only in the copy
  (`tools/project-kit/kit_transform.py`, header has the grammar). The template repo checks
  `copy == kit_transform(source)` byte for byte, so the guard is still exact: a hand edit of a copy turns its CI red.
  The markers are HTML or `#` comments, so the root pages render and run unchanged (YAML front matter included: a
  `# kit:drop` after a value is a YAML comment).
- **Tooling lives in `tools/project-kit/`, not `tools/kit/`.** `tools/kit/` already holds the UI kit sync of
  ADR 0016; one folder per kit avoids mixing the two "kits".
- **The list of copied files is `tools/project-kit/kit-sources.txt`** (`<source> <dest>` pairs); the template repo
  carries a copy of the list and of the transform, both checked like any other copy.
- **The denylist stays in the root repo** (`kit-denylist.txt`: AA names, issue keys, people, hosts, account-number
  shapes). The template repo reads the same list from an Actions variable (`LEAK_DENYLIST`), so the public template
  never carries a list of AA names. Root Docs lint runs the check on every PR that touches a kit source.
- **Generic skills read their values from the "Project parameters" section of `AGENTS.md`** (tracker, key prefix,
  repos, health URLs, deploy and merge commands); a skill names a parameter, never a value.
- **AA skills become the overlay** with a one-line pointer to the generic skill at the top; the AA text stays as it is
  (no big-bang rewrite, D12).
- **Hooks:** the shell guard is split into `shell_guard_core.py` (generic rules PKILL-1, ZSH-1, ENV-1, BG-1, WT-1,
  TF-1, RAM-1) and `aa_shell_guard.py` (imports the core, adds SHIP-1 and the AA rules). The subagent guardrail reads
  its patterns from `subagent-guardrails.d/*.txt`: `00-generic.txt` (kit) and `50-aa.txt` (AA). The MCP guardrail is
  generic already and gains a red-team test (`test_subagent_mcp_guardrails.sh`), so its "red-teamed by hand"
  exemption in `test_settings_hooks.py` goes.
- **Owner field** of the copied playbook pages and the templates index is the role `tech-lead`, not a person.

## Tradeoffs

- A raw byte copy would be simpler to explain but would force the root templates to lose their AA pointers (or the
  kit to fork them). The transform keeps one home per fact at the cost of a 100-line, tested tool.
- The PII guard (1,000 lines, AA data shapes) and the stop-open-work hook (reads AA plan files) are not copied in
  v1.0.0; the template ships the guardrails that are generic today. Follow-up below.
