# Decide, then prove it is done

**Objective:** make a routine call without waiting for permission, and close an issue only on live evidence.

Two habits keep work moving without losing control. Once a direction is approved, routine follow-up calls are made
and reported, not asked; only a real block stops the work. And "done" is not a feeling or a green build: an issue is
Done when the change runs on Dev and the live system shows the result.

Read the two sections shown with this lesson:

1. The engineering handbook's two working rules: "decide, don't ask" and "no agent-made gates".
2. The planning rules on when an issue is Done: verified live, frozen Done-when lines, Done with scope, and how
   commits reference an issue without closing it.

## Check yourself

- After the tech lead approved a plan, you find a small bug on the way. Do you stop and ask?
- Is "at most one migration per session" a rule you may set for yourself?
- Halfway through an issue you find more work it should cover. Where does that work go?
