# Operate, scale on a trigger, retire cleanly

**Objective:** keep a live product under its periodic reviews, scale only when a measured trigger fires, cheapest
lever first, and prove that a retirement left nothing running or billed.

Operating has no permanent gate: the review calendar is the control, and every lesson a machine can check becomes a
guard. Scaling is a business decision because it spends money, so it waits for a written trigger to fire, and the
production controls are switched on together, never one by one. Retiring ends only when the bill shows zero.

Read the six sections shown with this lesson:

1. Operate: the rules for runbooks, lessons, alarms and cost sources.
2. Operate: the review calendar.
3. Scale: the trigger table and its levers.
4. Scale: gate G7, the production controls switched on together.
5. Retire: the steps, from the decision to the final lesson.
6. Retire: gate G8, retirement complete.

## Check yourself

- Database CPU spikes once on a busy afternoon. Does that fire a scale trigger? What lever comes first when one does?
- Which event switches on the production controls, and why are they switched on at the same time?
- The infrastructure is destroyed. What else must be true before the retirement is complete?
