# AA-692 — [A1/A2 + Jev] Brand audit prefilter, judge tie-break, generic soft codes, meal/time regex, Review Queue order

Design: `docs/architecture/at-series-v2-design.md` §4.1 A1-2 … A1-5, A2-1. Applies to T2 too, for allow-listed tenants (§4.3 T2-1).

## Scope

* **A1-2 brand audit** (`s1_brand_audit`, GPT-4.1 + shadow Luna; S200 decision: "wait for Jev"):
  * one Noul per binary item / failure code;
  * all confident passes → skip the GPT call;
  * otherwise call GPT as today, because flag_fix needs its quoted `flagged_phrases`.
* **A1-3:** only on an `ITIN_MEAL_INVENTED` / `ITIN_CLOCK_TIME` hit, ask "a logistics claim the source doesn't make, or narrative?".
* **A1-4 judge tie-break:** when the `s1_judge` score is within ±0.5 of `MIN_QUALITY` (7.0), Nouls `brand_fit` / `mission_present` decide retry vs pass. The judge still writes the feedback.
* **A1-5:** Noul "generic, would fit any destination?" as a second signal for `SUBTITLE_GENERIC` / `HIGHLIGHTS_TOO_GENERIC` / `SUMMARY_OFF_BRAND` (the codes stay soft).
* **A2-1:** Review Queue sorted by Jev uncertainty; Jev reasons shown per code. Advisory only.
