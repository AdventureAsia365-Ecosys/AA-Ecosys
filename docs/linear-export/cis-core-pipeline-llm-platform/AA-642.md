# AA-642 — [EPIC] Model Gateway — one routing layer for Claude/Bedrock, OpenAI, Jev, driven by admin UI settings

*Created S198 (Claude Code). Design only, nothing built yet. Per the repo process, run* `/grill-with-docs` *on this spec before any code, and write an ADR in* `docs/adr/` *(this is a hard-to-reverse architecture decision).*

## Problem (verified by code read on `main` c5b8c6f)

Model calls go through **6+ separate mechanisms**, and the admin "LLM Models" page ([AA-518](https://linear.app/aa-ecosys/issue/AA-518/llm-ops-model-selection-qua-ui-admin-writer-claudepalmyra-x5-judge-gpt), `shared.llm_role_config`) only controls some of them:

| Mechanism | Where | Honours admin UI? |
| -- | -- | -- |
| `LLMClient.generate()` (fallback chain acc2 → acc3 → acc1 → GPT-4.1) | `shared/llm_client/client.py` | ✅ via `stage` (but `model_tier` overrides it) |
| `invoke_claude()` direct (T5 atomize, export, batch) | `shared/llm_client/bedrock_satellite.py` | partial (caller passes model) |
| `invoke_judge_gpt41()` — T10 F8/F9, N7 | `services/acp_produce/judge_client.py` | ❌ hardcoded `GPT41_MODEL`; `JUDGE_MODEL` env |
| `score_brand_fit()` — s1_judge, Debate | `services/content_generation/brand_fit.py` | ❌ hardcoded `model_tier="gpt-4.1"` |
| `brand_audit_node` — direct `OpenAI()` + strict json_schema | `services/content_generation/brand_audit_node.py` | ✅ |
| raw boto3 Haiku — `column_mapper.py`, `h3_rule_extractor.py` | `shared/llm_client/`, `services/acp_shared/` | ❌ |
| Cohere Embed v4 | `services/acp_shared/content_embedding.py` | ❌ (no stage) |
| TripPlanner's own `bedrock_satellite.py` + `config.py` env model ids | AA-TripPlanner-Web | ❌ separate copy |

Other gaps:

* Stage list drift: `a3_search_demand` and the Debate brand-fit call are missing from `SAFE_DEFAULTS`.
* The UI option lists (`_WRITER_OPTIONS` / `_JUDGE_OPTIONS`) and prices (`pricing.py COST_TABLE`) are hardcoded. An unknown model is priced as Sonnet ($3/$15), which silently mis-reports spend.
* `provider` cannot be edited, so a stage cannot be switched between vendors from the UI.
* There is no way to run a candidate model in shadow on real traffic. Every A/B so far (the GPT-5.6 trial documented in repo `docs/implementation-notes/AA-351-gpt56-judge-trial.md`, [AA-619](https://linear.app/aa-ecosys/issue/AA-619/sub-cmeasure-ab-atomize-haiku-vs-sonnet-ha-t5-atomize-xuong-haiku), [AA-620](https://linear.app/aa-ecosys/issue/AA-620/sub-gbe-tach-stage-t2-generate-config-ui-sonnet-cho-t2-tenant-a1-giu)) was a one-off script.

## Proposed architecture: `shared/model_gateway/`

**1. Three capabilities, each with its own narrow interface** (Ms. Thư's `Judge`-seam lesson: never widen one interface to hold everything):

* `generate(stage, system, user, schema=None) -> GenResult`: text or JSON from Claude / OpenAI.
* `decide(stage, state, questions) -> Decision`: typed probabilities (Noul / Choice / Score) from Jev.
* `embed(stage, texts) -> vectors`: Cohere and similar.

**2. Model catalog** (`shared.llm_model_catalog`, new table): the single source of truth for the UI dropdown **and** for pricing. Fields:

* `model_key`, `provider` (`bedrock_claude` / `anthropic` / `openai` / `bedrock_converse` / `typesafe` / `cohere`), wire model id or ARN per account.
* Capabilities: `supports_temperature`, `supports_seed`, `json_schema`, `reasoning_effort` levels, `max_output`.
* Prices: in / out / cache read / cache write.
* `status`: available / blocked(reason) / retired.

This replaces `_WRITER_OPTIONS`, `_JUDGE_OPTIONS` and `COST_TABLE`.

**3. Route per stage** (extend `shared.llm_role_config` → `llm_route`):

* `primary` model_key, ordered `fallbacks[]`, params (`effort`, `max_tokens`, `temperature`).
* Optional `shadow` model_key: runs in parallel, is logged, and never affects output. This is the A/B harness for GPT-6 Luna and Sonnet 5.
* For decide stages: `cascade` = {`pass_floor`, `fail_floor`, `escalate_to_stage`}.
* The admin UI edits all of this; the in-process cache is invalidated on PATCH (existing mechanism).

**4. Provider adapters**, each owning its wire quirks:

* **OpenAI adapter** translates for reasoning models: `max_tokens` → `max_completion_tokens`, drops `temperature` / `seed` when the catalog says unsupported, sets `reasoning_effort`.
* **Claude adapter**: native acc2 plus the acc3/acc1 satellites (existing AssumeRole cache). Future: the Anthropic Bedrock Mantle client (Messages API).
* **TypeSafe adapter**: plain HTTP POST `/v1/systemone`.

**5. Policy guards at config-write time:**

* Judge vendor ≠ writer vendor (ADR-2026-014/027).
* A blocked model cannot be selected.
* A role must be in the `llm_call_log` CHECK set (the constraint needs a decision: add `decide`).

**6. Observability:**

* Every call writes `llm_call_log` (add provider `typesafe`). The price comes from the catalog, so spend is never mis-priced.
* New `shared.decision_log` stores every Jev probability with the floor in force at the time. Floors can then move without re-paying, and joining to A2/T10 human outcomes gives a calibration dataset.

**7. Resilience:** per-provider timeout, retry and circuit breaker. The fallback order lives in route config, not in code (today the chain is hand-written in `client.py`).

## Migration phases (each one ships with no behaviour change until its switch is flipped)

1. **P0:** catalog table + seed from today's constants; UI reads the catalog. Fixes pricing for new models.
2. **P1:** move the 6 mechanisms behind the gateway with identical behaviour (golden tests on request payloads).
3. **P2:** remove the hardcoded judge paths (`GPT41_MODEL`, `model_tier="gpt-4.1"`), so the UI really controls F8/F9/s1_judge/Debate.
4. **P3:** shadow mode, used by the Luna A/B and Sonnet 5 eval issues in this project.
5. **P4:** `decide()` + Jev + `decision_log`, used by the Jev eval issue.
6. **P5:** TripPlanner consumes the same catalog/route config (read-only DB), or a small shared package. To be decided in the ADR.

## Out of scope

* Changing any model choice. That is decided by the eval issues, based on data.
* `score.py` rank-sum (ADR 0014).
* Prose prompts.
