## Problem

In the [AA-808](https://linear.app/aa-ecosys/issue/AA-808/place-cards-drafter-must-not-append-traveller-clauses-to-background) trial on Dev (S235, 14/10/2026), 5 new cards were drafted and 2 of them duplicated existing audited cards:

* "National Institute for Zorig Chusum" (Bhutan). The new card has exactly the same display name as an existing card.
* "Kuang Si Waterfall" (Laos). An existing card is named "Kuang Si Falls".

Both were merged by hand through the admin merge endpoint. On a platform-wide card build this would create many duplicates, which both cost money and split facts across cards.

Likely cause, from `services/acp_shared/place_cards.py`:

* `find_existing_cards` runs before the draft, using the itinerary place name. It matches by alias or by core key.
* After the draft, `_store_card` only checks `place_key = key` for the new 2-part key. An existing card stored under a legacy 3-part key (S233 cards) or under a different core name ("Falls" vs "Waterfall") is never matched, so a new row is inserted.
* The drafted card's own `display_name` and `aliases` are not used to look up an existing card.

## Scope

1. After drafting and before `_store_card`, resolve the drafted identity against existing non-rejected cards in the same country:
   * by the draft's display_name core key, including cards with legacy 3-part keys;
   * by the draft's aliases against `place_card_alias`;
   * by a conservative synonym fold for feature words (falls/waterfall, lake/nuur/tso, monastery/gompa/lhakhang where safe).
     On a match, link the atoms to the existing card, add the aliases, and add the cost. Do not insert.
2. Unit tests: the two S235 cases, the City Palace Jaipur/Udaipur invariant (generic names stay separate), and a rejected card that must not be matched.
3. One-off report, read-only: list current duplicate clusters with the existing `/place-cards/duplicates` endpoint and show them to Nghiệp before any merge.

## Done when

* Merged and deployed. A trial draft of an already-carded place links to the existing card, and the build counters show linked_existing rather than a new card.
