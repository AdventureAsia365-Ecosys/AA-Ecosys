## Luna schema fix shipped — #545 (`fb8601b`), ECS :430 COMPLETED
Removes the reason brand audit had to stay on GPT-4.1 (the Luna `status`-drop from the S208 A/B).

**Root cause:** GPT-4.1 (OpenAI) uses strict json_schema — server-enforced. Luna runs via Bedrock Converse's forced tool, which does NOT enforce the schema, so ~15% of audits came back missing `status`.

**Fixes:**
- **(C) Derive status, don't require it.** `status` removed from the schema's required list; `derive_status(failure_codes, publish_ready, model_status)` computes it — a manual-check code (fact/product-truth) → manual_check; else any code or publish_ready False → flagged; else pass. A model-sent status only pushes to the safer side.
- **(A) Gateway retries a Converse schema miss once** with an explicit "include every required key" instruction before failing over. Benefits every Converse stage (judges, T10 gates), not just brand audit.
- Fail-closed (#541) still holds a genuine two-strikes failure as manual_check.

**Verified live (:430):** derive_status present, `status` not in required, converse retry present, derive_status returns pass/flagged/manual_check correctly. Unit 2,338 pass, CI 5/5 + Vercel green.

Luna is now a candidate brand-audit primary; the actual switch stays a later decision — keep GPT-4.1 until stable on Dev. t10_judge left at gpt-5.6-luna primary / gpt-6-luna shadow (not switched — needs a T10-specific A/B on real tenant content first).
