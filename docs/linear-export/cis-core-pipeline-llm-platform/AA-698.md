# AA-698 — [A1 judge] GPT-5.6 Luna scores default-brand master rewrites ~3.0 (cross_brand_distinct) → every A1 tour goes to HITL; blocks the rerun

## Problem (found live, S204, 30/09/2026)

3-tour A1 smoke on Dev (taskDef :389, default brand, no DB writes):

* validate = 9.75, but `s1_judge` (GPT-5.6 Luna, route since S200 / [AA-659](https://linear.app/aa-ecosys/issue/AA-659/gateway-p1-stage-routing-for-every-call-site-acc3-first-fallback-chain)) returned `brand_fit=7.0`, `cross_brand_distinct=3.0`, `mission_present=False` → `judge_score=3.0` → below `MIN_QUALITY` 7.0.
* After 3 attempts all 3 tours ended in **HITL** (scores 4.0 / 2.0 / 3.0). The grounding node ([AA-691](https://linear.app/aa-ecosys/issue/AA-691/a1-jev-grounding-check-for-master-content-s1-output-must-be-supported)) was never reached.
* The last A1 runs on the GPT-4.1 judge (17–21/09/2026, same `default` brand): judge_score averaged **8.4–8.9** (185 rows). There has been no A1 run since the switch to Luna, so this was never observed.

If the rerun ([AA-653](https://linear.app/aa-ecosys/issue/AA-653/p2-at-flow-sync-audit-clean-rerun-runbook-bhutan-pilot-wave-jev-in)/594) starts now, nearly all master content goes to HITL.

## Likely causes (to verify)

1. `cross_brand_distinct` means little for A1: the master rewrite is deliberately brand-neutral ([AA-535](https://linear.app/aa-ecosys/issue/AA-535/s1brand-system-prompt-hardcode-giong-adventure-asia-viet-lai-trung)), so "distinct from other brands" is low by design. GPT-4.1 was lenient here; Luna follows the rubric literally.
2. `mission_present` presumes a brand mission. The default brand has none, or a thin one.
3. The judge rubric/threshold was calibrated on GPT-4.1 (AA-209). The S200 decision "calibrate thresholds again" was not done for s1_judge.

## Scope

* Read `shared.llm_shadow_log` for `s1_judge` (GPT-4.1 shadow at 100%): Luna vs GPT-4.1 on the same inputs, especially cross_brand_distinct and mission_present.
* Decide for A1 (default brand): drop or neutralise `cross_brand_distinct` / `mission_present`, or re-calibrate the gate. Keep T2 (tenant brands) unchanged unless the shadow data says otherwise.
* Option to consider: the A1 judge as a Jev tie-break (design A1-4) instead of a hard 7.0 gate.
* Re-run the 3-tour A1 smoke: it must reach `grounding` and pass on content that validates at 9.75.

## Done when

* A 3-tour A1 smoke on Dev passes the judge and runs the grounding node end to end.
* The decision and the shadow comparison are recorded (implementation notes, plus an ADR if the gate itself changes).
