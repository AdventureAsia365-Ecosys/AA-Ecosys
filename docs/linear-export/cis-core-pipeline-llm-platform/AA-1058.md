## Problem

S273 system picture (§4, §5 item 7): 30-day LLM cost is known per stage (S1 68.41 USD the largest), but cost per tour or per piece cannot be measured. Ledger rows from s1/a1/a3/t5 have no `tour_id`, t9/t10 rows no `content_piece_id`, recompute and writing jobs no `job_id`; `app` and `stage` are not enforced at write time (DFS rows included); S1 rows have no `prompt_version` (1,219 rows in 30 days with `none`).

## Scope

* Pass the keys at every call site through the gateway context; make `app` and `stage` mandatory when a row is written (DFS too).
* S1 writes `prompt_version`.
* A guard test that fails when a call site of these stages writes a row without its key.
* Columns only from `docs/architecture/db-schema-reference.md`; a migration only if a column is missing.

## Done-when

* On Dev, one S1 run, one T9 piece and one recompute write ledger rows carrying `tour_id` / `content_piece_id` / `job_id` and `prompt_version` (S1).
* A cost-per-tour query over the last day returns a number for the tours that ran.
