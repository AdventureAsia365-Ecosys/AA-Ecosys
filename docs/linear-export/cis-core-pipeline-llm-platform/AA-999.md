## Problem

From 29/10/2026 acc3 pays for its own Bedrock usage (the reseller cover ended; an AWS Lift credit of about $250 remains until 31/12/2026), and the same day Bedrock started refusing model calls on acc3 ("Error 002: Access to Bedrock models is not allowed for this account"). The team already pays for Kiro (Pro plan, per user per month; the tech lead's Kiro account showed about $250 of usage). The tech lead asked (S257): can the pipeline's LLM calls go through Kiro, and would that be cheaper or more reliable than Bedrock?

## Scope (read-only research, no code or infra change)

1. **Programmatic access:** does Kiro offer any supported way for a backend service to call its models — an API, `kiro-cli` headless/ACP mode, an SDK? What authentication does it use (user login vs a service credential)? Is unattended server-to-server use technically possible?
2. **Terms of service and licensing:** is using a per-user IDE subscription as a backend inference provider allowed (Kiro / AWS terms, acceptable use)? What do the terms say about data retention and training on prompts?
3. **Models and limits:** which models are available (Claude Sonnet/Opus/Haiku, others?), and what are the credit/request quotas per plan, overage pricing and rate limits?
4. **Cost comparison:** price our real volume with the current `shared.llm_call_log` numbers (last 30 days ≈ $249 on acc3, mostly S1 waves; baseline ≈ $1–5/day) on Kiro vs Bedrock on-demand vs the direct Anthropic API.
5. **Integration path, if feasible:** what a provider in `shared/llm_client` would look like; how cost would still be written to `shared.llm_call_log` ([AA-635](https://linear.app/aa-ecosys/issue/AA-635/be-llm-call-log-under-reports-bedrock-spend-vs-aws-bill-acc1-99percent) rule); fallback and observability; the effect on judge stages (OpenAI-on-Bedrock models).
6. **Alternatives worth listing:** the direct Anthropic API, Bedrock on acc2 (blocked by the payer today), and the OpenAI API (out of credits).

### 2026-10-29 08:43 — nghiep pham quoc

Research done (S257, 29/10) — root `docs/research/2026-10-29-kiro-llm-provider.md` (merged `20af97a3`, every claim linked to Kiro/AWS/Anthropic/OpenAI primary sources, adversarially fact-checked: 3 corrections recorded in its "Fact check" section).

1. **Recommendation: do not route backend LLM calls through Kiro.** Kiro's terms allow use only through its native interfaces (IDE / CLI / web / ACP, "automation in software development"), forbid harnesses that route requests outside them, and require one subscription per developer.
2. **No inference API:** only agent modes (`kiro-cli chat --no-interactive` with a user-bound KIRO_API_KEY, `kiro-cli acp`); no control of temperature / seed / schema / max_tokens, no per-call token or credit reporting → `shared.llm_call_log` cost rows (AA-635 rule) and the calibrated judges would break.
3. **Cost:** Kiro bills per request ($20 / 1,000 credits Pro … $200 / 10,000 Power, extra $0.04/credit); on our 30-day volume (≈ $249, ≈ 68k calls) it is only cheaper if an average call costs ≤ ~0.1 credit; for the cheap luna judge calls it is ~3× dearer.
4. **Order of action:** (1) restore acc3 Bedrock access via AWS Support (every model now returns "Error 002", payment method is set); (2) top up the OpenAI API for the luna judges (path already in code); (3) a direct Anthropic API account as the Claude fallback (same list price, Batch −50 %; needs a data-governance decision since data leaves AWS). Bedrock on acc2 stays blocked by its payer.
5. Biggest real saving later: Batch (−50 %) for S1-style catalogue waves.
