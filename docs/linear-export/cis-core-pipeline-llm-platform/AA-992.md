## Problem

Nghiệp asked (S252, 26/10/2026) for one admin page that shows only live numbers for the whole system, so missing data can be audited at a glance. The chain runs from the raw inputs to the consuming apps:

* raw Excel uploads for tours and brands;
* raw tours imported, then deleted/filtered;
* ready for S1, then written to Master;
* atoms, segments, routes/hubs, places, place cards and photos;
* T-series pieces and tenants;
* TripPlanner, Booking and CRM.

Today these numbers sit in an ad-hoc script (`coverage.py`, S252 propagation audit) and several separate admin pages.

## Scope

Design: root `docs/audits/2026-10-26-S252-propagation-audit/` plus the data-coverage design (critic-fixed, S252).

* `/admin/data-coverage` under Platform: about 95 rows in 9 stage groups. Each row shows:
  * count, what it is out of, %, missing;
  * the expected gap with its reason;
  * status: must / backlog / info;
  * a drill link.
* CIS `GET /admin/data-coverage`:
  * each source query runs read-only with its own timeout;
  * a failing source turns only its own rows into n/a;
  * two-tier cache;
  * admin only (`OPS_READ`).
* Count-only owner views:
  * TripPlanner tp-NNN;
  * Booking bk-NNN;
  * CRM through the `crm.ops.v1` 1.3 endpoint (ADR 0008a: no AA role access to `crm`).
* Infra: migration copies, consumer grants, isolation probe cells, RLS allow-list copy.

## Done when

* PRs merged with CI green. Migrations applied via DB Migrate, schema dump merged, deploys COMPLETED.
