## Problem

Found in S245 while checking [AA-779](https://linear.app/aa-ecosys/issue/AA-779/t9-faq-questions-from-people-also-ask-first-every-answer-names-its). The blog request `1dfbf5e6-bf67-45a3-84c8-7fc37d62868a` (tenant Atlas & Hearth) is about the Mongolia tour `4e35f6b4-fe5f-4c2f-945c-b44b6e21b99b` ("Khovsgol and Gobi tour Mongolia", atom `17296f7026d87e2c`). Its `route_segment_ids` (10 Segments) include two that are not in Mongolia:

* "Dal Lake | take an optional evening shikara ride" (Kashmir, India)
* "a local Buddhist monastery | visit and engage in cultural exchange with young monks" (country unclear)

Both have `questions_count` NULL. The other 8 Segments are Mongolian (Lake Khövsgöl, Mörön, Uran Togoo, Tsaatan settlements, Sod Camp).

A wrong-country Segment can put facts, questions and place names from another trip into T8 angles and T9 blogs, which breaks the writer source-fidelity rule.

## Scope

1. Trace how `route_segment_ids` is built for an angle-gate request: Route/Segment assembly in A3 (atom → Segment membership, Segment clustering/merging, canonical_place matching), and where the request copies it.
2. Find the root cause of the two foreign Segments: shared canonical_action text, an embedding/cluster merge across countries, a wrong `atom_segment_member` row, or route ids taken from another atom.
3. Measure how widespread it is (read-only): routes whose Segments span more than one country; count per country.
4. Fix the cause and add a guard: a Route/request never carries a Segment from another country (unless the tour itself is multi-country), with a test. Plan a clean-up for the rows already wrong.

## Done when

* Root cause written with evidence (SQL and file:line).
* Read-only count of affected routes before and after the fix; 0 cross-country Segments in tours that are single-country.
* Guard and test merged and deployed per aa-ship.
