## Problem

Migration 268 (S247, CIS [AdventureAsia365-Ecosys/AA-CIS-App#937](https://linear.app/aa-ecosys/review/feat-migration-268-restores-the-published-toursquality-score-id-8c269f2e4f44)) made `gold_aa_internal.published_tours.quality_score_id` a real FK. After that, we saw that revalidating a published tour writes NULL into `quality_score_id` instead of pointing it at the new accepted `silver_aa_internal.quality_scores` row. Readers that get the accepted score through this column then see nothing.

## Scope

* Find the revalidation write path and make it set `quality_score_id` to the newly accepted score row, all in one transaction.
* Backfill: for rows that have NULL today but have an accepted score, use a DRY RUN listing first, then a small fix script that goes through the documented path (rows only, no schema change).
* Add a regression test.

## Done when

* A unit/integration test covers revalidation and shows `quality_score_id` points at the new row.
* On Dev after the deploy: one tour is revalidated and its `quality_score_id` is non-NULL and equals the latest accepted score. The count of published rows with NULL `quality_score_id` that do have an accepted score is 0, before and after the backfill.

Refs [AA-894](https://linear.app/aa-ecosys/issue/AA-894/docsdata-erd-prd-as-code-generated-erd-per-schema-design-erd-drift) (migration 268).
