## Problem

The A-series (A1 write + A3 atoms) was audited end to end after the S218 waves: `docs/audits/2026-10-08-S218-a-series-pipeline-audit.html` (live: [https://claude.ai/artifact/BuaUQnyYeNYn9LSBxxyY1m](<https://claude.ai/artifact/BuaUQnyYeNYn9LSBxxyY1m>)). Measuring every stage from the DB found real design gaps that unit tests and single-tour checks never showed.

The T-series (T0 brief → T2 rewrite → T3 → T4/T5 → T7 slate → T8 angle → T9 write → T10 gates → export) has only been verified stage by stage on a few pieces. The current test tenants cannot answer the main question either: only WanderLux has a real brand (Atlas & Hearth); ExploreAsia has a one-line style and 5 forbidden words, test-1 is empty, and all three have 0 adopted tours / 0 pieces after the data reset (checked S219, 09/10/2026).

The tenant portal is the product sold to B2B customers. The audit decides what the portal UI/UX upgrade must fix.

## Scope (agreed with Nghiệp, S219)

1. **Replace the test tenants.** Retire the existing test tenants (wanderlux-travel, exploreasia-co, test-1) by **soft-delete / offboard** (S229 decision — there is no hard-delete code, and they hold \~0 rows after the reset; DRY RUN of dependent rows first; aa_internal untouched). Create 4 new tenants, one per reference brand in `apps/AA-CIS-App/docs/AI-gent-for automation works/brand identify for tenant trip content testing/`, each loaded through **T0 (docx upload in the portal)** so T0 itself is audited:

   | Brand | Style | Markets in the brief | Supported by DFS? |
   | -- | -- | -- | -- |
   | Atlas & Hearth | luxury cultural, slow, discreet | US, UK, UAE, Saudi Arabia, Singapore, Hong Kong | US/UK yes; 4 unsupported |
   | Terra Family Expeditions | premium family, reassuring | UAE, Singapore, Hong Kong, UK, Australia | UK/AU yes; 3 unsupported |
   | Trail Pulse | young, active, short sentences | Europe, Australia, North America, Singapore | AU/US/DE/FR/NL partly |
   | WildKind Travel | responsible nature, ethical wildlife language | Europe, Australia, Canada, New Zealand, US | partly; CA/NZ unsupported |

   DFS supports US, UK, AU, DE, FR, NL only — the unsupported markets are the "unfamiliar market" test ([AA-629](https://linear.app/aa-ecosys/issue/AA-629/bug-tenant-market-ngoai-6-whitelist-bi-silent-fallback-ve-us-djoc-nham) fallback + banner).
2. **Sample:** 12 tours per tenant (48 total, under the 50-tour paid-run rule), same tours across tenants where possible so the brands can be compared side by side; include wildlife/elephant and family/honeymoon tours (stress for WildKind and Terra). Pilot 3 tours per tenant first.
3. **Run the real workflow** through the portal APIs / job runner exactly as a tenant would (T0 → T2 → T3 → T4/T5 → T7 → T8 → T9 → T10). **No WordPress / social publish** — the end of the chain is the existing **export: HTML (**`<article>`**) and DOCX**.
4. **Measure each stage from the DB** (read-only scripts in the style of `docs/audits/scripts-s218/`):
   * brand distinctness: the same tour written for 4 brands — tone, forbidden words, persona leaks, judge scores per brand;
   * unfamiliar markets: what the system did (fallback market, banner, keyword quality);
   * codes at the first vs final check; why a piece was held (T10 F1–F9); rewrite count;
   * cost per stage (`llm_call_log`, `dfs_call_log`), job timings and failures;
   * tenant-visible outcome (approved / held / exported) and export file quality.
5. **Per-mechanism table** (designed for → what the run showed → keep / adjust / not fit → upgrade) + roadmap in 3 phases.
6. **Portal UI/UX review** as part of the report: walk every portal page with real data from the 4 tenants (desktop/mobile, light/dark) and list what must change for a professional, smooth, intuitive B2B product, benchmarked against market products. This list feeds the portal UI issues ([AA-670](https://linear.app/aa-ecosys/issue/AA-670/portal-information-architecture-page-by-page-ui-audit-fix-inconsistent), [AA-668](https://linear.app/aa-ecosys/issue/AA-668/portal-writer-panel-segmenttopic-opens-a-right-side-panel-goal-angle), [AA-671](https://linear.app/aa-ecosys/issue/AA-671/portal-marketplace-redesign-catalog-grid-with-filters-detail-drawer), [AA-672](https://linear.app/aa-ecosys/issue/AA-672/portal-account-pages-billing-activity-log-team-and-settings)).
7. **Report** in `docs/audits/` + artifact. Lessons into `skill/aa-lessons/lessons.md` at root-cause time.
