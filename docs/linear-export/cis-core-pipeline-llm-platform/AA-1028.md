## Problem

Three partial plan mechanisms exist and none can be edited as plans (research `docs/audits/2026-11-01-S263-pricing-and-plans/README.md` §2): CIS `shared.membership_plans` (no admin CRUD, SQL only), hard-coded `PLAN_LIMITS` and s2/s3/s4 quota 10/10/50, `shared.tenant_ai_budget` set per tenant by hand and not linked to the plan, CRM `crm.tenant_entitlement` free/core/pro CHECK with `allowed_features` stored but never enforced. Tech lead (S263, T-9): define plans once in admin, assign to a tenant or agency, limits follow; Dev default AI budget 5 USD/month per tenant with hard stop; prod amounts from the business owner's plans.

## Scope

* One catalogue (`shared.plan` or extended `membership_plans`) with product (content_studio | crm): price, tours quota, AI monthly USD + alert/approval %, hard_stop, rpm, s2/s3/s4 quotas, posts/week, seats, features\[\].
* CIS admin page: create/edit/retire plans (kit UI, audited, versioned).
* Assignment: tenant/agency plan; readers resolve plan default + per-tenant override (existing rows act as overrides).
* Contract `tenant.entitlements.v1` CIS → Partner; `crm.tenant_entitlement` becomes a synced mirror; CRM enforces `allowed_features` (e.g. `ai_assist` gates AI drafts); CRM AI budget = plan ceiling, owner may set lower.
* Replace hard-coded limits; seed Dev plans.

## Done-when

* Admin creates a plan, assigns it to an E2E tenant and an E2E agency: tenant AI budget, rpm and quotas and the agency's seats/features follow live (API + screenshots).
* A disabled feature is refused live in CRM (403).
* Hard-coded `PLAN_LIMITS` / 10/10/50 removed; tests green; $0.
