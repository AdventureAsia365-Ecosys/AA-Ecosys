# AA-728 — [Review Queue] failure_class + retryable per row; hide Regenerate for non-retryable failures

## Problem

The review queue mixes failures of different kinds: poor raw (should be trashed) and writer hype-tone ([AA-724](https://linear.app/aa-ecosys/issue/AA-724/s1-writer-cyclebike-tours-fail-brand-fit-writer-emits-hypepersona-tone)). Regenerate fixes neither — it is a retry on the same harness — yet the UI offers Regenerate for every row, including bulk ([AA-719](https://linear.app/aa-ecosys/issue/AA-719/review-queue-ui-bulk-regenerate-non-blocking-regenerate-ui-freezes-no)).

## Scope

Each review-queue row carries `failure_class` + `retryable`:

* `raw_insufficient` → retryable=false; suggest trash or enrich raw (example threshold: itinerary < 500 chars; GLIMPSE OF BHUTAN had 431).
* `writer_tone` / `forbidden_word` → retryable=false until the prompt/guard changes ([AA-641](https://linear.app/aa-ecosys/issue/AA-641/t2-pipeline-stop-flag-fix-from-creating-new-hard-failures) part B, [AA-724](https://linear.app/aa-ecosys/issue/AA-724/s1-writer-cyclebike-tours-fail-brand-fit-writer-emits-hypepersona-tone)).
* `transient` (timeout, 429, 5xx) → retryable=true.

Regenerate shows only for retryable rows; bulk regenerate skips non-retryable rows and reports how many it skipped.
