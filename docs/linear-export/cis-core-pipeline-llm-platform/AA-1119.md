## Problem

The S282 audit (R31, R32, R40) found several gaps in how releases are protected:

* TripPlanner main has no strict checks and no merge queue.
* A red post-deploy smoke neither rolls back nor opens an issue.
* The release-please PRs have stayed open for weeks.
* The CRM API sends nothing to Sentry.
* DB Migrate dispatches without checking its input first.

## Scope

* TripPlanner main gets strict checks, a merge queue and a coverage floor.
* A red post-deploy smoke rolls back, or opens an issue, for every web app.
* release-please is merged weekly, or removed.
* The CRM API sends a test event to its Sentry project.
* DB Migrate validates its input before dispatch.

## Done when

* Each item is in place and shown once live.
* The release-please decision is recorded.
