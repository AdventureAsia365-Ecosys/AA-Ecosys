## Problem

The S247 T9 FAQ work showed that 32 of 52 place_paa questions in the writer input had already been rejected by the Jev A3 check. The writer still receives them, spends tokens on them, and the FAQ filter then drops them downstream.

## Scope

* In the T9 writer input build, exclude place_paa questions whose Jev A3 verdict is reject. Read the verdict from where A3 stores it. Look up the table and column names in docs/architecture/db-schema-reference.md; do not guess.
* No new gate, no new LLM call. This is $0 and fits the M2a "no new gates" rule.
* Log how many were dropped per piece (an existing stage metric or a log field).

## Done when

* A unit test proves that rejected place_paa questions never reach the writer prompt, and that accepted ones still do.
* After the deploy: one T9 run on Dev for ≥3 tours, and the writer input count of place_paa questions equals the accepted count. Evidence comes from the log or the llm_call_log input size.

Refs: S247 log (place_paa 32/52), [AA-859](https://linear.app/aa-ecosys/issue/AA-859/security-tenant-pool-wave-2-move-tenant-write-and-planning-routes-to) T9 FAQ filter (CIS [AdventureAsia365-Ecosys/AA-CIS-App#924](https://linear.app/aa-ecosys/review/feat-json-logs-with-request-ids-for-the-cis-api-and-worker-8fd84cdab7e1) family).
