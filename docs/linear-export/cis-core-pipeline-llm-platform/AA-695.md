# AA-695 — [A3 Segment + Jev] Measure borderline Segment merges, then decide on a stored "same real-world place?" verdict

Design: `docs/architecture/at-series-v2-design.md` §4.2 A3-7.

`segment_matching` (Jaccard on place + verb) over-merges similar names, e.g. Kumano Hongu Taisha vs Kumano Nachi Taisha.

## Scope

1. Measure how many atom pairs sit in the borderline Jaccard band on current Dev data. No Jev spend in this step.
2. If the count matters, add a Noul "Same real-world place?" for borderline pairs only. The verdict is stored once, so `segment_id` stays stable across reruns (ADR 0002).

## Done when

The measurement is posted, with a go/no-go for Nghiệp; if go, the verdict is implemented and calibrated.

### 2026-10-09 00:47 — nghiep pham quoc

S219 (09/10/2026) — fragmentation measured after the rerun (read-only, `.tmp-session/s219_seg_frag.py`). The original scope (over-merge, `a3_same_place`) is done; the remaining problem is the opposite: **under-merge**.

**Numbers (880 active Masters, 14,522 Segments):**
- Atoms per Segment: 0 → 1,497 (empty, no active atom left), 1 → 10,296, 2 → 1,451, 3 → 473, 4 → 243, 5+ → 562.
- Live Segments 13,025; **81% hold atoms of one tour only** (10,563).
- **4,550 single-tour Segments share their exact place (normalised) with another Segment in the same country.** 1,962 place groups hold 6,257 Segments. Examples:
  - Kathmandu: "explore the city" (5 tours) / "walk through the city's market" (2) / "independent activity" / "contingency day" …
  - Jaipur: "optional hot air balloon" (13) / "stay overnight" (4) / "shop for textiles" (2) / "browse handicraft shops" …
  - Beijing: "walk through the city" (30) / "dine on Beijing duck" (10) / "arrive in" (4) / "overnight stay" …

**Cause:** the Segment key is place + free-text action. The same moment written with a different verb phrase becomes a new Segment. A large share of the singletons are logistics, not moments ("hotel check-in", "airport transfers", "arrive in", "stay overnight", "your accommodation").

**Proposal (go/no-go for Nghiệp — no code yet):**
1. Logistics atoms (arrive / depart / transfer / check-in / overnight / free time) stay atoms but do not form Segments. They carry no demand and no route value.
2. Key Segments on place + `activity_type` (already on every atom, Jev-checked by `a3_activity_type`) instead of the free-text action. The action text stays on the atom for writing. "explore the city" / "walk through the market" in Kathmandu then become one sightseeing Segment.
3. Remove the 1,497 empty Segments (DRY RUN → approval). They feed pseudo-atoms and re-derive the same ~187 aliases on every run.

Effect to measure first, on a copy of the key: Segment count, share of multi-tour Segments, and route/hub change. Then a single rebuild (Segment ids change → ADR 0002 note).
