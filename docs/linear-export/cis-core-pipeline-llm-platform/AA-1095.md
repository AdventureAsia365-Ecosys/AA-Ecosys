## Problem

acc3 is the only Bedrock LLM account today, and AWS blocks it at account level. Live check on 12/11/2026, 15:25 +07:

* Every call to the 7 models returns `AccessDeniedException … is not available for this account … contact AWS Sales`: Claude Sonnet 5.5, Opus 5.5, Haiku 5.5, Sonnet 5, GPT-6 Luna, GPT-5.6 Luna, GPT-6 Astra.
* The Bedrock API still reports these models as AVAILABLE / AUTHORIZED.
* The TPM quota is 0 for 5 of them.
* The AWS cases are still open.

The gateway falls back to the Anthropic and OpenAI APIs, so nothing is blocked. But the AWS-first route policy cannot be met.

acc1 is the payer of acc3's organisation since S277. On 12/11 every chat model the gateway uses answered a real Converse call on acc1 (us-west-1, `global.` profiles):

* Claude: Sonnet 5.5, Opus 5.5, Haiku 5.5, Sonnet 5, Sonnet 4.6, Opus 4.6, Haiku 4.5.
* GPT: GPT-6 Luna, Astra and Sol; GPT-5.6 Luna; GPT-6.1 Sol and Terra.
* Global TPM quotas are between 2M and 30M.

**Tech lead decision (S278, 12/11/2026):** if acc1 can use every model of the system, serve Bedrock from acc1 instead of acc3. This reverses [AA-998](https://linear.app/aa-ecosys/issue/AA-998/infra-remove-acc1-personal-aws-account-from-the-whole-ecosystem-audit) / ADR 0001a for Bedrock LLM serving only.

## Scope

1. **Infra:** a minimal `accounts/acc1-bedrock` root with the Bedrock invoker role only, trusted by the acc2 CIS task roles. The aa365 root grants the assume. Nothing else goes on acc1.
2. **CIS:** a gateway connection `acc1` with its deployments for the 13 models and a monthly cap.
   * acc1 rungs take acc3's place in every stage chain.
   * acc3 stays configured behind acc1 until its case is solved.
   * The "no acc1" tests now pin acc1 as a Bedrock connection only.
3. **Root:** an ADR 0001a amendment ("Note S278") and updated account-map lines.

## Done when

* The acc1 role is applied.
* The CIS migration is applied and deployed.
* A connection probe answers ok for all 13 models on `acc1`.
* `gateway_status` shows acc1 13 ok / 0 denied.
* At least one real stage call is logged in `shared.llm_call_log` with account `acc1`.
* The ADR amendment is merged.
