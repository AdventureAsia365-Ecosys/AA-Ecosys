## Problem

The tech lead asked (S279, 13/11/2026) for a learning site that teaches everything the AA ecosystem runs on. Today that knowledge is spread across many places, and nobody can learn it in order:

* company docs in `docs/`, with the role catalog `docs/README.md` and the `/admin/docs` reader (EN + VI);
* ADRs (`docs/adr/`), data standards (`docs/architecture/data-standards/`), runbooks (`docs/ops/runbooks/`) and contracts (`docs/contracts/`);
* agent skills (`skill/aa-*`), the lesson log (`skill/aa-lessons/lessons.md`), audits (`docs/audits/`) and each repo's `CONTEXT.md`;
* the engineering handbook (`docs/engineering-handbook.md`) and the Linear and Jira history.

A new engineer, operator, agency staff member or business owner has no path to learn the pipeline, gates, settings, job runner, MIG-4, tenant model, CRM and Booking flows, cost rules or the ship process. Each domain also has methods (trunk-based flow, contract-first, ratchets, maker-checker, DRY RUN first, evidence-gated quality) that are written down but never taught.

## Scope

**Phase 1: advisory and deep research.** Write to `docs/research/lms/` plus an artifact:

1. A knowledge inventory: every domain, technique, process, standard, governance rule, management method and tool in use, mapped to its source of truth in the repos.
2. Audiences and learning paths by role: engineer on duty, tech lead, ops/support, content operator, finance/booking staff, agency owner/agent, business owner.
3. Course and module design for each path: objectives, prerequisites, lesson types (reading, walkthrough video, hands-on lab on Dev synthetic tenants, quiz) and completion criteria.
4. Platform options with cost:
   * built into CIS admin on the UI kit, reusing the docs reader and the EN/VI pages;
   * an open-source LMS such as Moodle or Open edX;
   * a docs-site learning path, for example Docusaurus.
     Compare them on single source of truth (no copied content), EN/VI, progress tracking, quizzes, SSO with Cognito staff and partner pools, and maintenance cost.
5. Content pipeline: lessons generated from the repo docs, so a docs change updates the course; owner per module; review cadence; how the free local TTS harness (`tools/uat`) can produce lesson videos.
6. Governance: who approves content, versioning, and measuring learning (completion, quiz scores).
7. A recommendation, an MVP-free full design per the S245 direction, and an effort estimate.

Out of scope in phase 1: building the site. That is a follow-up issue after the tech lead approves the design.

## Done when

* `docs/research/lms/README.md` (plus `.vi.md`) holds the inventory, paths, course map, options comparison with costs, and recommendation, merged in a root PR.
* An artifact page presents the design for the tech lead's decision. Several decisions go on one clickable decision page.
* The tech lead has chosen the platform option and the first learning paths. The decision is recorded in this issue.
