## Problem

There is no fixed reference set to tell whether a prompt, model or threshold change makes content better or worse. Quality is measured by audit rounds (S218 A-series method, T-series). Nghiệp decided (S241, D-23) to keep measuring through audit rounds and to build a golden set of about 100 samples from data we already have. No CI LLM gate yet.

## Scope

1. Select \~100 samples from existing data: S1 rewrites, Master tours, T2/T9 pieces, stratified by country and tour type, including hard cases (cycle/bike, poor raw, 18-day tours), known failures, and a small prompt-injection set.
2. Labels from existing decisions: review-queue outcomes, Ms. Thư feedback, audit-round verdicts. Gaps labelled by an agent panel and approved by Nghiệp; label source recorded per sample.
3. Commit the set as a versioned fixture (ids, labels, reason; no PII).
4. Scoring script reusing the audit-round metrics: pass-rate, judge-vs-label disagreement, Jev agreement, writer calls, cost. Runs through `LLMClient`, `stage="adhoc_aa729"`, logged in `shared.llm_call_log`. Trial on 3 samples, then the full set; quote cost first (D-19).

Out of scope: required CI eval gate (U-29), until Nghiệp revisits.

## Done when

* Golden set committed with label provenance for every sample.
* First baseline run report in `docs/audits/` with metrics and cost taken from `llm_call_log`.
* The next S1 or T9 prompt, model or threshold change after the baseline (e.g. [AA-748](https://linear.app/aa-ecosys/issue/AA-748/s1-writer-feed-the-writer-structured-source-facts-days-places-numbers), [AA-714](https://linear.app/aa-ecosys/issue/AA-714/llm-judges-on-gpt-luna-instead-of-gpt-41-ab-gpt-6-luna-vs-gpt-56-luna)) cites before/after numbers on the same fixture version. *(Reworded S245, Nghiệp approved:* [AA-724](https://linear.app/aa-ecosys/issue/AA-724/s1-writer-cyclebike-tours-fail-brand-fit-writer-emits-hypepersona-tone) *was Done on 07/10, so the old line could not be met.)*
