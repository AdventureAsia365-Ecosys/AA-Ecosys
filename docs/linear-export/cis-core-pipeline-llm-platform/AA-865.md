## Problem

[AA-777](https://linear.app/aa-ecosys/issue/AA-777/t10-f9-judge-consistency-sticky-pass-for-unchanged-sentences-cut-truth) closed on its outcome metrics (r7: 20/20 approved, 0/8 blog F9 holds, 0 guard reverts, [AA-768](https://linear.app/aa-ecosys/issue/AA-768/t9-writer-source-fidelity-the-writer-invents-numeric-facts-55-pilot) set 5/5). One target stayed open: "retry added a blocking fail" was 13.0% (3/23) against ≤ 8%.

All 3 cases are `F9_cta_fact` re-flags after a sentence repair, and all 3 pieces were approved in the end. At about 23 retries per round, the 8% target means only 1–2 retries, so the metric swings between 4% and 15% from round to round (r5 3.8% → r6 15.4% → r7 13.0%). One round cannot tell real progress from noise.

Evidence: root `docs/audits/2026-10-16-S239-in-progress-audit/aa777-r6/` (with `diagnosis.md`) and `aa777-r7/`.

## Scope

1. Pool retries across rounds r5–r7 plus the next natural T9 jobs from `shared.llm_call_log` / `gate_ledger`, so that n ≥ 60 retries. This needs no new paid run unless the pool stays below 60.
2. Classify each retry-added fail: real new fault, F9 re-judging the repaired sentence, or a judge quote spanning two sentences.
3. If F9 re-judging dominates, extend the sticky pass to sentences whose only change is the repair edit itself, or let `F9_cta_fact` on a repaired CTA sentence warn instead of block. Pick one with data.

## Done when

* The pooled rate over n ≥ 60 retries is reported, with a 95% interval.
* Either the pooled rate is ≤ 8%, or one fix ships and a re-measure (≤ $1.5) shows ≤ 8% on the pooled set.

Split from [AA-777](https://linear.app/aa-ecosys/issue/AA-777/t10-f9-judge-consistency-sticky-pass-for-unchanged-sentences-cut-truth) (S240).
