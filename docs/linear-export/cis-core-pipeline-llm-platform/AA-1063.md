## Problem

The tech lead adjudicates W2 claim labels ([AA-1048](https://linear.app/aa-ecosys/issue/AA-1048/quality-w2-claim-level-ground-truth-and-calibration-of-the-pinned)) in Writing memory › Disagreement queue. Each row shows only `golden_claim <hash>`, the panel's common label and "disputed/audit", with three buttons (Judge right / Human right / Unclear). The row has no sentence, no source and no explanation, so it cannot be judged from the page.

Once resolved, a row leaves the queue. No admin page shows the labelled sentences or the label set versions (CL-1 1.0.0, 1.1.0), so it is unclear where the work went.

In S275 the 284 items were reviewed on a temporary artifact page instead: the sentence in Vietnamese and English, what the source says, the doubt, the agent's proposal, three buttons and "accept all proposals". The answers were then written back through the admin API.

## Scope

* **Review view** in Writing Lab (replaces the opaque queue rows for `golden_claim` items):
  * Each item shows the sentence with its context, the evidence lines and the full source (collapsible).
  * It shows the three panel lenses with their reasons, an agent proposal with a one- or two-line plain-language reason, the unsupported part highlighted, and Correct / Wrong / Unsure buttons.
  * One answer maps to the existing resolution (`judge_right` / `human_right` / `unclear`). For a panel with no majority, the answer imports a tech-lead row instead.
  * Bulk "accept every remaining proposal" with a confirm step; no `window.confirm`.
  * Filters by set version, writer, proposal and state. EN default, VI in the same messages.
* **Label set browser:**
  * Every set version (CL-1 1.0.0, 1.1.0, t2@2, ...) with its counts: panel agreed / tech lead / none, audit flips, splits.
  * Every labelled sentence, filterable, showing who decided it (panel or tech lead), when, and why.
  * Read only; tenant text shown to admins only, as the queue already allows.
* **Agent proposals stored with the item** (not in the page): a proposal job, or an import endpoint for proposals made by an agent panel. Each proposal records its source (agent run id).
* **Jev pre-filter (shadow first):**
  * Measure the existing claim-supported question on the labelled CL-1 sentences, per zone.
  * Where the accept zone is at least 99% right on held-out labels, an item that Jev and the panel both call supported is auto-resolved with the source recorded, and leaves the tech-lead queue.
  * The reject side stays shadow until measured.
  * Tenant content goes to Jev only for allow-listed tenants (demo/audit tenants only).
