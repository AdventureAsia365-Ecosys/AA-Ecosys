## Goal

The tech lead decided on 27/11/2026 (S295) that the system uses one currency, USD, and for now shows only USD. Today the code still offers VND in several places, so "USD only" needs a real change, not just new wording.

## Problem

Repo check (27/11, live data not yet checked):

* `shared.plan` has VND price columns (`price_vnd_monthly`, `price_extra_seat_vnd`).
* Tenant billing terms allow `USD` or `VND` (`billing_currency`, `agreed_currency` CHECK constraints).
* CIS admin › Tenants › Plans & add-ons shows VND inputs (plan drawer, commercial terms, Tenant 360).
* Booking SaaS invoice drafts format and group by VND when a tenant uses VND.
* Partner (CRM + Content studio) formats VND in money helpers, proposals, the payments ledger, Billing and the dashboard.
* Excel templates T02/T06/T07/T08 were already switched to USD only (S295, on Drive).

## Scope

1. One admin setting "Enabled currencies" (settings registry, default `["USD"]`), editable by an administrator, following the rule that policy values are never hard-coded.
2. Every currency picker and every VND column/input is hidden while VND is not enabled. APIs refuse writes in a currency that is not enabled (422 with a clear message).
3. Live data check (DRY RUN first): list plans/tenants/terms that hold VND values; switch them to USD after review.
4. Keep the VND columns (no DROP), so VND can be reopened later by the setting alone.
   Out of scope: supplier cost currencies in Booking FX (suppliers who quote in local currency are converted to USD by staff per the template rule); dropping columns.

## Done when

* The setting exists in admin with only USD enabled, and changing it is audited.
* No VND appears on CIS Plans & add-ons, Tenant 360, Partner Billing/dashboard/proposals/ledger, or Booking SaaS invoice drafts (screenshots).
* A write with `VND` is refused by each API while VND is disabled (curl evidence).
* The live data check is posted with counts, and any VND rows were converted after review.

## Verify

Admin UI screenshots (desktop/mobile), curl of the refused write per app, aggregate DRY RUN counts.

none (UI + validation); data change in step 3 follows the DRY RUN process.
