## Problem

Quality System v1 (root `docs/audits/2026-10-20-S245-quality-system/design.md`, Nghiệp approved D1–D11 on 20/10/2026, S245). Three things today let one change silently break another:

* **No shared error classes.** Errors are fixed one instance at a time and keep recurring.
* **Gate names are string literals in about 8 places**, so a rename or removal leaves dashboards and repair routing stale with no error (seen in [AA-787](https://linear.app/aa-ecosys/issue/AA-787/t10-gates-drop-f8-framework-promises-an-option-f3-f5-merge-f7f16)).
* **The 7.0 pass line is copied in 5 places**, so A1 retry, T2 status, T3 and the T7 cut can drift apart.

## Scope

1. `quality/taxonomy.yaml`, versioned, with about 17 classes plus `other.*` at warn. Each class has a definition, a severity (hard / block / warn), its detectors per writer, its owner gate, golden examples, a metric and a tolerance.
2. `registry.py` maps every gate code, admin chip and Jev question key to a class. `thresholds.yaml` becomes the single source for 7.0 and the other cut-offs.
3. Lint in CI: no gate-name literal and no 7.0 outside the registry or thresholds. Warn when one writer has a detector for a class that another writer lacks. Add `paths.yaml` and a diff-hash step that marks quality-relevant PRs.
4. Update Writing Memory README §8.2 in the same PR: hard stop 1 becomes "any `fact.*` class with severity hard".

## Done when

* Lint green, with 0 gate-name or 7.0 literals outside the registry and thresholds files.
* Every gate, chip and Jev key maps to a class.
* CI green, merged and deployed per aa-ship. The Content Quality page still shows every gate (live check).
