## Problem

The tech lead asked (S279, 13/11/2026) for a learning site **outside the AA ecosystem**. It is not about AA's own systems: it teaches the general engineering craft a professional team needs, by role.

[AA-1098](https://linear.app/aa-ecosys/issue/AA-1098/knowledge-aa-learning-site-lms-courses-built-from-every-domain-method) is the Academy for the AA ecosystem itself (AA pipelines, AA rules) and is approved. This issue is a separate product.

## Scope

**Phase 1: advisory and deep research.** Write to `docs/research/engineering-academy/` (EN + VI) plus an artifact.

1. **Curriculum by role**, each with levels (foundation, practitioner, lead) and a capstone:
   * roles: software engineer, DevOps / platform / SRE, data engineer, data scientist, ML / AI engineer (incl. LLM apps and agents), analytics engineer, security engineer, architect, QA / test, product and project management;
   * domains: SDLC and ADLC (agent development lifecycle), Git and trunk-based flow, CI/CD, GitOps, infrastructure as code (Terraform), cloud (AWS), containers and Kubernetes, observability and SRE, architecture (C4, ADR, patterns), data engineering (modelling, pipelines, quality, lineage), MLOps / LLMOps, security (OWASP, supply chain), documentation, and ways of working.
2. **Official sources per module**: Anthropic (docs, courses, Claude Code / agent guides), AWS (Skill Builder, Well-Architected, certifications), Git and GitHub docs, HashiCorp, CNCF and Kubernetes, Google SRE books, DORA, OWASP, dbt, Databricks / Snowflake, Hugging Face, and the relevant ISO/IEEE standards.
   * State for each source its licence and what may be used: link, quote, summarise or embed. No copying of copyrighted course content.
3. **Learning design**: paths, prerequisites, hands-on labs in a sandbox, quizzes, projects, progress tracking, certificates, and keeping content fresh when sources change.
4. **Platform and hosting**: a new site on Vercel (or another host), its own domain, a stack (e.g. Next.js + MDX, auth, a progress database), EN + VI, cost per month, and options compared (build vs an open-source LMS vs SaaS).
5. **Ownership and boundary**: which GitHub organisation and Vercel team own it, public or private, and how it stays separate from AA product code and data. This is a decision for the tech lead.
6. A recommendation, a full design (no MVP framing) with phased rollout, the effort in sessions, and costs.

Out of scope in phase 1: building the site.

## Done when

* The research doc (EN + VI) holds the role curricula, the source map with licences, the learning design, the platform options with costs and the recommendation, merged in a root PR.
* An artifact presents the design. Several decisions go on one clickable decision page.
* The tech lead has chosen ownership, domain and platform. The decision is recorded here and a build issue is created.
