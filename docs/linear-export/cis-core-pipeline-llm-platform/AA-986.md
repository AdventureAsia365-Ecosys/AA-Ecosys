## Problem

Nghiệp (S248): when a tour is deleted at S0/A0, every derivative must be hidden across the whole system, tenant side included; the tenant keeps only its T2 copy and is warned that the tour is no longer served.

S248 audit (root `docs/audits/2026-10-23-S248-tour-deletion-propagation/memo.md`, code-level, verified by a second agent per area) — today this does not hold:

* Only `PATCH /admin/tours/{id}/trash` cascades, and it is reachable only while the tour is still `ingested`. Excel replace (supersede), `set-active` and `DELETE /admin/raw-tours` change the source without cascading.
* Four paths silently revive a deleted tour (Activate Master, approving a pending review, re-upload with the same or a near-duplicate name); restore recomputes with `"inactive"` ([admin.py:1930](<http://admin.py:1930>)).
* `acp_contract.v_active_tour_atoms` checks only the Master, `catalog._live_tour` also checks the source; two hand copies of the rule (subject_seed, route_guard).
* `tour.discontinued` notifications are written but no tenant surface reads them; pending T2/T9 jobs, the T7 planner and T11 publish keep going.
* Booking hides retired plans from lists and the B2B feed, but quote and hold do not check the catalog; TripPlanner saved trips still show the tour; tour pages 404 instead of 410.

Live read-only probe (CIS half, 23/10): 44 trashed versions, 26 superseded, 65 dead groups — none of them has a derivative today (none had reached Master), so the gaps are latent.

## Scope (slices, in order; detail in the memo §4)

L7a ecosystem ADR "tour liveness & retirement propagation" → L1 close the A-side leaks (view + copies + export/approve/review guards) → L2 one CIS tour-lifecycle service for every writer (+ restore fix, 409 on activating a dead source, staging "deleted tour" path, dry-run counts) → L3 tenant `served_*` fields, badge, portal bell on tenant notifications, 409 `tour_discontinued` on new work, cancel pending jobs, publish-log flag → L4 CIS tombstone view/outbox + contract `catalog.tour.v1.3` + 410/301 → L5 Booking quote/hold refuse, staff flags, B2B `withdrawn` delta → L6 TripPlanner `available` per stop + banner + 410 → L7b nightly cross-system probe (red on violations).

Open questions Q1–Q10 (with proposed answers) are on the S248 decision page.

## Done when

* Every writer in memo §2.1 goes through one lifecycle service; the per-writer × per-derivative test matrix is green.
* Deleting a published tour on Dev (synthetic) hides it from Master, atoms, catalog, tenant pool, Slate, T7, TripPlanner browse, Booking quote/hold and the B2B feed; the tenant keeps its T2 copy and sees the badge + bell notice; restore brings everything back.
* The nightly probe runs and is green.
