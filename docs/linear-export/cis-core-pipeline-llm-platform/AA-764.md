# AA-764 — [T-series/Jobs] Move T7 slate + T8 angles + T9 fact-select onto the worker — end LLM calls inside HTTP requests (ADR 0003) (G5)

## Problem

T7 Debate and T8 angle generation/ranking run LLM + Jev calls inside the portal HTTP request (`services/acp_shared/debate.py`, `services/acp_angle_gate/service.py::set_goal_and_generate`). This contradicts ADR 0003 (background work on `shared.job`), blocks the event loop and produced a T8 502 through API Gateway's 29 s limit (S229 audit, `docs/architecture/t-series-audit-and-plan.md` §7 G5). Calls made there also miss the job-bound tenant/job attribution added in G1 (they pass tenant explicitly today).

## Scope

1. New job kinds `t7_slate`, `t8_angles` (+ split T9 buffer-retry into a child job).
2. Portal endpoints enqueue and return a job id; portal polls job status (same pattern as T2/T9, [AA-652](https://linear.app/aa-ecosys/issue/AA-652/p1-move-t2-rewrite-t9-write-research-and-a3-atomize-onto-jobs-job)).
3. Measure T7/T8 latency in the G3 pilot first — numbers go into this issue.
   Out of scope: Writer panel UI ([AA-668](https://linear.app/aa-ecosys/issue/AA-668/portal-writer-panel-segmenttopic-opens-a-right-side-panel-goal-angle)).

## Done when

* On Dev, generating angles for one request creates a `t8_angles` job that succeeds; the HTTP call returns < 1 s; `llm_call_log` rows for it have job_id + tenant_id.
* No portal request runs an LLM call (grep + CloudWatch request durations).
