## Problem

`GET /admin/usage-explorer/rollup/check` ([AA-1045](https://linear.app/aa-ecosys/issue/AA-1045/ai-gateway-usage-analytics-explorer)) reports `ok: false` on Dev although the rollup is right. The Jev ledger stores cost with 8 decimals (7-day total 0.06664078 USD), but `shared.ai_usage_hourly.cost_usd` is `numeric(18,6)`. Each hourly row rounds to 6 decimals, so the rolled sum (0.066641) differs from the exact ledger sum. The check compares exactly, so it is red for every window that holds Jev calls. The S293 admin evidence run ([AA-1042](https://linear.app/aa-ecosys/issue/AA-1042/ai-gateway-route-control-center-family-fallback-chains-admin-editable)/1045 spec) fails on this.

## Scope

* Widen `shared.ai_usage_hourly.cost_usd` to the ledgers' precision (`numeric(18,8)` or whatever the widest source ledger uses; read the schema reference), contract migration per ADR 0017.
* Re-roll the affected range with the existing audited re-roll job (`POST /admin/usage-explorer/rollup/run`, $0).
* A unit test that a sub-micro-dollar cost survives the rollup; the check stays exact (no tolerance).

## Done when

* `rollup/check` answers `ok: true` for the last 7 days on Dev (llm and jev sources equal).
* The [AA-1042](https://linear.app/aa-ecosys/issue/AA-1042/ai-gateway-route-control-center-family-fallback-chains-admin-editable)/1045 admin evidence spec passes again.
