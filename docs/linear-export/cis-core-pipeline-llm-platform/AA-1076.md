## Problem

Every gateway call today is a synchronous call at the full price. Bulk work that nobody waits on runs the same way:

* catalogue-wide S1 rewrites,
* A3 re-atomize waves,
* backfills and evaluation panels.

The Anthropic Message Batches API bills every token at 50% of the standard price. It takes up to 100,000 requests per batch, most batches finish within 1 hour (24 hours at most), and it works with prompt caching. OpenAI's Batch API has a similar discount; check its current price page before use.

The old CIS batch path ([AA-606](https://linear.app/aa-ecosys/issue/AA-606/build-bedrock-batch-inference-cho-s1-rewrite-100-tourlan-xin-iam-batch), `services/content_generation/s1_batch.py`) uses Bedrock Batch Inference with the Haiku writer. It does not fit today's routes: S1 runs Sonnet 5.5 on the Anthropic API direct, acc3 is blocked, and acc2 cannot run Claude.

The tech lead approved this in S276 (10/11/2026). The fix of existing Master tours that follows the [AA-1049](https://linear.app/aa-ecosys/issue/AA-1049/quality-w3-rewire-the-t9-s1-and-t2-control-planes-in-place-code) replay must run through this lane. The S276 estimate for that fix: about 75–95 USD for the whole catalogue at the full price, about 45–55 USD with batch.

## Scope

* **Gateway batch lane** in `shared/llm_client`:
  * submit, poll and ingest one batch per wave;
  * one `shared.llm_call_log` row per request with `pricing_mode` batch and `**billed_fields`;
  * a cost cap per batch, checked before submit;
  * retries and fallbacks stay outside the batch: an item that fails or expires goes back to the normal path.
* **Anthropic first** (Message Batches on the direct key); OpenAI Batch as the second provider behind the same interface.
* **Callers:**
  * S1 attempt-1 in a wave (the [AA-606](https://linear.app/aa-ecosys/issue/AA-606/build-bedrock-batch-inference-cho-s1-rewrite-100-tourlan-xin-iam-batch) split: the batch writes attempt 1; validate, repair and retries run on demand);
  * A3 atomize waves;
  * adhoc backfills.
  * Tenant-facing T-stages stay synchronous.
* **Wave rules kept** (skill aa-wave-rerun): 3 tours, then at most 50, then per country; the RDS snapshot; the 24 h freshness window for A3.
* **Admin:** batch status and spend per batch in the gateway admin view.

## Done when

* A Dev wave of 3 S1 tours runs through the Anthropic batch lane.
* The ledger shows the batch price per request: about half the unit cost of the same stage without batch, read from `llm_call_log`.
* A failed or expired item falls back to the on-demand path, proven in a test and live once.
* The spend for the wave appears in the gateway admin view.
