# AA-757 — [A3 atomize] Move t5_atomize from Haiku to GPT-6 Luna — offline A/B on existing atoms (≥100 labelled pairs)

## Problem

`t5_atomize` is the largest LLM cost: in the 30 days to 10/10/2026 it was **$56.3 of $129.1 (44%)** — 8,794 calls on Claude Haiku 4.5 ($37.07) plus 998 un-jobbed calls on Sonnet 4.6 ($19.22). GPT-6 Luna is \~10x cheaper than Haiku ($0.10 / $0.50 vs $1 / $5 per Mtok); on the same volume the Haiku part would be \~$3.7. ADR 0008 (S224) allows a `validate`-role stage (extraction the judge never scores) to use any vendor, which fits atomize.

Risks: atoms can carry invented detail (lessons: "atomize does not mean no fabrication"); Luna once dropped required JSON keys (ADR 0006) → gateway falls back to Haiku, which erases the saving if frequent; atoms feed Segments, ranking and tenant content.

## Scope

1. **Offline, no writes:** most tours already have Haiku atoms in `acp_contract.tour_atoms`. Re-run only the atomize call with `gpt-6-luna` (explicit model, per process) on the same published content and keep the output in S3 — do not touch `tour_atoms`, Segments or ranking.
2. **Sample size (Nghiệp, S224): large enough to generalise.** At least \~60 tours across several countries and tour lengths, so several hundred atoms per arm; **≥ 100 matched atom pairs labelled by hand** (stratified: same moment / only in Haiku / only in Luna / wording differs), not 20.
3. Measure per arm: atoms per tour; Jev `a3_atom_in_text` reject rate (unsupported atoms); share of calls that fell back to Haiku; structured-output failures; cost and latency per tour; for the labelled pairs: equal / Luna better / Luna worse, and any invented detail.
4. If equivalent: switch with one migration (role `validate`, `gpt-6-luna`, Haiku fallback) like migration 212; find out what the 998 un-jobbed Sonnet calls were.

## Done when

* A/B report (numbers above + the ≥100 labelled pairs) attached here.
* Decision: switch only if Jev unsupported-atom rate and labelled quality are not worse than Haiku and fallback rate is low (< 5%); then migration applied, a live re-atomize of a few tours verified.

Related: [AA-748](https://linear.app/aa-ecosys/issue/AA-748/s1-writer-feed-the-writer-structured-source-facts-days-places-numbers) (s1_source_facts moved to GPT-6 Luna under ADR 0008), [AA-619](https://linear.app/aa-ecosys/issue/AA-619/sub-cmeasure-ab-atomize-haiku-vs-sonnet-ha-t5-atomize-xuong-haiku) (Sonnet → Haiku atomize A/B), [AA-621](https://linear.app/aa-ecosys/issue/AA-621/sub-dbe-batch-atomize-mo-rong-bedrock-batch-aa-606-sang-t5-atomize) (batch atomize).

## Offline A/B report (S224) — GPT-6 Luna vs stored Haiku atoms

**Sample:** 60 published tours, 14 countries, **477 days** (only days whose stored Haiku atoms come from the same text). Luna via gateway, `model_tier="gpt-6-luna"` (no fallback). Raw: S3 `scripts/s224_aa757_full.json`; labels `.tmp-session/s224/aa757_label_items.json`.

| Metric | Haiku (stored) | GPT-6 Luna |
|---|---|---|
| Errors / JSON parse errors / fallback | — | **0 / 0 / 0** (477 calls) |
| Cost per day call | ~$0.0042 (30-day avg) | **$0.00069** (~6x cheaper) |
| Latency per day call | — | median 7.8 s, p90 15.8 s |
| Atoms per day | 3.49 (1,664) | 4.63 (2,210) — Luna more on 271/477 days |
| Jev `a3_atom_in_text` p < 0.5 | 1.5% | **0.5%** (p<0.3: 0.2% vs 0.1%) |
| Evidence verbatim in day text | 99.3%* | 95.0% |

*Haiku sample was selected by evidence match, so its rate is inflated.

**120 hand-labelled items (stratified):**
- 50 matched pairs: 36 equal, 10 Haiku better (Luna uses a more generic action, e.g. "visit" vs "swimming", or drops a detail), 3 Luna better; **0 invented detail on either side**.
- 35 Luna-only: 21 real moments (e.g. Tuol Sleng tour, Ta Som, watch archery, draw omikuji), 14 logistics ("return to hotel", "overnight", "arrive"); 0 invented. 21/35 have the same place in Haiku's list (different split).
- 20 Haiku-only: 16/20 are pairing artifacts (Luna has the place); 4 real misses (~2% of Haiku atoms).
- 15 Luna non-verbatim evidence: 14 are formatting — Luna copies the "Day N — title" header or the prompt's "(extract atoms only from this section)" line into `evidence`; 1 borderline (#108); 0 invented.

**Verdict vs Done-when:** Jev unsupported rate not worse ✅, no invented detail ✅, fallback 0% ✅ → switch is justified. Caveats: Luna adds logistics atoms and is sometimes less specific; evidence needs a header/prompt-line strip.

**Saving:** ~$31–33/month at current volume (Haiku part $37.07/30d → ~$6).

**Open decision (Nghiệp):** the day fingerprint includes `model_id`, so switching makes every day re-atomize when its tour is next processed (new content-hash atom_ids → Segment/ranking churn). Options: (a) accept gradual re-atomize; (b) drop model_id from the fingerprint so only changed day text re-atomizes (Haiku and Luna atoms coexist). Proposed: (b) + evidence clean-up + drop pure-logistics atoms. Switch after #642 (atomize on the gateway) is deployed.
