# AA-740 — [S1 pipeline] Deterministic seo_meta / seo_title length fit after the last LLM repair — length codes block Master with no repair path

## Problem

Since [AA-736](https://linear.app/aa-ecosys/issue/AA-736/s1-pipeline-hard-failure-codes-must-block-master-one-shot-haikusonnet) (07/10) the length codes `SEO_META_TOO_LONG`, `META_TOO_SHORT` and `SEO_TITLE_TOO_LONG` block Master on the automated S1 path. There is no repair step that guarantees a fix:

* `fit_seo_meta` ([AA-724](https://linear.app/aa-ecosys/issue/AA-724/s1-writer-cyclebike-tours-fail-brand-fit-writer-emits-hypepersona-tone)/[AA-641](https://linear.app/aa-ecosys/issue/AA-641/t2-pipeline-stop-flag-fix-from-creating-new-hard-failures)) only keeps a complete-sentence prefix inside 140–155. A meta that is **one long sentence > 155**, or **< 140**, is left unchanged.
* flag_fix + `_rerepair_meta` (AA-205/[AA-608](https://linear.app/aa-ecosys/issue/AA-608/s1rubricgatemodel-h3-djo-batch-20-50-tour-h2-noi-gate-quyet)) retry with the LLM up to 3 times, then keep the best candidate "without escalating". [AA-608](https://linear.app/aa-ecosys/issue/AA-608/s1rubricgatemodel-h3-djo-batch-20-50-tour-h2-noi-gate-quyet) chose this deliberately because length was soft back then. [AA-736](https://linear.app/aa-ecosys/issue/AA-736/s1-pipeline-hard-failure-codes-must-block-master-one-shot-haikusonnet) made it hard without adding a deterministic fallback.
* At DB write, `_trim_to_word_boundary` cuts seo_meta to ≤155, so the stored meta (e.g. 153) no longer matches the validated one (>155). This makes diagnosis misleading.

Evidence (S218, 08/10): **15 tours scoring ≥ 7 are in review only for length** — 12 in the Sri Lanka wave (126), 3 in Nepal after regenerate. The rate of the code itself is unchanged from earlier waves (Bhutan 16%, Thailand 14%, China 11%, Sri Lanka 17%). Before 07/10 it did not block.

## Scope

1. A deterministic final fit for `seo_meta` that runs after the last LLM edit (same position as the [AA-738](https://linear.app/aa-ecosys/issue/AA-738/s1-pipeline-deterministic-forbidden-word-strip-on-body-tighter-writer) re-strip in `revalidate_node`):
   * too long, one sentence → cut at the last clause boundary (`,` `;` `—`) that lands in 140–155, end with a period, check `meta_complete_sentence`;
   * too short → append a deterministic clause from tour facts (duration / country / main place), never filler, then check the band;
   * still out of band → keep the code (review), with a summary that names the length.
2. Same for `seo_title` > 60: `fit_seo_title` exists on T2 (`tenant_pipeline`); reuse it on the S1 path.
3. Store exactly what was validated: remove or align the write-time trim so the stored seo_meta equals the validated one.
4. Unit tests with the real S218 metas (single-sentence > 155, 106–137 short).
   Out of scope: loosening the gate (Nghiep S217: hard codes must block Master).

## Done when

* Unit tests: a one-sentence 170-char meta and a 120-char meta both end in band as complete sentences; impossible cases stay blocked with a clear reason.
* Live: regenerate the 15 S218 length-only tours → most reach Master. On the next wave, length-only review rows are ≤ 2%.
* Stored seo_meta length equals the length validate saw (spot-check 10 rows).
