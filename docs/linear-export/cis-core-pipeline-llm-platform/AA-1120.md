## Problem

The S282 audit follow-up found that DataForSEO spend keeps leaking even though earlier fixes made the live path cache-first. Those fixes were [AA-625](https://linear.app/aa-ecosys/issue/AA-625/dfscost-nang-ttl-cache-seo-24h-7-ngay-giam-chi-phi-dataforseo-khi) (7-day TTL), [AA-647](https://linear.app/aa-ecosys/issue/AA-647/p0bug-dfs-failures-poison-the-search-demand-cache-null-stored-as-fresh), [AA-646](https://linear.app/aa-ecosys/issue/AA-646/p0bug-dfs-research-runs-platform-wide-after-every-tenant-rewrite-scope), [AA-649](https://linear.app/aa-ecosys/issue/AA-649/p0-cost-guard-db-configured-budgets-for-dfs-llm-jev-per-run-and-per) and [AA-693](https://linear.app/aa-ecosys/issue/AA-693/a3-research-jev-keyword-belongs-gate-before-buying-dfs-volume-idea).

The [AA-1055](https://linear.app/aa-ecosys/issue/AA-1055/seo-data-keep-search-demand-research-fresh-budgeted-refresh-after) queue path (`services/seo_intelligence/dfs_queue.py`), used by the `segment_research` refresh, never reads or writes that cache. Read-only numbers from `shared.dfs_call_log`:

* **November:** 352 calls, 10.55 USD.
  * 10.04 USD of it came on 09/11 from one `segment_research` run: `search_volume_bulk_queue` 106 calls, 6.36 USD; `serp_advanced_queue` 65 calls, 3.68 USD.
  * Every queue call is `cache_hit = false`.
  * 216 of 335 live calls repeat an endpoint + keyword + location pair already fetched; one pair was fetched 64 times.
* **October:** 1,136 calls, 19.30 USD, with 10 cache hits in total.

## Scope

1. Root-cause write-up: every DFS call path, which ones use the cache, why the queue path does not, and what the earlier fixes covered.
2. The queue path:
   * reads the research cache before it enqueues;
   * de-duplicates endpoint + keyword + location within a run and across runs inside the TTL;
   * writes its results back to the same cache.
3. A guard (unit test or AST check) that fails when a DFS call site bypasses the cache helper, so a future path cannot leak again.
4. A pre-run estimate that shows the deduped call count and USD.
5. Prove it at $0: replay the 09/11 run's inputs through the planner (no API calls) and show the call count it would make now.

## Done when

* The guard is green.
* The replay of the 09/11 inputs shows at least 50 % fewer calls.
* The next scheduled refresh logs cache hits on the queue path.
* `dfs_call_log` shows no repeated pair inside the TTL.
