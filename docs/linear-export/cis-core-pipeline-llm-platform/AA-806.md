# AA-806 — [Infra] Split the CIS CI role (app-deploy vs terraform) + permissions boundary; enable WAF enforce after the count window

## Problem

S235 Phase 0: trust is narrowed, but aa-cis-dev-role still has IAMRoleManage (CreateRole/PassRole/PutRolePolicy on \*) + 10 \*FullAccess policies, usable from any branch of AA-CIS-App/Infra. WAF CommonRuleSet was rolled out count-only (Infra [AdventureAsia365-Ecosys/AA-CIS-Infra#99](https://linear.app/aa-ecosys/review/feat-close-alb-to-the-vpc-link-reorder-waf-commonruleset-count-first-89342bef64dc)); API GW stage association needs apigateway:SetWebACL; provider default_tags need broader iam:TagRole.

## Scope

* aa-cis-dev-app-deploy (ECR + own task families/services only, Booking-style) for AA-CIS-App; aa-cis-infra-tf (AA-CIS-Infra env prod + PR plan read-only) with a permissions boundary on CreateRole/PassRole scoped to aa-*-dev-*.
* Add apigateway:SetWebACL, iam:TagRole patterns; then default_tags {Project, App, Environment, ManagedBy}.
* After 1–2 days of CountedRequests review: flip waf_common_rules_count_only=false; associate WAF with CIS + Booking REST stages (geo list decision for Booking customers).

## Done when

* Deploy Dev, DB Migrate, terraform plan/apply all green on the new roles; old role removed; WAF enforce with 0 legitimate blocks over 48 h.
