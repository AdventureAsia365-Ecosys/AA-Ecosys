# AA-738 — [S1 pipeline] Deterministic forbidden-word strip on body + tighter writer prompt (stop paying for Sonnet twice)

## Why (evidence, S217 Nepal wave of 86 through the [AA-736](https://linear.app/aa-ecosys/issue/AA-736/s1-pipeline-hard-failure-codes-must-block-master-one-shot-haikusonnet) gate)

\~9/86 tours (\~10%) had a forbidden word that **survived BOTH the Haiku writer AND the one-shot Sonnet rewrite** ([AA-736](https://linear.app/aa-ecosys/issue/AA-736/s1-pipeline-hard-failure-codes-must-block-master-one-shot-haikusonnet)). So they were correctly blocked from Master and sent to review with `retried with sonnet, still FORBIDDEN_WORD`. That is the gate working — but two problems:

1. **The writer emits forbidden words far too often, even on Sonnet.** Relying on the LLM to "just avoid" the list ([AA-724](https://linear.app/aa-ecosys/issue/AA-724/s1-writer-cyclebike-tours-fail-brand-fit-writer-emits-hypepersona-tone) neutral-voice prompt) is not enough.
2. **The** [AA-736](https://linear.app/aa-ecosys/issue/AA-736/s1-pipeline-hard-failure-codes-must-block-master-one-shot-haikusonnet) **Sonnet-upgrade is expensive and, at the S1 admin stage, largely wasted.** Nghiep's point (S217): S1 is only a DRAFT. The tenant rewrites the tour again at **T2 with Sonnet** anyway. So spending a second Sonnet pass at S1 to chase a forbidden word is paying for Sonnet twice for the same end. A deterministic fix is cheaper and more reliable than a model retry here.

## Scope — two complementary layers, do BOTH

### A. Deterministic forbidden-word strip on the body (no LLM)

Mirror [AA-641](https://linear.app/aa-ecosys/issue/AA-641/t2-pipeline-stop-flag-fix-from-creating-new-hard-failures)'s `fit_seo_meta` discipline, applied to the body fields (summary, itinerary, highlights, name, subtitle). After validate/flag_fix, deterministically remove/replace the forbidden word in the sentence rather than asking an LLM to avoid it. Must preserve a complete, grammatical sentence (reuse the sentence-salvage helpers where possible); never leave a broken fragment. If a clean deterministic strip is not possible for a field, THEN fall back to review (keep the [AA-736](https://linear.app/aa-ecosys/issue/AA-736/s1-pipeline-hard-failure-codes-must-block-master-one-shot-haikusonnet) safety net).

### B. Tighten the writer prompt forbidden handling

Make the forbidden list an explicit hard constraint in the S1 writer prompt (not just the neutral-voice guidance from [AA-724](https://linear.app/aa-ecosys/issue/AA-724/s1-writer-cyclebike-tours-fail-brand-fit-writer-emits-hypepersona-tone)), so fewer forbidden words are emitted in the first place.

### C. Reconsider the S1 Sonnet-upgrade from [AA-736](https://linear.app/aa-ecosys/issue/AA-736/s1-pipeline-hard-failure-codes-must-block-master-one-shot-haikusonnet)

Given A, the [AA-736](https://linear.app/aa-ecosys/issue/AA-736/s1-pipeline-hard-failure-codes-must-block-master-one-shot-haikusonnet) haiku→sonnet upgrade on FORBIDDEN_WORD becomes mostly redundant at S1 (deterministic strip handles it) and costs a full Sonnet run that T2 will redo. Options to decide: (i) drop the Sonnet-upgrade trigger for FORBIDDEN_WORD specifically (keep it for BRAND_SEO_META_VIOLATION / MISSING_FIELD if still useful), relying on deterministic strip + review; or (ii) keep it only when deterministic strip fails. Measure the cost delta.

## Done when

* Unit tests: a body field with a forbidden word is deterministically cleaned to a valid sentence; an un-strippable case falls back to review.
* Live (via a wave): forbidden-word tours reaching review drop sharply vs the S217 Nepal baseline (\~9/86), and the number of S1 Sonnet-upgrade runs drops (cost measured).
* No published body contains a platform forbidden word ([AA-736](https://linear.app/aa-ecosys/issue/AA-736/s1-pipeline-hard-failure-codes-must-block-master-one-shot-haikusonnet) gate still holds as the backstop).
