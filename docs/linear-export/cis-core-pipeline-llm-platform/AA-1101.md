## Problem

The tech lead asked (S279, 13/11/2026) for a professional project template that is **independent of the AA ecosystem**. When a new project, app, product or whole ecosystem starts, the team should pick the kit up and work from day 1.

The kit should answer, step by step:

* how the full lifecycle starts and runs;
* which documents are written (spec, SOP, PRD, ERD, tech note…) and how code is delivered;
* how plan / do / check / act works, how results are validated, and how the product moves into operations, monitoring and observability;
* how data and data models are managed;
* how governance and project management run.

[AA-1099](https://linear.app/aa-ecosys/issue/AA-1099/playbook-new-project-kit-standard-technical-process-governance-and) is the kit for AA's own way of working and is approved. This issue is the generic version.

## Scope

**Phase 1: advisory and deep research.** Write to `docs/research/project-kit/` (EN + VI) plus an artifact.

1. **Lifecycle map** from idea to retirement, with phases, gates, roles (RACI), deliverables and exit criteria. Map it to SDLC and ADLC (agent-built software), PDCA, and well-known frameworks: ISO/IEC 12207, PMBOK 7, PRINCE2, Scrum / Kanban, Shape Up, the GDS service manual, DORA / SRE, ITIL 4 basics.
2. **Start-up pack:**
   * an initial questionnaire (business, users, data, compliance, budget, constraints);
   * a stakeholder map;
   * the kickoff agenda and checklist;
   * the meeting system: cadences, agendas, decision log, RAID log.
3. **Document templates**, each with purpose, owner, when and a filled example:
   * product and design: project charter, PRD, user stories / acceptance criteria, SRS / spec, architecture (C4 + arc42), ADR;
   * data: ERD / data model, data contract, data dictionary;
   * operations: API contract, SOP, runbook, tech note, test plan, release checklist, incident and postmortem;
   * governance: risk register, cost sheet, status report.
4. **Engineering delivery**: repo template (CI/CD, GitOps, IaC with Terraform, pre-commit / pre-push guards, code health), environments, branching, the definition of ready and done, review rules, AI-agent orchestration (ADLC: agent briefs, guardrails, evals).
5. **Validation and operations**: test strategy and quality gates, UAT, observability (logs / metrics / traces, SLOs and error budgets), monitoring and alerting, on-call, cost (FinOps).
6. **Data management**: data modelling standards, DVC / data versioning, lineage, quality checks, catalog, retention and privacy, MLOps / LLMOps where relevant.
7. **Governance and project management**: stage gates, approvals, change control, reporting to sponsors, vendor and budget management, security baseline (OWASP ASVS / SAMM).
8. **Packaging**: a docs site + a template repo (e.g. Copier) + checklists. Show how a new project instantiates it in a day, the 30/60/90-day plan, and how the kit itself is versioned and improved.
9. A recommendation, a full design (no MVP framing) with phased rollout, effort and cost. Ownership and hosting are decided together with the Engineering Academy issue, where this kit is a core course.

Out of scope in phase 1: building the kit.

## Done when

* The research doc (EN + VI) holds the lifecycle map, the start-up pack, the template catalogue, the delivery / validation / ops / data / governance chapters, the packaging design and the recommendation, merged in a root PR.
* An artifact presents it with a decision page.
* The tech lead has approved the structure. A build issue is created.
