# AA-717 — [Review Queue UI] REASONS column shows “—” for tours failed only on low quality / brand_audit manual_check

## Problem (found S209, 03/10/2026)

In the admin Review Queue, some pending tours show an empty REASONS column (just “—”) even though they clearly failed (e.g. China “Beijing to Hong Kong” score 6.0, South Korea “Seoul, Mountains & Island” score 5.0). A reviewer sees a blocked tour with no stated reason.

## Root cause (not missing data)

The DB always has `silver_aa_internal.review_queue.failure_summary`, e.g. `brand_audit=manual_check; codes=FORBIDDEN_WORD; low_quality(score=6.0<7.0)`.

But the REASONS column (`frontend/app/admin/review/page.tsx`, `ReasonChips codes={item.codes}`) renders only `item.codes`, which comes from `failures[]` — built by `_derive_field_failures()` (`api/routers/admin_pipeline.py`, AA-240). That function only re-derives codes that map to a specific field (META\_*, HIGHLIGHTS\_*, FORBIDDEN_WORD, MISSING_FIELD, a few static). It does NOT surface:

* `low_quality(score=X<7.0)` — overall score failure, not a per-field code
* `brand_audit=manual_check` — overall brand verdict
* several brand-audit codes not in the field map (UNSUPPORTED_NUMBER, ITINERARY_MEAL_TIME_INVENTED, ITINERARY_STILL_COMPRESSED, …)

So a tour failed ONLY on low score and/or brand_audit manual_check gets `failures[] = []` → the column renders “—”, despite a clear `failure_summary`.

## Fix

When `failures[]` yields no chips, fall back to the reasons in `failure_summary` — at minimum surface `low_quality(score=X)` and `brand_audit=manual_check` as their own chips, so the REASONS column is never empty for a blocked tour. Options: (a) FE fallback that parses `failure_summary` when `codes` is empty, and/or (b) BE: have `_derive_field_failures` (or the row builder) also emit non-field verdicts (low_quality, brand_audit=manual_check) as row-level chips.

## Done when

Review Queue never shows an empty REASONS for a blocked tour; low-quality / brand-audit-only failures display a chip. Verified live on the current pending China/Korea/Taiwan rows.

Found while running the China rerun (S209).
