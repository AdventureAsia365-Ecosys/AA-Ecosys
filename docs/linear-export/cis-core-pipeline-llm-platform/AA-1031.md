## Problem

The CIS admin Staff page manages one CIS role and one Booking role per staff account, but no CRM role: the CRM staff groups (crm-platform-admin, crm-ops, crm-support) can only be set by hand in the WORKFORCE pool. The tech lead (owner, cis-admin) could not create an agency in Platform › Agencies (CRM) until crm-platform-admin was added by command (S263, 01/11). Tech lead decision S263: add CRM roles to the Staff page and a "Platform owner" preset.

## Scope

* Staff page and drawer: a CRM role field, multi-select (Agency admin = crm-platform-admin, Operations = crm-ops, Support = crm-support), saved in CIS first (staff directory row / grant table), synced to the WORKFORCE pool, audited, same flow as the Booking role.
* Staff directory sync adds and removes CRM groups like CIS/Booking groups (today it only removes CIS/Booking groups).
* A "Platform owner" preset: one choice grants cis-admin + booking-admin + crm-platform-admin; only an existing platform owner can grant it; the self-change guard stays.
* List column "CRM role", CSV export, directory health check covers CRM groups (E2E accounts keep their ADR 0006a scopes: e2e-crm-staff = crm-ops + crm-support only).
* Docs: Staff section of the CIS admin runbook (EN + VI), ADR 0006b note if the grant model changes.

## Done-when

* On Dev, the tech lead grants and removes a CRM role for a test staff account from the Staff page; the WORKFORCE groups follow (admin-list-groups-for-user) and the audit log has the change.
* The Platform owner preset gives all three admin groups; Agencies (CRM) shows Create agency for that account after re-sign-in.
* Tests (unit + integration) green; screenshots of the Staff page and drawer; $0.
