## Problem

Tour photos are read from public Google Drive folders with a Google API key (`aa-cis/dev/gdrive-photo-reader`, `services/photos/drive.py`). Moving them into S3 would:

* keep them on AWS;
* remove an outside key;
* let the pipeline and the apps read one place, with IAM, lifecycle and no Drive quota.

Tech lead request, S267 (04/11/2026): test on a small sample, never overwrite current data, cap the cost.

## Scope

* Pick 2–3 tours with photo folders.
* Copy their photos from Drive into a separate experiment prefix in an existing S3 bucket, with the source file id, checksum and size kept in object metadata and a manifest. No change to the photo tables, current objects or the pipeline.
* Measure the files, bytes, time per photo, failures and duplicates.
* Check that the copied bytes match Drive (checksum) and that images open.
* Estimate the full move: number of folders and files, total GB, the S3 monthly cost, and a one-off copy plan (a job that copies once, keeps Drive as the source of truth until cut-over, then reads S3).
* Report in the root `docs/audits/<date>-S<nnn>-drive-to-s3-trial/`. The experiment prefix is deleted after the report.

## Done-when

* The report shows the sample numbers, the checksum results, the full-move estimate (GB, monthly cost, run time), and a recommendation with the cut-over steps.
* No existing data or pipeline setting changed.
* Trial spend stays under 1 USD.

## Comments

### 2026-11-04 11:00 — nghiep pham quoc

**S267 trial done.**

**Main finding:** the copy already exists. The AA-708 sync keeps every Drive photo in S3 (original + WebP, `shared.place_photo`). Drive has **3,232** images (2.95 GB, 7 countries) and all **3,232** are already in S3 with a database row: 0 missing, 0 errors. Storage costs about 0.08 USD/month and is billed already.

**Trial** (3 tours, 16 photos copied to an experiment prefix):
- md5 equal to Drive and after re-reading S3: 16/16;
- every image opens; 0.54 s per photo;
- cost ~0.0003 USD;
- the prefix was deleted afterwards (0 objects left);
- no existing row, object or setting changed.

1,919 images are the same file reused across tour folders.

**Recommendation:**
1. Read photos only from S3 everywhere.
2. Drive stays the content team's working folder and the sync adds new files.
3. Drop the Google key only once new photos are uploaded straight to S3 (an admin upload page writing the same layout and row).
4. Optional md5 dedupe would save about 1 GB.

Report: root `docs/audits/2026-11-04-S267-drive-to-s3-trial/` (in the S267 close PR).
