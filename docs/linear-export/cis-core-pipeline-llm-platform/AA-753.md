# AA-753 — [Cleanup] Remove dead N7 LLM stages (n7_draft/adapt/faq/repair/gap_research/judge) + orphaned services/acp_produce/gates.py

## Problem

The N7/N8 produce/deliver pipeline was removed 15–21/09 ([AA-603](https://linear.app/aa-ecosys/issue/AA-603/cleanup-drop-cum-bang-n7n8-dead-sau-khi-go-code-reader-deploy)), but its LLM stages survived in the gateway config and confuse the admin LLM UI ([AA-686](https://linear.app/aa-ecosys/issue/AA-686/gateway-p1c-admin-ui-edit-stage-routes-fallback-chain-shadow-model)): Settings → LLM Models still shows an "N7 — Production pipeline" group, and `n7_judge` even carries a 100% shadow (`gpt-6-luna`, set by the S208 judge switch that touched all 4 judges).

Verified dead in S222 (09/10/2026) on three layers:

* **Code (main):** no module imports `services/acp_produce/gates.py` (the only caller of `stage="n7_judge"`). The only importers are stale copies under `.claude/worktrees/*` and unit tests. The other five `n7_*` stage names have **0** references outside `shared/llm_client/role_config.py` and the Settings page label map. T-series judging uses its own `t10_judge` (`services/acp_content_writing/quality_gates.py`), which imports only `acp_produce/judge_client.py` (keep it).
* **Runtime (all-time):** `shared.llm_call_log` has **0 rows** with `stage LIKE 'n7_%'`; `shared.llm_shadow_log` has **0 rows**. `/admin/llm-usage/tree?days=90` shows no n7 calls either.
* **Config:** 6 rows in `shared.llm_role_config` (`n7_adapt`, `n7_draft`, `n7_faq`, `n7_gap_research`, `n7_judge`, `n7_repair`), all `is_active = true`, nothing reads them.

## Scope

1. Delete `services/acp_produce/gates.py` and the unit tests that only test it (`test_aa298_gates.py`, `test_aa298_judge.py`, `test_aa372_gates.py`, `test_aa396_repair_budget.py`, `test_aa404_atom_density.py`, `test_aa416_event_loop_not_blocked.py`). Before deleting each test file, check whether it also covers live code; move that part instead of deleting it.
2. Remove the six `n7_*` entries from `shared/llm_client/role_config.py` defaults and the N7 group/labels from `frontend/app/admin/settings/page.tsx`.
3. Migration: delete the six `n7_*` rows from `shared.llm_role_config`. Run a DRY RUN first (row list + before snapshot to `s3://aa-cis-bronze-005097885195/scripts/restore/`) and get Nghiệp's approval before the real run.
4. Re-run the CI guard that forbids raw model calls (`test_aa685_*`) and the full unit suite.

Out of scope: the other `acp_produce` modules with no importer on main (`atom_usage`, `dataforseo`, `metrics`, `reliability`, `rule_adapter`, `sweeper_lambda`). `metrics.py` is referenced in AA-CIS-Infra (`observability.tf`, `modules/ecs/main.tf` IAM comment) and `sweeper_lambda` may be a Lambda entry point. Audit them separately before deleting.
