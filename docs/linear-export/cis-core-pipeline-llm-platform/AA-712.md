## Why

Root ADR 0002 (01/10/2026, Nghiệp): only CIS writes content; other apps read views and write only their own schema. Today the TripPlanner still computes and writes:

* `shared.destinations` (insert by `extraction/geocode.py` and `locate.py`; coordinate/country updates by `regeocode_outliers.py` and `backfill_country.py`);
* `tripplanner.itinerary_components`, `tour_stop`, `tour_graph_*` (which places each AA tour visits).

Migration 201 already removed the `tripplanner` role's INSERT/UPDATE on `shared.destinations`, so those writers are frozen. The rerun waves ([AA-653](https://linear.app/aa-ecosys/issue/AA-653/p2-at-flow-sync-audit-clean-rerun-runbook-bhutan-pilot-wave-jev-in)) and photo covers ([AA-708](https://linear.app/aa-ecosys/issue/AA-708/photos-sync-aa-marketing-photos-from-google-drive-jira-con-photos-to)) need places rebuilt from the rewritten, atomized tours.

## Scope

* CIS job kinds (job runner, admin observable):
  * itinerary place extraction per published tour (port `extraction/components.py`, `tour_days.py`, `deterministic.py`);
  * geocode + `shared.destinations` upsert (Mapbox key → CIS secrets; port `geocode.py` / `locate.py`, keep the lower(name) cache);
  * tour stops + tour graph build (port `tour_graph.py`).
* Tables: decide ownership. Move `itinerary_components` / `tour_stop` / `tour_graph_*` into a CIS schema, or keep the names and have CIS write them. The TripPlanner reads them through views (contract like `shared.v_*`).
* Run per rerun wave, after A3 atomize; then photo sync with "Match places + covers".
* TripPlanner: remove or disable the extraction writers; read the views; CONTEXT.md in both repos.
* Cost: LLM extraction calls go through `LLMClient` + `llm_call_log`; trial on 3 tours, then ≤ 50 per batch.

## Done when

For one country (Laos, the first country built; replaces Korea, Nghiệp decision S239): places, stops and graph built by CIS jobs on Dev; photo covers set for that country. (TripPlanner map and suggestions from the views moved to [AA-847](https://linear.app/aa-ecosys/issue/AA-847/places-l4-catalog-read-model-fast-enough-for-places-sourcecis-flip).)
