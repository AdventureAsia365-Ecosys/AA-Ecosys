# AA-811 — [Platform] Transactional email channel (SES on acc2) — shared sender for Booking quotes/OTP and TripPlanner advisor notifications

## Problem

No app in the ecosystem can send email. TripPlanner `backend/assembly/notify.py` only logs; Booking needs email for quote sending ([AA-681](https://linear.app/aa-ecosys/issue/AA-681/aaa-trip-case-workflow-mvp-inquiry-versions-v1vn-approved-confirmed)) and customer OTP ([AA-680](https://linear.app/aa-ecosys/issue/AA-680/aaa-identity-customer-otp-auth-shared-with-tripplanner-staff-rbac)); CIS passwordless login ([AA-703](https://linear.app/aa-ecosys/issue/AA-703/auth-passwordless-login-for-admin-tenant-googlefacebook-sign-in-and-8)) needs it too (S236 design review).

## Scope

1. Terraform in AA-CIS-Infra: SES domain identity for a [lumiguides.it.com](<http://lumiguides.it.com>) sub-domain (DKIM, SPF, DMARC), configuration set with bounce/complaint SNS, sandbox exit request documented.
2. Per-app IAM permission `ses:SendEmail` scoped to the identity (CIS task role, Booking task role, TripPlanner assembly Lambda).
3. A small send helper per app (templates in code), suppression on bounce/complaint.
4. Wire TripPlanner `notify.py` advisor email as the first real consumer.
   Out of scope: marketing email, newsletter.

## Done when

* SES identity verified on acc2 (CLI `get-identity-verification-attributes` = Success).
* A Dev "Send to an advisor" delivers a real email to the staff inbox (screenshot/message id).

## Open

Sender domain and production access request — Nghiệp to confirm.
