# AA-801 — [T2 judge] Stabilise the brand_fit / mission verdict — repeated calls on the same draft swing 4–8

## Problem

S235 T2 rerun (13 versions, 77 t2_judge calls, [AA-792](https://linear.app/aa-ecosys/issue/AA-792/t2-tenant-voice-writer-prompt-t2-writes-in-the-tenants-brand-not-a1s)): the judge's `brand_fit_score` for the same tenant × tour swings from 4 to 8 between calls (e.g. WildKind Bhutan 4, 8, 7, 4, 6, 5, 4, 7, 5; Terra Bhutan 6, 7, 5, 7, 4, 8), and `mission_present` flips on near-identical drafts. With the `brand_fit_mission` gate (cap 6.0) a single noisy call decides whether a version is saved at 6 or 8, drives extra retries (up to 10 judge calls per job) and makes before/after measurements unreliable (A/A' spread ≥1.0).

## Scope

* Measure first ($ ≤ 1): re-judge 10 stored S235 T2 versions × 5 calls each with the current route; report per-version spread for brand_fit and mission.
* Options to A/B on the same set: (a) median of 3 calls on every T2 judge (not only near the threshold); (b) rubric anchors — per-score examples drawn from the tenant's own voice examples; (c) a different judge model for t2_judge (vendor-diverse per ADR 0008). Pick by spread × cost.
* Log the repeats + chosen median in `quality_signal` so admin Content Quality shows the spread.

## Done when

* On the 10-version set, max spread of the final verdict ≤ 1 point across 5 runs and mission verdict stable on ≥ 9/10; cost per T2 version stays ≤ $0.30 (S235: $0.269).
