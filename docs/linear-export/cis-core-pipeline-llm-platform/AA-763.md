# AA-763 — [T-series/Gateway] Separate T-series stage keys (t2_judge, t2_brand_audit, t7_debate_judge…) — split T cost and routing from A1 (G4)

## Problem

T2 reuses the S1 graph, so its judge / brand audit / flag_fix / grounding calls log under A1 stage keys (`s1_judge`, `s1_brand_audit`, …). After G1 (PR [AdventureAsia365-Ecosys/AA-CIS-App#661](https://linear.app/aa-ecosys/review/fix-tenant-id-on-every-llm-call-via-a-job-bound-contextvar-aa-741-g1-4fa2755bb35c)) those rows carry the tenant, but cost per stage, routing and shadow config for T-series cannot be set or read separately from A1. Found in the S229 T-series audit (`docs/architecture/t-series-audit-and-plan.md` §7 G4).

## Scope

1. Give T-series calls their own stage keys (`t2_judge`, `t2_brand_audit`, `t2_flag_fix`, `t2_grounding`, `t7_debate_judge`, …) in `shared/llm_client/role_config.py` SAFE_DEFAULTS + `shared.llm_role_config` rows (migration, same routes as the A1 twin).
2. Thread the stage key down the S1 graph from the T2 job (graph state, not a new parameter on every node where avoidable).
3. Admin gateway UI shows the new stages.
   Out of scope: changing any model choice.

## Done when

* One T2 job on Dev logs only `t2_*` stages in `shared.llm_call_log` (query by job_id), all with tenant_id; an S1 job still logs `s1_*`.
* Admin Settings → Model Gateway lists the new stages.
