## Problem

Part 1 writes the playbook and templates. A new project still needs a scaffold it can generate on day 1 and skills that are not tied to AA paths. Design: `docs/research/new-project-playbook/` §5.4–5.9 ([AA-1099](https://linear.app/aa-ecosys/issue/AA-1099/playbook-new-project-kit-standard-technical-process-governance-and), approved S279).

## Scope

1. R3: the public Copier template repo (§5.4): skeletons, CI, hooks, docs lint, byte-copy guard from the root templates, resource-ID lint, gitleaks, release-please and the versioning policy; first tag `v1.0.0`.
2. R4: the generic skills and the AA overlay (§5.5); hook rules split into generic and AA blocks.
3. R5: pilot: generate a throwaway sample project, run the day-1 checklist end to end, measure against §5.9, fix what breaks, then delete it (deploy only if D14 says so).
4. R6: register the playbook as a course on the learning site ([AA-1098](https://linear.app/aa-ecosys/issue/AA-1098/knowledge-aa-learning-site-lms-courses-built-from-every-domain-method)).

Out of scope: moving existing AA repos onto the template (D12).

## Done when

* The template repo is public, tagged `v1.0.0`, has a `CHANGELOG.md`, and its CI (byte-copy guard, resource-ID lint, gitleaks) is green.
* The generic skills and the AA overlay are merged, and the AA hook tests still pass.
* The R5 pilot log shows every pilot row of §5.9 met, and the pilot project is removed.
* The learning site lists the playbook course.

## Absorbed from [AA-1121](https://linear.app/aa-ecosys/issue/AA-1121/playbook-project-kit-v11-the-parts-v100-does-not-ship) (S285): project kit v1.1, the parts v1.0.0 does not ship

v1.0.0 of `project-template` (S282) shipped without nine parts of the design 5.4 tree and question table. Each is a new optional file or check, so it ships as a minor release without breaking generated projects.

1. Stop-open-work hook (generic; the AA hook reads AA plan files).
2. PII guard: a generic command-line guard.
3. API contract workflow.
4. UI smoke workflow (web projects only).
5. Shared UI kit components (v1.0.0 only names the kit path).
6. Database-backed settings registry and job store (SQL tables and the claim query already in migration 001).
7. Tenant-scoped pool and fair-share job gate (multi-tenant projects).
8. AI gateway core: one client with routing, fallback and caps.
9. A runnable UAT harness (v1.0.0 has only a README).

Done when (v1.1):

* Every row above ships in a minor release (v1.1.0, or v1.1.x as they land).
* The render matrix covers each new question or path.
* The leak scans stay at 0 findings.
* `copier update` from v1.0.0 applies with no conflict on an untouched project.
* `CHANGELOG.md` and `README.md` drop their "Not in this release" rows.

Source: `docs/implementation-notes/AA-1103.md`, section "Against design section 5.4: what v1.0.0 does not ship". Kit sources: `tools/project-kit/kit-sources.txt`.
