# AA-807 — [Data] Phase 1 foundation — per-app DB owner roles, migration ownership + byte-copy CI checks, nightly schema-drift job, Dead Table Registry, shared.countries ISO

## Problem

S235 data review: everything runs as master aa_cis_admin (BYPASSRLS) incl. DB Migrate for all owners; the tripplanner role was created out-of-band with IF EXISTS-guarded grants; no drift detection (223 had to capture hand-made objects); \~160 registered versions vs 217 CIS files; no ISO country table; Dead Table Registry file missing; migration Infra copies not CI-checked.

## Scope

* Owner roles per app (cis_owner/tp_owner/bk_owner or one migrator) used by DB Migrate; capture the tripplanner role in a migration; re-issue grants unguarded; revoke legacy grants (179 raw_tours, 180 tour_atoms) once catalog views exist.
* CI: each repo's migrations touch only its own schema; Infra CI checks byte-identical copies vs owner repo main.
* Nightly workflow dumps the live catalog, diffs against a DB built from all migrations, auto-commits db-schema-reference.md.
* docs/architecture/dead-table-registry.md + DRY RUN cleanup of acp_gold_output / acp_silver_s3 / acp_silver_s4 and confirmed legacy tables.
* shared.countries (ISO-3166) + v_countries / v_destinations contracts (unblocks [AA-679](https://linear.app/aa-ecosys/issue/AA-679/aaa-catalog-sync-from-cis-templates-activities-destinations-via), O7).

**What to build.** Add a job to `apps/AA-TripPlanner-Web/.github/workflows/ci.yml`, modelled on the Booking `test-integration` job:

1. **Database.** Start a `postgres:15` service as `aa_cis_admin`, which is the DB Migrate identity.
2. **CIS stubs.** Create minimal stubs of the CIS objects the tp migrations reference:
   - `shared.destinations`
   - `shared.schema_versions`
   - `shared.llm_call_log`
   - the roles the tp grants name, such as `booking` and `tripplanner`
3. **Replay.** Apply every `migrations/NNN_*.sql` in order, the same way `run_migration.py` does. Then apply them all a second time to prove they are idempotent.
4. **Assertions.**
   - Each file registers its `tp-NNN` key.
   - The grants on the `tripplanner` role are the expected ones.
   - If there is no database, the job must fail, not skip.

Then make the job a required check on TripPlanner main. A tp migration-only PR must not merge while the replay is red; otherwise it reaches the Infra copy and DB Migrate on the shared Dev RDS.

**Timing.** This must land before AA-712 X4 step 3, which adds the DROP migrations for the frozen tables and their 12 FKs.

- The replay job is green over tp-001..tp-010 on a PR.
- A deliberately broken tp migration on a throwaway branch turns it red.
