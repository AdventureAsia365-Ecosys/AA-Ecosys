## Problem

The S271 writing-quality audit listed 16 code-vs-code contradictions in T9 (root ADR 0020). [AA-1047](https://linear.app/aa-ecosys/issue/AA-1047/quality-w1-one-policy-registry-one-factsheet-one-exit-contract-report) part A (the writing policy registry, S272) closes the writing-policy ones. Two are gateway and route rules, not writing policy, and have no owner:

* **#13, retry ownership on** `token_budget`**.** The gateway retries a cut reply (S271, [AA-900](https://linear.app/aa-ecosys/issue/AA-900/llm-llm-operations-docs-prompt-versioning-and-eval-gate) W0). Some call sites also retry on their own. A cut reply can therefore be retried twice, with different ceilings, and billed twice.
* **#14, effort per provider.** The reasoning effort a stage sets (CIS 381, `t9_write` medium plus the low checks) is applied differently by each provider path (Anthropic API, OpenAI API, Bedrock Converse). The same stage gets a different effort, and a different token use, depending on which rung answers.

## Scope

* The gateway is the only place that retries a cut reply. Remove or forbid call-site retries on `token_budget`, with a guard test (AST or registry) that fails on a new one.
* One effort rule per stage, mapped explicitly for each provider kind. The route trace and the ledger record the effective effort.

## Done when

* A test fails if any call site retries on a cut reply. The live ledger shows at most one truncation retry per attempt over one T9 batch (a probe or a ≤3-piece run).
* For one stage, each provider path sends the mapped effort. Shown by a unit test per provider adapter, and live by the ledger effort column on a probe run.
