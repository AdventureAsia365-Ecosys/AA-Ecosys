# AA-716 — [A3] Raw-tour discontinuation cascade — trashing a source tour must inactivate its Master, drop its atoms, and warn the tenant

## Problem (found by live test, S209 03/10/2026)

[AA-713](https://linear.app/aa-ecosys/issue/AA-713/a3-atoms-follow-the-tours-master-content-status-inactivetrashed-tours) wired the **master_status → atom** direction (deactivate a Master tour → its atoms leave `v_active_tour_atoms` + ranking + routes; verified live). But the **upstream** link is missing: when a source tour is no longer supplied, trashing/deleting it in `silver_aa_internal.raw_tours` does NOT cascade.

Live test on China "1-Day Highlights of Xi'an" (reversible):
`PATCH /admin/tours/{id}/trash` → `raw_tours.source_status='trashed'`, `deleted_at` set. But:

* `published_tours.master_status` stayed **active** (expected: → inactive)
* its atoms stayed in `v_active_tour_atoms` (4) + `atom_ranking` (24) — still feeding segment/route/hub (expected: dropped)
* only `tour.source.trashed` fired, target_roles `[admin, content]` — **no tenant-facing notification**

Root cause: `trash_source_tour` / `restore_source_tour` (`api/routers/admin.py`) only flip `raw_tours.source_status`; they never touch `published_tours.master_status`, never call `_recompute_after_status_change`, and `v_active_tour_atoms` gates on `master_status` only (not on `raw_tours.source_status`/`deleted_at`).

## Desired business behaviour (Nghiệp, S209)

When a tour stops being supplied (raw trash/delete):

1. its Master Content tour becomes **inactive** (no sellable content),
2. its atoms are **hidden** and excluded from segment / route / hub — the system recomputes on the **remaining active tours**,
3. the affected **tenant(s) get a warning** that this tour is discontinued,
4. but tenants keep working normally with the still-active tours, and tour/content writing keeps producing good output from the recomputed (live-only) set.

Isolate the dead tour; never break the rest. Restoring the raw tour should reverse the chain.

## Scope

1. `trash_source_tour` (and hard delete, if any): also set the matching `published_tours.master_status='inactive'` (or trashed) in the same transaction, then `_recompute_after_status_change` (reuse [AA-713](https://linear.app/aa-ecosys/issue/AA-713/a3-atoms-follow-the-tours-master-content-status-inactivetrashed-tours) chain) so atoms leave the caches.
2. `restore_source_tour`: reverse — bring master back to active + recompute.
3. New tenant-facing notification (e.g. `tour.discontinued`) with `target_roles` including the tenant, for every tenant whose slate/pool used that tour. Must NOT touch their work with the other active tours.
4. **Dismiss the tour's pending** `review_queue` **rows** in the same transaction — a discontinued source tour must not remain an open review item (found live S212, 05/10/2026: trashing GLIMPSE OF BHUTAN / "Bhutan: Thimphu & Paro — 5 Days" removed it from the S1 ready-to-write list but left a `pending` review_queue row behind, because `trash_source_tour` only flips `source_status` + emits a notification). Restore does NOT auto-reopen a dismissed review row.
5. Tests: raw trash → master inactive + atoms absent from view/ranking/route + tenant alert emitted + no pending review_queue row for the tour; the rest of the platform unchanged; raw restore → fully reversed.

## Done when

Merge + CI + Dev deploy COMPLETED + live check on one tour: trash raw → master inactive, its atoms gone from view/ranking/route, tenant alert present, other tours intact; restore → back to baseline.
