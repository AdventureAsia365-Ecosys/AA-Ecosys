# AA-799 — [Security] /v1/pipeline — /run has no auth; review-queue approve/reject accept any tenant JWT

## Problem

Found by the S235 lane B agent while doing [AA-796](https://linear.app/aa-ecosys/issue/AA-796/portal-aa-770-compliance-for-t2-tenant-status-no-longer-derives-from); confirmed in code on main @666dfef.

* `POST /v1/pipeline/run` (`api/routers/v1_pipeline.py:243`) has no auth dependency: anyone who can reach the API can upload an Excel file and trigger a rewrite of up to 20 tours (LLM spend).
* `_get_tenant` (`v1_pipeline.py:337-351`) accepts the admin secret OR any valid JWT via plain `verify_jwt`, without checking the role. So a tenant JWT can call `GET /v1/pipeline/review-queue` (AA master review queue incl. `score_overall`) and `POST /v1/pipeline/review-queue/{id}/approve|reject` (`:433`, `:540`) — i.e. approve or reject Adventure Asia masters for export. `/execution/{id}` and `/sources` use the same dependency.

## Scope

* `/run`: require admin (or remove it if no caller remains — Step Functions retired in [AA-750](https://linear.app/aa-ecosys/issue/AA-750/infra-audit-the-7-cis-lambdas-with-0-invocations-in-30-days-confirm); check frontend/BFF and scripts for callers first).
* Replace `_get_tenant` on review-queue / execution / sources with an admin-only dependency (admin secret, plus the forwarded admin role where the BFF sends it). Tenants get 403.
* Guard test: every `/v1/pipeline/*` route rejects no-auth and tenant-JWT calls.

## Done when

* Merged + CI + Deploy Dev; live: `curl` without auth and with a tenant JWT → 401/403 on `/run`, `/review-queue`, approve, reject; admin path (BFF) still works on the admin review page.
