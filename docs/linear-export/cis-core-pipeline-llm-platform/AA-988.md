## Problem

The S1 catalogue rewrite ([AA-645](https://linear.app/aa-ecosys/issue/AA-645/eval-claude-sonnet-5-for-writer-stages-t2-generate-t8-angle-gen-t9), Done 25/10/2026) re-atomized all 892 active tours on writer v2. Atoms are current (892/892 tours, 25,877 active atoms, 0 tours whose atoms are older than the Master text), but the layers built on atoms did not all follow. Measured on Dev 25/10 (read-only, S251):

* Only 16,873 / 25,877 active atoms (65%) belong to a segment (`acp_contract.atom_segment_member`).
* 18,978 segments exist, 10,400 hold an active atom: **8,578 orphan segments** from replaced atoms.
* 82 hubs; **700 / 892 tours have a current route** (`acp_contract.route`, `superseded_at IS NULL`); 3 current routes are older than their atoms; 0 routes point at a dead segment.
* Ranking: 883 tours have current rows, 0 rows on dead segments (9 tours missing).

## Scope

1. Run segment match (`a3_segment_match` path) for the \~9,000 active atoms without a segment; paid calls in subsets (≈3 tours, then ≤50, then by country) with cost from `shared.llm_call_log`.
2. Orphan segments: DRY RUN count → delete or archive per `skill/aa-cis-schema/references/destructive-ops.md` (segments with no active atom and no route/ranking reference); merge duplicates the new atoms created.
3. Routes: build for the 192 tours without one, rebuild the 3 stale ones; add hubs when new segments need them.
4. Ranking for the 9 tours without current rows; recompute questions/contested on new segments.
5. Same wave mechanics as [AA-645](https://linear.app/aa-ecosys/issue/AA-645/eval-claude-sonnet-5-for-writer-stages-t2-generate-t8-angle-gen-t9) (no merge/deploy while jobs run, RDS snapshot before destructive steps).

### 2026-10-27 07:24 — nghiep pham quoc

S253 close: root-cause fix, repair and re-measure (Dev, 27/10/2026)

**Root cause** (confirmed on Dev with a read-only replay of the matcher): `_mint` hashes place | verb | country only, which is coarser than the join rule. Two Segments that never join could therefore get the same id, and `reconcile_ids` silently kept only one of them. Example: "Hutong / walk through …" and the existing "the Hutong / stroll through" both minted `cf8f846e8ae2fd08`. 227 forming atoms in 157 tours had no member row this way. A tour-scope recompute of the Hutong tour reproduced the drop.

**Fix**: CIS #1060 (`9a5d0aeb`, deployed: api :856 / worker :422, `/health` 200).
- Contested ids (shared by two derived Segments, or a pool pseudo's stored id) are re-minted with a more specific hash.
- `reconcile_ids` raises on duplicate ids.
- `run_segment_matching` asserts that each forming atom is in exactly one written Segment; otherwise the transaction rolls back.

Non-colliding ids stay byte-identical (golden test). Review by two independent agents found 2 more cases from the same root cause; both are fixed with tests. 229 tests.

**Repair**: `run_segment_matching` per tour, 155 tours, 0 failures, then one platform recompute scoped to their 3,260 Segments (job `e4bbfe63`, succeeded). No tour-scope recomputes were run, since those re-rank every market.

### 2026-10-27 07:28 — nghiep pham quoc

S253 follow-up: reverse-case glue left by the old id collision is now cleaned.

The old bug had a second face. When the colliding atom sorted first, it was glued into an unrelated existing Segment and took its id. A read-only audit found **104 member rows in 62 Segments** with that signature: the Segment id equals the member's own mint, but the label's mint differs. Examples: "Negombo / have dinner" sat in "the hotel / eat breakfast", and "Tiger's Nest / hike" sat in "Paro / stroll". The fixed matcher keeps an atom's prior assignment, so a rerun alone never moves these.

Steps (cis_app, `.tmp-session/S253/aa988_unglue.py`):
1. Deleted exactly those 104 member rows in one transaction, guarded by the count.
2. Re-ran `run_segment_matching` (CIS #1060 code) for the 91 tours, one at a time: **0 failures, 104/104 atoms placed**.
3. Enqueued one platform recompute for the 98 old and new Segments (job `ca206703`).

44 atoms went back to the same id. In each case the Segment held only glued atoms, so it was empty after the delete, and the rematch relabelled it after its own atoms. That is correct.

39 rows still match the signature. They are not collisions any more: the current join rules put them there (a Jev same-place verdict, or a transitive join).
- Most are right: "Yala National Park" in "Yala", "Karni Mata Temple" in "Rat Temple", "Panda Breeding Centre" in "Panda Center".
- A few look doubtful: "Tina's Guesthouse / lunch break" in "Lijiang / morning flight", and dinner joined with breakfast at the same residence.

Those few are join-rule quality (AA-695 territory), not this bug.
