# AA-758 — [A3/Route] Hub assignment broken — routes collapse onto 14 hub_ids, 862-on-one, 405 orphan hubs

## Problem

Found in the S228 data-quality audit (read-only). In `acp_contract.hub` / `acp_contract.route` on Dev:

* 419 hub rows exist, but **only 14 distinct** `hub_id` **are referenced by live routes** (superseded_at IS NULL). **405 hubs are orphans.**
* Of 1,331 live routes, 945 carry a hub_id but they collapse onto those 14, and **one single hub_id holds 862 routes** (`Lingshi basin → Doupchu La Pass → …`, a Bhutan trek). 386 routes have hub_id NULL.
* `route.hub_name` is distinct across \~400 values — so the per-route name looks right, but `route.hub_id` is pinned to a tiny, wrong set.

## Root cause (code)

`services/acp_contract/route_detection.py::run_route_detection()` — the hub-reuse matcher scored tour-set overlap as `|member ∩ old| / min(|member|, |old|)`. When an old hub covers only ONE tour, `min = 1`, so any family that merely shares that one tour scores `1/1 = 1.0 ≥ SHARED_ENOUGH (0.3)` and greedily reuses that unrelated hub. With a strict `>` tie-break, the first hub to hit 1.0 wins for every family → one hub absorbs hundreds of routes. Secondary: `INSERT INTO acp_contract.hub (hub_name)` has no unique key / ON CONFLICT, so every rebuild that doesn't match mints a fresh UUID for the same journey name → orphan accumulation.

Hubs are deterministic (no Jev), so this is a pipeline bug independent of the Jev calibration audit.

## Fix (PR, this issue)

* Overlap = **Jaccard over the union** (`|∩| / |∪|`), which only clears SHARED_ENOUGH on genuine overlap. Deterministic tie-break (ratio, absolute overlap, hub_id). Extracted `best_hub_match()` as a pure function with regression tests (`tests/unit/test_aa757_hub_match.py`, 8 tests + 30 existing route/hub tests green).
* Before minting a new hub, reuse an existing same-named free hub row → stops orphan duplicate accumulation across rebuilds.

## Done when

* PR merged + deployed to Dev.
* A route-detection recompute run on Dev, then verify: no single hub_id holds a disproportionate share of routes, orphan-hub count drops sharply, hub_id/hub_name back in sync. (The recompute is a platform-wide write — run deliberately, confirm with Nghiệp.)

Found + fix in `docs/audits/2026-10-11-S228-jev-aseries-closeout.md` (Part 5).
