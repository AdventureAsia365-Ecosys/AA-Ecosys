## Scope

1. infra/AA-CIS-Infra: rebase Infra PR #105 (aa-workforce + aa-external pools, app clients incl. breakglass, groups, WAF web ACL, Lambda triggers, domains; no Google IdP on the workforce pool; Facebook IdP disabled), merge, apply.

4. Evidence in docs/audits/. Point apps/AA-CIS-App/CONTEXT.md and docs/ecosystem-architecture.md at the Cognito target.

Out of scope: CIS, Booking and TripPlanner app code ([AA-816](https://linear.app/aa-ecosys/issue/AA-816/admin-staff-user-management-ui-createdisable-staff-roles), [AA-680](https://linear.app/aa-ecosys/issue/AA-680/aaa-identity-customer-otp-auth-shared-with-tripplanner-staff-rbac), [AA-813](https://linear.app/aa-ecosys/issue/AA-813/portal-tenant-user-accounts-invite-users-roles-ownereditorviewer-api)); Google/Facebook IdPs on the external pool.

## Done when

* `aws cognito-idp list-user-pools --max-results 10 --profile aa365-admin --region us-west-1` lists aa-workforce and aa-external.
* A test staff user receives an email code and signs in on Dev through the workforce managed login (screenshot + decoded token showing cognito:groups).
* A workforce user with no staff group is denied by the pre token trigger.
* Self sign-up on the workforce pool is rejected.
* Break-glass signs in end to end (password + TOTP), the token-issue alarm fires, and the user is disabled again afterwards.
