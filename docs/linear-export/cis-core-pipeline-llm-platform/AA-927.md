## Problem

The [AA-729](https://linear.app/aa-ecosys/issue/AA-729/eval-golden-set-100-samples-from-existing-data-scoring-script-for) baseline (S245, 20/10/2026) compared the in-process LLM call counter with the rows in `shared.llm_call_log`:

* Score-only run 8f07b98f: 216 calls were made, 100 were logged.
* Regenerate run dab254c4: 815 calls were made, 627 were logged.

The dollar totals are close: $0.214 in-process vs $0.215 logged, and $5.00 vs $5.19. So the missing rows may be cheap calls (embeddings, Jev cache hits, shadow calls), or calls logged under another key. Each paid call must be traceable ([AA-635](https://linear.app/aa-ecosys/issue/AA-635/be-llm-call-log-under-reports-bedrock-spend-vs-aws-bill-acc1-99percent) rule), and unlogged calls also hide from the cost report ([AA-896](https://linear.app/aa-ecosys/issue/AA-896/finops-finops-doc-cost-anomaly-detection-and-the-monthly-cost-report)).

## Scope

1. Classify the unlogged calls in both runs by stage and call type: which `LLMClient` path skips `record_call_*`, and whether the [AA-729](https://linear.app/aa-ecosys/issue/AA-729/eval-golden-set-100-samples-from-existing-data-scoring-script-for) `evalpatch` relabel drops rows.
2. Fix every path that makes a billable call without a log row. If a call type is deliberately not logged (for example a cache hit with no provider call), document it and exclude it from the counter.
3. Add a unit test that fails when a new `LLMClient` call path skips logging.

## Done when

* A rerun of the [AA-729](https://linear.app/aa-ecosys/issue/AA-729/eval-golden-set-100-samples-from-existing-data-scoring-script-for) score-only mode shows logged rows equal to billable calls (run id cited).
* CI green, deployed, live check per aa-ship.
