## Why

Once the A/T v2 redesign and the Model Gateway / job runner work settle, redraw the architecture for the whole ecosystem and for each repo using official AWS Architecture Icons, and bring the written documentation up to date with it. Today the architecture only exists as prose (`docs/ecosystem-architecture.md`, each repo's `CONTEXT.md`, `docs/architecture/ecosystem-review-2026-09.md`).

**Timing:** after the clean rerun ([AA-653](https://linear.app/aa-ecosys/issue/AA-653/p2-at-flow-sync-audit-clean-rerun-runbook-bhutan-pilot-wave-jev-in)), when the architecture is stable. Not before, or the diagrams go stale immediately.

## Tooling (recommended, S204)

Diagrams as code, versioned next to the docs they illustrate:

1. **Python** `diagrams` **(mingrammer), via the AWS Labs Diagram MCP server** (`awslabs.aws-diagram-mcp-server`). It ships official AWS icons and outputs PNG/SVG from a `.py` file kept in git. Claude Code can generate and edit it directly. Main tool for the AWS deployment views.
2. **TerraVision** (reads Terraform, draws with AWS icons). Used to cross-check the hand-written infra diagram against `AA-CIS-Infra` and catch drift. Not the source of truth.
3. **C4 levels (Context / Container) in Mermaid or Structurizr** for the ecosystem and app-internal views, where AWS icons add nothing (LangGraph stages, A/T pipeline, Jev decision seam).
4. Optional: [**draw.io**](<http://draw.io>) with the AWS 2025 shape library, only for a polished one-off deck for Ms. Thư / partners.

## Scope

* **Ecosystem (root repo):** 3 CIS accounts (acc2 infra, acc3 LLM primary, acc1 fallback), how the apps share RDS (schema ownership), the Model Gateway plus external APIs (Bedrock, OpenAI, TypeSafe Jev, DataForSEO, Mapbox, Cohere), Vercel frontends, API Gateway → ECS, S3 bronze, Lambdas, AA-Booking once it exists.
* **AA-CIS-Infra:** network, ECS service/task, RDS, API GW, Lambdas + schedules, IAM cross-account roles (AA3-Bedrock-Invoker), Secrets Manager, Terraform roots per account.
* **AA-CIS-App:** container view (API, job worker inside the API task, admin UI / tenant portal on Vercel), A0–A4 / T0–T11 pipeline flow, Jev `decide()` seam, cost/budget guard, data flow per schema.
* **AA-TripPlanner-Web:** Next.js FE, 2 Lambdas, Tour Graph, locate/Mapbox, reads CIS RDS.
* **Documentation:** each diagram is linked from the repo's `CONTEXT.md` and `ecosystem-architecture.md`. English. Sources under `docs/architecture/diagrams/` (the `.py` / `.mmd` files plus rendered SVG).

### 2026-10-28 14:11 — nghiep pham quoc

S255 (28/10) findings, to plan this for S257. The tech lead asked again for diagrams that use the real AWS icons, after seeing the plain Mermaid system diagram on `/admin/docs`.

**Checked today**
1. **Mermaid `architecture-beta` + an icon pack works inside the docs reader's safety model.**
   - Setup: mermaid 12.2.0 (the CIS version) plus `@iconify-json/logos` (65 AWS service icons) registered with `mermaid.registerIconPacks`.
   - Rendered under `securityLevel: strict`, then DOMPurify's SVG profile: 0 `foreignObject`, no outside reference (`svgIsSelfContained` true).
   - The prototype draws our stack with AWS-style icons: CloudFront, API GW, Fargate, Lambda, RDS, S3, Cognito, VPC, IAM. Source and screenshot are in root `docs/audits/2026-10-28-S255-aa697-aws-icons/`.
   - Limits: the layout is automatic (edges cross groups, labels overlap lines); there is **no Bedrock icon** in that pack; edges have no labels.
2. **The docs reader shows no images today.** `MarkdownView` renders `![…]` as the text `[image: …]` because there is no image store and remote images would leak the viewer's IP. An SVG made by `diagrams` / draw.io therefore cannot be shown until the reader can serve an SVG from the docs bundle.

**Proposed plan (replaces the S204 order where they differ)**
1. **Main AWS views:**
   - Draw them in Python `diagrams` (mingrammer), via `awslabs.aws-diagram-mcp-server`. It uses the official AWS Architecture Icons, Bedrock included, and lays out with Graphviz.
   - Sources go in `docs/architecture/diagrams/*.py`. The Docs sync workflow renders them to SVG in CI and ships them in the docs bundle.
2. **Reader support:**
   - CIS `MarkdownView` shows an image only when it is a relative `.svg` inside the bundle, fetched through the same docs API.
   - It gets the same DOMPurify SVG profile and the `svgIsSelfContained` check as Mermaid; anything else stays `[image: …]`.
3. **Quick inline diagrams:**
   - Mermaid `architecture-beta`, with `@iconify-json/logos` bundled as a lazy chunk (never fetched from a CDN).
   - A small custom pack fills the gaps: Bedrock and any other missing service, built from the official AWS Architecture Icons package (AWS allows them in architecture diagrams).
   - Also wait for `document.fonts.ready` before drawing; this fixes the mid-word wraps seen in S255.
4. **Keep:** TerraVision as the drift cross-check against `AA-CIS-Infra`; C4 / Mermaid flowcharts for non-AWS views.

**Scope update:** acc1 is gone (AA-998). Accounts are acc2 (infrastructure) and acc3 (LLM); add AA-Booking and AA-Partner (CRM + Content studio) to the views.

**Timing:** the architecture is stable after AA-998 and AA-979. Proposed slot S257, after the S256 list.
