## Problem

[AA-1040](https://linear.app/aa-ecosys/issue/AA-1040/kit-ai-notice-and-machine-readable-ai-content-marking-across-apps-eu) shipped the AI notice and machine-readable marks on the main surfaces. The S286 gap analysis found three channels still without a verified mark, and the AA platform does not get the transition period to 02/12/2026: that period covers only systems placed on the EU market before 02/08/2026. The first agency post published in the EU is in scope.

* WordPress publish: the mark is not verified on a live post.
* Facebook and plain-text exports: no machine-readable mark.
* TripPlanner planning chat: no row in the AI Use Register.

## Decision (tech lead, S286, D2)

Work in parallel; it does not block the pilot. A lawyer confirms the application date and scope later (with D6).

## Scope

* Add the mark to the Facebook and plain-text paths (visible disclosure line + machine-readable metadata where the channel allows it).
* Verify the WordPress mark on one live test post (test WP site).
* Add the TripPlanner chat row to the AI Use Register and check every LLM route in `shared.llm_role_config` has a register row (a test fails on a missing row).

## Done when

* One live post per channel (WordPress test site, Facebook test Page, a plain-text export) shows the disclosure and the machine mark (screenshots).
* The register test is green and lists every live route.
