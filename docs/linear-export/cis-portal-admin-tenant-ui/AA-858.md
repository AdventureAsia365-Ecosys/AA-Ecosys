## Problem

Ms. Thư asked (16/10) whether AWS has Grafana-like monitoring ("how many requests, how many errors…"). The data exists but is spread over technical places: CloudWatch alarms/metrics, Logs Insights, WAF logs, per-app budgets ([AA-828](https://linear.app/aa-ecosys/issue/AA-828/dataops-per-app-cost-allocation-tags-budgets-for-the-data-platform-rds)), the LLM spend e-mail, and admin pages. There is no single business-readable view she can open without AWS console access.

`/admin/overview` ([AA-664](https://linear.app/aa-ecosys/issue/AA-664/admin-overview-dashboard-whole-system-view-pipeline-a0a3-intelligence), Done) already shows: pipeline funnel per country, intelligence counts, tenants (active, rewrites / pieces / published 7d), jobs 30d, cost today and month-to-date vs budget, alerts. Detail pages exist: `/admin/llm-usage` (AI cost by account), `/admin/platform-stats` and `/admin/tenant-activity` (tenant content), `/admin/jobs`. **Do not build a second dashboard**; extend `/admin/overview`.

## Scope (final list after Ms. Thư picks her priorities)

1. **TripPlanner customers:** visits (Vercel Web Analytics), searches, trips built, "send to advisor" inquiries per day.
2. **Booking funnel:** inquiries → trip cases → proposals sent → confirmed, per week.
3. **System health per app** (CIS API, TripPlanner Lambdas, Booking API): requests, error rate, p95 latency, throttles — read from CloudWatch through a cached backend endpoint (no AWS console needed).
4. **Cost per app per day:** AWS by the `App` tag (Cost Explorer, cached daily) + AI spend from `shared.llm_call_log`.
5. Plain business wording, links into the existing detail pages; read-only for staff roles.
