# AA-760 — [Portal] Page-by-page audit + state fixes — statuses from the job, never inferred from rows ("Writing…" bug)

Split from [AA-670](https://linear.app/aa-ecosys/issue/AA-670/portal-information-architecture-page-by-page-ui-audit-fix-inconsistent) (S229). Runs after the PortalShell sub-issue, with real data from the 4 [AA-741](https://linear.app/aa-ecosys/issue/AA-741/t-series-audit-end-to-end-t0t11-test-run-on-controlled-tenants-per) brand tenants.

## Root cause already found (S229)

"Writing…" forever: `PoolTab.tsx` derives the badge on the client from `status==='pending' && edit_source==='ai_generated'`, ignores `job_status`, and never polls. A failed / cancelled / budget-stopped rewrite shows "Writing…" forever. `CatalogTab` already does it right via `catalogApi.isAiWriting/isRewriteFailed` + react-query `refetchInterval`.

Other state issues found: `AngleGateWizard` polls with `setInterval` + async callback (overlapping requests, stops at 180 s and shows "still writing"); shell `catTotal` badge stale after background completion; `my-versions?page_size=200` truncates for large tenants (needs server-side paging like [AA-718](https://linear.app/aa-ecosys/issue/AA-718/admin-ui-master-content-page-fix-5-dataux-bugs-redesign-for-a)).

## Work

* One status model for tenant-visible work (queued / writing / checking / done / failed + Retry), read from `shared.job` via the API, shared by tours and pieces.
* react-query `refetchInterval` while active, stop on terminal ([AA-719](https://linear.app/aa-ecosys/issue/AA-719/review-queue-ui-bulk-regenerate-non-blocking-regenerate-ui-freezes-no) pattern).
* Checklist per page (desktop 1440 + mobile 400, light/dark): states, empty, loading skeletons, labels, layout, dead links, a11y basics (landmarks, labels on icon buttons, contrast).
* Before/after screenshots in the PR.

## Done when

Checklist green for every portal page; no client-inferred job status left; smoke covers each page.
