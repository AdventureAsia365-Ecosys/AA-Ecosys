# AA-819 — [AUP 2026-11] Tenant AI notice at review/publish, T9 guard against reviews/testimonials/first-person-customer copy, per-tenant daily publish limit

## Problem

Anthropic Usage Policy effective 12/11/2026 (AWS Health notice for Bedrock acc3 786888028788) expands "Do Not Engage in Deceptive Campaigns or Artificial Activity": fake personas/reviews, astroturfing, concealed sponsorship, networks of fake outlets, spam/coordinated inauthentic behaviour, and seeding search engines/AI with content misrepresenting origin or authorship. T-series content (T2 rewrites, T9 blog/LinkedIn/Facebook) is published by tenants under their own names. Review: AA-Ecosys docs/audits/2026-10-14-S236-design-review/aup-2026-11-review.md (S236).

## Scope

1. Portal: one line at T10 review and T11 publish/export — "This content was generated with AI. Review it before publishing; you are responsible for what you publish." No gates, scores or flags exposed (tenant-sees-content-only rule).
2. T9 writer + gate: never write reviews/testimonials, never write as a customer/traveller in first person, never claim independence; deterministic check + prompt rule.
3. Per-tenant daily publish limit (configurable, default proposal 20/day) with publish_log as evidence; admin can see/override.
4. TripPlanner: confirm the AI badge shows on every AI-generated text block (mobile, share/export).
   Out of scope: legal Terms (separate issue).

## Done when

* On Dev: notice visible in portal review/publish (screenshots); a T9 test piece prompted toward a testimonial is blocked/rewritten (gate evidence); the 21st publish of a day returns a clear limit error; TripPlanner badge audit screenshots.
