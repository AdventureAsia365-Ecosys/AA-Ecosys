## Problem

ADR 0019 d3–d5 (S265, root `docs/adr/0019-b2b-only-ecosystem-model.md`, record `docs/audits/2026-11-03-S265-ecosystem-restructure/`) moves AA to a B2B-only operating model, which needs clear staff roles and scoped access. Today the staff POLICY has admin / content / reviewer and no way to give a manager only their own tenants.

## Scope

* **Roles.** New staff roles `content_lead`, `tenant_qa`, `customer_success`, `support`, `finance` and `ai_ops`; `reviewer` merges into `content` (fix `admin_users_email_chk` and `staff_app_grant_role_chk`). These are CIS migrations; Infra adds the Cognito group `booking-finance`.
* **Tenant scope.** `shared.staff_tenant_assignment` + a central `require_tenant_scope` dependency. A customer_success manager sees only their tenant book; admin sees all; support works from a pooled queue. Covered by a CI test and an isolation probe.
* **Assignments page** in the Tenants group.
* **Read-only view-as tenant.** 60 minutes, reason/ticket required, banner, logged in `shared.staff_view_as_session`.
* `ai_ops` **read in Writing Lab.** `tenant_content.read`, Lab pages only, every view logged (tech lead decision, S265).
* **Role table and permission matrix:** `clarifications.md` §2.

## Done-when

* Deny-by-default test, role × route, is green.
* Live on Dev:
  * a customer_success E2E user sees only the assigned tenants (403 on another tenant);
  * view-as opens read-only with a banner and an audit row;
  * an `ai_ops` user reads tenant text only in Lab, and the read is logged.
* Independent review before merge (auth change).
