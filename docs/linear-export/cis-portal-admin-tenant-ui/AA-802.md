# AA-802 — [T2/T9] Silent correction — a held piece repaired by admin/AI updates the tenant's unpublished copy (version history, no flags shown)

## Problem

[AA-770](https://linear.app/aa-ecosys/issue/AA-770/t2t9-tenant-always-receives-the-content-no-heldblocked-state-scores-or) rule (Nghiệp, reconfirmed S235 14/10/2026): the tenant always receives the content; gates/held/flags are admin-only. A held piece (e.g. an F9 product-truth sentence left after the last attempt) is therefore delivered as-is, and today an admin fix does not reach the tenant's copy.

## Scope

* Admin Content Quality: when an admin applies Cut/Rewrite/Edit ([AA-769](https://linear.app/aa-ecosys/issue/AA-769/admin-content-quality-tab-on-adminatom-curation-every-tenants-t2-tours)) or an AI repair re-passes the gates on a held piece, write a new version of the piece; if the tenant has not published/exported it yet, the tenant's view switches to the new version silently (no flags, no scores); version history kept for audit.
* If already published/exported: show the admin that the tenant has an older copy; optional neutral notice to the tenant ("an updated version is available") — no gate wording.
* Same for T2 tour versions (needs_review → repaired).

## Done when

* Repair on an unpublished held piece → tenant API returns the repaired text; history has both versions; tenant responses still contain no gate/score keys ([AA-796](https://linear.app/aa-ecosys/issue/AA-796/portal-aa-770-compliance-for-t2-tenant-status-no-longer-derives-from) key-walk test).

### 2026-10-15 11:50 — nghiep pham quoc

**Scope addition (S238 backlog audit): latest-piece rule on every tenant read** (S237 UI verify D1).

**Problem.** `GET /v1/publish-log/pending` (`v1_publish.py::list_pending`) returns every approved or held `content_piece` that has no published or requested `publish_log` row. Older versions of the same piece therefore show up as separate cards:
- **atlas-hearth:** T11 Ready to Publish shows 46 cards with only 3 unique titles. One title, "Where Two Worlds Meet…", appears 20 times. My Content shows 5.
- **terra-family:** the same pattern.

My Content already applies the AA-497 rule: `DISTINCT ON (angle_gate_request_id)`, keeping the latest `created_at`.

**Fix.** Apply the same rule to `/pending`. Superseded pieces, earlier attempts and older admin/AI-repaired versions must never appear as publishable. The repaired version from this issue should be the only card.

**Extra Done-when:**
1. For atlas-hearth and terra-family, the T11 count equals the number of My Content items with no live publish, and no `angle_gate_request_id` repeats.
2. After a repair on an unpublished held piece, `/pending` returns only the new `piece_id` for that request.
3. An integration test on real Postgres, with 3 pieces under one request, asserts both of these:
   - `/pending` returns 1 row, the latest piece;
   - a request whose latest piece is published returns 0 rows.
