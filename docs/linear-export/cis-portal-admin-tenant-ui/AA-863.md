# AA-863 — [Admin] Show the Slate seed place and country next to each Subject and T9 piece

Split from [AA-857](https://linear.app/aa-ecosys/issue/AA-857/slatea3-tenant-picks-a-subject-but-the-post-is-about-another-place), scope item 4 (closed S239).

## Problem

The Slate seed (the member atom a Subject is written from) now comes from `subject_seed.choose_representative`, so a Subject is only offered when a member on the tenant's own tours matches its place in one country. Admins still cannot see which place and country a Subject or a T9 piece was seeded from. A wrong-place post can only be found by reading the text.

## Scope

* Content Quality and the atom-curation tabs show the seed atom's place and country, and the Segment label, next to each Subject and each T9 piece. For a piece, use `angle_gate_request.atom_id`, the frozen seed.
* Flag rows where the seed place does not match the Subject place under `match_grade`, or the seed country differs from the Segment's country.
* Admin only: tenants see content only.

## Done when

On Dev, the admin pages show seed place and country for Subjects and pieces. A mismatch row shows the flag (screenshots at 1440 and 390, light and dark).

Done (S241, 17/10/2026). AA-CIS-App PRs #787 (`748c12c`), #789 (`cafd13a8`) and #790 (`a439085a`) are merged and deployed to Dev (ECS api :658 / worker :215, then the follow-ups).

**What changed**
- `services/acp_shared/seed_audit.py` adds a `seed` object to three admin endpoints: `GET /admin/content-quality/pieces[/{id}]` and `GET /admin/dashboard/slate`. The object holds:
  - atom_id, place, country, and source (`request` = frozen `angle_gate_request.atom_id`, or `computed`);
  - segment label and Segment countries;
  - flags `place_mismatch`, `country_mismatch` and mixed Segment.
- The place check reuses `subject_seed.match_grade`. The Route anchor rule moved to `choose_route_anchor`, with the same behaviour.
- Reads are set-based: 4 per page, nothing per row.
- A test guards that only the admin routers import it.
- UI: `SeedLine` in the Content Quality Title cell and drawer ("Slate seed" section), and a "Seed (place · country)" column in the atom-curation Slate tab (sortable, filter "mismatch").

**Live evidence on Dev**
- API: Content Quality has a seed on 200/200 pieces; 35 are flagged (34 place, 1 place + country). Slate has a seed on 342/342 rows across 4 tenants: Atlas & Hearth 89/1 flagged, Terra Family 90/4, Trail Pulse 76/1, WildKind 87/2.
- Example flag: Segment "Paro — stroll" with seed "Tiger's Nest Monastery · Bhutan" is marked **PLACE ≠ SUBJECT**.
- UI (Playwright, 1440 and 390, light and dark):
  - The Title cell shows the Segment, the seed and the badge.
  - The drawer has the Slate seed section.
  - The Slate tab shows the seed column. Sorting moves the mismatch row (Pawangka Monastery · China) first, and the filter leaves 1 row.
  - 0 console errors and 0 non-2xx.
- The 390 overflow in the Slate tab is fixed in #789. It already existed, and the Seed column added about 226 px of min-content. Now only the table scrolls: `.aa-admin-main` is 390/390 with scrollLeft 0.
- Screenshots: root `docs/audits/2026-10-17-S241-ui-verify/admin-seed/`, `reverify-789/`, `reverify-790/`.

**Product note:** the place flag is literal. Tiger's Nest is near Paro, but `match_grade` has no alias for it, so it is flagged. This is a review cue, not an error.
