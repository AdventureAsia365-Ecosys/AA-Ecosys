## Problem

Tenants can connect a Facebook Page in the portal ([AA-815](https://linear.app/aa-ecosys/issue/AA-815/portal-facebook-connect-ui-tenant-self-unpublish-wire-existing), CIS [AdventureAsia365-Ecosys/AA-CIS-App#731](https://linear.app/aa-ecosys/review/feat-portal-facebook-page-connect-tenant-unpublish-that-removes-the-18424e6a51d0)). The connect card's help text is wrong and incomplete:

* `apps/AA-CIS-App/frontend/app/(tenant)/portal/_components/FacebookConnect.tsx:97-101` names only `pages_manage_posts`. The S237 round trip needed all three permissions: `pages_show_list`, `pages_read_engagement` and `pages_manage_posts`.
* It does not say that the Meta app must be in Live mode. Posts made with a Development-mode app are visible only to app roles; a logged-out viewer sees "This content isn't available".
* It does not explain how to get a long-lived Page token.
* It renders "pages_manage_postspermission" with no space (S237 UI verify D5).

A tenant who follows this text ends up with a token that lacks permissions, or with posts the public cannot see.

On Jira PR-7 we promised Ms. Thư a written Facebook connection guide for tenants. The guide does not exist yet.

There is also a coverage gap in testing. The S237 test cloned a LinkedIn piece to channel='facebook', because no Dev tenant plan produced a Facebook piece. A Facebook piece made by normal T8/T9 planning has never gone through T11.

## Scope

1. Rewrite the connect-card help text in `FacebookConnect.tsx`. It must:
   * name all 3 permissions, rendered with correct spacing;
   * state that the Meta app must be in Live mode;
   * say how to get a long-lived Page Access Token;
   * say where to find the Page ID.
     Keep it short, and link to the guide.
2. Write a tenant-facing guide, "Connect your Facebook Page", with screenshots from the Live-mode run.
   * Steps: create or choose a Meta app → switch it to Live (privacy policy URL) → generate a Page Access Token with the 3 permissions → exchange it for a long-lived token → find the Page ID → Test & Connect in the portal.
   * Common errors to cover: invalid or expired token, missing permission, posts visible only to admins.
   * Tenants must be able to open it from the connect card (portal help page or linked doc).
3. Confirm that normal T8/T9 planning produces a channel='facebook' piece for a tenant whose channels include facebook. Then publish and unpublish that piece through T11, with no cloning. If the planner never emits facebook, record that and open a follow-up issue.
4. Draft the PR-7 Jira reply that delivers the guide. Nghiệp approves it before it is posted.

Out of scope: the Live-mode round trip itself. Nghiệp confirmed in S238 that it is done and reported on PR-7.
