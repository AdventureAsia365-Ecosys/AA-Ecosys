# AA-882 — [Admin] Server-side staff authorization: capability map, require_perm, route-policy CI

## Problem

S241 P0-5/P1-3: the backend checks only the shared admin secret and trusts the role header sent with it, so any staff role can call money/model write routes; role checks live only in the BFF. GĐ −1 (unauthenticated `/admin` routes closed + route-auth CI guard) shipped in CIS [AdventureAsia365-Ecosys/AA-CIS-App#791](https://linear.app/aa-ecosys/review/fix-tighten-auth-on-admin-and-staff-routes-add-route-auth-ci-guard-70c1c2c49eb2) (live 17/10: anonymous calls 403).

## Scope

1. GĐ1: `api/core/staff_authz.py`: one `ROLE_PERMS` capability map shared with `lib/rbac.ts`, `POLICY` keyed by (method, route template), `staff_policy` dependency; machine principal (secret without role) limited to the CI smoke/preflight and Lambda scheduler paths. Apply to LLM config/catalog/Jev writes, budgets, job-runner cancel/retry/retention, decisions, settings writes.
2. GĐ3: remaining `/admin` routers, `/v1` routes the BFF calls with the secret, tenant-proxy staff branch; route-policy test moves from report-only to enforcing.
3. `staff.write` owner-only: Nghiệp + one emergency account (Q2). Per-app roles in a grants table (person, app, role) (Q3) via ADR 0006 amendment.
4. Header trust ends with Cognito Phase 1 ([AA-854](https://linear.app/aa-ecosys/issue/AA-854/identity-phase-0-apply-cognito-pools-infra-105-break-glass-account)/[AA-703](https://linear.app/aa-ecosys/issue/AA-703/auth-identity-epic-adr-0006-cognito-workforce-external-pools-email), done in parallel with X1).
