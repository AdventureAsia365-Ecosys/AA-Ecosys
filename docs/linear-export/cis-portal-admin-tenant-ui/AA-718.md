# AA-718 — [Admin UI] Master Content page — fix 5 data/UX bugs + redesign for a professional, commercial-grade catalog view

Found S209 (03/10/2026) while running the China rerun. The Master Content admin page has several data/UX bugs; it also needs a redesign because it will be the template for the future tenant-facing page.

## Bugs to fix

1. **“Pipeline Runs” stat stuck at 20.** The header count reflects the length of a list that is already `ORDER BY started_at DESC LIMIT 20` (`api/routers/admin.py` tenant/master detail). So once there are ≥20 runs it always shows 20. Fix: a separate `COUNT(*)` (unbounded), or relabel to “last 20 runs”.
2. **Total LLM Cost is all-time and unlabelled.** `SELECT SUM(cost_usd) FROM shared.llm_call_log WHERE tenant_id=… OR tenant_id IS NULL` with no time window → it sums the entire history ($55.3094 now), which is not actionable. Fix: scope to a window (this month / last 30d) with a clear label, and/or a small time toggle. Should reconcile with the External Spend page.
3. **Recent Pipeline Runs status always “INGESTING”.** Rows show processed 72/80/136 but passed 0 and status `ingesting` — these are old runs whose `pipeline_runs.status` was never advanced to a terminal state. Fix: either backfill/age-out stuck runs to a terminal status, or derive display status from actual completion (tours_total vs tours_passed + end time) instead of the raw stuck column. `passed 0` also looks wrong and needs checking.
4. **No column sorting.** TOUR NAME / COUNTRY / SCORE / VERSION / STATUS are not sortable; backend returns a fixed `ORDER BY published_at DESC LIMIT 200`. Fix: sortable headers (server-side sort + paging, since 200-row cap already hides rows — the list says “12 of 193”/filtered).
5. **Avg Quality stat ignores the active filters.** The header Avg Quality (7.7) is computed over the whole catalog, not the current country/status/score filter (e.g. when filtered to China). Fix: recompute the summary stats against the same filter set as the table so the number matches what the user is looking at.

## Redesign guidance (see my design note — to be attached)

This internal page is the blueprint for the tenant portal, so it should look professional and be genuinely manageable: clearer stat cards with time scoping + reconciliation, filter-aware summaries, sortable + paginated table, honest pipeline-run status, bulk actions, saved views, and consistent empty/loading/error states. Full proposal in the session design note.

Reference: shares the DataTable needs of [AA-662](https://linear.app/aa-ecosys/issue/AA-662/ui-kit-shared-adminportal-components-datatable-filter-sort-columns) (shared admin/portal components) and the dashboard framing of [AA-664](https://linear.app/aa-ecosys/issue/AA-664/admin-overview-dashboard-whole-system-view-pipeline-a0a3-intelligence).

6. Header/stat cards and footer (Recent Pipeline Runs) are not sticky - they scroll away while paging a long table, so the user loses KPI context and the pipeline panel. Fix: sticky stat bar + sticky table header; move Recent Pipeline Runs into its own panel/tab.Update S209: bug 4 confirmed worse - DB has 207 active master tours but UI shows 200 (LIMIT 200 + Total Tours = tours.length miscount). Newest 7 tours dropped from table and stat. Needs server-side pagination + real COUNT, not just sort.
