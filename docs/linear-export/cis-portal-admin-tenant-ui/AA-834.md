# AA-834 — [CI][UI] Fix flaky AA-752 smoke test "(b) collapse toggles the rail and survives reload" — click lands before hydration

## Problem

The UI Smoke workflow runs on every successful Vercel Preview deployment. On 15/10 it failed on the [AA-752](https://linear.app/aa-ecosys/issue/AA-752/admin-ui-v2-admin-shell-redesign-collapsible-sidebar-logo-overview) admin-shell test `(b) collapse toggles the rail and survives reload`:

* Run: gh run 38684738547, branch feat/[AA-817](https://linear.app/aa-ecosys/issue/AA-817/security-cis-api-runtime-role-aa-cis-admin-is-not-filtered-by-rls)-mig-229.
* Test: `tests/e2e/smoke/aa752-shell.spec.ts:55-79`.
* The first try and retry #1 both failed at line 67 with `Expected: < 186, Received: 236`.

This is not a transition-timing problem. The test already polls the rail width for 5 s after clicking `sidebar-collapse`, and the rail never collapsed.

Likely cause: the click lands before React hydrates the button. The test calls `page.goto('/admin/jobs', { waitUntil: 'domcontentloaded' })` and then only waits for the rail to be visible. SSR makes the rail visible before the client is interactive.

The failure is rare (1 of the last 35 UI Smoke runs) but non-deterministic. When it happens, an unrelated PR turns red and a failure email goes out.

## Scope

* In test (b), wait until the shell is interactive before clicking. Either:
  * have the sidebar expose a hydration marker (e.g. `data-hydrated="true"`) once its toggle handler is mounted, and wait for it; or
  * re-click inside the poll while `data-collapsed` is not `true`. Test (a) already uses this pattern for the logo.
* Assert `data-collapsed="true"` first and the width second, so a failure shows which one broke.
* Check the other smoke specs under `tests/e2e/smoke/` for the same click-right-after-`domcontentloaded` pattern, and apply the same wait where it occurs.
* Do not raise Playwright `retries` to hide the flake.

## Done when

* The next 10 UI Smoke runs on Preview deployments show no failure of test (b).
