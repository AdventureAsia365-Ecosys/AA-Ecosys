# AA-883 — [Admin] AA Console nav (Platform / CIS Content) + read-only Staff page + links to all apps

## Problem

The admin mixes platform tasks (people, apps, tenants, spend, jobs) with CIS content work, and there is no page showing who has staff access. Nghiệp chose option A: one console with two sections, and every app links across (Q1).

## Scope

1. GĐ0 (FE only): nav sections Platform / CIS Content, "Tenant output" group, Content Quality as its own item, "A4 Quality" label, BottomNav filtered by role, remove `/admin/pipeline` + `AdminSidebar`. No URL changes; smoke spec updated in the same PR.
2. App links: console links to Booking admin, TripPlanner and the tenant portal; each of those links back to the console.
3. GĐ2: `GET /admin/platform/staff` and `/{id}` (`staff.read`, admin only) on existing `shared.admin_users` columns; page `/admin/platform/staff` (kit DataTable + Drawer) with "Open in Booking"; `PAGE_RULES` and `API_READ_RULES` for `platform`.

Depends on the server-side authz issue (GĐ1) for the staff route guard.

Out of scope: creating, disabling or resetting staff from the UI. That waits for Cognito (Q6) and stays in [AA-816](https://linear.app/aa-ecosys/issue/AA-816/admin-staff-user-management-ui-createdisable-staff-roles), rescoped to post-Cognito write actions.

## Done when

* aa-ui-verify screenshots (desktop/mobile, light/dark) of nav and Staff page on Dev with real data.
* Reviewer account gets 403 on the staff list through the BFF; admin sees it.
* Every cross-app link opens the right page in both directions; UI smoke green.
