## Problem

`/admin/docs` is admin-only, has no topic sidebar, no full-text search and no page history, so staff guides do not reach their readers and pages are hard to find. Advisory: `docs/audits/2026-11-17-S283-docs-advisory/README.md` sections 3 and 4.3.

## Scope

Slices B1–B8 of the advisory, with the tech lead's S283 choices (evolve the current reader; sidebar from front-matter; server-side FTS5 search; feedback widget stored in a CIS table; "Source / History on GitHub" for everyone, "Edit" for admins; open to all staff after the fixes; page owner slug `tech-lead`; `draft` pages become `active` once fixed):

1. B1 friendly page header, code blocks (copy, label, highlight), heading anchors.
2. B2 trust banner + Docs home + link fixes.
3. B3 topic sidebar from front-matter (+ lint), 3-column layout, sticky scroll-spy table of contents, breadcrumb, previous / next.
4. B4 full-text search (FTS5 in the CIS API) + Docs group in ⌘K + the `/` key.
5. B5 updated at / history / GitHub links (uses the sync engine page history) + related pages + feedback widget (CIS migration) + admin view of feedback.
6. B6 diagram zoom, mobile layout, Copy Markdown.
7. B7 open to every staff role.
8. B8 app / Infra docs, agent rules and release notes in the reader.
   Every UI slice follows `aa-ui-verify` (desktop / mobile / light / dark screenshots).

## Done when

* A staff user without the admin role opens `/admin/docs`, finds a page by full-text search and by the sidebar, and sees its history and GitHub source links (live, screenshots).
* Feedback from the widget lands in the CIS table and shows on the admin view.
