## Problem

Nghiệp (S252, 27/10/2026): "mọi thứ cần làm đồng bộ và chuyên nghiệp" and "có UI kit mà chưa làm chuẩn à".

There are **five separate UI kits**, and none of them is enforced:

| App | Kit | State |
| -- | -- | -- |
| CIS admin | `frontend/app/_kit` (29 files) | most complete; had no page frame until `AdminMain` ([AdventureAsia365-Ecosys/AA-CIS-App#1055](https://linear.app/aa-ecosys/review/fix-guide-fills-the-page-width-writing-memory-uses-the-standard-admin-47793c830e45)) |
| Tenant portal / Content studio (AA-Partner) | `portal/app/_kit` (17) | vendored copy of CIS, with a drift check |
| CRM web (AA-Partner) | `web/app/_kit` (7) | its own small kit |
| Booking admin | `frontend/ui` (50) | its own kit |
| TripPlanner (B2C) | `frontend/ui` (11) | customer brand UI |

Pages drift because nothing enforces the kit:

* **Hand-written frames.** Admin pages write their own `<main style>` with different paddings; about 8 CIS pages have no frame at all.
* **Bespoke widths.** The Guide had a fixed 880px width.
* **Page overflow.** Writing memory overflows 10px at 390px.

CI stays green through all of this. Screenshots cover only the pages being edited.

## Scope

1. **Decide the sharing model** (ADR, root; ≥2 repos).
   * Option A: one shared admin kit package for the four staff/partner UIs (CIS admin, portal, CRM web, Booking admin).
   * Option B: vendored copies kept byte-identical by a drift check (the portal pattern).
   * Either way, the design tokens (colour, type, spacing, radius, dark mode) are shared by all five apps, including TripPlanner.
2. **Fill the kit gaps once:**
   * page frame (`AdminMain`, done in CIS);
   * page header with actions;
   * forms and fields; filters and toolbars;
   * tables with in-card scroll;
   * tabs; drawers and modals;
   * loading / empty / error states; toasts;
   * Guide (`GuidePanel`, done in CIS).

   Each gets a live reference page (Settings › UI Kit) per app.
3. **Conformance guards** in CI and the pre-push hook, per repo:
   * no hand-written page frame;
   * no raw `<table>` outside the kit table;
   * no colour literals outside tokens;
   * no hand-styled buttons;
   * no fixed max-width on full pages;
   * every page renders a PageHeader.
4. **Migrate every page** of CIS admin, the portal, CRM web and Booking admin to the kit; TripPlanner moves to the shared tokens.
5. **Automated visual check** from GitHub Actions (not the agent's IP, which Vercel rate-challenges): every changed page at 1440 and 390, light and dark, with a page-level horizontal overflow assertion (`scrollWidth == viewport`) and console errors. Run on PR previews and after the production deploy.

## Done when

* The ADR is merged, and the token set is shared by all five apps.
* The kit reference page exists in each staff/partner app and shows every component.
* Guards run in CI in all four staff/partner repos and are green; a planted violation fails each guard.
* 0 pages outside the kit frame and header (guard-proven).
* The visual job is green on every page: no page-level horizontal overflow at 390, 0 console errors. Screenshots are stored as artifacts.
