## Why

S212 needed Nghiệp to catch UI bugs by hand repeatedly (SEO 500 rendered as 401, Live view button missing, Tenant 360 entry path, Thailand count). `npm run build` passing says nothing about whether a page renders real data. The agent needs to *see* the result (handbook Sec 28/36: feedback loops, observability for the agent).

## Scope

1. **Playwright smoke** in CI against the Vercel preview URL of each PR (admin + portal test-tenant login via a CI secret):
   * \~10 key pages: Overview, Master Content, Review Queue, SEO Intelligence, Jobs, Tenants (inline 360), S1 Rewrite, portal Social Content, My Content, Publish.
   * Assert: page renders, no console errors, no 4xx/5xx on its API calls, main table has ≥1 row (or the expected empty state).
   * Save screenshots (desktop + 390px mobile, light + dark) as CI artifacts; link them in the PR.
2. **ESLint rule(s)** for the UI v2 conventions: pages import primitives from `app/_kit/` (no ad-hoc table/modal), no Tailwind `className` on kit pages (inline style + brand tokens).
3. Document the flow in the `aa-ui-verify` skill.

## Done when

* A PR that breaks a page's API call turns CI red and the screenshot shows the failure.
* Screenshots appear on every UI PR.

Portal pages (Social Content, My Content, Publish) are wired but skip until a tenant test account exists (AA-741, `E2E_TENANT_API_KEY`).

The leaked `e2e-test-admin` user is deactivated (login → 401).
