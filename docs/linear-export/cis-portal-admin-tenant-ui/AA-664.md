# AA-664 — [Admin] Overview dashboard — whole-system view (pipeline A0→A3, intelligence, tenants, jobs, cost vs budget, alerts)

Ms. Thư's requirement: the dashboard must show the **whole system** at a glance.

**Sections:**

1. **Pipeline funnel** — raw → S1 generated → review (HITL) → published → atomized, per country, with deltas over 7 days.
2. **Intelligence** — atoms, segments (distinct places), routes/hubs; research coverage (places with fresh search demand per market, with a NULL-data warning).
3. **Tenants** — active tenants, rewrites and pieces this week, publish count, quota usage outliers.
4. **Jobs** — running / queued / failed / stuck, with links.
5. **Cost** — month-to-date vs budget per provider (Bedrock per account, OpenAI, DFS, Jev); today's spend; DFS balance.
6. **Alerts** — DFS below threshold, LLM fallback rate, failed jobs, budget at 80% or more, stale research.

Every widget links to its detail page. Data comes from a single `/admin/overview` endpoint, cached for 60 s.

### 2026-09-28 11:37 — nghiep pham quoc

**Added requirement (Nghiệp, 28/09, S200): CloudWatch in the admin UI**, so ops can be monitored without the AWS console. Feasible; notes for the build:

**What to show**
* **Errors & warnings panel:** counts per event name over 1h / 24h / 7d from `/ecs/aa-cis-dev`, e.g. `llm_model_catalog_read_failed`, `llm_price_unknown_model`, `t3_failed_all_providers_down`, DFS errors, `Traceback`. Recent tracebacks as an expandable list, filterable by stage / tenant / job id.
* **Service health:** ECS CPU/memory and running task count, current task-def revision + rollout state, ALB 5xx / p95 latency, RDS CPU / connections / free storage.
* **Alarms:** existing CloudWatch alarms and their state (links to the AWS console for detail).

**How**
* Backend-only access: new admin endpoints `GET /admin/ops/logs/summary`, `GET /admin/ops/logs/recent`, `GET /admin/ops/metrics`. The browser never gets AWS credentials. Same admin-secret gate as the other `/admin/*` routes.
* Logs through **CloudWatch Logs Insights** (`StartQuery` / `GetQueryResults`), metrics through `GetMetricData`. Cache results about 60s so a page refresh is not a new query.
* **IAM (AA-CIS-Infra):** the ECS task role needs `logs:StartQuery`, `logs:GetQueryResults`, `logs:FilterLogEvents` scoped to the `/ecs/aa-cis-dev` log group, plus `cloudwatch:GetMetricData` / `DescribeAlarms`.
* **Cost:** Logs Insights bills about $0.005 per GB scanned. Cap the time window (max 7 days) and always filter by event name; never scan raw.
* **Safety:** redact anything secret-like (keys, DSNs, JWTs) server-side before it reaches the UI.

This could also be a separate "Operations → Logs & Health" page under the new IA (AA-663). Decide when AA-664 is built.
