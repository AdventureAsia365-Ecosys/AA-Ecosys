# AA-857 — [Slate/A3] Tenant picks a Subject but the post is about another place (even another country): mixed-country Segments + representative atom by atom_id

## Problem

S239 live verify ([AA-668](https://linear.app/aa-ecosys/issue/AA-668/portal-writer-panel-segmenttopic-opens-a-right-side-panel-goal-angle)): a tenant (terra-family) picked the Slate subject "Gyeongju" (South Korea) and the T9 post was written about the Lok Virsa Museum in Islamabad (Pakistan); "National Library" (Bhutan) produced a post about the Zorig Chusum school.

Read-only DB check (`.tmp-session/s239/d1_subject_atoms_out.json`):

* Segment `d8aa8991e02d6754` (subject "Gyeongju") holds **37 atoms from 6 countries** (Bhutan 25, South Korea 7, Pakistan 2, Laos, Thailand, Mongolia): "Folk Heritage Museum", "National Museum", "Textile Museum", "National Museum of Korea", "Lok Virsa Folk & Heritage Museum". A3 segmentation merged similar museum visits across countries.
* Segment `8cc3b252cddaa88f` (subject "National Library") mixes National Library (9) with the Traditional Arts & Craft School (8), all Bhutan.
* `services/acp_shared/slate.py:863` `_resolve_representative_atom` takes `ORDER BY atom_id LIMIT 1` within the segment, so the seed is whichever member sorts first (Pakistan museum; craft school).

The tenant sees a subject and gets content about a different place. With mixed-country segments this can put the wrong country in a tenant's post.

## Scope

1. Slate representative atom: choose the member that matches the subject's `canonical_place` (and its country), never `ORDER BY atom_id`; if none matches, do not offer the subject.
2. A3 Segment: never merge atoms of different countries into one Segment (country is part of the merge key); add a guard + test.
3. Repair existing data: list every segment spanning more than one country, split them (re-run the segment step scoped to the affected tours, per the A3 recompute path), and re-point affected Slate subjects. Paid steps (if any) per the paid-runs rule.
4. Admin visibility: Content Quality / atom curation shows the seed place next to the subject for each T9 piece.

## Done when

* Query: 0 segments with atoms from more than one country (before/after counts posted).
* For the two S239 cases (Gyeongju, National Library) the seed place equals the subject place; one live T9 write on a fixed subject shows the right place in the post.
* Unit tests for the representative atom choice and the cross-country merge guard.

  - The cause: a Segment id is the hash of the moment it was first minted, and labels drift. A tour from another country re-mints the same id, its atoms join that Segment and relabel it. Example: Thailand "hotel / check in" re-mints the India Segment e11cd23f51829202.

  - Only claimed ids (or empty rows) are relabelled.
  - A written id that gains a second known country rolls the transaction back.
  - Subjects on alias old ids resolve to the live id and label.
