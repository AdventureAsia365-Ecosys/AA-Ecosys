# AA-666 — [Admin] Tenant 360 — full tenant management page (profile, brand, content, channels, usage/billing, quality, audit, settings)

## Today

`/admin/tenants` is a list plus 6 thin tabs (tours, pipeline, activity, api, brand, social_content). It has no overview, markets/channels, usage/cost, integrations, quality or lifecycle view.

## Target (review §5.5)

**Header:**

* name, logo, plan, status;
* markets, channels;
* health score (activity, quality, quota, integration health);
* last activity;
* quick actions: open portal as tenant (read-only), rotate key, suspend.

**Tabs:**

1. **Overview** — KPIs: tours rewritten, pieces by channel, published, quota used/overage, cost-to-serve (LLM + DFS share) vs plan revenue, alerts.
2. **Profile & Brand** — company profile and contacts; full brand identity with **version history + diff**; CTA defaults; forbidden words; examples.
3. **Tours** — the catalog versions table (status, score, rewritten at, source tour), rewrite history.
4. **Social Content** — Slate per channel (proposed/picked/used/cut), pieces table, goal/angle usage.
5. **Channels & Integrations** — WordPress connection health + publish log, API keys (create/rotate/revoke), rate limit.
6. **Usage & Billing** — quota meter, overage, invoices (when billing exists), cost by stage.
7. **Quality** — gate telemetry and held/failed reasons for this tenant (moved from Platform Stats).
8. **Audit** — timeline of admin and tenant actions (filter by actor and type).
9. **Settings** — plan, RPM, markets, posts/week, activation/deactivation, danger zone.

## Done when

Every tab shows real data for WanderLux, built on the shared UI kit. Screenshots are reviewed with Ms. Thư.
