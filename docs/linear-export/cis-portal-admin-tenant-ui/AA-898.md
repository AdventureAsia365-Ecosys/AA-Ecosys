## Problem

Docs live in git (the source of truth), but Ms. Thư has no GitHub access and the root repo is private; there is no easy, professional way to read them (S243 proposal §3: a Docs page in the admin is recommended after the content is standardised and after [AA-885](https://linear.app/aa-ecosys/issue/AA-885/portal-split-the-tenant-portal-into-its-own-app-and-domain)).

## Scope

* Infra: private docs bucket, OIDC write role for root/Infra `docs/*`, ECS task read (cost < 0.05 USD/month).
* Root/Infra workflow: build `manifest.json` (path, repo, sha, title, audience, last_reviewed, headings) + optional search index, then `s3 sync`.
* CIS backend `GET /admin/docs/manifest`, `GET /admin/docs/file?path=` (path must be in the manifest).
* CIS frontend `/admin/docs` under Platform → Developer: tree, audience toggle, react-markdown + remark-gfm + rehype-slug, lazy mermaid, no raw HTML, source footer.

## Done when

* Ms. Thư can open an `audience: owner` page with her staff Cognito login.
* Content updates within minutes of a merge with no Vercel deploy.

## Related

Depends on [AA-885](https://linear.app/aa-ecosys/issue/AA-885/portal-split-the-tenant-portal-into-its-own-app-and-domain) (portal split) and the docs standard issue. S243 docs standard (I13).
