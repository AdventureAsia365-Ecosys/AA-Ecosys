# AA-885 — [Portal] Split the tenant portal into its own app and domain

## Problem

The tenant portal ships inside the CIS admin frontend, sharing its deploys, cookies and failure blast radius. Nghiệp decided to split it now (Q8).

## Scope

1. Separate Next.js app (or second Vercel project on its own root) for `/portal`, own sub-domain of [lumiguides.it.com](<http://lumiguides.it.com>).
2. Vercel Hobby (D-18): check the project count limit and the daily deployment cap before creating it; CI-created deploys (S241 vercel-deploy.yml) must stay within the cap across both projects.
3. Tenant auth cookie scoped to the portal domain; admin app stops serving portal routes; old `/portal` URLs redirect (308).
4. Own UI smoke project; security headers; `/privacy` + `/terms` links (legal issue).
5. Update `CONTEXT.md` and `ecosystem-architecture.md`.

## Done when

* Portal live on its domain; tenant login and main flows pass UI smoke on the new project.
* An old `/portal/...` URL returns 308 to the new domain; the admin app no longer serves portal pages.
* Deploys per day for both projects measured from CI config and under the Hobby cap (numbers in PR).
* aa-ui-verify screenshots at 390 px and desktop.

## Source

S241 decisions Q8, D-18; root (private) `docs/audits/2026-10-17-S241-admin-console/README.md` §8.
