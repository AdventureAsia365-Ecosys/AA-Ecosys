# AA-769 — [Admin] Content Quality tab on /admin/atom-curation — every tenant's T2 tours and T9 pieces with gate results, held reasons, flagged sentences, writer inputs and per-gate stats

## Problem

All T-series quality signals (T10 gate ledger, held reasons, F9 flagged sentences, repair log, what the writer was given) are stored in `acp_shared.content_piece` / `gold_aa_internal.tenant_tour_versions` but no admin page shows them across tenants. Today they are only readable through SQL. The S232 audit (`docs/audits/2026-10-12-S232-t9-social-audit/`, 49 pieces, 127 labelled claims) had to be done by script.

Product rule (Nghiệp, S232): tenants only ever see content; all QA lives in admin, on `/admin/atom-curation`, for AA admins to improve the system.

## Scope

1. New tab "Content Quality" on `/admin/atom-curation` (after Slate / Social Content), built with the UI kit (DataTable, Drawer):
   * list of T9 pieces and T2 tour versions for all tenants: tenant, channel, created, attempts, status, first blocking gate, cost; filters by tenant / channel / gate / status / date;
   * per-gate statistics: runs, failures, hold share, trend by day;
   * drawer per item: final text with each flagged sentence highlighted (reason, the source line it was checked against), actions "cut sentence" / "rewrite sentence" (logged, admin only), gate ledger, repair log + discarded attempts (diff attempt 1 vs 2), and "what the writer was given" (seed, facts, brand pack, angle brief) with a warning when the seed is thin or the brand rubric is the generic fallback.
2. Admin API endpoints for the above (admin secret, read-only except the two sentence actions).
   Out of scope: anything tenant-facing (tenants keep seeing content only).

## Done when

* On Dev, the tab lists today's pieces for all 4 test tenants with correct gate counts (spot-check 3 against `gate_ledger` in SQL).
* Opening a held piece shows its flagged sentences highlighted with reasons and the writer inputs; "cut sentence" updates the text and is audit-logged.
* UI verified (aa-ui-verify): desktop + mobile, light + dark, 0 console errors.
