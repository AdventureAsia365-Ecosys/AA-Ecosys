## Goal

One evidence-backed report on every frontend page the ecosystem serves on Dev: does it load, does it show live data that matches the backend, does it follow the UI kit, and what is broken or out of date. Audit only: nothing is fixed in this issue. Fixes become proposals the tech lead approves.

## Problem

Since S265 the four apps shipped many pages in parallel lanes (pricing B, Settings registry, Delivery, CRM W6/W7, TripPlanner custom domains, Content studio in CRM web). Pages are verified one by one when they ship, but nobody has looked at all of them together against the current live backends. The tech lead asked for this audit in S283 (17/11/2026).

## Scope

1. Inventory every page from the code, using the catalogue surface snapshot `docs/catalogue/surface.snapshot.json` (refreshed S283, root #843) plus the app routers:
   * CIS admin (`aa-cis.lumiguides.it.com`);
   * Booking admin (`booking.lumiguides.it.com`);
   * CRM web and the agency studio (`portal.` host);
   * TripPlanner web (`tripplanner.lumiguides.it.com`, tenant pages).
2. For each page, with Playwright and the E2E logins (Cognito; viewer-capped where the policy says so):
   * HTTP status, console errors, failed network calls;
   * empty / loading / error states;
   * desktop 1440 and phone 390, light and dark;
   * EN/VI where the page offers it;
   * kit compliance;
   * visible text that is stale or wrong for today (B2C leftovers, old prices, issue ids in UI, "Adventure Asia" on tenant pages);
   * live data cross-checked with the API it reads, on a sample.
3. Report: one row per page (status, severity, finding, screenshot path), grouped per app, and a proposal list ranked by severity with effort estimates.

Out of scope: any code change, any write action on live data (read-only navigation; no form submits that write), paid calls.

## Done when

* Every page in the inventory has a row (or a stated reason it could not be opened).
* The report and screenshots are saved under `docs/audits/<date>-S283-fe-audit/` (root PR) and published as one artifact page.
* Each finding carries evidence (screenshot or the failing request) and a proposed fix with a size.
* The tech lead has the proposal list to approve; nothing is changed by this issue.

## Verify

Open the report; spot-check 5 random rows against the live page.
