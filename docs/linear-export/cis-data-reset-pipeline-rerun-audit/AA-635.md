# AA-635 — [BE] llm_call_log under-reports Bedrock spend vs AWS bill (acc1 ~99% missing, acc3 ~20%)

## Context

Found in S195 while verifying [AA-623](https://linear.app/aa-ecosys/issue/AA-623/sub-fbeinfra-aws-cost-explorer-reconcile-djoi-chieu-hoa-djon)'s follow-up (PR [AdventureAsia365-Ecosys/AA-CIS-App#429](https://linear.app/aa-ecosys/review/fix-cost-explorer-panel-splits-bedrock-vs-infra-page-wide-date-range-d4a3290950fc)). The External Spend page can now compare **Bedrock actual**, taken from Cost Explorer with only the Bedrock service lines, against **Bedrock estimated**, the `shared.llm_call_log.cost_usd` rows for acc1/acc2/acc3, over the same UTC window. The two figures do not reconcile.

Window: 2026-09-16 → 2026-09-22 (UTC, inclusive). Source: live `GET /admin/cost-explorer` and `GET /admin/llm-usage/tree`, taskDef `aa-cis-dev-api:328`.

| Account | Bedrock actual (CE) | Estimated (llm_call_log) | Gap |
| -- | -- | -- | -- |
| acc3 786888028788 | $25.99 (Sonnet 4.6 $19.84 + Haiku 4.5 $6.16) | $20.86 | \~$5.13 (\~20% under) |
| acc1 867490540162 | $0.766 | $0.009 | \~99% missing |
| acc2 005097885195 | $0.0009 (Cohere/Palmyra) | $0 | negligible |

The acc1 CSV shows Haiku 4.5 **$0.73 on 2026-09-17** and $0.036 on 2026-09-21. Almost none of this appears in `llm_call_log`.

## Hypotheses (unverified)

1. Some Bedrock call paths bypass `LLMClient` / `call_log.record_llm_call`, for example ad-hoc A/B scripts ([AA-619](https://linear.app/aa-ecosys/issue/AA-619/sub-cmeasure-ab-atomize-haiku-vs-sonnet-ha-t5-atomize-xuong-haiku)/[AA-620](https://linear.app/aa-ecosys/issue/AA-620/sub-gbe-tach-stage-t2-generate-config-ui-sonnet-cho-t2-tenant-a1-giu) model A/B, S187–S188), Bedrock Batch jobs ([AA-606](https://linear.app/aa-ecosys/issue/AA-606/build-bedrock-batch-inference-cho-s1-rewrite-100-tourlan-xin-iam-batch)/[AA-621](https://linear.app/aa-ecosys/issue/AA-621/sub-dbe-batch-atomize-mo-rong-bedrock-batch-aa-606-sang-t5-atomize)), or other scripts run via ECS exec.
2. The acc3→acc1 fallback path logs the call under the wrong `account`, or with `cost_usd` = 0.
3. There is a pricing-table gap in `shared/llm_client/pricing.py`. Candidates: Sonnet 4.6 vs 4.5, prompt-cache read/write tokens not priced, or cross-region inference-profile pricing.
4. Calls that fail or are retried are billed by AWS but never logged.

## Scope

* Pull CE per-day Bedrock spend and `llm_call_log` per-day spend per account for Sept 2026, then find the days and models where they diverge.
* For each diverging day, identify the caller: `llm_call_log.stage` and CloudWatch `/ecs/aa-cis-dev`. Also check acc1/acc3 CloudTrail `InvokeModel` for any principal other than the ECS task role.
* Fix the root causes: log the missing call paths, correct the account attribution, and correct the pricing.
* Out of scope: the OpenAI and DataForSEO estimates, which never appear on an AWS bill.

## Done when

* The gap per account per week is explained. Either it is below \~5%, or the remaining difference is documented with its cause.
* Any fixed logging or pricing path has a unit test, and a live re-check on the External Spend page with a custom date range after the fix.

## S196 — root causes verified live + code fix deployed (PR #431)

### Root causes, verified against CE snapshot + llm_call_log + CloudWatch (read-only)
1. **Haiku 4.5 priced at Claude 3 Haiku rates ($0.25/$1.25 per MTok instead of $1/$5)**, which is the main cause. Every Haiku row was logged at 25% of the real cost. Proof on 21/09, a day with clean attribution: logged tokens × $1/$5 gives acc3 $0.3783, equal to CE $0.3783, and acc1 $0.0361, equal to CE $0.0361. Sonnet 4.6 at $3/$15 was already correct: 17/09 t5_atomize logged $19.2226, equal to CE $19.2226.
2. **acc1 "99% missing" is historical misattribution on 17/09.** CloudWatch shows 212 Haiku calls hit `ThrottlingException` on acc3 between 07:00 and 11:00 UTC and were served by acc1 (`t2_5b_satellite_used account=acc1`). Every 17/09 row says `account='acc3'`, and those rows still carry the `satellite-haiku-4-5` model string, which only pre-AA-617 code writes. So `account` was filled in later as acc3 by an undocumented backfill; migration 153 does not backfill. Post-AA-617 attribution works: the 8 acc1 fallbacks on 21/09 are logged as `acc1`.
3. **18/09 spend ($0.83 on acc3) came from outside the app.** CE shows Haiku $0.2128 and Sonnet $0.6165, with zero log rows and one `llm_success` event in CloudWatch that day. This matches the S187/S188 A/B scripts (AA-619/AA-620), which the app cannot log.
4. Two code gaps with no measurable Sept impact, fixed anyway: prompt-cache tokens were never priced, and the A3 Search Demand ReAct loop never wrote `llm_call_log`.

Also: `llm_call_log` starts at 2026-09-17 07:18 UTC because of the 16/09 data reset, so 01–16/09 has no log to reconcile by design.

## S196: historical Haiku repricing, dry-run done and commit pending

Nghiệp approved a data fix for the existing Haiku rows in `shared.llm_call_log`. They were logged at the old $0.25/$1.25 per MTok rate, and the fix recomputes `cost_usd` at $1/$5 from the stored tokens.

**Script:** a single transactional `UPDATE`.
- It only touches rows whose current `cost_usd` equals the old-rate formula (±0.000002). Rows written by the new code, and re-runs of the script, are therefore unaffected.
- It is reversible without a backup, because the old value is simply the old formula applied to the same tokens.
