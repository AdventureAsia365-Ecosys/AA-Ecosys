# AA-608 — [S1][Rubric/Gate+Model] H3 đo batch 20-50 tour → H2 nới gate + quyết haiku↔sonnet

## Bối cảnh (chốt S185, sub #1+#2 gộp của [AA-607](https://linear.app/aa-ecosys/issue/AA-607/epic-djanh-gia-lai-andamp-redesign-2-luong-viet-admin-s1-social))

Lo ngại: rerun 700+ tour S1, tour điểm cao vẫn rớt review queue vì **brand_audit AA generic quá chặt** (\~40 forbidden words, rule từng field, `manual_check` cứng cho elephant/fabricated). Lưu ý: judge brand-fit ĐÃ skip cho A1 (brand row 'default' trống brand-diff) — cái chặt là brand_audit generic, KHÔNG phải judge.

## Việc (thứ tự)

### H3 — đo trước (bắt buộc làm đầu tiên)

* Chạy batch nhỏ **20-50 tour** qua S1 hiện tại (haiku writer, gate hiện tại).
* Đo: pass rate, phân bố `quality_score`, tỉ lệ vào review_queue, lý do fail (gate nào chặn: score<7 / manual_check / flagged-chưa-fix), phân loại lỗi (product-truth vs brand-voice).
* Kết quả quyết định mức nới ở H2 + chọn model writer.

### H2 — nới gate (sau khi đo)

* Đổi `manual_check` → `flagged` cho lỗi **brand-voice** (giọng văn, forbidden words phong cách).
* **GIỮ chặn cứng product-truth**: bịa fact, sai giá, elephant/fabricated claim — vẫn `manual_check`/block.
* Ranh giới product-truth vs brand-voice phải rõ trong code (không nới nhầm).

### Model writer (quyết dựa H3)

* Hiện `s1_generate`/`s1_flag_fix`/`s1_itinerary_nudge` = haiku/acc3.
* Nếu H3 cho thấy haiku fail rate cao (chất lượng) → cân nhắc lên **sonnet**. Batch sonnet rẻ \~50% ([AA-606](https://linear.app/aa-ecosys/issue/AA-606/build-bedrock-batch-inference-cho-s1-rewrite-100-tourlan-xin-iam-batch)) nên chi phí không phải rào cản.
* Đổi qua `shared.llm_role_config` (admin PATCH /admin/llm-config/{stage}), không cần đổi code.
