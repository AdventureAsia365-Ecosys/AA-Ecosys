## Context

[AA-637](https://linear.app/aa-ecosys/issue/AA-637/tenant-portal-live-writing-progress-stream-steps-text-while-a-tour)'s live production check (25/09/2026, tenant WanderLux, tour "Everest Base Camp and Island Peak — 16 Days", version `ba4db187-77a2-42b6-a4ab-05f35cd5d8cf`) ran 1 write plus 3 full revisions of the whole tour, each about 9–10k characters, over about 4 minutes before QA passed (qa_repair_count=2). Every revision is a full writer call, so this multiplies cost and makes the tenant wait. The progress view now shows each revision as "Revising…".

## Questions

1. Which gate or check fails on the first draft, and on each revision? Candidates: validate_node codes, the judge brand-fit score, brand audit, and T3 QA (grounding and structural).
2. Is it the same failure every time (a systematic prompt or gate mismatch), or a different one each time?
3. Would a targeted field fix (flag_fix) have been enough, instead of a full rewrite?

## Done when

* A fix is proposed and agreed with Nghiep, or it is shown that the revisions are legitimate.

### 2026-09-25 15:27 — nghiep pham quoc

**Done. Four root causes were found in CloudWatch and fixed, with live before/after on the same tour.**

| # | Root cause (evidence) | Fix | PR |
|---|---|---|---|
| 1 | T3 repair rounds were blind re-rolls (`feedback=""`) | T3 findings are passed to the writer, and the repair log records the codes and numbers | #444 |
| 2 | Grounding false positives: the source writes `4,460m`/`710m`, and `\b\d+\b` can't read "460m", so the rewrite's "4,460 m" gave a "novel" 460 | The number regex allows unit suffixes and normalises thousands separators; the 79-unit real dataset still has 0 false positives | #445 |
| 3 | T3 failed on soft codes (`HIGHLIGHTS_TOO_GENERIC`) that graph.py deliberately doesn't block on | T3 uses `_HARD_BLOCK_CODES` only | #445 |
| 4 | `SEO_TITLE_TOO_LONG` alone cost a full 18-day rewrite | Deterministic `fit_seo_title()` in T3 | #447 |
| 5 | **The writer was truncated at the 4096-token default** (`stop_reason=max_tokens` three times in a row, then `MISSING_FIELD`) | `GENERATE_MAX_TOKENS=8192` (billed as used); the A1 batch default matches | #448 |

**Live runs on Manaslu Circuit Trek (18 days, WanderLux):**

| When | Writer calls | Time |
|---|---|---|
| Before (×2) | 4 and 4 | ~354s |
| After #445 | 2 | 193s |
| After #447 | 4 (the logs showed this was truncation, fixed in #448) | 246s |
| **After #448 (×2)** | **2 and 1** | **207s and 105s** |

After #448 the writer's output is 4256 and 4402 tokens (`end_turn`), which is more than the old 4096 cap, and the first draft passes the graph (score 9.75). The other tours checked took 1 writer call each (Kuari Pass, 29s; Sacred Circuit, 33s).

**The remaining second call is legitimate.** In that run, `flag_fix` (Haiku) introduced a `FORBIDDEN_WORD` while editing the itinerary and did not shorten `seo_meta`. Both are hard failures, so a rewrite is correct. A possible follow-up, not in scope here: a deterministic `seo_meta` fit, similar to the title fit, and making flag_fix respect the forbidden-word list.

**Approximate cost per 18-day rewrite:** about $0.31+ with 4 calls, down to about $0.10–0.18 with 1–2 calls.
