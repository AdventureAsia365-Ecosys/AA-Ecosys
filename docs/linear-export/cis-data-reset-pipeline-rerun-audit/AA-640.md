# AA-640 — [Billing] One source for plan tour quota (membership_plans); over-quota rewrites allowed + billed as overage

## Context

Found in [AA-636](https://linear.app/aa-ecosys/issue/AA-636/tenant-portal-trust-fixes-real-quota-reset-date-working-bellsearch), and decided by Nghiep on 25/09/2026.

* The portal and billing use `shared.membership_plans`: starter 50, growth 200, business 500 tours per month.
* The [AA-489](https://linear.app/aa-ecosys/issue/AA-489/build-rewrite-quotathang-theo-tenant-chua-tung-djuoc-enforce-can-thiet) 429 enforcement used `PLAN_LIMITS` in `admin.py`: 100, 500 and 2000.
* So a Growth tenant saw "x / 200" but was blocked only at 500.

## Decision (Nghiep)

* `membership_plans.tours_quota_monthly` is the **single** source for the tour quota. `PLAN_LIMITS` keeps only the RPM.
* **Over quota: allow the rewrite and bill it as overage**, using the plan's `overage_rate_usd_per_tour`, which `v_tenant_monthly_usage` already computes. No 429 while the product is in trial.

## Done when

* The quota helper and `GET /v1/quota` read `membership_plans`, and the admin tenant detail shows the same number.
* Over-quota rewrites succeed and are logged as `rewrite_over_quota`.
* Tests are updated, the change is merged and deployed, and it is checked live: `/v1/quota` on production shows the same quota as the portal.
