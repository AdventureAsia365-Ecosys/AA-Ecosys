# AA-588 — [INFRA][G5] Gỡ OIDC trust org cũ (AdventureAsia365-CIS) sau khi ổn định

## Bối cảnh

Phiên S181 (15/09/2026, Kiro) đổi tên org GitHub `AdventureAsia365-CIS` → `AdventureAsia365-Ecosys`. Theo nguyên tắc an toàn, OIDC trust được mở rộng nhận CẢ 2 org (transitional, đã apply: 0 add/4 change/0 destroy). Đây là bước G5 — dọn tên org cũ sau khi ổn định.

## Khi nào làm

Sau **vài ngày** deploy ổn định thuần org mới, xác nhận KHÔNG còn workflow nào chạy dưới tên org cũ (Actions history sạch tên cũ). Gỡ sớm sẽ hỏng deploy nếu còn ref nào dùng tên cũ.

## Việc cần làm (theo `docs/g5-remove-old-trust.md`)

* `accounts/aa365/cicd.tf` (aa-cis-dev-role): bỏ `repo:AdventureAsia365-CIS/*:*` + biến thể wildcard dư, chỉ giữ dạng phẳng `repo:AdventureAsia365-Ecosys/*:*` (đã xác minh org KHÔNG bật include-repo-ID → dùng dạng phẳng).
* `accounts/aa365/tripplanner.tf` (aa-tripplanner-dev-app-deploy): bỏ `...-CIS*/...`, chỉ giữ `repo:AdventureAsia365-Ecosys*/AA-TripPlanner-Web*:*`.
* `terraform plan` (kỳ vọng chỉ 2 role đổi) → `terraform apply` (MFA) → verify deploy xanh (Deploy Lambdas + terraform-plan CI dưới org mới).
* Cập nhật docs/ecosystem-architecture.md bỏ phần transitional.

## Lưu ý kỹ thuật

* terraform apply cần MFA: `export $(aws configure export-credentials --profile aa365-admin --format env | xargs) && unset AWS_PROFILE` rồi chạy (TF không tự prompt MFA).
