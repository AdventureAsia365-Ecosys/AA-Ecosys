## Context

Both tenant writing flows run as background jobs: the tour rewrite ([AA-223](https://linear.app/aa-ecosys/issue/AA-223/run-tour-gateway-504-duplicate-upstream-execution-wrong-model) 202 + job poll) and the T9 social post ([AA-466](https://linear.app/aa-ecosys/issue/AA-466/arch-chuyen-goal-write-sang-pattern-async-202poll-thay-patch-timeout) 202 + poll). The UI shows only a pulsing "Writing…" until the whole result lands. Nghiep wants a Claude-like experience: visible steps plus text appearing as it is written.

`LLMClient` already calls Bedrock with `invoke_model_with_response_stream` (AA-224), but it accumulates the deltas and returns only the final text. Showing progress adds **no LLM cost**.

## Approach (decided: Option 1, Redis progress + fast poll)

* The background job publishes progress to Redis, keyed by job/piece: a step list (pending/active/done) plus an append-only text buffer.
* A new tenant-scoped endpoint returns steps plus the text since an offset. The frontend polls about every 700ms and animates the new text with a typewriter effect. It resumes after a reload or tab switch.
* No infrastructure change: this works through Vercel BFF → API Gateway REST (29s limit) → ECS as they are today.
* True SSE (API Gateway response streaming) is deferred. Revisit only if about 1s latency is not good enough.

## Requirements

* Tenant-facing step labels are plain language: no F1–F9 gate names, no model names.
* Internal citation tags `[R:…]` / `[F:…]` are never shown. They must be stripped from the stream, including tags split across chunks.
* Tour rewrite output is JSON. The live view shows text per field (title, subtitle, summary, itinerary day N) and never raw JSON.
* If a quality gate triggers a repair or retry, the UI shows it as a step (for example "Revising…") and the draft text is replaced by the final text.
* The final persisted content is unchanged. Progress is a view only; DB writes are identical to today.
* Progress keys have a TTL and are tenant-scoped (tenant A cannot read tenant B's job).
* Needs an ADR in `docs/adr/` (architecture decision per the [AA-539](https://linear.app/aa-ecosys/issue/AA-539/process-cai-djat-bo-skill-matt-pocock-domain-modeling-grill-with-docs) process).
