# AA-632 — [Debate follow-up] Extend "not already on slate" place de-dup across Channels

## Context

Follow-up from [AA-631](<https://linear.app/aa-ecosys/issue/AA-631>) (Debate stage for Slate, Done, PR [AdventureAsia365-Ecosys/AA-CIS-App#423](https://linear.app/aa-ecosys/review/aa-631-debate-stage-for-slate-contested-metric-brand-fit-filter-0c564e2596ee)). [AA-631](https://linear.app/aa-ecosys/issue/AA-631/enhancement-debate-stage-for-slate-contested-metric-brand-fit-filter)'s own description flagged this as a separately-landable piece of standard #3 ("not already on slate") that was not included in that PR:

> "not already on slate" across Channels — no LLM needed; `_choose()`'s existing place de-dup is scoped to one Channel at a time (fresh `seen_places` per `_choose()` call) — extend to dedupe across Channels too. Small, independent of the Debate LLM question, can land separately/first.

Note: standard #2 ("said") does NOT need porting here — it was already ported in [AA-610](https://linear.app/aa-ecosys/issue/AA-610/enhancement-nang-cap-score-ranking-atomsegment-theo-rank-sum-4-chieu) Sub 1 and is reused as cut evidence, not a gap.

## What's missing today

`_choose()` in `services/acp_shared/slate.py` de-dupes candidate places via a `seen_places` set, but that set is scoped to a single call of `_choose()` — i.e. de-dup only happens within one Channel's candidate list. Two Subjects on different Channels claiming the same place/keyword are NOT deduped against each other, even though they're on the same tenant's Slate.

## Scope

* Extend place de-dup in `_choose()` (or the caller in `propose_slate()`) to share `seen_places` across Channels for the same tenant, not just within one Channel's call.
* Deterministic, no LLM — same category as the existing de-dup logic already in place.
* Independent of the Debate `contested`/brand-fit LLM work ([AA-631](https://linear.app/aa-ecosys/issue/AA-631/enhancement-debate-stage-for-slate-contested-metric-brand-fit-filter)) — can be built and shipped on its own.
