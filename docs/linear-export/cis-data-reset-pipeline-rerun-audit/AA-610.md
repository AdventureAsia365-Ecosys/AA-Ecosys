# AA-610 — [Enhancement] Nâng cấp score ranking atom/segment theo rank-sum 4 chiều (mô hình Ms.Thư)

## Bối cảnh (chốt S185, sub #4b của [AA-607](https://linear.app/aa-ecosys/issue/AA-607/epic-djanh-gia-lai-andamp-redesign-2-luong-viet-admin-s1-social))

Thay vì "curation chọn atom" (không cần — xem sub gỡ star), nâng cấp **ranking** để nói cái gì đáng viết, theo mô hình `score` của repo Ms.Thư (`aa-social-media`, `src/aa_social/stages/score.py`, ADR-0014).

## Mô hình tham chiếu (rank-sum, deterministic, KHÔNG LLM)

Đơn vị xếp hạng = **Segment** (một moment thực), không phải atom (tránh xếp cùng moment nhiều lần theo số phrasing). Rank riêng trên 4 term rồi cộng, thấp nhất thắng:

1. **search demand** — theo market, giữ market mạnh nhất (segment không đo lấy median = "không khẳng định gì").
2. **recurrence** — bao nhiêu itinerary lặp lại moment này.
3. **PAA questions** — số People-Also-Ask gần đủ (median distance, không hằng số).
4. **said** — số ký tự itinerary mô tả moment (proxy "có gì để viết không").

**Không trọng số, không hằng số** — "cái gì tune là bịa, không phải đo". 2 luật loại (vẫn liệt kê arguable, không biến mất): là transit / place không tên riêng (không research được).

## Việc

1. Đọc kỹ `score.py` + `segments.py` + ADR-0014/0019/0020 repo Ms.Thư.
2. Đối chiếu score/segment/route hiện tại của CIS (`acp_contract`, recompute_segment_score_route) — CIS đã đi đúng hướng ranking thuật toán, cần xác định gap so với rank-sum 4 chiều.
3. Đề xuất áp dụng (giữ deterministic), có thể thêm term `said` + PAA nếu CIS chưa có.
4. STEP0 điều tra trước, không build ngay.

## Ranh giới

Scope lớn hơn gỡ star. Ưu tiên thấp hơn #1 (gate/model). Điều tra + đề xuất trước khi build.

### 2026-09-21 12:13 — nghiep pham quoc

## Sub 1 (fix `said` — evidence field) — Done, verified live on Dev

**Root cause (investigated):** `said` (atom_ranking.py's 4th rank-sum axis) was `SUM(LENGTH(tour_atoms.text))`, but AA-509's Decision 1 changed `text` to a terse `f"{place} — {action}"` mechanical join — so `said` no longer measured how much an itinerary elaborates on a moment.

**Fix:** ported Ms. Thư's `Atom.evidence` (aa-social-media models.py) — T5 atomize now asks the LLM for a verbatim source-text quote per atom. `checkable_evidence()` validates the quote actually appears in the day's body (whitespace/case-insensitive), falling back to the whole day body if it doesn't. `said` now reads `COALESCE(evidence, text)`.

**PR:** [AA-CIS-App #416](https://github.com/AdventureAsia365-Ecosys/AA-CIS-App/pull/416) — merged (squash). Migration 160 (`tour_atoms.evidence`) applied to Dev.

**Live test (5 never-rewritten raw tours — chosen to avoid touching the 116 already-published tours):**
- Ran real S1 rewrite (`/admin/run-tour-async`) on 5 tours (Mongolia + 4 India), all approved+published.
- Re-ran atomize (`_run_a3_atomize_background`, via ECS exec — the automatic A3 fire-and-forget had raced ahead of the migration apply, so the first pass had no `evidence` column) — all 5 tours succeeded: atomize → segment_matching → ranking (6 markets) → route_detection, no errors.
- **Result: 137/137 atoms (100%) have real evidence.** avg `text` length 40-60 chars vs avg `evidence` length 106-317 chars — the signal is real now. Sampled evidence is genuinely verbatim (e.g. "Sukhbaatar Square" atom quotes exactly "the itinerary moves to Sukhbaatar Square in the city centre, the principal site of Mongolia's 1990 democratic transition" — matches the actual rewritten itinerary text, not a paraphrase).

### 2026-09-22 03:25 — nghiep pham quoc

**Sub 2 (PAA embedding-match) — verified complete on Dev.**

After 2 follow-up fixes beyond the original redesign (PR #419 decoupled the per-market loop + added a question-embedding cache; PR #420 fixed a remaining scope bug), live re-test on Dev confirms the pipeline now completes in a reasonable time and produces real vector matches:

- **Cold-start trigger** (empty `questions_count` cache, 3463 platform Segments): segment matching → PAA landing → ranking (6 markets) → route detection completed in **~6 minutes**. Previously (before PR #420's scope fix) a single tour-triggered recompute did not complete after **over 6 hours**.
- **Warm-cache trigger** (2506/3463 Segments already cached): same full pipeline completed in **~19 seconds**.
- `atom_matches`: 482 real vector matches vs 17 claim-by-name fallbacks — embedding-match is doing real work, not silently falling back.
- `question_embedding` cache: 78 distinct PAA questions cached (no re-embedding across runs/Segments).
- Confirmed no adverse effect on already-published tours' `atom_ranking`/`route` data — the earlier redesign test (before the scope fix) never actually reached `run_atom_ranking()` for any of those tours (verified via CloudWatch logs — `ranking_done` never fired), so no published tour's ranking was overwritten with wrong data during testing.

**Root cause chain** (for the record): redesign (PR #419) fixed the 6x-per-market duplication and added a question-embedding cache, but `precompute_question_landings()` was still scanning the WHOLE platform's Segment set on every single tour-triggered call. PR #420 added a `questions_count` cache column on `atom_segment` (migration 163) so only the triggering tour's own Segments get recomputed; every other Segment's count is read back from cache instead of re-landed.

All 4 rank-sum axes (demand, recurrence, questions, said) are now measuring real signal, not a disclosed limitation:
- Sub 1: `said` now reads `evidence` (verbatim source text), not the terse `text` join.
- Sub 2: `questions` now lands PAA via embedding-match (Cohere Embed v4), with claim-by-name as a visible fallback (`matched_by` column), not silently indistinguishable.

PRs: #416 (Sub 1), #417/#418/#419/#420 (Sub 2 + follow-ups).

**Scope note:** a separate investigation into Ms. Thư's full model (beyond this issue's "rank-sum 4-axis, deterministic, no LLM" scope) surfaced a "Debate stage" (`contested` metric, Critic/Judge LLM calls that can cut a Segment from a slate) — this is a materially different mechanism (LLM-based cut, not rank-sum) with several open design questions (SERP-domain data source, Brand Identity document, model choice). Tracking as a separate issue, not folded into this one.
