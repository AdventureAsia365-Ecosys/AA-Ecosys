# AA-638 — [Tenant Portal] Product polish: onboarding checklist, skeleton loading, notifications, ⌘K palette, usage chart

## Context

Follow-up to [AA-605](https://linear.app/aa-ecosys/issue/AA-605/uiux-djong-bo-phong-cach-admin-portal-voi-trang-chinh-adventureasia). The aim is for the tenant portal to feel like a commercial SaaS product (Stripe, Linear and similar), not an internal tool.

## Scope

1. **Getting-started checklist** on the Dashboard for new tenants, based on real state: set up Brand → rewrite the first tour → write the first social post → connect WordPress. Each step has a check and a link. The card hides once all steps are done, and can be dismissed.
2. **Skeleton loading.** Shared skeleton primitives replace the spinners on the main pages, so layout does not jump when data arrives.
3. **Notifications panel** behind the top-bar bell, fed by the existing activity data: tour finished, post held, published. It shows an unread dot based on the last-seen timestamp (per browser).
4. **⌘K command palette.** Jump to any portal page, search tours by name (opens Browse Tours filtered), and run quick actions.
5. **Usage chart.** A small daily API-calls / rewrites sparkline for the current month on the Dashboard, beside the quota bars. Only if a per-day source exists; otherwise document the gap and skip.
