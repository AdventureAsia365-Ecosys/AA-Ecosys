## Việc (backend)

1. **Gate** `severity` **(block/warn/note)** trên `GateResultLite` (`services/acp_content_writing/quality_gates.py`) — thay/bổ sung 2 cờ `blocking`/`repairable`:
   * `block`: grounding(F1), banned(F2), cta_clear, FACT_CHECK, cannibalization(F10).
   * `warn`: F8 framework/formula-fit, brand_fit + GENERIC_AI_WORDING (tách khỏi F9), within_tenant_reuse.
   * `note`: promises_an_option.
   * `block` KHÔNG còn nghĩa "chặn tenant thấy bài" → chỉ trigger writer retry ≤2 (MAX_ATTEMPTS=2 giữ nguyên), sau đó vẫn ship.
2. **Tách F9**: giữ block cho cta_clear + FACT_CHECK (product-truth/contract); chuyển brand_fit + GENERIC_AI_WORDING sang `warn`. F8 → `warn` toàn bộ.
3. **Bỏ** `held` **phía tenant**: sau ≤2 retry, piece = "xong"/approved cho tenant (severity là cờ nội bộ). Publish cho phép cả bài từng-held. Điều chỉnh `run_quality_gates` outcome + `service.py` finalize + router publish gate (`v1_publish.py` đang chặn `status!='approved'`).
4. **Dọn leak** `/pieces/{id}`: `service.py::_row_to_dict`/`fetch_piece` bỏ `held_reason`/`gate_ledger`/`repair_log`/`flags` khỏi response tenant (GIỮ trong DB cho admin). Bỏ `ready_state=not_ready`.
5. **Metrics table phẳng (migration 153)**: ghi lúc finalize piece — piece_id/tenant/channel/gate/severity/passed/attempt_number/created_at. Cho admin monitor query nhanh (không aggregate JSONB `gate_ledger` mỗi lần). Xem tái dùng `audit_log` (mig 030) nếu đủ.
6. **Fix blog publish MARKDOWN→HTML (BUG hiện tại)**: `v1_publish.py::_call_adapter` đẩy `content_html=content_text` nhưng content_text là markdown → WordPress hiển thị `##`/`**` thô. Render fragment (`<article>`) trước khi publish.
7. **Export full-HTML VÀ bare-article**: `export.py::render_content_text_to_html` tách 2 chế độ — `document` (full-HTML, download + preview) + `fragment` (bare `<article>`, publish + nhúng CMS). Router `export_piece` nhận thêm param chọn chế độ cho blog.
8. **Export & publish ghi audit** để admin đếm (tenant/bài/kênh/thời điểm). Export hiện chưa ghi.
