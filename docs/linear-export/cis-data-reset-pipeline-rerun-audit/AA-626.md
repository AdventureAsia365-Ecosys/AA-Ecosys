## Bối cảnh (S189, Nghiệp chốt)

Làm rõ mô hình version (query DB thật S189): `generated_content` 124 tour / 180 version (approved 122 / hitl 58); `published_tours` (Master Content) = 116 tour, **1 row/tour** (UPSERT khi publish version mới, master_status active/inactive/trashed); `review_queue` pending = 58 version thuộc 44 tour (1 tour fail nhiều lần = nhiều row).

**Vấn đề UX:** 1 tour có thể vừa có version approved (đã publish) VỪA còn version hitl cũ trong review_queue. Các version hitl đó là **rác** — không cần sửa, chỉ cần bỏ (dismiss). UI hiện chưa cho làm việc đó, và review_queue dạng card khó thấy version/ngày viết/lý do rớt.

## Việc 1 — Review Queue: LÀM LẠI UI cho đẹp + rõ (frontend/app/admin/review/page.tsx)

* Đổi từ **card → BẢNG, mỗi row click MỞ RỘNG xuống xem chi tiết** (giữ toàn bộ chức năng hiện có: edit/save PATCH, regenerate, re-validate — ĐÃ CÓ, không bỏ).
* Cột bảng: Tour · Nước · **Version (vN)** · **Ngày viết** · Điểm tổng · Lý do rớt (chip). Sort được mọi cột.
* **Chip lỗi phân màu theo bản chất:** đỏ = product-truth (chặn thật), cam = brand/style (có thể nới), xám = low quality — để nhìn phát biết tour "oan" (điểm cao chỉ lỗi cam) vs tệ thật.
* Row expand: breakdown điểm (brand/seo/struct/qual) + danh sách lỗi đầy đủ + nội dung.
* **NÚT MỚI "Dismiss" (bỏ version fail):** với version hitl mà tour đã có version approved khác → bỏ thẳng khỏi review_queue KHÔNG cần sửa. Cần endpoint BE mới (chỉ update review_status='dismissed' hoặc tương đương, KHÔNG đụng content). Xác nhận enum review_status hỗ trợ + không phá logic re-enqueue idempotent.
* Toggle "gộp theo tour" (58 version → 44 tour) để bớt rối.
* Summary strip nhóm theo lý do (manual_check / flagged / low-quality), bấm lọc.
