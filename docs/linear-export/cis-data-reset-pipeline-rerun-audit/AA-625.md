## Bối cảnh (S189, Nghiệp chốt)

Cache SEO (Redis) trong `services/seo_intelligence/handler.py::process_seo` hiện TTL **86400s (24h)**, scope theo `(seed, location_code)` — tour cùng nước/market trong 24h thì cache HIT (cost $0), quá 24h thì MISS lại → mỗi MISS tốn **3 request DataForSEO tính phí** (search_volume + SERP advanced + keyword_ideas).

Rerun 763 tour thường rải qua nhiều ngày → cache hết hạn giữa chừng → tốn lại tiền cho cùng seed/market. Search volume + SERP của keyword du lịch đổi rất chậm (theo tuần/tháng), nên 24h là quá ngắn.

## Việc

* Đổi TTL cache Redis SEO **86400 → 604800 (7 ngày)** ở `services/seo_intelligence/handler.py`:
  * Nhánh fetched: `cache.set(redis_seed_key, seo_data, ttl_seconds=...)` (\~dòng 139).
  * Nhánh custom_keywords: `cache.set(redis_seed_key, existing, ttl_seconds=...)` (\~dòng 118).
  * Nên tách thành 1 hằng số `_SEO_CACHE_TTL_SECONDS = 7 * 24 * 3600` để 1 chỗ sửa.
* Lưu ý: cột DB `seo_context.expires_at` hiện set `+24h` (\~dòng 171) — đây là trace-only (row identity là tour_id, migration 075), cân nhắc đồng bộ 7 ngày cho nhất quán hiển thị (không ảnh hưởng logic cache).

## Bằng chứng hiện trạng (query DFS thật S189)

* Tài khoản `thu@adventure.asia`: đã nạp lại, balance \~$49.96 (tổng nạp $201). 1 call search_volume = $0.09.
