## Context

Found while planning G4 (rerun) sequencing (S194): `platform-stats` page still has a `TrustRampSection` calling `GET/POST /admin/a4/trust-ramp*`, but that backend route was deliberately removed in [AA-603](https://linear.app/aa-ecosys/issue/AA-603/cleanup-drop-cum-bang-n7n8-dead-sau-khi-go-code-reader-deploy) (S191, PR [AdventureAsia365-Ecosys/AA-CIS-App#413](https://linear.app/aa-ecosys/review/aa-603-remove-dead-n7n8-produce-flow-feedback-loop-trust-ramp-83fcc91c1732)) — the FE call site was missed when the backend was cleaned up. Result: the section renders `HTTP 404` in production right now.

This is a class of bug, not a one-off: whenever a backend route/table is removed as dead ([AA-603](https://linear.app/aa-ecosys/issue/AA-603/cleanup-drop-cum-bang-n7n8-dead-sau-khi-go-code-reader-deploy) removed 13 source files across N7/N8), any FE page still calling it will silently 404 unless someone specifically checks. Given G4/G5/G6 ([AA-599](https://linear.app/aa-ecosys/issue/AA-599/g4-chay-lai-s1-master-content-verify-s1-hoat-djong-ui)/600/601) are about to rerun the pipeline and surface fresh data across every admin page, better to catch these now than discover them mid-rerun or have G6 ([AA-601](https://linear.app/aa-ecosys/issue/AA-601/g6-audit-ui-admin-verify-moi-trang-hien-thi-djung-du-lieu-that-khong), which only runs AFTER rerun) be the first place they're found.

## Scope

* Audit every admin page under `frontend/app/admin/**` for `fetch()`/API calls, cross-reference against currently-registered backend routes (`api/routers/*.py`, `main.py` includes).
* Flag any FE call site pointing at a route that either 404s live or is not registered in any router — not just Trust Ramp, the whole surface.
* Fix trivial ones inline (dead section removal, same treatment as Trust Ramp — see \[AA-633 companion fix\]). Anything requiring product-level decision (e.g. "should this section come back in another form?") — log and hand back to Nghiệp instead of guessing.
* This is NOT [AA-601](https://linear.app/aa-ecosys/issue/AA-601/g6-audit-ui-admin-verify-moi-trang-hien-thi-djung-du-lieu-that-khong) (G6) — G6 verifies DATA correctness against fresh post-rerun content. This issue verifies the UI has no dead/404 call sites BEFORE rerun even starts, independent of what data exists.

## Out of scope

* Data correctness checks (that's [AA-601](https://linear.app/aa-ecosys/issue/AA-601/g6-audit-ui-admin-verify-moi-trang-hien-thi-djung-du-lieu-that-khong), runs after rerun).
* Design/style pass (that's [AA-605](https://linear.app/aa-ecosys/issue/AA-605/uiux-djong-bo-phong-cach-admin-portal-voi-trang-chinh-adventureasia), unrelated).
