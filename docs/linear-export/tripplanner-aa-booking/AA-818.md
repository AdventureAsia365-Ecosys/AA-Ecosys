# AA-818 — [Infra] Custom domains for TripPlanner and AA-Booking on lumiguides.it.com — frontends + APIs off vercel.app / execute-api

## Problem

S236 (DNS check 14/10/2026): only CIS uses sub-domains (`aa-cis.lumiguides.it.com`, `api-cis.lumiguides.it.com`). TripPlanner runs on `aa-tripplanner.vercel.app` + `9vqkfbukvh.execute-api.us-west-1.amazonaws.com`; AA-Booking on `aa-booking-admin.vercel.app` + `9z3xnalp59.execute-api.us-west-1.amazonaws.com/dev`. ADR 0004 O2 already decided `api-booking.lumiguides.it.com`. Consequences today: Mapbox token works only on the [vercel.app](<http://vercel.app>) alias, SEO canonical points at [vercel.app](<http://vercel.app>), deployment URLs are noindex.

## Scope

1. Names (proposal): `tripplanner.lumiguides.it.com`, `api-tripplanner.lumiguides.it.com`, `booking.lumiguides.it.com` (staff admin), `api-booking.lumiguides.it.com`.
2. Terraform (AA-CIS-Infra): ACM certs, API Gateway custom domains + base path mappings, DNS records (where the [lumiguides.it.com](<http://lumiguides.it.com>) zone lives).
3. Vercel: add domains to `aa-tripplanner` and `aa-booking-admin`; keep Vercel Authentication on previews only for the admin.
4. App config: TripPlanner `NEXT_PUBLIC_SITE_URL`/canonical + sitemap host, BFF API base URLs, Booking `BOOKING_API_URL`/`CIS_API_URL`, CORS, Mapbox token URL restrictions, Cognito callback/logout URLs (ADR 0006), CIS JWT issuer/audience unchanged.
   Out of scope: production environment (Dev only).

## Done when

* All four hostnames resolve with valid TLS; TripPlanner pages + sitemap use the new canonical host; Booking staff admin logs in and lists trip cases on `booking.lumiguides.it.com`; `curl https://api-booking.lumiguides.it.com/booking/health/ready` → 200.
