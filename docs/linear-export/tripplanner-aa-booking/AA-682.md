### 2026-10-06 00:41 — nghiep pham quoc

Highest-risk side effects in the whole ecosystem live here (invoices, payment schedule, supplier bills). From the Harness Engineering review:

- Every payment/charge call carries an idempotency key the provider honours; store the provider's reference before marking anything paid.
- Retry = read-before-retry against the provider, never a blind re-send.
- No payment credentials in agent sessions or LLM prompts/logs; payment actions are never executed by an agent.
- Invoice/payment state transitions enforced in the DB (same pattern as the trip-case state machine).

**Key decisions**
- The 13 case statuses stay. "Confirmed & Booked" is a computed badge.
- Post-sale statuses are system-managed: `change_status` refuses them except `cancelled`.
- Payments use record-then-verify by a second person, with an evidence file (except cash). Every money write takes an idempotency key with `request_sha256`.
- MVP invoices are proforma.
- The B2B tie-in reuses the desk function. `booking.b2b.v1` stays at 1.1.
- No traveller data on B2B cases.
- Evidence files go to a private KMS bucket.
- Cost ≈ $1.05/month (the KMS key); no LLM.

**Critic:** fixed 9 blocking issues. They include:
- `change_status` could set `paid` with no invoice;
- the B2B cancel path broke after an auto-advance;
- a declined booking blocked a replacement;
- the payment verify race;
- amendments after a deposit;
- reminder duplicates.
