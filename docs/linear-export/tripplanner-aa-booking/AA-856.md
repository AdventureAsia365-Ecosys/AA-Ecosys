# AA-856 — [TripPlanner] Search fails under load: Cohere Embed V4 quota is 20 requests/min on acc2 — cache query embeddings, keyword fallback, raise the quota

## Problem

S239 burst test ([AA-833](https://linear.app/aa-ecosys/issue/AA-833/dataops-tripplanner-lambda-throttle-alarms-stop-paging-on-single-5), 15 concurrent for 60 s on the home-page browse paths, 1,959 requests): 59 browse Lambda errors, all in search: `All models failed for stage 'tp_search_embed': cohere-embed-v4@acc2: ThrottlingException ... Too many requests`. Service Quotas on acc2 us-west-1: Cohere Embed V4 cross-region **20 requests per minute** (300k tokens/min). Every search query is embedded once, so the whole site can serve about 20 searches per minute; above that search returns 500.

## Scope

1. Cache query embeddings: normalised query text → vector (in-Lambda LRU + a shared cache table or Redis if available), so repeated queries never call Bedrock.
2. On a Bedrock throttle/error, search falls back to keyword/trigram ranking over the catalog instead of 500 (log the fallback).
3. Request a Service Quotas increase for Cohere Embed V4 requests per minute on acc2 (e.g. 20 → 300) and record the case id.
4. Keep `tp_search_embed` calls logged in `shared.llm_call_log` (cache hits not billed).

## Done when

* Re-run of the S239 burst (`docs/audits/2026-10-16-S239-in-progress-audit/time-gated-now/aa833-burst.py 15 60`) returns 0 HTTP 500 on search; throttled embeds show as fallbacks, not errors.
* Cache hit rate on repeated queries visible in logs; quota request submitted (case id) or raised value visible in Service Quotas.
