## Context

AA-Booking runs on the **same acc2 infrastructure and RDS** (new schema, decided 28/09). The hand-off can therefore be an in-database **transactional outbox**, not a cross-region webhook.

## Scope

* On "Send to advisor", TripPlanner writes `tripplanner.outbox` (`event = inquiry.submitted`, `schema_version = 1`), in the same transaction as the draft.
* **Payload:**
  * customer with a consent flag and timestamp;
  * the draft days and components;
  * the **leg chain** (`source_tour_id`, `day_from`, `day_to`) and the transfers;
  * narration;
  * an idempotency key (`draft_id` + revision).
* An AA-Booking job consumes the outbox:
  * creates the `trip_case` (status **New Inquiry**), linked to the template(s) of the tours used;
  * creates V1 (`is_sent_to_customer = false`) with the itinerary mapped to activities/destinations via `external_ref`;
  * assigns staff (`staff_assignments`) by rule.
* Replace the `notify.py` stub with an advisor notification (email/SES when ready; in-app notification first).
* Contract file: `docs/contracts/inquiry.submitted.v1.json` (root repo).

## Done when

A draft submitted on Dev appears as a Trip Case with V1 in AA-Booking. A re-submit with the same key creates no duplicate.

Supersedes the open items in `docs/tripplanner-to-aaa-handoff.md`.
