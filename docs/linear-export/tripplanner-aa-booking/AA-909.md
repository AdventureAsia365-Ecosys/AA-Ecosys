## Problem

TripPlanner `CONTEXT.md` (line \~157) states that guest-owned reads are checked against the hashed guest token (tp-011/012), but the assembly read GETs for a trip (trip, suggestions, coverage, activities) load by `trip_id` only. Anyone holding a trip id can read that trip (S244 master plan, gap list). Writes and `/narrate` already check ownership ([AA-805](https://linear.app/aa-ecosys/issue/AA-805/tripplanner-ai-phase-0-narration-spend-caps-cache-session-ownership-ai) Phase 0).

## Scope

1. Inventory every GET in the assembly Lambda that takes a `trip_id` (grep in the PR).
2. Require the guest token (or, later, the signed-in owner) and answer 404 for a mismatch (no existence leak).
3. BFF passes the token the browser already holds; no new env var.
4. Unit tests per route: right token 200, wrong/missing 404.

## Done when

* Tests above in CI.
* Live on Dev: a trip read with another session's token answers 404; the owner's planner flow (map, plan, send to advisor) still works (preview + production smoke).
