## Problem

The S237 UI verify of live TripPlanner found three small defects on /plan that no issue owns:

* D10 was marked "tracked under [AA-674](https://linear.app/aa-ecosys/issue/AA-674/tripplanner-multi-tour-trip-composition-route-constrained-suggest-next)", but [AA-674](https://linear.app/aa-ecosys/issue/AA-674/tripplanner-multi-tour-trip-composition-route-constrained-suggest-next) is Done and covered trip composition, not this.
* [AA-812](https://linear.app/aa-ecosys/issue/AA-812/tripplanner-tour-detail-pages-destination-pages-ssr-seo-tripcom-style) brought the tour, destination and home pages to WCAG AA (PR #77), but /plan was out of scope.

The three defects:

* **D10 — 7 axe color-contrast violations on prod /plan (light mode).** The planner still uses the raw `aa-gold` and gray Tailwind classes instead of the [AA-812](https://linear.app/aa-ecosys/issue/AA-812/tripplanner-tour-detail-pages-destination-pages-ssr-seo-tripcom-style) tokens. Examples:
  * gold label #db9628 on #fff = 2.49:1
  * badge #b87a1a on #fff = 3.59:1
  * muted text #6b7280 on #f8f6f2 = 4.47:1
  * 11 px helper text in the trip list
* **D11 — Customise on tours with no planner places** (e.g. Sri Lanka `63d21f32`, Vietnam HCM Trail `ca1d7500`).
  * `tour-route` returns 404. The fallback from PR #73 works, but the expected 404 shows as a red console error.
  * This issue covers only the client behaviour. Building places for every tour is [AA-712](https://linear.app/aa-ecosys/issue/AA-712/adr-0002-move-the-place-pipeline-itinerary-places-geocoding-tour-graph).
* **D12 — "1 DAYS" on one-day tours.**
  * `TourListPane.tsx:163` renders `${duration_days} days`.
  * The same pattern is in `RoutePlanner.tsx:139`, `PlanPrefill.tsx:76/102` and `HomeSearch.tsx:94`.

## Scope

1. Move the /plan components onto the [AA-812](https://linear.app/aa-ecosys/issue/AA-812/tripplanner-tour-detail-pages-destination-pages-ssr-seo-tripcom-style) contrast tokens, in light and dark:
   * planner panel, TripPanel, TourListPane
   * badges, gold labels, muted helper text
2. Treat the expected "no planner route" response as a normal result, not a failed fetch:
   * either return 200 with `match: none`, or check before fetching;
   * the console stays clean;
   * the fallback message and the pre-filled route finder stay as they are.
3. Add one shared `formatDays(n)` helper ("1 day" / "N days") and use it at every day-count label, including destination ranges.
4. Optional: an axe check for /plan in the UI smoke step.

Out of scope: building planner places for tours that lack them ([AA-712](https://linear.app/aa-ecosys/issue/AA-712/adr-0002-move-the-place-pipeline-itinerary-places-geocoding-tour-graph)), the ecosystem design system ([AA-655](https://linear.app/aa-ecosys/issue/AA-655/design-one-design-system-for-the-ecosystem-shared-tokens-component-kit)), the Mapbox preview token (D7).

## Done when

* On prod `/plan`, axe reports 0 color-contrast violations:
  * in light and dark mode;
  * at 1440 and 390.
    The axe JSON and screenshots are saved in the audit folder.
* Customise on Sri Lanka `63d21f32` shows the fallback with Sri Lanka + 10 days pre-filled, and the console shows no error.
* A one-day tour shows "1 day". Unit tests cover `formatDays(1)` and `formatDays(2)`.
