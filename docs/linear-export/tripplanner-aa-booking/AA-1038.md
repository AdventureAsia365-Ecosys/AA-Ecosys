## Problem

ADR 0019 d10/d11/d23 (S265). TripPlanner is a single-brand AA B2C site. Under the B2B-only model it becomes a product each tenant sells: their brand, only AA live tours, and leads going to the tenant, with AA keeping no end-traveller data long term. The frontend leaves Vercel for ECS on Dev first (tech lead decision S265: one Spot task + CloudFront + CLOUDFRONT-scope WAF, about 13–15 USD a month; prod sized later). Plan: `docs/audits/2026-11-03-S265-ecosystem-restructure/` README §8, clarifications TL-10, TL-11, TL-23, BO-4. Takes over [AA-1005](https://linear.app/aa-ecosys/issue/AA-1005/identity-traveller-googlefacebook-sign-in-booking-customer-app-sign-in) and [AA-703](https://linear.app/aa-ecosys/issue/AA-703/auth-identity-epic-adr-0006-cognito-workforce-external-pools-email) (re-scope).

## Scope

* **Tenancy.**
  * `tenant_id` on `tripplanner.*` with FORCE RLS; existing trips are backfilled to a demo tenant.
  * Tenant resolved by path `/{slug}`, plus a launcher snippet.
  * New views `catalog.v_tenant_tripplanner_v1` (tenant config, theme tokens) and `catalog.v_tenant_tour_v1` (AA live tours plus the tenant's own T2 text).
* **Leads and cost.**
  * Travellers are guests; the trip request goes as `lead.submitted.v1` to the tenant CRM (add-on), a webhook or e-mail, and TripPlanner keeps it only until delivered.
  * Per-tenant AI cap and usage view.
* **Hosting.**
  * Dockerfile standalone; `tripplanner_web.tf` based on `crm_portal.tf`; ECR immutable.
  * CloudFront distribution plus a web ACL (rate rule + Challenge on search/narrate) replaces BotID.
  * Previews become `next start` in CI.
  * The approved cost yeses apply here (Fargate, WAF).

## Done-when

* On Dev, two synthetic tenants open the planner at their own path with their own brand and see only AA live tours.
* A request lands in tenant A's CRM, not B's.
* RLS isolation probe is green.
* The frontend runs on ECS behind CloudFront + WAF with Vercel unused.
* Monthly Dev cost is observed after 2 weeks and reported.
