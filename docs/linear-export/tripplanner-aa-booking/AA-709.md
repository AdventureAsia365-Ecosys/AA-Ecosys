# AA-709 — [AAA] Research: load supplier price and AA selling price for raw tours

## Context

Most raw tours from the Jira Contents board have no price (S207 upload: Philippines 68/72 rows, Pakistan 8/18 without `price_raw`). Nghiệp's rule (01/10/2026): a missing price never blocks or drops a tour. Supplier price and our selling price are loaded later.

Today `raw_tours.price_raw` is one free-text string from the supplier sheet (e.g. `$1,722/person`, `from USD 495 per person`, `2355.0`). There is no supplier price vs selling price split, currency, unit (per person / per group), validity period or group-size tiers.

## Research questions

1. Where prices come from: supplier sheets, rate contracts, emails, the content team. Who owns the update.
2. Data model: supplier cost (net) vs AA selling price (markup or manual), currency, per-person/per-group, pax tiers, season/validity, single supplement. Does it belong in CIS (`raw_tours` / a `tour_price` table) or in AA-Booking (`booking.*`, see [AA-677](https://linear.app/aa-ecosys/issue/AA-677/aaa-erd-v2-re-evaluate-the-quanskill-erd-and-redesign-it-for-the) ERD)?
3. Loading path: admin Excel template + S0-style upload, admin UI editing, or a supplier API. Versioning when prices change.
4. Consumers: tour pages / TripPlanner "from" price, tenant marketplace, AAA quotes ([AA-681](https://linear.app/aa-ecosys/issue/AA-681/aaa-trip-case-workflow-mvp-inquiry-versions-v1vn-approved-confirmed)/682). What each one needs.
5. Parse the existing `price_raw` strings into a structured first value (with a review flag) vs re-collect them.

## Output

A short design note + recommendation (where the data lives, schema, loading flow), then build issues.

Raised in S207 (Claude Code session).

### 2026-10-14 03:36 — nghiep pham quoc

S235 (14/10/2026) — research answered as ADR 0005 "Pricing and supplier rates" (Proposed), AA-Ecosys PR #61 (`docs/adr/0005-pricing-and-supplier-rates.md`).
- Ownership: all price/supplier data in schema `booking`; CIS keeps content + day/service structure; entry UI in the shared staff admin calling the Booking API.
- Model: supplier contracts with validity → net rates per service type → cost sheet per tour × pax band × season → selling price = net ÷ (1 − margin).
- Margins (Nghiệp asked for a proposal; to confirm with Ms. Thư): B2C tailor-made 30% (floor 20%), B2C fixed departure 25% (18%), B2B reseller 15% on net (10%), peak +3–5 pts; overrides below floor need a reason (audited).
- Currency (Nghiệp): base USD, also EUR/GBP/AUD/SGD; supplier costs in their currency with dated FX; FX buffer 2–3%; FX locked when a quote is sent; quotes valid 7–14 days.
- Outputs: `trip_plan_prices` + `booking.v_from_prices` (contract `price.from.v1`) for TripPlanner/CIS "from" prices.
- Loading: Excel template upload → validate → review → publish (versioned), then admin UI; `price_raw` parsed once into a flagged reference price.
- Open: who enters prices + file formats; tenant resale (assumed yes, B2B net list); tax/VAT.
