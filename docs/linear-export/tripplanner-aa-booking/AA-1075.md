## Problem

The S275 study of an Odoo tour & travel app (AA-1065, report root `docs/research/2026-11-10-odoo-tour-travel-plugin-comparison.md`) found these gaps. The tech lead approved building all of them (S275, 10/11/2026). We build the features in our own code; the app's code is OPL-1 and is never copied.

## Scope

* **Staff-entered bookings on behalf of an agency** (bk-11, missing, value high, effort M).
  * Today: Since ADR 0019 the only way to create a trip case is the B2B hold confirm through the M2M API (app/b2b/holds.py); POST /booking/trip-cases and 'new case from trip plan' return 410 (app.b2c.refuse_new_case). An agency booking that arrives by e-mail cannot be keyed in.
  * Build: Staff route POST /booking/b2b-desk/bookings (permission b2b_desk.book: admin, sales): choose agency (b2b_partners), product components, departure, pax split, room mix, agency reference; runs the existing quote -> hold -> confirm services in one call with entered_via='staff', entered_by, idempotency key; credit stop and allotment rules apply; price override below floor needs a second approver. trip_cases.source_system stays 'crm' path semantics with a new column entered_via (api|staff). Outbox event booking.created_by_aa (contract booking.b2b.v1 minor) so the agency's CRM imports the booking as
  * Depends on: none (bk-03 if allotments exist)
* **Service vouchers for agencies** (bk-12, partly, value medium, effort M).
  * Today: Agency-facing GET /booking/b2b/v1/bookings/{id}/confirmation (JSON or printable HTML; no names, no prices). No vouchers on B2B cases: ops_files refuses documents there (422 document_not_allowed_b2b, DM-6.8). No PDF renderer. supplier_bookings has confirmation_ref but no time or pick-up fields.
  * Build: supplier_bookings gains service_time, pickup_point, dropoff_point, voucher_note (non-PII). New B2B read GET /booking/b2b/v1/bookings/{id}/vouchers (JSON + printable HTML, one page per confirmed supplier booking: service, date, time, pick-up, supplier name and booking phone, confirmation_ref, pax counts by age band, AA 24h contact). Generated, never uploaded, no net prices, no traveller names; the CRM fills in the lead traveller name when the agency prints (CRM-side merge). Event line.confirmed already tells the CRM when to refresh.
  * Depends on: bk-06
* **Departure operations manifest and rooming list** (bk-13, partly, value medium, effort L).
  * Today: Booking stores counts only (trip_cases.pax/adults/children; pax split and room mix per b2b_quote_lines). Traveller identity lives only in crm.traveler and related tables (DM-6.8, ADR 0019 d11: AA is processor). No manifest or rooming list exists.
  * Build: Step 1 (no new PII): staff page /departures/{id}/manifest printable from stored data: per agency and case -> adults/children/infants, room mix, agency reference, supplier confirmations. Step 2 (needs DM-6.8 / ADR 0019 amendment): new contract crm.rooming.v1 where the agency's CRM pushes the rooming list for a confirmed hold (names, room grouping, meal, nationality only) into booking.b2b_rooming (processor data, pii-tagged, purpose ops, auto-deleted 30 days after trip end by the retention job); manifest and supplier PO (bk-06) then show names. Permission ops-only, every view audited.
  * Depends on: bk-04; step 2 needs a data-standard amendment

No staff override or waive, no link to supplier bookings, no supplier penalty cost, whole-booking cancel only.

Staff route POST /booking/b2b-desk/bookings/{id}/cancel (with dry run) for e-mail requests. On any cancel: pending/requested supplier_bookings -> cancelled automatically; confirmed ones -> task 'cancel with supplier' with a supplier_cancel_fee amount + currency recorded when the supplier answers (feeds bk-08 profit). New partial cancel POST .../bookings/{id}/lines/{ref}/reduce (fewer seats on a line): fee by policy on removed seats, seats released, new approved version. Event booking.canc
  * Depends on: bk-06 (supplier order link), bk-08
* **Child, infant and single-supplement net prices for agencies** (bk-15, partly, value medium, effort M).
  * Today: b2b_quote_lines store pax_adult/child/infant, but app/b2b/components.py prices children like adults and infants as free; room mix handles singles only on room components. The trip plan price matrix (booking.trip_plan_prices) has one per-person amount per pax band, no child/infant/single columns; tariff CSV shows the same.
  * Build: booking.trip_plan_prices gains child_amount, infant_amount, single_supplement_amount (+ net columns); booking.trip_plans gains child_age_max, infant_age_max. Cost sheet computes single supplement = single room rate - half the double rate per night, and child amount from a child rule (pricing_rules gains child_pct, infant_flat) or a child rate on the supplier rate when present. Quote engine applies them to tp: lines; GET /tariff and price.from.v1 unchanged for adults. CRM reads the extra columns for its traveller-facing price.
  * Depends on: none
* **Per-product deposit and balance terms** (bk-18, partly, value low, effort S).
  * Today: booking.billing_terms default or per agency (deposit_pct 30, balance 30 days before departure); bk_settlement_draft bills deposit then balance per confirmed hold. Not per trip plan.
  * Build: booking.billing_terms gains nullable trip_plan_id scope (unique per agency/plan/default with effective window). The settlement draft and GET /terms pick the most specific row (agency+plan > plan > agency > default). Staff UI: terms override on the trip plan page.
  * Depends on: none
