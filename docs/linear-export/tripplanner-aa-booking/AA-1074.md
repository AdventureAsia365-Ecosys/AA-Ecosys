## Problem

The S275 study of an Odoo tour & travel app (AA-1065, report root `docs/research/2026-11-10-odoo-tour-travel-plugin-comparison.md`) found these gaps. The tech lead approved building all of them (S275, 10/11/2026). We build the features in our own code; the app's code is OPL-1 and is never copied.

## Scope

* **FX-normalised costs and realised FX difference** (bk-10, partly, value medium, effort M).
  * Today: booking.fx_rates (rate_per_usd, buffer, as_of, maker-checker); FX locked on each quote and version; supplier rates, bills and payouts in any ISO currency; selling USD/EUR/GBP/AUD/SGD + VND for B2B. Cost vs billed does no conversion, so mixed-currency cases cannot be totalled.
  * Build: Pure helper app/pricing/fx.to_usd(amount, currency, on_date) using the approved plain rate in force (no buffer). Snapshot columns fx_rate_per_usd + fx_as_of on supplier_bookings (set at confirm) and supplier_bills (set at approve). View columns planned_usd, billed_usd, fx_difference_usd = billed_usd - planned_usd at the same native amount. Used by bk-07 and bk-08; the original currency always shown beside USD.
  * Depends on: none

  * Build: New table booking.departure_costs (id, departure_id, supplier_id, service_id, supplier_rate_id, basis group|vehicle|day|person, quantity, net_amount, currency, priced_for_pax, frozen_at, supplier_booking_id).   * Build: New table booking.supplier_orders (code PO-######, supplier_id, currency, status draft -> sent -> confirmed|partly_confirmed|cancelled, sent_at, sent_to, sent_by, total_net, snapshot jsonb, note) and supplier_bookings.supplier_order_id.   * Depends on: bk-05 (to include departure shared lines)
