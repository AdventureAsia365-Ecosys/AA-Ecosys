## Problem

The business owner bought an Odoo 19 app, "Tour and Travel Management" (Modvanta `mdv_tour_travel` 19.0.1.1.0, licence OPL-1), and asked for an analysis. The app is a B2C travel CRM / operations module. The asks are:

* compare its features with what we have;
* see how a mature travel app models the travel operations flow;
* above all, study its database design.

Odoo community modules for travel on GitHub (OCA and others) are in scope as extra references.

## Scope

* Read the module (models, views, security, data, wizards, reports, controllers). Map:
  * its **data model**: entities, key fields, relations, states, pricing and costing tables;
  * its **flows**:
    * package / itinerary;
    * departures and seats;
    * pricing rules;
    * booking, deposit and payment schedule;
    * travellers, passport and visa;
    * supplier components and purchase orders;
    * vouchers and manifests;
    * cancellation;
    * profit per booking, departure and channel;
    * agent portal and commission;
    * multi-currency.
* **Compare** with our ecosystem: AA-Booking (B2B only, R4), the AA-Partner CRM (agency app), the CIS catalogue (tours, atoms) and TripPlanner. For each feature: we have it / partly / missing / not wanted (B2B-only scope, ADR 0019).
* **Database design lessons:** what to adopt in Booking / CRM schemas and what not to, with reasons.
* Scan Odoo community travel modules on GitHub (OCA and the most-used others) for the same comparison, briefly.
* **Licence:** OPL-1 code is read for internal analysis only. No code is copied into any repo (all app repos and the root repo are public). The zip stays out of git.

## Done-when

* A research report in root `docs/research/`:
  * an English feature matrix and a data model comparison with diagrams;
  * recommendations ranked by value and effort.
* A short Vietnamese summary for the business owner, ready to send in the Jira draft at the session close.
* Follow-up issues are proposed (not created) for every recommended change, for the tech lead to approve.

  - supplier contracts and rates;

  - B2B holds and agency invoices;
  - traveller PII protection;
  - tour content.
