# AA-679 — [AAA] Catalog read in Booking: sellable trip plans over the live CIS catalog (catalog.v_tour) + "Use for trip case"

## Problem

Booking staff need to sell CIS tours as trip plans and start trip cases from them. S237 decision D4 (Nghiệp): Booking reads the CIS catalog **live** through the contract views (`catalog.v_tour`, `v_tour_day`, `v_tour_photo`, `v_destination`, CIS migration 225 grant to role `booking`) and keeps only its own commercial row; no outbox, no copied templates. Replaces the original outbox-sync design (kept in the S239 comment).

## Scope

* `booking.trip_plans` (bk-009): one commercial row per CIS tour, keyed on the CIS `source_id` (sellable, trip style, price hint, default channel, commercial notes). Content (title, days, photos) is always read live from the catalog views.
* Staff admin: trip plans list over the live catalog with sellable / commercial filters; commercial edit (`trip_plan.write`); "Use for trip case" creates a new trip case with V1, or a new version on an existing case, from the plan's days.
* A tour CIS unpublishes disappears from the list (the view only returns published tours).
* AAA never writes CIS tables; CIS never writes commercial data.

## Done when

* Commercial-row PUT is idempotent (same plan_id, no duplicate row, one audit row per real change).
* Staff list sellable plans with their commercial fields (API + UI), desktop and mobile.
* "Use for trip case" creates a trip case / version from a plan on Dev (UI), with one item per plan day.
* A tour unpublished in CIS no longer appears in the Booking trip plans list (evidence on Dev).
* The 390 px "Use for trip case" dialog footer is fully visible (S237 UI verify defect).
