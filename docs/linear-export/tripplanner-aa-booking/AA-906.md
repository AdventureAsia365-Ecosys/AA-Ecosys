## Problem

[AA-904](https://linear.app/aa-ecosys/issue/AA-904/tripplanner-planned-nextjs-14-15-upgrade-replaces-dependabot-pr-104) moves AA-TripPlanner-Web to Next 15.5 / React 19 / ESLint 9. CIS and Booking are on Next 16. Every Next 15 release pins postcss 8.4.31 (high advisories), so [AA-904](https://linear.app/aa-ecosys/issue/AA-904/tripplanner-planned-nextjs-14-15-upgrade-replaces-dependabot-pr-104) carries a `package.json` override to postcss 8.5.31; only Next ≥ 16.3 drops that pin. A scratch try of 16.4.2 on top of the [AA-904](https://linear.app/aa-ecosys/issue/AA-904/tripplanner-planned-nextjs-14-15-upgrade-replaces-dependabot-pr-104) branch builds and type-checks unchanged, but the React Compiler lint rules in eslint-config-next 16 report 23 errors.

## Scope

1. Bump `next` and `eslint-config-next` to 16; native flat config (drop `@eslint/eslintrc` FlatCompat) and the postcss override.
2. `middleware.ts` → `proxy.ts` (as CIS did in [AdventureAsia365-Ecosys/AA-CIS-App#831](https://linear.app/aa-ecosys/review/chore-rename-next-middlewarets-to-proxyts-next-16-convention-712662349bf4)).
3. Fix the 23 React Compiler lint errors (react-hooks/refs 14, set-state-in-effect 8, immutability 1) in `lib/useTrip.tsx`, `MapView`, `TripPanel`, `DestinationPopup`, `GuestResetNotice`, `TourListPane` — a careful refactor of the trip-state hook and map components, not rule disables.
4. Full preview smoke: map (Mapbox), search, /plan (country/days, `?tour=…&ask=1`), send-to-advisor; desktop + 390 px.

## Done when

* `npm ci`, lint (0 errors), typecheck, unit tests, `next build` green in CI; `npm audit --omit=dev` 0 vulnerabilities without the postcss override.
* Preview smoke screenshots attached; production deploy verified live.
