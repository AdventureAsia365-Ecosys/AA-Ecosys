## Problem

ADR 0004a (hybrid): Booking owns the supply/commercial data of hotels and activities (supplier, room/service types, net rates, allotment notes); CIS owns the customer-facing content. Staff cannot attach a hotel or service from a supplier to a trip case version today.

## Scope

* Migration bk-010: `booking.hotels` (supplier_id, CIS destination/place ref, name, category, status), `booking.hotel_room_types`, `booking.services` (supplier_id, kind, unit, CIS place ref), net rate rows with currency and validity. Migration-only PR → Infra byte copy → DB Migrate apply → code PR.
* API: CRUD + search; version items can reference a hotel room type / service and take its net rate as the default net.
* Staff admin: /hotels grid + detail drawer, /services list, using the CIS UI kit tokens. No customer-facing hotel photos in v1 (Q17).
* Known gap (ADR 0004a): DB-level isolation from CIS stays open until CIS stops connecting as the owner role ([AA-817](https://linear.app/aa-ecosys/issue/AA-817/security-cis-api-runtime-role-aa-cis-admin-is-not-filtered-by-rls) follow-ups).

## Depends on

Wave 2a (suppliers, bk-008); [AA-810](https://linear.app/aa-ecosys/issue/AA-810/aaa-minimal-pricing-engine-adr-0005-first-cut-pricing-rules-dated-fx) FX rates for non-USD nets.

## Done when

* bk-010 applied on Dev; a hotel with 2 room types and a service are created under a supplier and used as items in a trip case version, with the net rate pulled in and the sell price computed by the [AA-810](https://linear.app/aa-ecosys/issue/AA-810/aaa-minimal-pricing-engine-adr-0005-first-cut-pricing-rules-dated-fx) engine.
* Staff admin pages verified on the Vercel preview (desktop + mobile), CI green, deployed, evidence on this issue.
