## Problem

TripPlanner (B2C) LLM stages have only one shared daily cap (5 USD/day) and route throttles that apply to every visitor together. There is no limit per session, per IP or per signed-in traveller, and no bot check, so one visitor or a bot can use the whole day's budget and make the feature unavailable for everyone (capacity plan S261 §2.5, §3).

## Scope

1. Per-session and per-IP limits on `/narrate` and `/search` at the BFF or with Vercel Firewall rules (numbers from the plan, e.g. 10 narrations/hour/session, 30 searches/minute/IP, tuned on Dev).
2. Bot check (BotID or Turnstile free tier) before LLM-backed calls.
3. Higher allowance for signed-in travellers (business owner decision B7; default double).
4. Separate daily caps for search and narration; alert at 80 % and at the cap.
5. Graceful degradation text when a limit is hit (no spinner).

## Done when

- [ ] Playwright on Dev: the 11th narration in an hour from one session gets the limit message; a second session still works.
- [ ] A scripted burst from one IP is limited; the bot check blocks a headless client without a token.
- [ ] Daily caps per stage visible in the CIS cost page; the 80 % alert fires in a test.

## Deadline

Go-live minus 4 weeks (can be done before S8).
