## Problem

TripPlanner has one client-rendered page (`/`). There is no tour detail page, no destination page, no sitemap and no per-page metadata, so nothing is indexable and a customer cannot read a tour before building a trip (S236 design review vs [trip.com](<http://trip.com>)).

## Scope

1. `/tours/[slug]` server-rendered: gallery (CIS photo views), highlights, day-by-day itinerary, inclusions/exclusions, map of stops, "from $X" when available, sticky CTA "Customise this trip" (opens planner pre-filled) and "Ask an advisor".
2. `/destinations/[country]`: intro from CIS content, top tours, place highlights (place cards), map.
3. List view + sort next to the map pins on `/` (duration, intensity, month).
4. `sitemap.xml`, `robots.txt`, per-page metadata + JSON-LD (TouristTrip).
5. Data only through the CIS catalog contract (`catalog.tour.v1`, [AA-679](https://linear.app/aa-ecosys/issue/AA-679/aaa-catalog-sync-from-cis-templates-activities-destinations-via)) — no direct reads of `gold_aa_internal`.
   Out of scope: reviews, price calendar per date, instant booking.

## Done when

* On the Vercel preview, 3 tour pages and 2 destination pages render server-side (curl HTML contains the itinerary), Lighthouse SEO ≥ 90, mobile + desktop screenshots.
* No query in the new code touches `gold_aa_internal.*` directly.
