## Problem

ADR 0019 R8: an agency wants its TripPlanner on its own domain, for example `trip.agency-domain.com`, instead of our path `/{slug}`. Approved by the tech lead in S278 (D10, D13 NEW-D), estimated cost about 0 USD.

## Scope

* The agency adds a domain in its settings.
* The page shows the DNS records to create; ACM validates them.
* The CloudFront alternate name and the routing resolve the host to the tenant.
* The tenant's TLS certificate and the WAF rules carry over.
* The domain can be removed.
* Terraform in AA-CIS-Infra.
* A monthly cost estimate before apply, per the cost-before-new-AWS rule.

## Done when

* A synthetic tenant on a test sub-domain serves its branded TripPlanner over HTTPS.
* Removing the domain falls back to the path.
* Cost is stated and approved before apply.

**Custom domain gaps found in the S282 TripPlanner sales-model review (tech lead approved)**

Custom domain stays a Pro feature (or a 15 USD add-on under option B). Before it is sold:
1. Gate on `tp.custom_domain` at both ends:
   - when adding: `add_domain` today only checks for any TripPlanner subscription;
   - when serving: `catalog.v_tenant_tripplanner_v1` (CIS 429) and `lookup_host` return every active domain with no entitlement check. A tenant that moves from Pro down to Hosted keeps its live domain, so the domain should stop serving or drop.
   - The pricing lane l15 (S4) covers the add check. The serve check is added to this card.
2. `subject_gate` accepts the tenant's own domain for sales links (already open).
3. B2C leftovers leak onto agency hosts: `lib/tenantHost.ts` PASS_PATHS lets `/sign-in`, `/trips`, `/privacy` and `/terms` through on an agency domain. Agency hosts should get 404 on the B2C paths (removed with the B2C tables from 28/11, AA-1061), and the agency's own legal links instead of AA's platform pages.
