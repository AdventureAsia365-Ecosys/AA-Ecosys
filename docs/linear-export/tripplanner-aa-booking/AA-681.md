# AA-681 — [AAA] Trip Case workflow MVP — inquiry → versions (V1..Vn) → approved → confirmed order; staff assignment; customer "My Trips"

This follows the PRD end-to-end flow:

* A trip case is created from a TripPlanner inquiry (see the hand-off issue) or from a template inquiry.
* Sales builds versions: V1 is pre-filled from the leg chain. Versions are relational itineraries, as in the ERD rule. The customer always sees the latest version.
* **Status:** Building → Confirmed, using the enum of 13 statuses.
* **Approval:** the customer approves a version → it is locked → a Confirmed Trip Order is created.
* `staff_assignments` and notifications.
* **Customer app:** My Trips (list + status badge + itinerary view).

**Out of scope** (next issue): supplier bookings, invoices/payments, trip checks.

## Done when

A demo on Dev goes from a TripPlanner draft → trip case → V1 → V2 → approve → confirmed order, with an audit trail.
