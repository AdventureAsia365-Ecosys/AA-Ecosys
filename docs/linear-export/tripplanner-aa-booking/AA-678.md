# AA-678 — [AAA] Architecture + repo bootstrap on acc2 — AA-Booking repo (FastAPI + Next.js), ECS service, CI/OIDC, Terraform in AA-CIS-Infra

## Decisions (Nghiệp, 28/09)

* Build from scratch.
* Same acc2 infrastructure: no new account, region or database. The old AAA accounts are closed.

## Proposal

* **Repo:** `AdventureAsia365-Ecosys/AA-Booking`, with `backend/` (FastAPI, asyncpg, same patterns as CIS) and `frontend/` (Next.js; two surfaces: staff admin and customer app).
* **Runtime:**
  * a new ECS service `aa-booking-dev-api` on `aa-cis-dev-cluster`;
  * its own task role, allowed only on schema `booking` (a DB role with schema-level grants) and read-only on `shared.*` and the catalog views;
  * API Gateway route or subdomain (for example `api-booking.<domain>`);
  * frontend on Vercel.
* **Jobs:** reuse the job-runner pattern (catalog sync, inquiry intake, notifications).
* **CI/CD:** the same 5-check CI as CIS and the OIDC deploy role (`repo:AdventureAsia365-Ecosys*/AA-Booking*:*`).
* **IaC:** Terraform in AA-CIS-Infra, `accounts/aa365` (ECS service, ECR repo, secrets, DB role, API route).
* **Docs:** from day one, README + CONTEXT.md + `docs/adr/` in English.
* **Design system:** consumes the shared tokens/kit.

## Done when

* The repo exists with a health endpoint deployed to Dev via CI.
* Migration 001 creates `booking` schema v2 (from the ERD v2 issue).
* `ecosystem-architecture.md` is updated.
