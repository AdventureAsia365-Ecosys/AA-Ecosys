# AA-675 — [TripPlanner] Re-extraction job — rebuild itinerary_components + Tour Graph after each CIS rerun wave (Jev classification in shadow)

## Why

`itinerary_components` is built by an offline pipeline (`backend/extraction/*`) and is not refreshed when CIS publishes. The 16/09 CIS reset means it must be rebuilt after the rerun ([AA-600](https://linear.app/aa-ecosys/issue/AA-600/g5-atomize-segmentscoreroute-social-content-admin-verify-rebuild)).

## Scope

* The extraction runs as a job (job runner), triggered per country wave (or by a `catalog.tour.published` event later).
* It is idempotent per `(source_tour_id, day)`. Components of trashed tours are removed.
* It reads through the CIS **catalog read model** (views), not raw pipeline tables (ADR 0001, decision 1).
* Classification (activity / intensity / duration) through the Gateway. Jev Choice runs in shadow beside the current LLM extraction. On 28/09 the smoke test gave trekking 0.84 / strenuous 0.91.
* Geocoding outlier check (reuse `regeocode_outliers.py`).
* Rebuild the Tour Graph at the end.

## Done when

After the Bhutan wave, the components and graph exist for every Bhutan published tour, with a verification report.
