## Problem

Jira PR-31 (business owner, added 24/11): supplier prices are valid for a period (typically one year) and the system must remind the admins when a contract is about to end. Today ([AA-1151](https://linear.app/aa-ecosys/issue/AA-1151/booking-cis-optional-activities-as-aa-offers-with-places-sale-rules), bk-068) a daily job writes one in-app staff notification `contract.expiring` per contract ending within `contract_expiry_alert_days` (Pricing › Policy, 60), but:

* there is no e-mail, so an admin who does not open the Booking admin is not reminded;
* the "expiring" list is shown only on the Add-ons page, not on the supplier / contract pages or the dashboard, although the job covers every contract kind (hotels, transport, guides, activities);
* only an add-on contract was checked live; a hotel contract was not.

## Scope

* Dashboard **My work** tile "Contracts ending soon" (count, links to the list) and the expiring list on the supplier pages (supplier › Rates / contracts list) for every contract kind, reading `GET /booking/contracts/expiring`.
* One e-mail per contract and end date to the Booking staff who hold admin or contracting (or a recipient list that is a Pricing › Policy / Platform setting, never hard-coded), through the existing e-mail path; same `reminder_key` idempotency as the in-app notification, so a contract is mailed once per end date. English + Vietnamese body.
* Docs: Booking CONTEXT.md, the booking price setup guide (EN + VI).

## Done when

* A SYNTHETIC hotel contract ending within the window shows on the dashboard tile and the supplier page, gets one in-app notification and one e-mail (seen in the E2E mailbox), and a second job run sends nothing new.
* The window stays the Pricing › Policy value; changing it changes what is listed.
* CI green, deployed, live check recorded here.
