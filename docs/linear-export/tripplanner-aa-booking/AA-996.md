## Problem

`docs/ui-spec.md` §3 lists Figma screens "deliberately not built" (content editors for country/destination/activity/template, hard-delete dialogs, change password / reset / invite) and Destinations / Countries still render a WaveFrame. Nghiệp (S253): Booking must cover every Figma screen (120 PNG in `docs/AAA/figma_AAA/`).

## Scope

* CIS-owned content (Country / Destination / Activity / Template forms) shown in the Figma layout, read-only with a "From CIS" label and "Edit in CIS ↗" to the record's CIS admin page (or read through the CIS API); Booking commercial fields stay editable in place.
* Hard-delete dialogs become Deactivate / Archive / Cancel (soft delete); DELETE SUPPLIER → Deactivate supplier.
* "Sign-in & security" screen (sign-in method: email code via Cognito; link to the CIS staff/invite page ↗) in place of change password / reset password / invite.
* Destinations and Countries pages built on the "CIS content + Booking state" pattern.
* Compact density for zoomed laptops (backlog §2 proposal, approved S254).
* Last: Figma visual audit (120 PNG vs live screenshots, scored per screen).

## Done when

* Every PNG in `docs/AAA/figma_AAA/` maps to a live route/modal in `docs/ui-spec.md` §3 (no "not built" rows left).
* Booking CI green, deployed to Dev, live screenshots of each new screen (desktop + mobile, light + dark).
* Visual audit report in `docs/audits/` with a score per screen.
