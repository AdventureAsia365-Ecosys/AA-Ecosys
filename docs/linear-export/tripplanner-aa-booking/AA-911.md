## Problem

Booking staff sign in through Cognito WORKFORCE (managed login) on Production, but Booking Vercel **Preview** deployments have no Cognito callback URL, so the only staff sign-in on a Preview is the legacy CIS bridge: CIS username/password → `POST /auth/booking-token` (CIS) → a Booking JWT signed with the booking JWT key. Owner decision S245 (20/10/2026): keep the bridge until Previews have a proper sign-in, then remove it. The same gap blocks [AA-816](https://linear.app/aa-ecosys/issue/AA-816/admin-staff-user-management-ui-createdisable-staff-roles) S2 (turning the API-side `LEGACY_ADMIN_LOGIN_ENABLED` off), because CIS Previews also rely on the legacy path (viewer-capped Preview credential, [AA-816](https://linear.app/aa-ecosys/issue/AA-816/admin-staff-user-management-ui-createdisable-staff-roles) C9).

Facts from S245 (run 39349316013): `booking.staff_users` has 3 bridge-era rows keyed by CIS id and not Cognito-linked (`admin`, `e2e-claude-code`, `e2e-claude-code-2`); `e2e-claude-code-2` is disabled in CIS but still `active` in Booking.

## Scope

1. **Design (short ADR amendment to 0006a):** how a Preview gets staff sign-in. Options to compare: (a) a fixed Preview alias per app (e.g. `booking-preview.lumiguides.it.com`) registered as a Cognito callback, with the Vercel preview served behind it; (b) Cognito app client with a wildcard-free callback list updated by CI per preview (limits, security); (c) Preview-only machine principal capped at viewer (like CIS C9) with no user sign-in. Pick one with cost and security notes.
2. Implement the chosen Preview sign-in for Booking (and CIS if the same mechanism applies).
3. Retire the bridge: remove `/auth/booking-token` (CIS) and the bridge verifier (Booking), schedule deletion of the booking JWT signing-key secret (7-day recovery window), update the secrets register.
4. Link or deactivate the 3 bridge-era `booking.staff_users` rows (link to the Cognito identity where a real person exists; deactivate test rows).
5. Docs: Booking + CIS CONTEXT.md, ADR 0006a, runbook.

## Done when

* A Booking Preview deployment lets a staff user with a `booking-*` group sign in, and refuses one without (screenshot or E2E run link).
* `POST https://api-cis.lumiguides.it.com/auth/booking-token` returns 404/405; a bridge-style token is refused by Booking (401).
* The booking JWT signing-key secret is scheduled for deletion and the register row says so.
* `booking.staff_users` has no active unlinked row (read-only run-script output).
