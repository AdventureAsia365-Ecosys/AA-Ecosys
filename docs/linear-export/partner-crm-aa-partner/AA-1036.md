## Problem

ADR 0019 d6/d7 (S265, tech lead chose `merge_now`). AA-Partner runs two Next.js apps today: `portal/` (Content studio) and `web/` (CRM). Tenants have two sign-in histories, and tenant API-key code is still present even though `PORTAL_API_KEY_SIGNIN` has been off since S256. The tenant's main surface must be Content, with CRM and TripPlanner as add-ons. Plan: `docs/audits/2026-11-03-S265-ecosystem-restructure/clarifications.md` (TL-6, TL-7). This issue takes over [AA-1007](https://linear.app/aa-ecosys/issue/AA-1007/ui-partner-portal-crm-web-on-the-kit-s6c-delete-portal-uitsx) (suppressions, the studio showing the user's own email).

## Scope

* **Merge (about 3 sessions).** Move `portal/app/portal` and `portal/lib` into `web/`. Merge the two `proxy.ts` (host → /staff → /c → /portal → CRM), the CSP and `/healthz`. `/terms` and `/privacy` move to `/legal/*` (308). One kit copy.
* **Retire the portal deploy.** Remove the portal CI/deploy, the ALB rule, the `aa-crm-dev-portal` service, task definition, target group, ECR repository and log group.
* **Remove tenant API keys.** Both `tenant-login` handlers, `verify_tenant_api_key`, the Lambda authorizer, the key code in `admin.py` and the API-key card. Set `api_key_hash` to NULL, then drop it by DRY RUN. Offboarding uses `account_status`.
* **Keep AA M2M.** AA app-to-app client credentials (`aa-m2m`) stay. A machine API for agencies is R8.
* **One invitation with a role map.** Add-ons (CRM, TripPlanner) switch on by entitlement or request, never by a second invite.
* **Content is the home page,** with an app switcher showing entitled add-ons and a "Request add-on" action. The CRM shows a banner when AA pauses AI for the whole app (S265 follow-up).
* [AA-1007](https://linear.app/aa-ecosys/issue/AA-1007/ui-partner-portal-crm-web-on-the-kit-s6c-delete-portal-uitsx) **leftovers:** suppressions to 0; the studio shows the signed-in user's own email.

## Done-when

* On Dev there is one app on host `portal.` with one partner-pool sign-in (MFA).
* `aa-crm-dev-portal` is gone.
* No route accepts a tenant API key: `/auth/tenant-login` answers 404/410 after a 30-day audit_log check.
* An invited user lands on Content and sees CRM only with the entitlement.
* UI smoke at 1440/390, light and dark; ADR 0010a and CONTEXT.md updated.
