## Problem

The S275 study of an Odoo tour & travel app (AA-1065, report root `docs/research/2026-11-10-odoo-tour-travel-plugin-comparison.md`) found these gaps. The tech lead approved building all of them (S275, 10/11/2026). We build the features in our own code; the app's code is OPL-1 and is never copied.

## Scope

* **Price per traveller type (adult / child / infant / single supplement)** (crm-05, partly, value high, effort M).
  * Today: crm.trip party_adults + party_child_ages; crm.trip_party.age_band_at_departure; proposal.room_config. Booking quote lines already split pax adult/child/infant (booking.b2b_quote_lines). But crm.option has one sell_amount / net_amount per option, so the agency cannot show or price per pax type.
  * Build: Add crm.option_price(option_id, tenant_id, pax_type adult|child|infant|single_supp, unit_sell, unit_net, qty, currency) with option.sell_amount = sum. Tenant settings child_age_max / infant_age_max (default from AA product rules). Builder: per-type sell grid prefilled from the Booking quote split x retail markup; client page shows 'Adult x2, Child x1, Single room x1'. Price hash covers the rows. Infant excluded from seat count sent to Booking.
  * Depends on: Booking quote pax split (exists)
* **Retail price rules: season, group size, early booking** (crm-06, partly, value medium, effort M).
  * Today: tenant_settings.retail_markup_pct per product type (AA-1030, crm-046, app/proposals/retail.py) gives one suggested sell; below-'from'-price warning (ADR 0005a). No season / group / early-bird adjustments.
  * Build: crm.retail_price_rule(rule_id, tenant_id, kind season|group_size|early_booking|last_minute, product_scope (all|aa_tour|component kind|tour_source_id), date_from/to, min_pax, days_before, adjust_pct, priority, stacking add|best_only, active). retail.suggested_sell applies matching rules after markup and returns the rule names (stored on the option as price_note). Settings > Pricing page, owner only.
  * Depends on: crm-05
* **Discount with owner approval above a limit** (crm-07, missing, value medium, effort S).
  * Today: No proposal-level discount in the CRM. Margin roles exist ([permissions.py](<http://permissions.py>) \~64 actions) and refund thresholds (tenant_settings.refund_owner_threshold_base) give a precedent for owner thresholds.
  * Build: Add proposal.discount_pct / discount_amount, tenant_settings.discount_owner_limit_pct, and crm.discount_approval(proposal_id, requested_by, pct, status, decided_by, decided_at). Publish/send blocked (409 discount_needs_approval) for an agent above the limit; owner approves from a task; raising the discount re-opens approval. Also flag sell below cost (negative margin) through the same approval.
