## Problem

[AA-956](https://linear.app/aa-ecosys/issue/AA-956/crm-w5-crm-26-module-8-ops-release) (Module 8 ops release) and [AA-971](https://linear.app/aa-ecosys/issue/AA-971/crm-w7-crm-13b-aa-support-l2-break-glass-l3) (support L2 + break-glass L3) shipped their staff APIs (`/crm/staff/v1/*`, groups crm-ops / crm-support), and these APIs are verified live in S262. AA staff still have no screen for them: the CRM web has no WORKFORCE sign-in, and there is no Dev E2E staff user in crm-ops / crm-support. As a result, the staff side can only be checked from inside the container.

## Scope

* Infra: callback and sign-out URLs for the crm-staff client on the agency host. Web env for the staff Cognito client. A second key in the CRM web secret.
* Web: `/staff/auth/*` with its own sealed cookie, and a staff BFF allow-list onto `/crm/staff/v1`.
* S-02 board: completeness, deletion countdown, the Booking incident admin link, one release, and the manifest download.
* S-04: support and break-glass sessions (start/end, reason code + ticket, banner).
* A Dev E2E WORKFORCE user in crm-ops + crm-support, read-limited like the other E2E users.
* Screenshots at 1440 and 390, light and dark.

## Done when

* A staff user signs in on Dev and sees the S-02 board. Opening one release adds +1 to the agency-visible view count, and the manifest downloads with its watermark.
* A support read returns 403 after the agency revokes access. A break-glass session sends the owner mail and the alarm (live).
* Merged + CI green + Dev rollout COMPLETED + live check (aa-ship), with an implementation note.
