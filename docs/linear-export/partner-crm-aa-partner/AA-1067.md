## Problem

The S275 study of an Odoo tour & travel app (AA-1065, report root `docs/research/2026-11-10-odoo-tour-travel-plugin-comparison.md`) found these gaps. The tech lead approved building all of them (S275, 10/11/2026). We build the features in our own code; the app's code is OPL-1 and is never copied.

## Scope

* **Payment schedule with several instalments and live status** (crm-08, partly, value high, effort M).
  * Today: crm.payment_schedule (crm-016) only kind deposit|balance, status due|paid|void, one live row per proposal and kind; proposal.deposit_pct, balance_due_on; invoices per row (crm.invoice.schedule_id); partial payments on invoices allowed (crm.payment).
  * Build: Widen payment_schedule.kind to deposit|instalment|balance with seq, percent, due_on; status adds partial / overdue (overdue derived in a view crm.v_schedule_status, stored paid_at per row so history is kept, unlike the plugin). Tenant default template (e.g. 30% now, 40% at T-60, rest at T-30) in tenant_settings.schedule_template jsonb; builder lets the agent edit lines before publish; price-hash covers them; stage gate still keys on the deposit row.
* **Payment reminders to the traveller** (crm-09, partly, value medium, effort S).
  * Today: Overdue reminders go to the agent only (bell + task, max 5; invoice.last_reminded_at, reminder_count). Workflows (crm.workflow_rule, app/workflows/) have an 'invoice overdue' trigger and a send_email step, but no 'due in N days' trigger and no AA library template for it.
  * Build: Add workflow trigger schedule_due_soon (N days before due_on) and ship two AA library templates (due-soon, overdue) with a 3-day cool-down per schedule row; send from the agency mailbox, opt-in per tenant (the CRM still never mails the client unless the agency turned the rule on).
  * Depends on: crm-08
* **Traveller cancellation policy (days-before charge table)** (crm-11, missing, value high, effort M).
  * Today: Cancel run (crm.trip_cancellation, app/cancellation) cancels AA bookings (AA fee written as booking_line_money kind cancellation_cost), voids unpaid invoices and opens one refund request per payment for an amount the member types. No agency-to-traveller policy table; the charge to the client is not computed.
  * Build: crm.cancellation_policy(policy_id, tenant_id, name, is_default, version, published_at) + crm.cancellation_policy_tier(policy_id, days_before_min, charge_pct, min_charge_amount); proposal.cancellation_policy_id frozen at accept and merged into the booking-terms agreement text. Cancel dialog computes days before start, the policy %, charge, paid, refund due; agent may override with a reason or waive (owner approval above refund threshold). Suggest 'charge >= AA fee' warning so the agency never refunds below its own AA cost.
  * Depends on: Booking cancellation fee read (exists via cancel dry_run)
* **Cancellation charge invoice and refund due** (crm-12, partly, value medium, effort S).
  * Today: crm.invoice kind deposit|balance|service_fee|adjustment, void with reason; crm.refund_request proposed->approved->executed with owner thresholds; cancel run voids unpaid invoices and keeps paid ones until refunded (app.cancellation.void_if_refunded).
  * Build: Add invoice.kind 'cancellation_fee' issued by the cancel run from crm-11's computed charge; refund requests prefilled with paid - charge per payment; trip P&L after cancel = cancellation fee - AA cancellation_cost - non-refundable agency supplier costs (crm-30).
  * Depends on: crm-11, crm-30
