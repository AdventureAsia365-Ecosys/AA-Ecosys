## Problem

Found by the S277 [AA-1071](https://linear.app/aa-ecosys/issue/AA-1071/crm-partners-sub-agent-referral-commission-payable-and-a-sub-agent) lane. When a row is deleted through a foreign-key cascade, PostgreSQL runs the cascade without row-level security. The `crm.guard_held_travel_doc` style legal-hold triggers on the crm-054 tables (`crm.booking_line_voucher`, `crm.room_assignment`, `crm.visa_application`, `crm.visa_checklist_item`) then look up holds without the tenant filter, so they can see holds of other agencies.

* The guard may block a cascade because of another agency's hold.
* The guard's error path may tell one agency that a hold exists elsewhere.
* [AA-1071](https://linear.app/aa-ecosys/issue/AA-1071/crm-partners-sub-agent-referral-commission-payable-and-a-sub-agent) left this guard off `crm.partner_commission` for this reason.

## Scope

* Make every legal-hold guard read holds of the row's own tenant only, by an explicit `tenant_id` predicate in the guard function, not by relying on RLS. Cover crm-054 and any older crm table with the same pattern.
* An integration test with two agencies: a hold on agency A never blocks a cascade delete on agency B, and still blocks on agency A.
* A lint or test that flags a hold guard without an explicit tenant predicate.

## Done when

* The two-agency test passes on the replayed schema, and the migration applies on Dev.
* No legal-hold guard reads `crm` hold rows without a tenant predicate (lint).
