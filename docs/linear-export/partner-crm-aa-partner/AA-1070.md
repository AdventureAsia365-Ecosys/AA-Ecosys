## Problem

The S275 study of an Odoo tour & travel app (AA-1065, report root `docs/research/2026-11-10-odoo-tour-travel-plugin-comparison.md`) found these gaps. The tech lead approved building all of them (S275, 10/11/2026). We build the features in our own code; the app's code is OPL-1 and is never copied.

## Scope

* **Departure roster: all the agency's travellers on one AA departure** (crm-22, partly, value high, effort M).
  * Today: crm.booking_line.departure_id and crm.option.aa_departure_id link lines to Booking departures; ops release + manifest CSV are per trip (crm.ops_release, crm.supplier_manifest_export); departure.guaranteed is pulled but only recorded. No view grouping several trips on one departure.
  * Build: Page /departures: one row per AA departure the agency has lines on (from booking_line), with its trips, pax by type, guaranteed status (from feed, stored in crm.aa_departure_state(departure_id, status, min_to_operate, guaranteed_at)), Stage 3 completeness; merged manifest export (field-picked, audited like the ops manifest) for the agency's tour leader; calendar layer on /calendar.
  * Depends on: Booking departure status in the feed (exists)
* **Per-service vouchers for travellers** (crm-20, partly, value high, effort M).
  * Today: crm.document kind 'voucher' for uploaded files; booking_line has confirmation_no, service_from/to, visible_to_travelers; Booking GET /bookings/{id}/confirmation for AA lines (no names, no prices). No generated voucher.
  * Build: Generate a voucher per confirmed booking_line (agency lines from their own fields + new optional pickup/dropoff/time/pnr columns; AA lines from the Booking confirmation) as an HTML page on /c/t with print-to-PDF, later server PDF (crm-21). Lead traveller name filled server-side; supplier contact decrypted for the voucher only. Released when the trip is booked and the line confirmed.
  * Depends on: crm-21 for real PDF
* **Server-side PDF documents (confirmation, invoice, proposal/brochure)** (crm-21, partly, value medium, effort M).
  * Today: Invoices and text proposal are HTML (GET /invoices/{id}/document) printed by the browser; no server-side PDF anywhere; PAdES signed PDF parked (AA-1012, after S280).
  * Build: One render service in the CRM api (HTML templates -> PDF via a headless renderer in the job worker, job kind crm_pdf_render), stored as crm.document (sealed with the tenant docs DEK) with kind confirmation_pdf / invoice_pdf / proposal_pdf / voucher; agency branding from the Content studio tenant profile.
* **Rooming list (who shares which room)** (crm-17, partly, value medium, effort S).
  * Today: proposal.room_config (room mix of the party, Fix B10); Booking quote lines carry a rooms jsonb; ops release has no room assignment per traveller.
  * Build: crm.room_assignment(tenant_id, trip_id, room_no, room_type, traveler_id, bed_pref) editable by the lead traveller on /c/t and the agent; validated against proposal.room_config; included in the ops release payload to AA (codes and names only) and in vouchers/manifest.
  * Depends on: crm-22 (manifest), ops release payload version bump
* **Passport validity check against the trip** (crm-15, partly, value medium, effort S).
  * Today: Workflow special date 'passport expiring' (200 days, AA library) on the client; Stage 3 requires passport fields; no check against the trip's end date + N months.
  * Build: Computed per trip_traveler in the Stage 3 progress (app/portal/progress.py): passport_ok = expiry >= trip.end_date + tenant_settings.passport_valid_months (default 6), decrypted server-side only; badge on the trip party and /travelling, filter 'passport issue' on pipeline; workflow trigger passport_invalid_for_trip creating a task at booked.
* **Visa tracker per traveller and country** (crm-16, missing, value medium, effort M).
  * Today: Prep packs show visa sections as official links only (app/proposals/prep_packs.py, AI policy: visa advice only by a qualified member); workflow 'visa and documents' task list; supplier category 'visa'. No per-traveller visa record.
  * Build: crm.visa_template(tenant_id, country, visa_type, processing_days, fee, documents jsonb, official_url) maintained by the agency (BYO responsibility, no AA advice). crm.visa_application(tenant_id, trip_id, traveler_id, country, visa_type, status, deadline, submitted_on, decided_on, visa_no_enc, valid_from/until_enc) + crm.visa_checklist_item. Created by an agent action on a booked trip (suggest countries from trip destinations vs nationality). Traveller portal shows their checklist; overdue deadline -> task. Visa as an ancillary booking_line if the agency sells it.
  * Depends on: crm-14
* **Included / not included lists on the proposal** (crm-35, partly, value low, effort S).
  * Today: Accepted page lists 'included' lines = titles of live agency and AA booking lines (no price); invoice_line kind 'included'. No agency library of standard inclusions/exclusions (e.g. 'international flights not included').
  * Build: crm.inclusion_item(tenant_id, kind include|exclude, text, locale, sort, active) library; proposal_inclusion(proposal_id, item_id or free text) picked in the builder; AA tour inclusions read from the CIS tour content and shown as a fixed block; part of the published (frozen) version.
* **AA cancels a departure: waive and rebook flow for travellers** (crm-13, partly, value medium, effort M).
  * Today: Booking feed departure.cancelled / departure.incident pulled into crm.inbox_events; AA-961 raises crm.incident_flag + urgent tasks; booking.cancelled moves the trip to cancelled. Booking charges no fee when AA cancelled the departure. No guided 'offer another date or full refund' flow.
  * Build: On departure.cancelled: mark affected trips 'AA cancelled', open a guided card: (a) re-quote the same tour on another departure into a new proposal version, or (b) cancel with the traveller charge forced to 0 (waived, reason aa_departure_cancelled) and refunds prefilled in full. Workflow template to notify the lead traveller from the agency mailbox (opt-in).
  * Depends on: crm-11, Booking departure events (exist)
