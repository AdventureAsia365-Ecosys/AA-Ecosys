## Scope

* **Settings → LLM Models:**
  * edit the fallback chain per stage (ordered, drag to reorder);
  * edit the shadow model and sample %;
  * same writer ↔ judge vendor rule and catalog `enabled` checks as the model PATCH.
  * Every change is audited: `updated_by`, before/after.
* **Catalog view:** every Model Key with its price, source, `enabled` / `blocked_reason` and accounts. Admin can enter a verified price and enable a model; a model without a price cannot be enabled (the DB CHECK already enforces this).
* **Shadow A/B report** from `shared.llm_shadow_log`, per judge stage:
  * agreement rate between primary and shadow (same pass/fail and score deltas; the parser differs per stage);
  * cost and latency side by side;
  * repeat-scoring variance, for the AA-209 reproducibility question.

  This is the data [AA-644](https://linear.app/aa-ecosys/issue/AA-644/eval-gpt-41-gpt-56-luna-on-bedrock-acc3-for-judges-s1-judge-brand) needs to close.
* Use the shared DataTable ([AA-662](https://linear.app/aa-ecosys/issue/AA-662/ui-kit-shared-adminportal-components-datatable-filter-sort-columns)).

## Done when

The admin can change a judge route and a shadow from the UI with no deploy, and see the Luna-vs-GPT-4.1 A/B numbers per judge stage.
