## Mục tiêu

Build full trip_case lifecycle: versioning (V1/V2/V3), HITL approval flow, wishlist-to-trip conversion, staff assignment, và trip_case_checks.

## Trip Case Lifecycle (State machine)

```
new_inquiry → in_planning → version_sent → approved → confirmed → completed
                          ↘ revision_requested → in_planning
```

## Tasks

 1. \[ \] Trip Case CRUD API (POST, GET, PATCH status)
 2. \[ \] Version creation: POST /api/trip-cases/{id}/versions
 3. \[ \] Itinerary builder: POST /api/trip-cases/{case_id}/versions/{v}/itinerary (add activities day by day)
 4. \[ \] is_sent_to_customer = true → trigger customer notification (email/SMS)
 5. \[ \] is_approved = true → lock version, create invoice draft
 6. \[ \] Staff assignment: POST /api/trip-cases/{id}/assign (staff_user_id, role)
 7. \[ \] Trip case checks: PUT /api/trip-cases/{id}/checks (checklist items)
 8. \[ \] Wishlist-to-inquiry: POST /api/wishlist/{id}/inquire → creates trip_case from trip_plan
 9. \[ \] Admin portal: versioning UI, itinerary drag-n-drop builder
10. \[ \] Notifications: send email/SMS on version sent + approval

## Key business rules

* Each trip_case can have multiple versions (V1, V2, V3...)
* Only ONE version can be approved (is_approved = true)
* Version sent to customer triggers notification
* Approved version locks itinerary (read-only)
* staff_assignments.role: 'lead', 'support', 'ops'
