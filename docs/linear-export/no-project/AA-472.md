## Bối cảnh (STEP 0 đã xác nhận, [AA-468](https://linear.app/aa-ecosys/issue/AA-468/admin-don-trang-n0-n8-cu-bo-bat-buoc-tao-planchon-tour-khi-tao-tenant) việc 2, 26/08/2026)

Tenant hiện tại KHÔNG THỂ được Gate A approve nếu chưa chạy `POST /admin/tenants/{id}/seed-atoms` với `portfolio_id` (UUID, bắt buộc, NOT NULL FK vào `acp_shared.marketplace_portfolios`, status phải `finalized`).

Điều này mâu thuẫn với kiến trúc T-series/ADR-2026-038: tenant tự chọn tour qua `GET /v1/marketplace`, AA không gate nội dung. Bước bắt buộc chọn portfolio khi onboarding là tàn dư mô hình cũ (staff chuẩn bị sẵn tour cho tenant).

## Vị trí code đã xác nhận (STEP 0)

* `api/routers/admin.py:108-199` — `create_tenant()`: tạo tenant row, KHÔNG cần portfolio (đã đúng, không cần sửa)
* `api/routers/admin.py:896-973` — `seed_tenant_atoms()`: `SeedAtomsRequest.portfolio_id` bắt buộc, không default
* `api/routers/admin.py:1179-1257` — Gate A approve: dòng 1201-1205 chặn cứng 404 nếu chưa có `tenant_onboarding` row (tức chưa chạy seed-atoms)
* Migration 098 — `tenant_onboarding.portfolio_id` là FK NOT NULL
* Comment code dòng 909-914 tự ghi: "portfolio_id is a real NOT NULL FK... this call cannot be removed without a migration (out of scope for [AA-444](https://linear.app/aa-ecosys/issue/AA-444/marketplace-build-view-tong-hop-t4t6-tenant-tour-versions-join-tour))"

## Hướng B đã chọn (26/08/2026, Nghiệp quyết định qua Claude Chat)

⚠️ BLOCKER cho việc khác: [AA-472](https://linear.app/aa-ecosys/issue/AA-472/tenant-onboarding-bo-rang-buoc-bat-buoc-portfolio-id-khi-tao-tenant) phải Done TRƯỚC khi xoá `/admin/marketplace` ([AA-467](https://linear.app/aa-ecosys/issue/AA-467/cleanup-don-dep-kien-truc-worktree-rac-djieu-tra-archive-aa-acp) Phần 3). Lý do: nếu xoá trang admin marketplace trước khi bỏ ràng buộc `portfolio_id NOT NULL`, sẽ không còn cách nào tạo `marketplace_portfolios` row mới → `seed_tenant_atoms()` luôn thất bại → tạo tenant mới bị chặn hoàn toàn, không ai Gate A approve được. Xác nhận thứ tự với Nghiệp 26/08/2026.

1. Migration mới: đổi `tenant_onboarding.portfolio_id` thành nullable
2. Gộp seed-atoms vào ngay `create_tenant()` — tự tạo `tenant_onboarding` row với `portfolio_id=NULL`
3. Gate A approve: bỏ điều kiện "no row → 404"

Phát hiện CHẶN NGHIÊM TRọNG giữa chừng build (26/08/2026): `seed_tenant_atoms()` thật sự làm 2 việc, không phải 1 — (1) insert `tenant_onboarding` (portfolio_id), (2) insert `tenant_atom_state` (seed danh sách tour + `assigned_angle`). Xoá endpoint chỉ chuyển (1), bỏ sót (2) — hậu quả dây chuyền: `assign_tenant_angle()`, Gate A `approve_gate_a()`, `get_tenant_mirror()` đều phụ thuộc cứng vào có row `tenant_atom_state` → tất cả luôn 404/400 cho tenant mới, Gate A KHÔNG BAO GIỜ approve được.

Nguyên nhân gốc xác nhận (Nghiệp, 26/08/2026): `assigned_angle` ở cấp `tenant_atom_state`/N1 onboarding là **SAI KHÁI NIỆM NGAY Từ đầu** — angle KHÔNG PHẢI thuộc tính cố định của tenant (chọn 1 lần lúc onboarding), mà thuộc về TỮNG BÀI VIẾT riêng lẻ (T8 Angle Gate, chọn lại mỗi piece). Đây là tàn dư thiết kế N1 cũ trước khi T8 tồn tại, chưa từng được dọn khi T8 xây xong.

**Quyết định: Bỏ HẮN khái niệm angle/tenant_atom_state khỏi luồng N1 onboarding + Gate A** (Option 1 Claude Code đề xuất). Gate A chuyển check sang điều kiện khác không phụ thuộc `tenant_atom_state` (VD cột `tenants.assigned_angle` hoặc bỏ hẳn check angle ở Gate A, chỉ giữ điều kiện khác liên quan onboarding cơ bản). Mirror tab: tính atom_count theo catalog thật (KHÔNG qua `tenant_atom_state` nữa). Cần Claude Code thiết kế lại chi tiết Gate A check + Mirror tab trước khi tiếp tục Frontend (Bước 4).
