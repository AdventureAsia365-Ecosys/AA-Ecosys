## Why

The models are already usable on acc3: agreement AVAILABLE and AUTHORIZED, checked with `get-foundation-model-availability` on 28/09 (S199).

But `AA3-Bedrock-Invoker` (`infra/AA-CIS-Infra/accounts/acc3-bedrock/main.tf`, policy `InvokeApprovedClaudeModelsOnly`) allow-lists only Sonnet 4.6 and Haiku 4.5, so ECS is denied for every new model.

acc1 and acc2 have not accepted the agreements for these models. **acc3 is the primary account.**

## Scope

* Add, for each model, all 3 ARN forms already used for the existing models:
  * `inference-profile/{us,global}.<id>` (acc3);
  * `foundation-model/<id>` with the region;
  * `foundation-model/<id>` without the region.

  Models: `anthropic.claude-sonnet-5`, `anthropic.claude-opus-5-5`, `openai.gpt-5.6-luna`, `openai.gpt-6-astra`.
* Keep `bedrock:InvokeModel` + `bedrock:InvokeModelWithResponseStream`. These also cover the Converse / ConverseStream APIs.
* Rename the policy (for example `InvokeApprovedModelsOnly`), since it is no longer Claude-only.
* Human apply with profile `nghiep_aa365` (the acc3 root has its backend profile set).

## Done when

From ECS exec, a 1-token Converse call per model succeeds, logged via `LLMClient` with `stage=adhoc_aa<this>`.
