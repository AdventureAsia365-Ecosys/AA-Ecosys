# AA-141 — [OBS-02] Run-Health single-pane dashboard + SLO/alerting

## Goal

A single "Run Health" monitor in the **aa-cis** admin (flow-1 UI) that shows the live state of every ACP run across both flows — the system-wide monitor the team currently lacks.

## Why

`acp_stage_runs` + `acp_run_context` already record run state, but there is no single pane to watch it. Reviewers/ops fly blind between gates.

## Scope

1. Dashboard reads `acp_stage_runs` + Langfuse ([AA-140](https://linear.app/aa-ecosys/issue/AA-140/obs-01-langfuse-trace-standardization-across-all-acp-stages)): per run → stage status (pending/running/done/failed), duration, cost, validator pass/fail, evaluator score, gate status, retry count.
2. Filter by tenant, country, date, status. AA sees all; a B2B tenant view (in `acp` portal) is scoped by RLS to own runs only.
3. SLO/SLA layer: define targets (gate SLA, stage duration, cost/run) and surface breaches; CloudWatch alarms → SNS for stuck-run (relates [AA-123](https://linear.app/aa-ecosys/issue/AA-123/hrn-09-s0-eventbridge-publish-retry-stuck-at-s0-detection)), cost-cap breach, evaluator-score drop, gate-SLA breach.

## Verify

* Open dashboard mid-run → see exactly which stage is active, its cost so far, and any validator failures.
* Trigger a stuck run → alarm fires.

## Relates

[AA-140](https://linear.app/aa-ecosys/issue/AA-140/obs-01-langfuse-trace-standardization-across-all-acp-stages) (Langfuse), [AA-123](https://linear.app/aa-ecosys/issue/AA-123/hrn-09-s0-eventbridge-publish-retry-stuck-at-s0-detection) (stuck-run), [AA-127](https://linear.app/aa-ecosys/issue/AA-127/hrn-25-gate-3-social-stage-context-panel-trang-sees-full-audit-trail) (gate context — this is broader). Observability backbone.
