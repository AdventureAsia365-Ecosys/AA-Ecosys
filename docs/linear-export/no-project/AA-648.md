# AA-648 — [P0] DFS batching is ineffective (~4.5 keywords per paid task) — two-phase research with real bulk tasks + Standard queue mode

## Problem (verified S199) — answers Ms. Thư's question "is the batch working?"

DFS charges **per task**. On 25/09 the cost per bulk call was flat (\~$0.057–0.059) whether the call carried 4 or 13 keywords.

`_VolumeBatcher` (linger 5 s, `CONCURRENCY = 4` places at a time) produced **678 bulk calls averaging 4.5 keywords, max 13** — $39.24. Ms. Thư's reference repo ran 16 workers as a standalone batch, so her batches were much larger. That is why "a few hundred tours" cost her far less.

The `keywords_for_keywords` (suggestions) call is one paid task per place: 100 calls, $9.00. Across \~1,800 zero-volume places, that alone could exceed $150 per market pass.

## Fix — research as a batch job, not a per-place live loop

1. **Phase A — propose (LLM only, no DFS).** For every stale place, the LLM proposes up to N seed keywords.
2. **Phase B — buy volumes in real bulk.** One `search_volume` task per market per ≤1,000 keywords.
3. **Phase C — decide (LLM or Jev).** On the results, decide the long-tail and SERP keywords (volume > 0 only).
4. **Phase D — buy SERP/PAA** (only keywords with volume) and suggestions with multi-seed tasks (several seeds per task).
5. **DFS Standard (**`task_post` **/** `task_get`**) mode** for this non-urgent batch, which is cheaper than Live per task (confirm current prices on the DFS pricing page). Live stays for interactive calls only.
6. **Optional Jev relevance gate** before Phase B/D ("is this keyword about this place/activity?", [AA-643](https://linear.app/aa-ecosys/issue/AA-643/eval-jev-typesafe-offline-eval-on-real-cis-data-f8-t3-grounding-a3)). Shadow first.

## Expected

One full pass over \~2,200 places × 3 markets should cost a few dollars in volume tasks, instead of \~$39 in volumes plus a potential $150+ in suggestions. The estimate and the actual are shown in Cost Operations.

## Done when

A Bhutan-only research job runs with a pre-run estimate; the actual cost is within the estimate; the average keywords per volume task is ≥ 200 (or all of the job's keywords).

### 2026-09-29 10:58 — nghiep pham quoc

**S203 follow-up — suggestions pass stored 0 ideas (PR #478, merged + deployed Dev :375)**

**Root cause**
- Both batch runs on 28/09 logged `ideas_returned=4/2, ideas_with_volume=0`, and the returned "ideas" were the seeds themselves.
- The pass only takes zero-volume places, but it seeded each one with its own zero-volume keyword. Google Ads echoes a task made only of unknown seeds back with no ideas. Parsing was correct.

**Fix:** seeds are now `"<place> <country>"`, with the country taken from the place's platform tours (2,189 / 2,222 places resolve on Dev). No migration.

**Evidence**
- Probe, 1 paid task (~$0.09): 8 broadened Bhutan seeds → 26 ideas, 22 with volume (`mongar bhutan` 40, `ura valley bhutan` 70, `phobjikha valley` 260).
- Live run after deploy, job `511d9550`: Bhutan, US, 10 places, $0.20.
  - `seed_sample=['robluthang bhutan']` confirms the new seed.
  - Only 1 place had zero volume and it is very obscure, so DFS echoed it back (0 ideas).
  - This run does **not** prove ideas get stored. That rests on the probe.

**Open point:** an all-obscure batch still costs one task and returns nothing. Possible follow-up: skip the ideas task when it would carry very few seeds. Not done; it needs a decision.
