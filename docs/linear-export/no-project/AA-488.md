## Bối cảnh

Phát hiện phụ khi audit chất lượng đường Commit ([AA-476](https://linear.app/aa-ecosys/issue/AA-476/dashboard-6-muc-audit-aa-438-con-treo-3-double-fire-ingestion-p1-1211), Phần A STEP0, 28/08/2026) — trước khi tắt Lambda ingestion trigger, cần xác nhận đường Commit đủ sạch. Xác nhận dedup file + dedup tour + versioning đều thật và hoạt động tốt — nhưng có 2 gap nhỏ phát hiện thêm, ngoài phạm vi double-fire, không sửa vội theo yêu cầu lúc đó.

## Gap 1 — Duplicate trong CÙNG 1 file Excel không bị chặn

Dedup theo tour (so `lower(trim(src_name)) + lower(trim(provider))`) chỉ so với DB đã có (`raw_tours`), KHÔNG so giữa các dòng NGAY TRONG CÙNG 1 FILE đang xử lý.

**Kịch bản lỗi:** nếu 1 file Excel có 2 dòng trùng tên+provider (lỗi copy-paste ở nguồn cung cấp) — tại thời điểm check, cả hai đều CHƯA có trong `raw_tours` → cả hai lọt qua thành `new_records` → cả hai được insert thành **2 tour mới**, không qua staging, không cảnh báo. Hiếm gặp (phụ thuộc lỗi từ nguồn cung cấp) nhưng khi xảy ra sẽ tạo dữ liệu trùng lặp không kiểm soát.

## Gap 2 — dry_run và Commit lệch logic dedup-by-hash, gây "0 tours saved" im lặng

* Bước `dry_run` (preview, `admin_pipeline.py:1113-1126`) chỉ báo `blocked: duplicate_file_hash` khi **cả hash VÀ filename** (đã strip UUID) đều khớp.
* Bước Commit thật (`process_file()`, `handler.py:97-100`) chỉ query `WHERE file_hash = $1` — **không lọc theo filename**.

**Hậu quả:** file trùng nội dung nhưng KHÁC tên → preview báo "N tours ready" (không cảnh báo gì) → admin bấm Commit → `process_file()` trả `skipped_duplicate` → UI hiển thị **"0 tours saved" với dấu tick xanh** (`frontend/app/admin/upload/page.tsx:1457-1466`), không có thông báo phân biệt với "file hợp lệ nhưng thật sự 0 tour". Admin không biết đây là file bị chặn do trùng nội dung, dễ hiểu nhầm là lỗi khác hoặc file rỗng.

## Việc cần làm khi build

- [ ] **Gap 1:** thêm bước dedup trong-file (so các dòng trong cùng 1 batch parse trước khi insert) — nếu phát hiện trùng tên+provider trong cùng file, đẩy cả 2 vào `upload_staging` (giống cơ chế dedup-với-DB hiện có) thay vì insert thẳng.
- [ ] **Gap 2:** đồng bộ logic dry_run và Commit — cả 2 nên dùng CÙNG điều kiện dedup (chỉ theo `file_hash`, bỏ điều kiện filename ở dry_run để nhất quán). Sửa response của Commit để trả `status: "duplicate"` rõ ràng khi bị `skipped_duplicate`, và sửa frontend (`page.tsx:1457-1466`) hiển thị đúng thông báo (không map cứng thành "done").
