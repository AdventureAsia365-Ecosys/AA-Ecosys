# AA-194 — [AA-193·F5] SEO title/meta cut-off — canonical 60/155 + word-boundary trim across 4 layers

Parent: [AA-193](https://linear.app/aa-ecosys/issue/AA-193/s1-content-quality-dataforseo-keyword-sourcing-brand-differentiation). **Decision locked: canonical limits = SEO_TITLE ≤60, SEO_META 140–155** (matches v5 + `brand_standards.py`).

## Root cause (STEP 1–6 audit)

Mid-word truncation happens at `api/routers/admin_pipeline.py:274-275` — blind slice `[:70]` / `[:170]`, no word-boundary check. LLM is told 70/170 in `prompts.py`, validate_node only deducts -0.5 (non-blocking), so over-length strings pass through and get blind-sliced. **3 thresholds currently disagree** ([prompts.py](<http://prompts.py>) 70/170 · validate_node · brand_standards.py 60/155 — already self-documented as a known mismatch at brand_standards.py:56,62).

## Scope

1. Reconcile to **60/155** in all 4 places: `prompts.py` OUTPUT JSON FORMAT, `graph.py` validate_node deduction thresholds, `brand_standards.py` audit thresholds, `admin_pipeline.py:274-275` slice.
2. Replace blind `[:N]` slice with **word-boundary trim** — port v5 `_trim_to_word_boundary()` (rsplit at nearest space; for meta, prefer sentence boundary `./!/?` to avoid META_INCOMPLETE_SENTENCE).
3. Optional: make SEO_TITLE_TOO_LONG / SEO_META length codes blocking (force retry) instead of -0.5.
