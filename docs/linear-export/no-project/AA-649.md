# AA-649 — [P0] Cost guard — DB-configured budgets for DFS / LLM / Jev per run and per day, hard stop, pre-run estimate

## Why

Nothing capped the 25/09 DFS drain. The daily Lambda ([AA-627](https://linear.app/aa-ecosys/issue/AA-627/dfsops-canh-bao-so-du-dataforseo-thap-djoc-balance-1-lanngay-alert)) only reads the balance.

## Scope

* Table `shared.spend_budget`:
  * provider: `dfs` / `bedrock` / `openai` / `jev`;
  * scope: global, per job kind, per tenant;
  * limits: `per_run_usd`, `per_day_usd`;
  * `hard_stop` boolean.
  * Editable in admin **Settings → Budgets**.
* A `CostGuard.check(provider, est_usd, scope)` helper, called before every paid external call (DFS client, Gateway). It raises `BudgetExceeded`.
  * Jobs catch it, stop cleanly and set status `stopped_budget`.
* DFS balance precheck before a research job starts (reuse `shared/dfs_client/balance.py`).
* Pre-run estimate API for research and rerun jobs.
* An alert (admin notification) at 80% and 100% of a daily budget.

## Done when

A job with a $1 budget stops at ≤ $1 in live Dev (proven via `dfs_call_log` / `llm_call_log`), and the budget is visible in Cost Operations.
