# AA-186 — [ACP-ORCH-5] Gate-as-event-boundary wiring (Gate 1/2/3) + HITL request + resume

## Goal

Implement gates as **event boundaries, not blocking waits** (ADR-2026-013 §Decision.3). A stage completing creates a HITL request in DB and STOPS — no live compute waits on a human (gates may take days).

## Gates

* Gate 1 — post-S2 (admin)
* Gate 2 — post-S3 (Ms. Thu)
* Gate 3 — post-S4 (Trang)

## Scope

* On `acp.{stage}.completed`: create `acp_hitl_requests` row, set stage status `awaiting_gate`, suppress next-stage chain event.
* Approval endpoint publishes `acp.hitl.approved` → triggers next stage runner.
* **Define** `acp.hitl.approved` **payload schema** (ADR open question): `run_id`, `stage`, `gate`, `decision`, `reviewer_type`, `next_stage`. Reuse `reviewer_type` (aa_internal/tenant_self) from [AA-89](https://linear.app/aa-ecosys/issue/AA-89/acp-v12-b2b-self-approval-dashboard-s2s3s4-tenant-side-review-flow).
* Reject path: set stage `rejected`, no chain event.

## Decision ref

ADR-2026-013 §Decision.3 + open question "gate→resume event contract".
