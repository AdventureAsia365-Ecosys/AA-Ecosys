## Summary

`_execute_run_tour` (api/routers/admin_pipeline.py) crashes at the `generated_content` INSERT whenever a run is **not publishable** (e.g. judge `manual_check`, post-fix score < 7, brand-flagged unresolved).

## Root cause

admin_pipeline.py:410

```
status = "approved" if _is_publishable(result) else "pending"
```

This `status` flows into the INSERT (line ~450) cast as `$13::content_status_enum`. But `content_status_enum` (defined in migration 002, superseded by 003, no later ALTER ADD VALUE) is:
`{draft, passed, hitl, approved, rejected, published}` — `pending` **is not a member.**

`pending` only exists in `review_status_enum` (used legitimately by `_enqueue_review` for `review_queue.review_status`). The two enums were conflated.

Result: Postgres rejects `'pending'::content_status_enum` → asyncpg `InvalidTextRepresentationError` → `_execute_run_tour` re-raises → the whole run fails, nothing persists.

## Impact

* **Production**: any UI/admin `run-tour` whose content lands not-publishable crashes instead of being enqueued for human review. Silent data loss of the generation (LLM cost already spent, no row written).
* Only runs that end `approved` (publishable) have worked so far — that is why it stayed hidden until a cell first hit `manual_check`.
* Surfaced during [AA-193](https://linear.app/aa-ecosys/issue/AA-193/s1-content-quality-dataforseo-keyword-sourcing-brand-differentiation) Phase B verification (WildKind × sonnet cell), 22/06/2026.

## Fix (single point)

admin_pipeline.py:410

```
- status = "approved" if _is_publishable(result) else "pending"
+ status = "approved" if _is_publishable(result) else "hitl"
```

`hitl` is the correct enum member (semantics: needs human review; matches the `_enqueue_review` path). Line 543 also recomputes a `status` var but only branches in Python (never written to the enum column), so it does not crash — optionally sync to `hitl` for readability.

## Verification

After fix + Deploy Dev/Prod, re-run a deliberately not-publishable cell (e.g. WildKind × sonnet) and confirm: row persists with `status='hitl'`, `_enqueue_review` fires, no crash.
