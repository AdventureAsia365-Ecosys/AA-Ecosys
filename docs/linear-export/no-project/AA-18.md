# AA-18 — Migrate geographic content — areas, countries, destinations, users from legacy MySQL

# Migrate Geographic Content — Legacy MySQL → PostgreSQL

Migrate areas, countries, destinations, customers từ legacy MySQL DB `adventureasiajamstackvn_db` sang new PostgreSQL RDS.

## Scope (migrate selectively — NOT all tables)

| Legacy Table | New Table | Action | Content |
| -- | -- | -- | -- |
| areas | areas | MIGRATE | 17 geographic areas |
| countries | countries | MIGRATE + ENRICH | 17 Asian countries, rich JSON (description, weather, events, FAQs) |
| destinations | destinations | MIGRATE + GEOCODE | Cities/regions, need to add lat/lng |
| customers | users | MIGRATE partial | Email only, no password, role=customer |
| hotels | — | SKIP | Use free-text accommodation in trip_case_days |
| tours | — | FRESH | New content from suppliers/CIS |

## Migration Sequence (order matters)

1. Phase 1 — Image migration to S3 FIRST (blocked on [AA-7](https://linear.app/aa-ecosys/issue/AA-7/legacy-image-migration-s3-cloudfront-cdn))
2. areas → add slug, sort_order
3. countries → add slug, code (ISO-3166), map_lat/lng, hero_image_id (after files ready)
4. destinations → add lat/lng for priority destinations first
5. users (from customers) → email deduplicate, role=customer, is_active=true, NO password
6. files → INSERT records mapping S3 keys to entity_type/entity_id

## Zero-Disruption Rule

* Legacy MySQL `adventureasiajamstackvn_db` is NEVER touched
* All reads/writes from [adventure.asia](<http://adventure.asia>) continue on old DB
* No downtime, no changes to Nuxt.js app code

## Blockers

* [AA-7](https://linear.app/aa-ecosys/issue/AA-7/legacy-image-migration-s3-cloudfront-cdn) (image migration) must complete first
* D-06 (Ms. Thư schema approval) must be received
