# AA-263 — [CIS][S1] Tách node editor độc lập khỏi validate_node trong S1 graph (từ ADR-2026-020)

## Nguồn gốc

Từ ADR-2026-020 (chốt [AA-260](https://linear.app/aa-ecosys/issue/AA-260/acp-chot-3-quyet-djinh-treo-cbt-65-s1-contract-formula-count-editor) Q3, 06/07/2026): giữ editor step riêng đúng research gốc. S4.2 đã có editor riêng ([AA-93](https://linear.app/aa-ecosys/issue/AA-93/acp-s42-social-media-content-engine-dual-mode-8-channels-11-formulas) `quality.py`). S1 (CIS) hiện gộp việc revise vào validate_node/llm_judge — cần tách 1 node **editor** độc lập.

## Scope

Tách trách nhiệm trong S1 graph (`v1_pipeline.py` / `services/content_generation/graph.py`):

* **editor node** = revise/viết-lại content (sửa).
* **validate node** = chấm điểm/đánh giá (không sửa).

Graph S1 hiện tại (7 node): generate → validate → llm_judge → brand_audit → flag_fix → revalidate → END. Cần xác định vị trí chèn editor node (nhiều khả năng giữa llm_judge và brand_audit, hoặc thay thế vai trò revise đang lẫn trong flag_fix — STEP 0 xác nhận).

## ⚠️ STEP 0 bắt buộc trước khi build

* Đọc source S1 graph thật xác nhận node nào đang làm việc "revise" hiện tại (nghi flag_fix_node) vs "chấm điểm" (validate/llm_judge).
* Xác nhận `ContentState` TypedDict field cần thêm cho editor output (nhớ bài học: field không trong ContentState bị strip; `_rewrite_tour` rebuild từ named keys — field mới phải thêm explicit).
* Đo cost/latency delta của việc thêm 1 LLM call.

## Consequences ghi nhận

* Thêm 1 LLM call/node → tăng cost + latency mỗi tour. Cần đo trước/sau.
* Thay đổi kiến trúc S1 graph thật → full pipeline: STEP 0 → CI → Deploy Dev → digest verify → UAT Preview → merge main → Deploy Prod.

### 2026-09-04 12:14 — nghiep pham quoc

**STEP0 verdict: NOT building — the substantive architectural goal is already satisfied. No code touched, no branch opened, heavy pipeline gate not invoked (it only applies once a real build starts).**

Per this issue's own mandatory STEP0, read `services/content_generation/graph.py` + `flag_fix_node.py`/`judge_node.py`/`brand_audit_node.py` node-by-node, not assumed from the issue's 06/07/2026 description.

**Finding**: `flag_fix_node` already IS the separate "editor" node ADR-2026-020 asks for. It's the ONLY node in the entire S1 graph that makes an LLM call whose purpose is to rewrite content fields (`LLMClient().generate()` w/ `FIX_SYSTEM`, writes back into `generated`). Every other node — `validate_node`, `judge_node` ("llm_judge"), `brand_audit_node`, `revalidate_node` — is a pure scorer: confirmed by reading each fully, they build `issues`/`score`/`brand_audit_status`/`quality_score` and return them, never rewrite content via an LLM call. `revalidate_node` just re-invokes `validate_node`+`judge_node` (pure re-score).

**The issue's own premise ("S1 hiện gộp việc revise vào validate_node/llm_judge") doesn't match the current graph — and via `git log`, didn't match it even when the issue was written**: `flag_fix_node` was committed **2026-05-29** (migration 050, PR #3, `[AA-133][AA-134][AA-132][AA-135]`), over 5 weeks before this issue's creation date (**2026-07-06**). Not drift since — the premise was already stale when filed.

**One real, narrow, technically-accurate gap found (NOT the substantive gap this issue describes)**: `validate_node` (lines ~501-542) does an inline, deterministic (regex-only, no LLM) itinerary text-format cleanup — markdown bold stripping, dash normalization, blank-line collapsing — before scoring. Strictly read, this IS `validate_node` "sửa" something, a narrow violation of "validate = chấm điểm, không sửa." But it's pure text/whitespace formatting, zero LLM cost/latency delta, no brand-voice/factual content change — categorically different from, and far lower-stakes than, the "add an editor LLM-call node" change this issue's own Consequences section describes (cost/latency delta, full CI→Deploy→UAT→Prod pipeline).

**Recommendation**: close this issue as "already satisfied by flag_fix_node (AA-133/134/135)" — or, if ADR-2026-020 compliance is still wanted down to that granularity, rescope to just the small itinerary-normalization extraction (much lower risk, no new LLM call, doesn't need the heavy pipeline this issue currently specifies).
