### 2026-09-19 12:11 — nghiep pham quoc

Canceled after STEP0 (S190, Kiro) — the premise no longer holds.

This issue (06/09) assumed `fetch_keyword_ideas()` is called "one keyword per request inside a loop" at `segment_research.py:326`. Re-reading the current code (post AA-515 refactor to the Ms.Thư ReAct model), that is no longer true:

- `fetch_keyword_ideas()` is called in exactly ONE place: the `suggestions` tool (`_suggestions_tool`), inside the ReAct loop.
- The `suggestions` tool is hard-capped: `MAX_SUGGESTIONS = 1` → **at most 1 call per place**, and only fires when `suggestions_spent < 1` AND no keyword yet has any volume (`any_volume` false). It is a last-resort fallback (see the tool's own docstring "only while nothing here has measurable volume"), rarely triggered.
- Each call = 1 seed keyword, primary market only.

So there is no multi-keyword loop of `keyword_ideas` to batch. The genuinely expensive path (many `volumes` keywords) was already batched by AA-515 via `_VolumeBatcher`. Building a coalescing batcher for a tool that runs ≤1×/place would add complexity for ~$0 savings (the fallback almost never fires).

Closing as no-longer-applicable. If the `MAX_SUGGESTIONS` cap is ever removed / suggestions becomes a hot path, revisit then.
