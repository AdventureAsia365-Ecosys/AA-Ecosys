## Problem

ACP tenant authentication requires satisfying THREE layers with conflicting header contracts. No single header works; a normal client sending one header is rejected. Discovered during [AA-174](https://linear.app/aa-ecosys/issue/AA-174/investigation-acp-e2e-attempt-discovered-s1s42-pipeline-is-not).

## The three layers

1. **API Gateway TOKEN authorizer** (`tenant-key-authorizer`, REST API `owq9as3wjl`)
   * `identitySource = method.request.header.X-API-Key`
   * Lambda `aa-cis-dev-authorizer` hashes the **raw token verbatim** (no `Bearer` strip): `sha256(token)` vs `shared.tenants.api_key_hash`.
   * → Requires header `X-API-Key: <raw cis_... key>`.
2. **FastAPI app layer** (`api/routers/auth.py`)
   * Uses `HTTPBearer` → requires `Authorization: Bearer <JWT>`.
   * JWT is obtained from `POST /auth/tenant-login` (body `{api_key}`) → returns signed JWT.
   * → Requires header `Authorization: Bearer <JWT>` (NOT the raw key).
3. **Net effect:** a working request to `/acp/s1/run` needs BOTH:
   * `X-API-Key: <raw key>` (for gateway authorizer)
   * `Authorization: Bearer <JWT-from-/auth/tenant-login>` (for FastAPI)
     Plus a prior call to `/auth/tenant-login` to mint the JWT.

## Why this matters

* Undocumented; took 6 failed attempts to reverse-engineer the working combination.
* A standard API client (one auth header) cannot trigger any ACP run → contributes to all ACP UI pages being empty.
* Secrets Manager `aa-cis/dev/acp-partner-api` shipped as placeholder `{"api_key":"REPLACE_ME"}` — tenant keys were never seeded.

## Working sequence (documented for now)

```
1. POST /auth/tenant-login   H: X-API-Key: <raw key>      body: {"api_key":"<raw key>"}   → JWT
2. POST /acp/s1/run          H: X-API-Key: <raw key>  +  Authorization: Bearer <JWT>
```

## Acceptance criteria

- [ ] Decide the intended contract: single-header (raw key end-to-end) OR documented 2-step (key→JWT). Pick one.
- [ ] Align all 3 layers to the chosen contract (authorizer identitySource, FastAPI dependency, docs).
- [ ] Document the canonical auth flow in ACP wiki + openapi description.
- [ ] Seed real tenant keys into Secrets Manager (replace REPLACE_ME placeholder).
- [ ] Verify a single-header client can trigger a run end-to-end.
