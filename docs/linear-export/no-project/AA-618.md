# AA-618 — [Sub B][BE] DFS/DataForSEO usage logging — bảng dfs_call_log (cost/cache_hit/live) tại điểm gọi

## Bối cảnh (epic [AA-616](https://linear.app/aa-ecosys/issue/AA-616/epic-giam-sat-chi-phi-llmdfs-toi-uu-modelbatch-tung-stage), S187)

DFS/DataForSEO **KHÔNG được log chi phí ở đâu cả**. Điều tra DB:

* `silver_aa_internal.seo_context` = cache kết quả (columns: keyword_search, provider, keyword_ideas, demographics, trends, top_keywords, cache_key, fetched_at, expires_at, people_also_ask, related_keywords). Không có cost.
* Chỉ có cột bool `dataforseo_used` trong `generated_content.metadata` (AA-osystem) + label "Live/Mock" trên master-content UI.
* DFS là API bên thứ 3 (không AWS) → Cost Explorer KHÔNG thấy. Hiện KHÔNG có cách nào biết tiêu bao nhiêu tiền DFS, bao nhiêu call live vs cache hit.

## Việc

1. **Tìm điểm gọi DFS thật** — client gọi DataForSEO (grep `dataforseo`, `get_dataforseo_creds`, seo fetch trong services/seo hoặc api). Xác định response DFS có trả `cost` không (DataForSEO trả `cost` per task trong response JSON).
2. **Bảng mới** `shared.dfs_call_log`: id, tenant_id (nullable), tour_id (nullable), endpoint (keyword_ideas/serp/...), keyword, location_code, cost_usd, cache_hit (bool), fetched_live (bool), created_at.
3. **Ghi tại điểm gọi**: cache hit (lấy từ seo_context/Redis) → cache_hit=true, cost=0; live call → cost từ response DFS, fetched_live=true. Fire-and-forget như `record_call` (không crash luồng chính nếu log fail).
4. Endpoint admin đọc rollup DFS (cho Sub E dùng).

## Verify

* Migration sạch; 1 fetch DFS live + 1 cache hit → 2 row đúng cost/cache_hit.
* Đối chiếu tổng cost DFS với hóa đơn DataForSEO (nếu Nghiệp có).
