**`test_h3_rule_extractor.py` (3 fails)** — a real mock/signature mismatch. `_call_haiku()`'s real return type is `tuple[dict, int, int]`; the test's `_haiku_response()` helper returned a bare 6-key dict. Fix: `_haiku_response()` now returns the same `(dict, int, int)` shape the real function does.

**`test_run_health.py` (4 fails)** — a bigger, real finding: AA-441 (already shipped, Done) rewrote `GET /admin/acp/run-health` from the legacy v1 tables to the real, live v2 tables (`acp_shared.acp_v2_runs`/`acp_v2_slots`) — this test file's mock still matched the OLD v1 table names in its SQL substring check, so every `conn.fetch()` fell through to `return []` — every endpoint test got 0 rows back. (`test_run_health_filters_by_tenant` only "passed" before because its assertion was vacuously true on an empty list — strengthened while fixing.) 3 of the 4 endpoint tests also asserted business behavior (stuck detection, cost cap, gate SLA) that AA-441's own docstring documents as **structurally disabled for v2 runs today, by deliberate design** (no v2 SLO/cost/hitl-equivalent tracking exists yet) — rewrote them to assert the real, current, documented behavior instead of a scenario the code cannot produce. Still real regression coverage: they'll fail the moment someone wires v2 tracking back in without updating these.
