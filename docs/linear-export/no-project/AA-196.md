# AA-196 — [AA-193·F4] Day-by-day titles must name place/activity (string format + validator, no schema change)

Parent: [AA-193](https://linear.app/aa-ecosys/issue/AA-193/s1-content-quality-dataforseo-keyword-sourcing-brand-differentiation). F4 — day-by-day titles must name place/activity and read attractively. **Decision locked: keep itineraries as STRING** (format `Day N -- [title] + prose`), NO schema change to structured list (avoids ripple across generated_content / S2 / S3 / blog / exports / UI).

## Root cause (STEP 4 + 6)

Itineraries is a single free string; prompt requires `Day 1 -- [title]` format but gives NO instruction that title must name place/activity. brand_standards.py AA_ITINERARIES has no day-title spec. The `_normalize_generated`/validate_node list-handling code is a dead path (prompt never emits that structure).

## Scope

**Prevent (generation):**

* `prompts.py` OUTPUT JSON FORMAT + `brand_standards.py` AA_ITINERARIES: day-title spec — each day title MUST name the place and/or primary activity (e.g. `Day 2 -- Trekking to Sapa Valley Villages`), never generic (`Day 2 -- Exploration` / `Free Day`). Keep within the existing string format.
* Use lessons-log target pattern (Lesson 2: `Mae Taeng Valley Cycling Day: Waterfalls, Farmland & Temple`).

**Catch (audit):**

* `brand_audit_node.py`: heuristic regex for generic day titles (`Day \d+ -- (Exploration|Free Day|Arrival Day|Departure|Transfer)$`) → new code `ITINERARY_DAY_TITLE_GENERIC`.
* `flag_fix_node.py` STAGE2_FIX_MAPPING: add `ITINERARY_DAY_TITLE_GENERIC → itineraries`.
* `brand_standards.py` FAILURE CODES list: add the new code.

## Notes

* String-format choice confirmed to avoid downstream ripple (per impact analysis).
* Depends on string-format decision (locked). Ready to build.
