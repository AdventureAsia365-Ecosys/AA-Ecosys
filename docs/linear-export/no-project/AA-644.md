# AA-644 — [EVAL] GPT-4.1 → GPT-5.6 Luna on Bedrock acc3 for judges (s1_judge, brand audit, Debate, T10 F8/F9) — A/B then staged switch

*Created S198. Ms. Thư proposed switching the GPT-4.1 judges to GPT-6 Luna to save cost. Advice and risks are recorded here.*

## Facts

* **GPT-6 Luna** (OpenAI, released 22–23/09/2026) costs **$0.10 / $0.50 per 1M** input/output tokens. `pricing.py` has GPT-4.1 at **$2 / $8**, so Luna is about **20× cheaper on input and 16× on output**.
* Luna supports JSON-schema structured outputs and 6 reasoning-effort levels (none … max). Sources: public pricing and benchmark pages (OpenRouter, VentureBeat, Artificial Analysis). The OpenAI docs page was not reachable from the cloud session, so confirm parameters with a real call.
* There is **no GPT-4.1-mini** in the code; every judge uses `gpt-4.1` via the OpenAI API directly.
* Bedrock offers only **GPT-5.6** Luna ($0.22 / $1.32). Its agreement was never accepted, and GPT-5.6 Sol was stuck on AccessDenied (repo `docs/implementation-notes/AA-351-gpt56-judge-trial.md`). The OpenAI API directly is cheaper and simpler.
* ADR-2026-014/027 (judge vendor ≠ writer vendor) stays satisfied: Luna is OpenAI and the writers are Claude.

## Risks to verify with real calls

1. **Reasoning-model parameters.** Luna may reject `temperature` / `seed` and require `max_completion_tokens` instead of `max_tokens`. That breaks the AA-209 determinism contract, so re-measure run-to-run variance at `reasoning_effort` none/low.
2. **Reasoning tokens are billed as output.** Keep effort at none/low for judges and measure the real tokens.
3. **Pricing entry.** Add Luna to `pricing.py` (or the [AA-642](https://linear.app/aa-ecosys/issue/AA-642/epic-model-gateway-one-routing-layer-for-claudebedrock-openai-jev) catalog). Otherwise it is priced as Sonnet ($3/$15) and External Spend over-reports.
4. **Recalibration.** `MIN_QUALITY=7.0`, `_MISSION_ABSENT_CAP=6.0`, the F9 pass rate and the Debate cut rate were all tuned on GPT-4.1's score distribution.

## Plan

1. Pull the current OpenAI volume per stage from `llm_call_log` (stages `s1_judge`, `s1_brand_audit`, `t10_judge`, `n7_judge`, debate) to size the real saving before promising a number.
2. **Offline A/B** on stored content: same prompts, both models, reusing the AA-351 compare-script approach. Measure verdict agreement, score shift, per-code agreement for F9 failure codes, JSON validity, latency and cost.
3. **Switch in order of risk:** F8 (warn-only) and Debate brand-fit → `s1_brand_audit` / `s1_judge` → **F9** `cta_fact` **(blocking) last**, only if agreement is high.
4. Once [AA-642](https://linear.app/aa-ecosys/issue/AA-642/epic-model-gateway-one-routing-layer-for-claudebedrock-openai-jev) P3 exists, use shadow mode on live traffic for 1 week before each switch.
5. **Rollback:** a single admin-UI change, once all paths read the stage config.

## Long-term shape (with the Jev eval)

Jev (screen) → Luna (cheap judge) → GPT-4.1 or a stronger model only on escalation.
