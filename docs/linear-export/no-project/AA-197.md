## Ms. Thu's 4-part logic (Jira comment 15/06)

1. **Seed = trip location + activity (+ special highlight)** — e.g. "hiking in Jeju" — searched in the **tenant's buyer market**. Result = how people in that market search for that trip.
2. **People also ask** — localized to buyer country.
3. **Related keywords** — activity/location-adjacent (e.g. "homestay in Jeju").
4. **Keyword ideas** — location+activity focus; fallback when the target market lacks data.

## Current state (STEP 2/3/6)

Cloud `seo_intelligence/dataforseo_client.py`: hardcoded US (`location_code=2840`), seed = `"{country} tours"` (+ double-"tours" bug), only search_volume + PAA — **no related, no ideas**. Further from Ms. Thu's spec than even v5.

## Scope

* **Replace** `dataforseo_client.py` with v5-style `serp/google/organic/live/advanced` call returning related_searches + people_also_ask + competitor_angles → derive keyword_ideas + keyword_suggestions.
* **Seed (admin_pipeline.py:182-184):** build from location + activity (+highlight), not `"{country} tours"`. Fix double-"tours".
* **Market source:** `shared.tenant_seo_config.target_market.primary` via `TenantConfigService.load_seo_config()` (buyer-market locale, Redis-cached). **NOT** `shared.tenants.country` (= supplier home country, e.g. bluepoppy=Thailand — wrong semantics).
* **Location map:** `DFS_LOCATION_MAP = {en_US:(2840,"United States"), en_UK:(2826,"United Kingdom"), en_AU:(2036,"Australia")}`, key = target_market.primary.
* **Fallback:** when target-market query returns no keyword data → widen to keyword_ideas (per Ms. Thu #4).
* PAA/keywords already consumed by `build_rewrite_prompt` ([prompts.py](<http://prompts.py>) L56-57) — only source data needs fixing.
