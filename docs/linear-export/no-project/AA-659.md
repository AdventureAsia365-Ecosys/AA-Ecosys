## Why

The admin UI controls only `s1_brand_audit`. These call sites bypass `shared.llm_role_config`:

* `services/content_generation/brand_fit.py` (s1_judge + Debate) — hardcoded GPT-4.1;
* `judge_client.py` (F8 / F9 / N7) — hardcoded GPT-4.1;
* the segment research loop (`model_tier="haiku"`);
* TripPlanner assembly (`global.anthropic.claude-sonnet-4-6`).

## Scope

* Every call goes through `gateway.generate(stage=...)`. The stage config picks the catalog model plus a **fallback chain**, for example:
  * GPT-5.6 Luna@acc3 → GPT-4.1@OpenAI;
  * Sonnet 5@acc3 → Sonnet 4.6@acc3 → Sonnet 4.6@acc1.

  acc3 is the primary. acc1 and acc2 are used only for models they actually have.
* **Shadow model** per stage: runs async on a sample %, logs only, never affects output. Used for the [AA-644](https://linear.app/aa-ecosys/issue/AA-644/eval-gpt-41-gpt-6-luna-for-judges-s1-judge-brand-audit-debate-t10-f8f9) / [AA-645](https://linear.app/aa-ecosys/issue/AA-645/eval-claude-sonnet-5-for-writer-stages-t2-generate-t8-angle-gen-t9) A/B tests.
* Guard: a judge stage's vendor must differ from its writer stage's vendor (warn in the UI).
* TripPlanner assembly calls the same Gateway, either through a thin shared client package or an internal endpoint. **\[DECISION\]** at build time.
* Admin Settings: model, fallback chain, shadow and sample % per stage. Changes are audited.

## Done when

No `grep` hits for hardcoded model IDs outside the catalog/seed. Switching the `s1_judge` stage to GPT-5.6 Luna in the UI takes effect within 20 s (config cache) with no deploy.
