## Root cause (STEP 2/3 + DBeaver)

**Not a prompt problem — a wiring + fallback bug.** Brand injection mechanism works (`graph.py` appends brand_system_prompt→system, style_guide→user). But:

* `admin_pipeline.py:119-134` fetches brand_rules by `brand_name`; `brand_identity_id` from S1 RunConfig (`v1_s1.py:47`) is **never used**.
* When brand_name not passed → fallback `WHERE tenant_id AND is_active ORDER BY version DESC LIMIT 1`. DBeaver: tenant `0000…001` has **5 active rows**; highest version = **Terra Family Expeditions v2** → every run silently gets Terra Family regardless of intended brand.
* `default` brand row has empty system_prompt.

(The 4 brand rows DO have distinct system_prompts — data is fine; the selection logic is broken.)

## Scope

1. Wire `brand_identity_id` → brand_rules lookup in `admin_pipeline.py` (map id→brand_name or query by id).
2. Fix fallback: don't silently pick highest-version active row — require explicit brand or use `default` explicitly; dedupe to 1 active row per brand (data cleanup).
3. **Admin brand-picker preview:** in CIS Admin S1, let AA team select a brand identity and run S1 preview WITHOUT creating/logging-in as a separate tenant (Ms. Thu's actual request). Confirm endpoint contract first (`/admin/run-tour` brand_name vs `/acp/s1/run` brand_identity_id — the latter currently disconnected).
4. Optional: inject `brand_forbidden_words` into prompt (currently only checked post-hoc in validate_node, never told to LLM).
