# AA-311 — [Bug] Upload S0 báo "Commit failed (500)" sai — data đã lưu DB đúng, lỗi thật là StartExecution AccessDenied gọi thừa sau khi INSERT xong

## Nguồn gốc

Phát hiện khi Nghiep upload 14 file Excel thật qua Upload S0 ([AA-247](https://linear.app/aa-ecosys/issue/AA-247/djo-du-lieu-tour-tho-jira-content-cowork-rewritten-prefix-aa-vao-cis), 20/07/2026). UI báo "Commit failed (500)" cho 8/13 file, gây hiểu lầm mất dữ liệu.

## ✅ Verify qua DB + CloudWatch thật (S3-mediated ECS exec, KHÔNG đoán)

**Dữ liệu AN TOÀN 100%** — 720 tours đã `INSERT` đúng vào `silver_aa_internal.raw_tours`, reconcile khớp chính xác (inserted + staged duplicate = parsed) cho toàn bộ 9 file bị báo lỗi (8 file "500" + TAIWAN báo nhầm "0 saved"). `pipeline_status='ingested'`, `review_status='pending_review'` — trạng thái bình thường sau ingest.

## Root cause thật (CloudWatch `/ecs/aa-cis-dev`, stream `api/api/4b84257deeff48b9b228c974a1480f88`, ~04:59:25 UTC 20/07)

```
processing_failed  error=An error occurred (AccessDeniedException) when calling the StartExecution
operation: User: arn:aws:sts::005097885195:assumed-role/aa-cis-dev-ecs-task-role/... is not
authorized to perform: states:StartExecution on resource:
arn:aws:states:us-west-1:005097885195:stateMachine:aa-cis-dev-pipeline
  File "/app/api/routers/admin_pipeline.py", line 1154, in ingest_s3
  File "/app/services/ingestion/handler.py", line 184, in process_file
  File "/app/services/ingestion/handler.py", line 257, in _start_pipeline
```

`process_file()` (`services/ingestion/handler.py:175`) INSERT tours vào `raw_tours` **TRƯỚC**, rồi gọi `_start_pipeline()` (dòng 183-193) cố kích hoạt Step Functions execution `aa-cis-dev-pipeline` — ECS task role thiếu quyền `states:StartExecution`. Exception raise, `process_file()` re-raise (dòng 209), endpoint trả 500 — **NHƯNG DB write đã commit xong trước đó.**

## Liên quan trực tiếp [AA-182](https://linear.app/aa-ecosys/issue/AA-182/cis-verify-aa-cis-dev-pipeline-sm-works-migrate-cis-to-sm-or-retire-it) (Backlog)

[AA-182](https://linear.app/aa-ecosys/issue/AA-182/cis-verify-aa-cis-dev-pipeline-sm-works-migrate-cis-to-sm-or-retire-it) đã ghi nhận: Step Functions SM `aa-cis-dev-pipeline` là **"deployed but bypassed — direct API flow only"** trong kiến trúc hiện tại (CIS rewrite chạy trực tiếp qua `_rewrite_tour()`, không qua SM). Cuộc gọi `_start_pipeline()` này **không cần thiết** trong kiến trúc hiện tại, chỉ là code cũ chưa dọn, và nó **fail MỖI LẦN upload** — gây báo động giả liên tục.

## Đề xuất (chưa làm — cần xác nhận hướng trước khi code)

Tuỳ theo quyết định [AA-182](https://linear.app/aa-ecosys/issue/AA-182/cis-verify-aa-cis-dev-pipeline-sm-works-migrate-cis-to-sm-or-retire-it) (migrate SM hay retire hẳn):

1. Nếu retire SM: xoá lời gọi `_start_pipeline()` khỏi `process_file()`, hoặc bọc `try/except` không re-raise (log warning, không chặn response 200).
2. Nếu migrate sang SM thật: fix IAM policy `aa-cis-dev-ecs-task-role` thêm `states:StartExecution` — nhưng cần cân nhắc kỹ vì [AA-182](https://linear.app/aa-ecosys/issue/AA-182/cis-verify-aa-cis-dev-pipeline-sm-works-migrate-cis-to-sm-or-retire-it) chưa quyết định hướng.

**Không nên tự chọn hướng — phụ thuộc quyết định** [AA-182](https://linear.app/aa-ecosys/issue/AA-182/cis-verify-aa-cis-dev-pipeline-sm-works-migrate-cis-to-sm-or-retire-it) **trước.**

## Tác động hiện tại

Không mất dữ liệu, nhưng UX xấu — người dùng thấy "failed" tưởng phải re-upload trong khi dữ liệu đã lưu đúng. Rủi ro: nếu ai đó tin UI và re-upload lại → có thể tạo duplicate không cần thiết (dù `upload_staging` đã có cơ chế phát hiện duplicate).

## STEP 0 khi bắt đầu

Đọc lại `services/ingestion/handler.py` dòng 175-209 + `AA-182` để xác nhận hướng retire/migrate trước khi sửa.
