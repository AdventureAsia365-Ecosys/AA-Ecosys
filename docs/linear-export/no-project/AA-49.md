## Overview

v0.3 adds 3 harness engineering upgrades to ACP. All **$0 cost delta** — architectural changes only.

| Upgrade | Summary | Sprint |
| -- | -- | -- |
| H-1 | Generator/Evaluator isolation — Haiku evaluates text-only, no brand context | M4 |
| H-2 | acp_output_rules table — deterministic post-processing after every LLM call | M0 + M4 |
| H-3 | HITL rejection → deterministic rule pipeline | M5 |

---

## H-1 Tasks — Generator/Evaluator Isolation (M4)

1. Create Lambda: `acp-s4-evaluate`
   * Input: `{text: draft_content_only}` — NO brand_brief, NO outline, NO context
   * Compute: SHA256 hash of input → store as evaluator_input_hash (audit trail)
   * Model: Bedrock Haiku 4.5
   * Rubric: Readability, Factual trust, Engagement, Keyword naturalness, Completeness
   * Output: `{evaluator_score, dimension_scores: {}, issues: [], evaluator_input_hash}`
2. Update S4 blog engine flow:
   * After LLM draft: call apply_output_rules() FIRST
   * Then: call acp-s4-evaluate Lambda with text-only payload
   * Store: blog_drafts.evaluator_score + evaluator_input_hash
   * Gate threshold: 7.5 (not 8.0 — isolated evaluator is more objective)
3. Verify isolation in test: evaluator_input_hash must match SHA256(draft_content only)
   No other fields should appear in Lambda request log

---

## H-2 Tasks — acp_output_rules (M0 + M4)

**M0 (DB migration):**

* Create table `acp_shared.acp_output_rules` (see PRD v0.3 Section 2.3.1 for full schema)
* Seed 10 system rules (SYS-001 to SYS-010):
  * SYS-001: S4 score_gate keyword_density > 0.020 → block
  * SYS-002: S4 score_gate keyword_density < 0.005 → block
  * SYS-003: S4 score_gate word_count < 1500 → block
  * SYS-004: S4 score_gate word_count > 3000 → flag
  * SYS-005: S4 truncate seo_title > 60 → truncate
  * SYS-006: S4 truncate meta_description > 160 → truncate
  * SYS-007: S4 score_gate internal_links < 2 → block
  * SYS-008: S3 block primary_keyword in s1_keywords_used → block
  * SYS-009: All replace tenant forbidden_words → approved_alternatives
  * SYS-010: S4 flag price/date patterns without source → flag
* Add new columns to blog_drafts:
  * evaluator_score NUMERIC(3,1)
  * evaluator_input_hash VARCHAR(64)
  * review_flags JSONB DEFAULT '\[\]'
  * rules_applied JSONB DEFAULT '\[\]'
* Add new columns to acp_hitl_requests:
  * rejection_note_structured JSONB
  * rule_created_id UUID FK → acp_output_rules

**M4 (S4 integration):**

* Write `acp_post_processor.py`: apply_output_rules(output, stage, tenant_id, run_id)
  * Query active rules for stage + tenant
  * Apply: block → raise OutputRuleViolation, replace → deterministic swap, truncate → cut at word boundary, flag → append to review_flags, score_gate → raise if threshold violated
  * Update run_count for fired rules
  * Store rules_applied array in blog_drafts
* Integrate into S4 flow: call AFTER LLM generation, BEFORE evaluator and BEFORE DB save
* Add Rules Dashboard tab to ACP frontend: list rules, run_count, source, toggle active

## H-3 Tasks — Mistake→Rule Pipeline (M5)

1. Update acp-hitl-router Lambda:
   * On rejection (status='rejected' + review_notes present):
   * Call Haiku to extract: {pattern_type, pattern_value, suggested_action, confidence_score}
   * Haiku prompt: structured extraction only (NOT creative generation)
2. Rule creation logic:
   * confidence_score ≥ 0.80: auto-create acp_output_rules row (source_type='hitl_rejection', source_hitl_id=hitl_id)
   * confidence_score < 0.80: show proposed rule in dashboard → reviewer confirms → create
3. Link rule to rejection:
   * Update acp_hitl_requests.rule_created_id = new rule_id
   * Dashboard: "Rule created from rejection \[link\]"
4. Test: reject Gate 3 blog with note "mentions prices" → verify rule created → verify next S4 run for tenant flags price patterns
