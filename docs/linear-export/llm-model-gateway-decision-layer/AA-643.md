# AA-643 — [EVAL] Jev (TypeSafe) offline eval on real CIS data — F8, T3 grounding, A3 keyword/PAA gates

*Created S198. Offline script only; no App code change. Follows* [AA-634](https://linear.app/aa-ecosys/issue/AA-634/research-typesafe-ai-jev-system-one-model-khao-sat-toan-dien-at-series) *(research) and the per-stage map in its S198 comments.*

## Why

Ms. Thư's own measurement (branch `add-the-typesafe-skill` of `thule78/aa-soscial-media`, `output/jev-blind-sample.md`) found **51% agreement between Jev and a human** on landing-belongs, with disagreements one-directional (Jev cutting landings the marketer kept). Nothing ships until we measure on our own data, with a better-posed human label.

## Candidates, in order (from the [AA-634](https://linear.app/aa-ecosys/issue/AA-634/research-typesafe-ai-jev-system-one-model-khao-sat-toan-dien-at-series) S198 per-stage map)

1. **T10 F8 framework:** warn-only since [AA-613](https://linear.app/aa-ecosys/issue/AA-613/social-tenantsub1-be-gate-severity-metrics-table-don-leak-pieces), yet still one GPT-4.1 call per attempt. Compare one Jev Noul per rubric item against the stored GPT-4.1 verdicts in `llm_call_log.quality_signal`.
2. **T3 / F1 grounding prefilter:** for each stored regex hit that triggered a full-tour rewrite, ask Jev "is this number supported by the source (conversion, sum, rephrase)?". Count the rewrites that would have been avoided.
3. **A3 keyword belongs** (port of Ms. Thư's ticket 03): run on `segment_research_log` keywords. Count the DataForSEO spend that would have been saved.
4. **A3 PAA landing and country scope** (her tickets 04/05): run on `atom_matches` rows with kind `question`. CIS is looser than her original: a PAA question joins the shortlist by sharing one word and lands on the nearest atom inside that Segment, with no distance cut-off.
5. **T8** `rank_angles`**:** one Noul per (angle, PAA question) pair, versus today's verbatim-copy check.

## Method

* Script under `scripts/` in AA-CIS-App, run via ECS exec (the steering rule for manual LLM scripts applies: log to `llm_call_log`, `stage="adhoc_aa<this issue>"`, `role` in the CHECK set, provider `typesafe`).
* **Human labels, done Ms. Thư's way but better posed:** only pairs where both sides name the same entity type, and a question that asks exactly what the gate asks. Target 100–200 labelled rows per candidate.
* **Metrics:** agreement with the human, agreement with GPT-4.1 (for F8), calibration (reliability curve), saved calls and dollars, and p50/p95 latency.
* **Budget:** under $0.10 in Jev tokens (Jev charges $0.042 per 1M input tokens; output is free). Ask Nghiệp before any DataForSEO or LLM spend beyond that.

## Blockers

* Cloud sessions: the environment's network allow-list must include `api.typesafe.ai`. It was set on 28/09 and takes effect only in new sessions. From WSL there is no blocker.
* The API key is held by Nghiệp. Never commit it; use the `TYPESAFE_API_KEY` env var.
* A smoke-test script (`typesafe-sdk` 0.7.2, 4 scenarios) was written in S198 but has not yet reached the real API (it got 403 at the proxy).

## Data / privacy

Tenant content would go to a new sub-processor, and TypeSafe offers ZDR only on its enterprise plan. Eval on admin (`aa_internal`) content first; a DPA review is needed before tenant content goes through.

## Done when

There is a results table per candidate, with a go / no-go recommendation and a proposed floor. The recommendation feeds [AA-642](https://linear.app/aa-ecosys/issue/AA-642/epic-model-gateway-one-routing-layer-for-claudebedrock-openai-jev) phase P4.
