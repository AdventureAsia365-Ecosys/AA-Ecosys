## Problem

Several operating rules live only in `memory.md` / steering, and agents still break them:

| Rule | Broken in |
| -- | -- |
| No merge/deploy while `shared.job` has queued/running jobs | S212 — 3 PRs merged mid Thailand wave → 16 S1 jobs killed |
| Verify LIVE before marking Done | S212 — SEO 500, Live view button, Thailand count |
| No helper between `@router.get` and `async def` | S211 — hotfix [AdventureAsia365-Ecosys/AA-CIS-App#559](https://linear.app/aa-ecosys/review/aa-718-hotfix-restore-route-decorator-on-get-tenant-details-14c6e22e9f01) (422) |
| New top-level module needs `COPY` + path filter | S210 — worker missing `COPY worker/` |
| Deploy must update the worker too | S211 — worker stuck on task-def `:1` |

A rule a CI check can enforce should not depend on the agent remembering it (Harness Engineering handbook, Sec 35).

## Scope

1. **Pre-deploy guard** in `deploy-dev.yml`: query `shared.job` for queued/running (no time filter). Fail when > 0, unless the PR touches FE only. Manual override input with a logged reason (Nghiệp only).
2. **Post-deploy smoke**: curl each endpoint changed in the PR (or a maintained list) on the real domain; assert 200 + response shape. Workflow red on failure.
3. **Route sanity test**: call every registered FastAPI route with minimal args; fail on 422 caused by a mis-bound decorator.
4. **Dockerfile check**: every top-level app module has a `COPY` line and a path-filter entry.
5. **Post-deploy revision check**: api and worker run the same image SHA; `job_worker_started` logged for every kind.

## Done when

* A deploy attempted with a running job is blocked (or overridden with a logged reason).
* A deliberately broken endpoint turns the workflow red.
* Rules 1–5 are removed from steering once their checks are live.
