## Findings (middleware.ts, AA-252/AA-253 notes)

* The `content` staff role has **no JWT**: the `cis_role` cookie is trusted as-is after login.
* The BFF proxy routes `/api/admin`, `/api/pipeline`, `/api/tour-full` and `/api/tenant/pipeline` are outside the middleware matcher.
* The admin nav shows an "ADMIN" tag that does not match real permissions.

## Scope

* Every staff role (`admin`, `reviewer`, `content`) gets a signed JWT, verified in the middleware and in every BFF proxy.
* A single RBAC matrix (a permissions table), reused by AA-Booking staff roles (`admin`, `sales`, `content_creator`), so the ecosystem has one staff identity model.
* Remove the cosmetic "ADMIN" tag. Permissions decide what is visible.

## Done when

A forged cookie without a token is rejected on every page and on every proxy route (tested). The RBAC matrix is documented in CONTEXT.md.
