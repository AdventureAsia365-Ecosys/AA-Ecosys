## Problem

Admin → Jobs always requests `limit=100` (`frontend/app/admin/jobs/page.tsx:70`) and the API caps `limit` at 200 (`api/routers/admin_job_runner.py:45`). Filters (`kind`, `status`, `tour_id`) run server-side, but only the newest 100 matches come back; the pager shows "1–100 of 100 · Page 1/1", so the page silently truncates (10/10/2026: `a3_atomize` 941 jobs, `s1_rewrite` 797). Column sort acts only on the loaded 100 rows.

Nghiệp (S223, screenshots): when scrolling the list, the filter bar and the table header scroll away, so long lists are hard to read. Root cause: the kit `DataTable` header is `position: sticky; top: 0` inside an `overflow: auto` wrapper with no height limit, so it never sticks to the viewport. The Workers / Queue panel and the Job kinds table also push the list down and sit above/below it on one long page.

## Design (decided S223)

Top to bottom:

1. PageHeader (title + Refresh) — unchanged.
2. Status chips (Queued / Running / Succeeded / Failed / Stopped / Cancelled) — clicking one sets the status filter.
3. Tabs: **Jobs** (default) · **Queue & workers** (current workers + queue-by-kind panel) · **Job kinds** (current table). Tab kept in the URL (`?tab=`).
4. Jobs tab: toolbar (search, Kind, Status, Created by, date range since/until, Views / Columns / CSV) and the table header stay visible while scrolling — the table sits in a viewport-height scroll container with a sticky header row and the pager pinned at its bottom. Pager reads "1–100 of 1,778" with 50/100/200 per page.
5. Every column header sorts **server-side**: Kind, Status, Attempt, Duration, Cost, Created (default: newest first), By. Mobile card layout keeps working.

## Scope

1. API `GET /admin/job-runner/jobs`: `offset` + `limit` (≤ 200), `sort` (whitelist: created_at, kind, status, attempt, duration, cost, created_by) + `dir` (asc/desc), `since` / `until` (created_at), `created_by`, `q` (search on id prefix / kind / created_by), and `total` = rows matching all filters. Backward compatible: `jobs` unchanged, old params still work.
2. Kit `DataTable`: opt-in `serverSort` (manual sorting driven by the caller) and an opt-in viewport-bounded scroll container (`maxHeight`) so the sticky header actually sticks. Other pages unchanged unless they opt in.
3. Jobs page per the design above; filters, sort, page, page size and tab kept in the URL.
4. Unit tests: query builder (sort whitelist rejects unknown columns, offset/limit, range, total uses the same filters).

## Done when

* Live on Dev: filtering `a3_atomize` shows the real total (≈ 941) and the pager reaches the oldest job; sorting by Cost / Duration orders across all pages, not just the current one.
* Scrolling the Jobs tab keeps the toolbar and header row visible (desktop + mobile, light + dark screenshots).
* Unit tests + CI + UI smoke green.
