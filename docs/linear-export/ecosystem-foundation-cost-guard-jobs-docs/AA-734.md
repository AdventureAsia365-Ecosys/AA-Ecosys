# AA-734 — [Jobs] atom_ranking versioned-swap so recompute never dips the live count (ADR 0003 nac 2)

## Why

Follow-up to [AA-723](https://linear.app/aa-ecosys/issue/AA-723/p1-move-all-remaining-in-process-api-background-tasks-onto-the-worker). The `recompute` job now runs on the worker, but the write logic is unchanged: `run_atom_ranking` rebuilds `acp_contract.atom_ranking` with DELETE+INSERT **per market, in six separate transactions**. A reader hitting mid-loop sees the count drop then climb back. Most visible on `admin_overview` (`SELECT count(*) FROM acp_contract.atom_ranking`) and the Slate / admin_dashboard score panels.

`route` is already swap-safe (`superseded_at IS NULL`, [AA-532](https://linear.app/aa-ecosys/issue/AA-532/t7bug-route-detectionpy-xoa-toan-bo-roi-insert-lai-vi-pham-fk)). `atom_ranking` is not.

## Approach (decided S213 — option B, MVCC, no new column)

Make the recompute swap atomic by wrapping the writes in ONE transaction instead of adding a version column + touching \~8 readers. Postgres MVCC then shows a concurrent reader the whole old set until COMMIT, then the whole new set.

Complication found while scoping: `run_route_detection` READS `atom_ranking` (`excluded_reason IS NULL` membership) to derive routes. For a trueno-dip across BOTH ranking and route, the six-market ranking write and the route re-derivation must be in the same transaction/connection. So:

* Refactor `run_atom_ranking` and `run_route_detection` into **compute** (reads + Jev exclusions + demand + ranking math, NO transaction held — Jev calls are slow) and **write** (DELETE+INSERT / supersede+insert, takes a connection already in a transaction).
* The orchestrator (`recompute_segment_score_route` / `recompute_rankings_and_routes`) opens one transaction, writes all six markets, then re-derives + writes routes, then commits.
* Keep the recompute on its own thread/loop/connection (a3 pattern) — mind that a long transaction now spans the write, but NOT the Jev/embedding compute.

## Done when

Poll `admin/overview` (atom_ranking count) and a tenant Slate continuously while a platform recompute runs → the count never dips, it steps straight from the old total to the new total. No reader change needed. Merge + CI + deploy COMPLETED + live verify.

## Risk

Data-correctness + a longer-held write transaction on `atom_ranking`/`route`. Verify SELECT readers are never blocked (MVCC: writers don't block readers). Its own session, done carefully — not bundled with other work.

Implements ADR 0003 nac 2 (`AA-Ecosys/docs/adr/0003-one-durable-job-model.md`).
