## Why (S200, 28/09/2026)

Three apps (soon four) share one RDS on acc2, but schema migrations are scattered without an ownership rule:

* `AA-CIS-App/api/migrations/` — 162 files (001→169), create `acp_*`, `silver/gold`, `ops`, `bronze` and 25 `shared.*` tables. Applied by hand via ECS exec; each registers in `shared.schema_versions`.
* `AA-CIS-Infra/modules/rds/migrations/001–008` — **byte-identical copies** of App 001–008. No Terraform or CI references them: dead code.
* `AA-TripPlanner-Web/migrations/` — `001` (`tripplanner.*`) and `002` (`shared.destinations`). **Not registered in** `schema_versions`, so nobody can tell whether they were applied.
* AA-Booking will add `booking.*` on the same RDS (ADR 0001 decision 6).

Decided with Nghiệp (grilling round 2): do **not** move App migrations to Infra or the root repo. Each service owns the migrations of the schema it owns, so schema and code change in one PR. Infra owns the RDS instance, DB roles and grants — not schema.

## Scope

1. Delete the 8 duplicated files in `AA-CIS-Infra/modules/rds/migrations/`. Keep in Infra only per-app DB role / grant bootstrap, if and when needed.
2. Write `AA-Ecosys/docs/database/schema-ownership.md`: owner repo per schema, plus per table for `shared.*`. Example: `shared.destinations` is a golden record created by TripPlanner today; decide whether CIS should own it. `shared.llm_model_catalog` is owned by CIS and read by the other apps (ADR 0005).
3. Prefix `schema_versions.version` per repo for new migrations (`tp-003`, `bk-001`; App keeps plain numbers as history). Make TripPlanner migrations register their version. Backfill `tp-001`/`tp-002` after checking the live DB.
4. Rule, recorded in ecosystem ADR 0001 decision 6 and the steering: an app never migrates another app's schema.

## Done when

The ownership doc is merged, Infra has no schema SQL, TripPlanner versions are visible in `shared.schema_versions`, and every repo's CONTEXT.md points to the ownership doc.
