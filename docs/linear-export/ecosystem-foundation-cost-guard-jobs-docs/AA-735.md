# AA-735 — [Jobs] Job-model modularization follow-ups (ADR 0003 nac 3-6)

## Why

[AA-723](https://linear.app/aa-ecosys/issue/AA-723/p1-move-all-remaining-in-process-api-background-tasks-onto-the-worker) + [AA-734](https://linear.app/aa-ecosys/issue/AA-734/jobs-atom-ranking-versioned-swap-so-recompute-never-dips-the-live) deliver the durable job model and the no-dip recompute. These are the remaining, lower-priority steps from ADR 0003 (`AA-Ecosys/docs/adr/0003-one-durable-job-model.md`) and the plan in `docs/architecture/job-model-modularization.md`. Grouped here so they are not lost; split into their own issues when a session picks one up.

## Nac 3 — full stage registry

Turn segment / score / route / hub into declared stage modules (pure `run(ctx, scope)`, each declaring the tables it reads/writes), with the orchestrator reading the stage list. Fold the `a3_atomize` job's inline `recompute_segment_score_route` call into the same `recompute` gate so there is ONE entry into the platform recompute, not two.

## Nac 4 — cron/event Lambdas enqueue jobs

The standalone Lambdas (dfs_balance_check, s4_trigger, acp_produce sweeper, acp_canary, dlq_classifier) run work inside the Lambda, invisible to the Jobs page. Where the work is non-trivial, have the Lambda enqueue a `shared.job` instead so it is durable + visible. (CIS + Infra.)

## Nac 5 — remove worker fragility + dead code

* Flip `JOB_WORKER_IN_API` default to **false** (today it defaults true; only a manually-set env on the api task-def stops two workers running).
* Retire the legacy `shared.pipeline_jobs` path (startup `sweep_interrupted`) once no pre-[AA-723](https://linear.app/aa-ecosys/issue/AA-723/p1-move-all-remaining-in-process-api-background-tasks-onto-the-worker) jobs remain.
* Remove the dead `_background_tasks` drain in `api/main.py` ([AA-723](https://linear.app/aa-ecosys/issue/AA-723/p1-move-all-remaining-in-process-api-background-tasks-onto-the-worker) removed every task that fed it; the shutdown drain is now a no-op).

## Nac 6 — cross-repo (when needed)

Grant `shared.job` to a second repo and make TripPlanner's extraction + embeddings-backfill durable job kinds instead of hand-run scripts. Only when there is a real second consumer (TripPlanner has none today; AA-Booking does not exist yet).

## Done when

Each nac is its own PR when picked up; this umbrella issue closes when nac 3 + nac 5 land (nac 4 and 6 may stay deferred).
