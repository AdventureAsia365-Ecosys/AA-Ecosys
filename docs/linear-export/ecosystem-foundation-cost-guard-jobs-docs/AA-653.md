# AA-653 — [P2] A/T flow sync audit + clean-rerun runbook (Bhutan pilot wave, Jev in shadow)

## Goal

Before the full rerun ([AA-594](https://linear.app/aa-ecosys/issue/AA-594/epic-cis-data-reset-and-pipeline-rerun-giu-raw-tours-reset-dan-xuat)/599/600/601), prove that one small country flows correctly end to end:

A0 → S1 → Review → Master Content → atomize → Segment/Score/Route/Hub → Slate → T8–T11 → TripPlanner extraction.

## Checklist for each hand-off

* Reads the platform-wide sets. Never recomputes a platform set per tenant.
* **No DFS purchase is triggered by a tenant action.**
* Runs as a job, with budget, progress and cost visible in admin.
* Idempotent re-run (no duplicate atoms/segments).
* The admin page for that stage shows real data.

## Runbook

* The pilot is **Bhutan (35 raw tours)**, then the small countries, then India/China/Japan.
* Each wave has:
  * a pre-run estimate;
  * a budget;
  * a verification query pack;
  * a UI check;
  * TripPlanner re-extraction.
* Jev runs in **shadow** at the agreed stages (see the Jev calibration issue), writing to `decision_log`.

## Depends on

* the DFS P0 fixes;
* the cost guard;
* the job runner;
* [AA-642](https://linear.app/aa-ecosys/issue/AA-642/epic-model-gateway-one-routing-layer-for-claudebedrock-openai-jev) Gateway P0 (models);
* [AA-641](https://linear.app/aa-ecosys/issue/AA-641/t2-pipeline-stop-flag-fix-from-creating-new-hard-failures).

## Output

`docs/runbooks/clean-rerun.md` in the App repo, plus the Bhutan wave results.
