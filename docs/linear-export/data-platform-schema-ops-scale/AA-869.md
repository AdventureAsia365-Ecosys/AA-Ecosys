## Problem

S241 P0-11: CIS ECR is mutable and still pushes `:latest`; the lifecycle keeps 10 images while CIS deploys \~129 times a week, so task definitions older than about a day point at deleted images. There is no rollback runbook and no incident process. Manual RDS snapshots have no expiry. (The DB restore drill passed in S241, D-10.)

## Scope

1. Stop pushing `:latest`, then ECR `IMMUTABLE` via Terraform; lifecycle keeps 30 `dev-*` images, untagged expire after 7 days (quote storage cost first, D-19).
2. Rollback = point the service at the previous task-def revision; document it in `skill/aa-ship`.
3. Document Vercel instant rollback (deploys are CI-created since S241).
4. `docs/ops/incident-response.md`: SEV1–3, who is told (incl. Ms. Thư and tenants), first 15 minutes, notice template.
5. Expiry rule for manual RDS snapshots (DM-7.5).

## Done when

* Rollback drill on Dev: api rolled back to the previous revision, rollout COMPLETED, `/health` 200 with the old SHA, then rolled forward (commands + output in the session log).
* `aws ecr describe-repositories` shows `IMMUTABLE` and the new lifecycle policy.
* Runbook and incident page merged.
