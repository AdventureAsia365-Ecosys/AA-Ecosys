## Problem

From "code done" to "live on Dev with evidence", most of a session's wall clock goes into the pipeline, not into code (S252, 26/10/2026):

* **Deploys wait for idle job tables.** CIS Deploy Dev and DB Migrate refuse while `shared.job` has rows, so a paid build (place cards, places) blocks every backend deploy and run-script for hours.
* **Strict "up to date" branch protection.** Each merge makes the other PRs BEHIND, then update-branch, then a full CI rerun (CIS 6–10 min), so PRs merge one after another. On a guarded file, update-branch also strips the `secret-scan-baseline-reviewed` label.
* **A migration takes four hand steps:** app PR → byte-copy PR in Infra → DB Migrate check + apply → schema-dump PR → merge the app PR.
* **Post-deploy verify is manual:** health, schema version, Playwright smoke and screenshots are run by the agent after each deploy.
* **Failures surface late.** CI-only gates (coverage, ruff format) fail after the push.

## Scope (one slice per PR group)

1. **Merge queue** in CIS, Booking and Partner. `merge_group` triggers on every required check (done, [AdventureAsia365-Ecosys/AA-CIS-App#1038](https://linear.app/aa-ecosys/review/ci-run-the-required-checks-on-merge-group-for-the-merge-queue-8f95dd14e1cb) / #98 / #85; the gitleaks trigger is CIS [AdventureAsia365-Ecosys/AA-CIS-App#1041](https://linear.app/aa-ecosys/review/ci-report-the-gitleaks-check-on-merge-group-5b73f466b0d4), Partner #87, Booking #101). Rulesets, `tools/github/mergeq.sh`, aa-ship update.
2. **Post-deploy verify job** in each Deploy Dev:
   * health / ready plus `git_sha` = merged SHA, and `schema_version` where it exists;
   * Playwright public smoke;
   * a summary written to the run.
   * A red verify marks the deploy failed.
3. **Workers stop gracefully:**
   * SIGTERM → stop claiming → finish the current job (or release it to `queued` within the ECS stop timeout);
   * jobs stay idempotent on retry.
   * Then the Deploy Dev guard checks only an open wave, not queued/running jobs.
   * DB Migrate keeps the job guard only for migrations that rewrite or delete data.
4. **Migration in the app PR** (ADR first, it changes the D8 / MIG flow):
   * a bot keeps the Infra byte copy in sync;
   * an additive migration (expand only) is applied by the pipeline before the deploy;
   * a migration that drops or rewrites data still needs DB Migrate by hand plus review;
   * the schema-dump PR auto-merges.
5. **Local gates:** a pre-push hook per repo runs the CI lint/format/unit+coverage commands.

## Done when

* A green PR lands through the queue with no update-branch. Measured: 3 PRs to one repo merge without a CI rerun per PR.
* A CIS backend deploy completes while `shared.job` has running jobs; no job is lost or duplicated (evidence: job ids before/after).
* An additive migration ships from one app PR to Dev with no hand step.
* Each Deploy Dev run ends with an automatic verify summary (SHA, health, smoke).
* `skill/aa-ship` and `docs/ops` describe the new flow; an ADR records decisions 3 and 4.
* Lead time (PR opened → verified on Dev) before/after, measured on ≥ 5 PRs.
