## Problem

Traffic that reaches the regional WAF through CloudFront (CRM web and API, portal) is allowed before the rate-limit rules, so those hosts have no per-client rate limit.

## Decision (tech lead, S286, D10)

Add one rate rule now (about 1 USD/month). Move to a full CloudFront web ACL when prod starts.

## Scope

* One WAF rate-based rule keyed on the viewer IP (forwarded header from CloudFront), placed above the CloudFront allow rule, in count mode first, then block.
* An alarm on the rule's blocked count.
* State the monthly cost in the Infra PR.

## Done when

* Terraform applied; a burst test from one IP past the limit gets 403 on a CRM host while normal use stays 200.
* The rule's count is visible on the WAF metrics.

Done (S287, 21/11/2026).

**Changes**
- Infra #954 `90efefa0` adds the rule `CloudFrontViewerRateLimit` to the existing regional web ACL. There is no new ACL.
- The rule is keyed per viewer on `x-aa-viewer-ip`, written by viewer-request CloudFront Functions.
- It covers the 3 CRM hosts. TripPlanner and our NAT egress are scoped out.
- The limit is 5000 requests per 5 minutes per viewer, set by the variables `crm_edge_rate_limit` and `crm_edge_rate_count_only`.
- Infra #956 `6b3f2b44` switches the rule from COUNT to BLOCK.
- When it blocks, the WAF answers **429** `{"error":"rate_limited"}`, not 403. That tells a rate limit apart from the 403 auth answers.
- Cost: about 1 USD/month.
