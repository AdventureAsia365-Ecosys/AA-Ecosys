## Problem

The data model and product intent live apart from the code:

* `docs/architecture/db-schema-reference.md` (nightly dump) lists columns but shows no relationships. Nobody can see PK/FK structure across the \~3 apps' schemas without reading SQL.
* New schemas are designed in prose (CRM design v3: \~88 `crm.*` tables) and reviewed without a diagram. Nothing checks that what gets migrated matches what was designed.
* Product requirements are scattered across Linear issues, `docs/research/*`, `docs/audits/*`, ADRs and `CONTEXT.md`. Linear is on the Free plan (S245), so detail must live in the repo. There is no structured PRD that links to its ERD, contracts and migrations.
* Which env vars and secrets each app uses is only known by reading task defs, Lambda configs and Vercel by hand (S243 proposal APP rows).

S247 decision (Nghiệp): ERD + PRD as code, reviewable in Git, with a live interactive view in the CIS admin.

## Scope

1. **Generated ERD (live).** Extend the Infra `db-schema-dump.yml` / `db/gen_schema_reference.py`: from the same catalog dump, emit one Mermaid `erDiagram` per schema to root `docs/architecture/erd/<schema>.md` (rendered by GitHub; the nightly bot PR then diffs relationships too), plus `erd.json` (tables, columns, types, PK/FK, PII tags, owner) uploaded to a private S3 key.
2. **Live view in the CIS admin.** `GET /admin/data-model` (owner/admin only) serves the latest `erd.json`; admin page `/admin/data-model`: search, schema/domain filter, dbt-style neighbour selector (table +1), click a table for columns and FKs, "changed since the previous dump", design-vs-live drift badge. The CIS repo is public: it holds only the renderer, never table/column lists (DM-6.10). IAM: CIS task role reads that one key (risky → review).
3. **Design ERD + drift check.** Hand-written design files `docs/architecture/erd/design/<schema>.*` (Mermaid or QuickDBD/DBML text), reviewed in PRs with the ADRs before the migration. A CI check compares design vs live after apply and reports drift. Pilot: `crm` before [AA-932](https://linear.app/aa-ecosys/issue/AA-932/crm-w1-crm-04-infra-db-owner-crm).
4. **PRD as code.** `docs/product/<app>/<feature>.md` with front matter (`id`, `status`, `owner`, `linear`, `adrs`, `contracts`, `erd`, `migrations`) and acceptance criteria that Linear Done-when points to; docs lint checks that every referenced path exists. Pilot: Partner CRM.
5. **Env-config register** (original scope). Env var **names** only (secrets by name, no values) from the live ECS task defs, Lambda configs and Vercel projects → root `docs/generated/env-config.md`, via the Infra docs pattern.

Out of scope: generated CI/CD matrix and contracts table; third-party ERD tools in runtime (any CLI such as quickdbd-cli only as a pinned, reviewed dev/CI tool in the root repo); public hosting (GitHub Pages / Gist).
