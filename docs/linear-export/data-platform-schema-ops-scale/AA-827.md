## Problem

`tripplanner.sessions.guest_token = id::text` — a plaintext, guessable bearer equal to the session id (S237 data review P10, X8). ADR 0006 Phase 4 guest-trip claiming would rest on it.

## Scope

* New random token (≥128 bit) per session, store `sha256` only; migration tp-NNN additive (new column), backfill by issuing new tokens on next request; old value accepted for a short grace window then rejected.
* Cookies/headers updated in the BFF; no token in logs.

## Done when

* DB has no plaintext token column populated; a request with the old id-as-token fails after the grace window; owner flows (narrate, apply-route, send to advisor) still pass on Dev.
