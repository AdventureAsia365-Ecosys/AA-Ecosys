## Problem

The CI scans an image that is built for the check but never pushed; the deploy builds again. Several images running on Dev carry known high-severity findings in their base layers that nobody reads, and the two main API images are image indexes that basic ECR scanning skips.

## Decision (tech lead, S286, D11)

Use a free workflow, not Inspector enhanced. Rebuild the Node images now.

## Scope

* A nightly workflow (Infra or root) that resolves the image digest each ECS service is running, scans it with Trivy or grype, maps findings to KEV/EPSS (same rule as the vulnerability-management issue), and alerts on P0/P1.
* An SBOM (syft) per running digest stored as a workflow artifact.
* Rebuild and redeploy the Node-based images on a current base.
* Later step, noted only: build once and deploy the scanned digest.

## Done when

* One nightly run lists every running service with its digest, finding counts by level and SBOM.
* After the rebuild, the Node images show no CRITICAL findings with a fix available.
* Cost stays 0 USD (public-repo Actions).

Done (S287, 21/11/2026). Cost 0 USD.

**What shipped**
- Infra #960 `057ffdd5` adds the workflow **Image Scan (running images)**: schedule 05:37 UTC, plus manual dispatch.
- Each night it:
  - lists every RUNNING task digest in `aa-cis-dev-cluster`;
  - writes a CycloneDX SBOM per digest with Trivy (pinned, sha256 checked), cached per digest;
  - rescans those SBOMs with that day's vulnerability DB;
  - triages with the root `vuln_triage.py` (KEV, EPSS, CVSS → P0–P3) against the one exception register;
  - fails the gate on a finding that has a fix and is P0/P1 or CRITICAL/HIGH.
- The summary is masked and uploaded to the private docs-reader prefix.
- New role `aa-cis-dev-image-scan-upload`: PutObject on one key. The repo secret was set by the tech lead.
- Node base images are pinned by digest (`node:22.23.5-alpine3.24`) and take Alpine fixes at build, plus weekly Dependabot for docker: Booking #295, CIS #1625, Partner #376, TripPlanner #291, all deployed.
- The E2E WordPress sidecar moves 7.1.4 → 7.1.5.
