## Problem

The data standards define three recurring reviews and say each is "enforced by the session ritual". In practice none of them appears in any ritual or skill. Nothing under skill/, .kiro/steering/ or .claude/ mentions them, and docs/audits/ has no review folder.

The three reviews:

* **C4.3 — weekly** (03-scaling.md)
  * top-20 `pg_stat_statements` per role, by total and mean time
  * slow-query log (> 500 ms)
  * lock waits
  * Performance Insights top SQL
  * pg_stat_statements and PI have been live since [AA-824](https://linear.app/aa-ecosys/issue/AA-824/dataops-rds-guardrails-connection-budget-storage-autoscaling-parameter) (migration 234, 15/10).
* **C8a–C8c — monthly** capacity review
  * 9-point checklist
  * saved in `docs/audits/<date>-S<nnn>-capacity-review/`
  * ends with a decision list that cites the C3 trigger rows
* **DM-8.10 — quarterly** access review (02-data-management.md)
  * roles, grants, default ACLs
  * IAM readers of each DB secret
  * Cognito `aa-workforce` users

The C3 scale triggers and the C1.2a rule ("two consecutive weekly misses go to Nghiệp") only work if someone measures them on a schedule. Nobody does today.

S238 showed what this costs. A consumer PR (TripPlanner #77) made `catalog.v_tour_place` cost 2.4 s per call and throttled the browse Lambda. It was found through alarm emails; a weekly `pg_stat_statements` check would have caught it first (fixed by migration 235).

## Scope

* **Session ritual.** Add the three cadences to `skill/aa-session/SKILL.md` as session-start checks:
  * weekly C4.3 check: first session of each ISO week, and after every wave
  * monthly C8 review: first session of the month
  * quarterly DM-8.10 review: first session of the quarter

  Each check reads the date of the last matching audit folder or log note and proposes the review when it is due. Add a pointer line in `.kiro/steering/session-workflow.md`.
* **Probe script.** A reusable, read-only script run through S3-mediated ECS exec. It collects:
  * top 20/50 `pg_stat_statements` per role
  * table and index sizes, with dead-tuple ratios
  * `rolconnlimit`, and live connections per `application_name`

  It makes no writes and never calls `pg_stat_statements_reset()`.
* **Templates.** A capacity-review template (C8b items 1–9 plus the C8c decision list) and an access-review template (DM-8.10).
* **First reviews.**
  * Run the first monthly capacity review now. Save it in docs/audits/ via a root PR, with Nghiệp's approval.
  * The first access review can wait for the N1 grant data ([AA-807](https://linear.app/aa-ecosys/issue/AA-807/data-phase-1-foundation-per-app-db-owner-roles-migration-ownership)); the template records that dependency.

## Done when

* The three cadences are in `skill/aa-session/SKILL.md`, merged on master.
* `docs/audits/<date>-S<nnn>-capacity-review/` exists with:
  * all 9 C8b items, with measured values
  * the C2.2 budget recomputed from live values
  * every C3 trigger marked fired or not fired
  * a decision list approved by Nghiệp
* At least one weekly C4.3 check is recorded in a session log.
* The access-review template exists and states its N1 dependency.
