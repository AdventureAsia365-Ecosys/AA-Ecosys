## Problem

A 4th app (tenant CRM [AA-821](https://linear.app/aa-ecosys/issue/AA-821/research-tenant-crm-customerlead-management-for-tenants-ms-thus-idea), supplier portal, mobile, BI) has no rules: owner facts are hard-coded in 3 places (`db-migrate.yml` case, `check_migration_copies.py` OWNERS/PATH_RE, `schema-ownership.md`), roles are created by hand, contract copies in consumer repos have no guard (S237 data review §6, X7).

## Scope

* ADR 0008 accepted (S237) + `docs/architecture/data-standards/` as the detailed rules.
* `infra/AA-CIS-Infra/db/owners.yaml` (dir, repo, path, key prefix, owner role, runtime roles, allowed consumer grants); DB Migrate + copy guard read it (no code edit to add an owner).
* Reviewed bootstrap template for `<app>_owner` NOLOGIN / `<app>_app` LOGIN with CONNECTION LIMIT.
* Hash guard for consumer copies of contract JSON Schemas.
* Checklist from §6.3 copied into the [AA-821](https://linear.app/aa-ecosys/issue/AA-821/research-tenant-crm-customerlead-management-for-tenants-ms-thus-idea) epic.

## Done when

* A dry-run "add owner" PR adds a fake owner via owners.yaml only and the guard + DB Migrate validation pick it up (then reverted).
* Contract hash guard red on a modified consumer copy, green otherwise.
