## Problem

The Delivery page answers "how fast and how safely do we ship" for one fixed window: Overview, every app tab and Merge queue always show the last 28 days, and only Git map has a 30 / 90-day switch. The tech lead cannot look at the last week, a quarter or a chosen range. The 12-week and 3-month trends are already collected but appear only as small sparklines. Nothing shows where a change waits on its way from pull request to verified deploy. The repo cards cannot be sorted.

## Scope

1. **Time range on every tab**: presets 7 / 28 / 90 days computed by the collector in `summary.json` (same static bundle, $0), plus a custom date range (from / to). The custom range is computed by a read-only CIS endpoint from the collector's daily event files (NDJSON on S3), with a cap on the range length as a setting. The range lives in the URL, like the tab.
2. **DORA trend chart**: the four keys per week over 12 weeks, one app or all apps compared.
3. **Delivery flow diagram**: pull request opened → CI green → entered the queue → merged → deployed → verified, with the median and p95 of each step for the chosen range; the slowest step is highlighted.
4. **Merge queue charts**: wait-time histogram, ejection reasons as bars, ejection rate per week.
5. **Git map**: churn treemap by directory with drill-down, and the recent commit graph with pull request links.
6. **Card sorting** on Overview and Merge queue: worst first, by name, or by the metric shown.

Every threshold and range cap is a setting in the Platform › Settings registry. Kit components only; EN/VI, light/dark, mobile.
