# AA-866 — [Security] Restrict deploy/apply/migrate OIDC trust to main (env policy, ref guard, IAM)

## Problem

S241 SDLC review P0-1: the GitHub environments behind CIS deploy, Terraform apply and DB Migrate have no branch policy, so their AWS roles are not limited to `main`. A comment in `cicd_split.tf` claims a protection that does not exist. Details stay in the private review.

## Scope

1. AA-CIS-App envs `dev`/`prod`: deployment branch policy = `main` only (copy Booking `dev`).
2. `terraform-apply.yml`: job-level `if: github.ref == 'refs/heads/main'`.
3. IAM trust of the tf-apply, db-migrate and CIS deploy roles: add the `token.actions.githubusercontent.com:ref` = `refs/heads/main` condition. Trial on a scratch role first; fallback as in the review.
4. Move `ADMIN_SECRET` into the main-only `dev` env (rotated S241; underscore env var, Nghiệp edits by hand).
5. Correct the `cicd_split.tf` comment; record the accepted risk for repo-level E2E/Vercel secrets (compensated by the secrets-register issue and D-18).

Out of scope: required reviewers, agent GitHub App identity (U-25).

## Done when

* A dispatch from a non-main branch is rejected (env policy or `AccessDenied`), run link attached.
* The next `main` CIS deploy, Terraform apply and DB Migrate succeed (run links).
* `gh api .../environments` shows the branch policy on `dev` and `prod`.
