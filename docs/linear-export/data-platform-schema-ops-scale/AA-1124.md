## Goal

One report on every documentation page of the ecosystem: does it describe what actually runs on Dev today, and what is wrong, stale, broken or missing. Audit only: nothing is fixed in this issue. The proposals feed [AA-1118](https://linear.app/aa-ecosys/issue/AA-1118/docs-bring-runbooks-architecture-pages-and-the-feature-catalogue-back) (bring the docs back to reality) after the tech lead approves them.

## Problem

The docs grew fast:

* the root repo has \~320 pages with front-matter (catalog `docs/README.md`), runbooks, ADRs, contracts, the feature catalogue, the learning site modules, CONTEXT.md files;
* each app repo has its own CONTEXT.md and docs.

Lints check format and links, but not whether a page is still true: service names, hosts, migration numbers, job kinds, settings keys, prices, flows. The tech lead asked for this audit in S283 (17/11/2026).

## Scope

1. Inventory every docs page in the root repo and the five app repos (`docs/**`, `CONTEXT.md`, READMEs that act as docs, `skill/` pages that describe the system). Exclude session logs, linear exports and dated audit folders: those are records, not claims.
2. For each page, check its factual claims against the live state:
   * ECS services and hosts, `/health` and `/health/ready`;
   * `db-schema-reference.md` (live dump), migration numbers;
   * job kinds in the job tables, settings registry keys, catalogue surface snapshot;
   * workflow files, Terraform roots, prices in the Plans API, ADR status.
   * Also check: broken internal links, contradictions between pages, pages with no owner or `last_tested`, and EN/`.vi.md` pairs out of sync.
3. Report: one row per page (verdict current / partly stale / wrong / orphan, the stale claims with evidence, severity), and a proposal list ranked by impact (which runbooks would mislead an engineer on duty first).

Out of scope: editing any page, any write to live systems.

## Done when

* Every page in the inventory has a verdict row.
* The report is saved under `docs/audits/<date>-S283-docs-audit/` (root PR) and published as one artifact page.
* Every "wrong" or "stale" verdict cites the live evidence it was checked against.
* The proposal list is ready for the tech lead to approve into [AA-1118](https://linear.app/aa-ecosys/issue/AA-1118/docs-bring-runbooks-architecture-pages-and-the-feature-catalogue-back); nothing is changed by this issue.

## Verify

Open the report; spot-check 5 random verdicts against the live system.
