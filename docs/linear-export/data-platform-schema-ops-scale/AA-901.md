## Problem

Agents and automations act on GitHub with Nghiệp's personal identity (PAT / gh login), so their actions are not distinguishable, a release PR opened with the default `GITHUB_TOKEN` does not trigger required checks, and a future human review gate (CODEOWNERS) would block Nghiệp's own PRs (an author cannot approve their own PR). S241 roadmap U-25; S243 reconciliation (`docs/audits/2026-10-19-S243-sdlc-docs-versioning/reconciliation-s241-standards.md`, N-6 approved 19/10).

## Scope

* GitHub App (free) `aa-agent` on the org, least-privilege permissions per repo; installation token minted in CI (no long-lived PAT). Record it in the secrets register ([AA-878](https://linear.app/aa-ecosys/issue/AA-878/security-secrets-register-orphaned-secret-cleanup-read-only-e2e)).
* release-please ([AA-891](https://linear.app/aa-ecosys/issue/AA-891/release-version-traceability-release-please-changelog-and-first-tags)) uses the App token so the release PR runs the required checks.
* ADR 0010 (agent identity + merge rights per risk tier, matching D-13: Dev self-merge; human gate from prod) and ADR 0011 (repo visibility / GitHub plan, D-14 Free) in the root repo.
* CODEOWNERS for sensitive paths (`.github/workflows/**`, `**/migrations/**`, `accounts/**`, `.claude/**`, `skill/**`) prepared, enforced only from prod.

## Done when

* A test PR opened by the App shows its identity and runs the required checks.
* release-please release PR created with the App token on at least one repo.
* ADR 0010/0011 accepted; secrets register lists the App.
