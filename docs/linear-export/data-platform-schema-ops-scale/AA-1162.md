## Problem

The S286 security gap analysis (ISO 27001 A.8.32, SOC 2 CC8.1) found that root `master` can be deleted or force-pushed, and that the independent agent review of risky PRs leaves no review record on the PR itself.

## Decision (tech lead, S286, D4)

Risky PRs (Terraform/IAM, migration, auth, data deletion) need the tech lead's approval once the pilot holds real data. Before that, add the cheap guards now.

## Scope

* A ruleset on root `master` (and each child repo's `main` where missing) that blocks deletion and force-push. 0 USD.
* The lane reviewer's verdict is posted as a GitHub PR review (approve / request changes) by the `aa-agent` App, so the review is evidence on the PR.
* A written trigger in skill `aa-ship`: from the first pilot with real data, `ship_merge.py` refuses a risky-class PR without a tech-lead approval.

## Done when

* A test force-push and a branch delete on root `master` are refused (screenshot or API error).
* One risky PR in S287 shows the agent review as a PR review.
* `aa-ship` names the pilot trigger.
