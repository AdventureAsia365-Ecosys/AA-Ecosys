## Problem

The [AA-1167](https://linear.app/aa-ecosys/issue/AA-1167/security-ai-output-and-prompt-hardening-sanitized-html-before) trap run on 21/11/2026 measured 8 of 9 traps passed, both with the prompt data fence on and with it off. Cost: 0.81 USD; evidence in root `docs/audits/2026-11-21-S287-session/live/aa1167/trap-run.md`. The one failing trap is `t9_facts_override`: an instruction planted inside the fact field made the T9 blog writer use an invented name. The fence does not change this case, so the weakness is how T9 treats its fact input.

## Decision (tech lead, S287)

* Keep `cis.llm.prompt_data_fence` off: there is no measured gain on this trap set.
* Record 8/9 as the [AA-1167](https://linear.app/aa-ecosys/issue/AA-1167/security-ai-output-and-prompt-hardening-sanitized-html-before) baseline.
* Fix the fact-field override here.

## Scope

* Find why T9 trusts imperative text inside facts: the prompt wording and how facts are assembled, both from the source and from the tenant.
* Fix it with the least prompt change. Candidates:
  * a fact validator that drops imperative or instruction-like lines before they reach the prompt;
  * a post-write check that refuses names absent from the source atoms.
* Add 2–3 invented trap variants of the same kind.
* Re-run the trap set: a small paid run, ≤ 1 USD, stage `adhoc_<issue>`.

## Done when

* `t9_facts_override` and its new variants pass.
* The other 8 traps still pass.
* The run's cost is reported from `shared.llm_call_log`.
* A unit test covers the validator or check offline.
