## Problem

S241 P1-4: CIS has no required typecheck or frontend build; Trivy never fails (`exit-code: 0`); TripPlanner `deploy-lambdas.yml` does not depend on CI and has no smoke; no security-header check on previews; ECS deploy triggers on `frontend/**`; CIS coverage is \~30%.

## Scope

1. CIS required `tsc --noEmit` and `next build`.
2. Trivy `exit-code: 1`, `ignore-unfixed`, `.trivyignore` entries with expiry.
3. TripPlanner Lambda deploy runs only after CI passes, then a smoke curl; add Booking's security job.
4. Header check on preview deploys.
5. Drop `frontend/**` from the ECS deploy path filter.
6. CIS coverage ratchet (+5%/month).
7. TripPlanner migration replay on `postgres:15` is [AA-849](https://linear.app/aa-ecosys/issue/AA-849/dataci-tripplanner-migration-replay-ci-replay-tp-migrations-twice), referenced, not duplicated.

## Done when

* Branch protection lists the new required checks on each repo.
* A PR with a seeded type error fails CIS CI (run link).
* A TripPlanner deploy run shows `needs: ci` and a green smoke step.
* A frontend-only CIS PR does not trigger the ECS deploy.
