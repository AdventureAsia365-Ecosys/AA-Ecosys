## Problem

The admin has no place that shows how far the system meets the security and AI standards. The S286 scores (ISO 27001 45.8 %, SOC 2 44.0 %, ISO 42001 46.9 %, OWASP Top 10 64.8 %, OWASP LLM 66.7 %, DevSecOps 50 %) were scored once, by hand. Security signals are spread over 6–8 admin pages and nothing records when a control was last proven.

## Decisions (tech lead, S287, decision page)

* Q1: build a lean "Compliance readiness" area in the CIS admin (option C) with data an auditor can take (export). No SaaS GRC now.
* Q2: the register lives in a DB schema `compliance` plus a nightly snapshot to private S3. The repo holds code only (it is public).
* Q3: the headline number is **Evidenced %** (only fresh, passing evidence counts), strict and weighted, with the S286 scores drawn as a reference line.
* Q4: every requirement of each in-scope framework is listed (full coverage) and mapped onto a common control set (about 40 controls at the start, growing). One control can satisfy requirements in several frameworks.
* Q5: a new read-only GitHub App for the collectors, separate from the merge App `aa-agent` (tech lead creates it, phase 2).
* Q6: a new AWS role `compliance-evidence` (SecurityAudit + ViewOnlyAccess + write to one prefix, trust pinned to the workflow, no delete).
* Q7: phase 1 writes evidence with the Docs sync role under `docs-reader/compliance/`, like the Delivery page, marked "readiness, not immutable".
* Q8: phase 2 adds a small new evidence bucket with versioning + Object Lock, bypass denied, a chained manifest, SSE-S3 (\~0 USD/month). No Object Lock on the bronze bucket.
* Q10: new permissions `compliance.read` / `compliance.write`, administrator only at first.
* Q11: no paid Security Hub / AWS Config / Access Analyzer now; use free Prowler; revisit at prod.
* Q12: an agent review does not count as met; compensating control: the tech lead samples PRs and signs off monthly.
* Q13: no second signer for reviews and exceptions for now (one tech lead).
* Q14: Vietnam PDPL and GDPR stay out of scope until the pilot (data is hosted in the US; the main market is not Vietnam).
* Q15: acc1, acc3 and acc4 are in scope; acc1 is a risk-register entry tied to the early-December review.
* Q16: certification only on a real trigger; shortlist Thoropass (SOC 2 with audit) and Secureframe; ISO 27001/42001 directly with a certification body using our SoA.
* Q17: no public trust center until a pilot customer sends a security questionnaire.

## Scope

**Phase 1 (1–2 sessions)**

* CIS migration: schema `compliance` with `control`, `requirement` (every requirement of ISO 27001:2022 clauses 4–10 + Annex A, SOC 2 TSC common criteria, ISO 42001 clauses + Annex A, OWASP Top 10, OWASP LLM Top 10, EU AI Act articles that apply), `requirement_mapping` (full / partial), `evidence` (source, collector, collected_at, valid_until, status pass / fail / stale / manual, link), `score_snapshot`.
* Seed: requirement IDs with our own short wording only (ISO / AICPA text is copyrighted); controls and mappings from the private S286 matrix through DB Migrate `run-script`, not committed.
* Root workflow `compliance-evidence.yml` (daily) with about 10 checks that need no new permission: rulesets / required checks, CodeQL setup, scheduled guards green, SBOM + Trivy in CI, secrets register diff, docs overdue, last drill, last access review, vulnerability exceptions still valid, collector heartbeat.
* CIS API + page `/admin/platform/compliance`: Overview (Evidenced % per framework, trend, stale evidence) and Controls (drawer with requirements and evidence). Validity windows, partial weight and heartbeat hours are admin settings (`cis.compliance.*`), never hard-coded.
* Fix `docs/security/baseline.md` where it is stale (Trivy gate, CodeQL).

**Phase 2 (2 sessions)**

* Read-only GitHub App (tech lead), Dependabot / secret scanning / code scanning checks.
* Infra: evidence bucket (Object Lock) and role `compliance-evidence`; collector moves to it; daily chained manifest.
* Weekly Prowler (acc2, acc4; read on acc1 / acc3), DB checks (RLS on every app schema) as a CIS worker job, weekly drift alert.

Out of scope here: exceptions, risk register, SoA export and the monthly review record (with [AA-1166](https://linear.app/aa-ecosys/issue/AA-1166/security-isms-lite-and-aims-lite-policy-scope-risk-register-soa-ai)), OSCAL, trust center, PDPL / GDPR (Q14).

## Done when

* The migration is applied on Dev and the schema-reference PR is merged.
* `/admin/platform/compliance` shows Evidenced % for each in-scope framework from live data, and a stale piece of evidence lowers it (shown live by setting a short validity window in Settings).
* The daily collector has run on master at least once and its heartbeat shows on the page.
* A non-administrator gets 403 on the compliance routes.
* No account ID, ARN, bucket name or control text from a copyrighted standard is in a public repo (guard test).
