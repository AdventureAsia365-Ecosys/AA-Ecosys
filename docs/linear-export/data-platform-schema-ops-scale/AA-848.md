## Problem

ADR 0008 assigns the X2 guard to [AA-817](https://linear.app/aa-ecosys/issue/AA-817/security-cis-api-runtime-role-aa-cis-admin-is-not-filtered-by-rls) (design in `docs/audits/2026-10-14-S237-lane-backlog/aa817/aa817_design.md` §4, "proposed, not built"). It was folded into [AA-817](https://linear.app/aa-ecosys/issue/AA-817/security-cis-api-runtime-role-aa-cis-admin-is-not-filtered-by-rls) as scope addition 2 (S238) and moved here by Nghiệp decision S239 (16/10).

S239 audit: `NO_RLS_ALLOWLIST` does not exist on CIS main and no guard exists. The only RLS test is `tests/integration/test_aa817_rls_tenant_isolation.py`, which covers the migration 229 tables only. Nothing stops a new migration from adding a `tenant_id` table without RLS, a `TO PUBLIC` policy, or a policy without `NULLIF`.

## Scope

One check, run in two places: CIS CI against the replayed migrations DB (`tests/integration/test_rls_catalogue_guard.py`), and the nightly schema dump against Dev, with findings written into `docs/architecture/db-schema-reference.md`.

The check fails when:

* (a) a table with a `tenant_id` column has no RLS plus an `app.tenant_id` policy, and is not on `NO_RLS_ALLOWLIST`;
* (b) a policy in a new schema is `TO PUBLIC`;
* (c) a policy uses `app.current_tenant`;
* (d) a policy uses `current_setting('app.tenant_id')` without `NULLIF`;
* (e) a foreign key crosses owners (the 12 `tripplanner -> shared.destinations` FKs are allowlisted until X4).

Each allowlist entry carries a one-line reason.

Out of scope: rule (f), a non-owner grant not on the `owners.yaml` allowlist; it turns on after [AA-826](https://linear.app/aa-ecosys/issue/AA-826/dataadr-new-app-integration-playbook-adr-0008-ownersyaml-registry-role). Fixing existing violations found on Dev (allowlist with a reason, or a follow-up).

## Done when

* The guard runs in CIS CI and is green on main.
* Each rule a-e fails CI on a throwaway mutation; the red run links are posted here.
* The Dev run of the nightly dump shows 0 unallowlisted violations, recorded in `db-schema-reference.md`.
