## Problem

S241 P0-6: CIS has Sentry code but the DSN secret does not exist, so error tracking is off. The CIS API Gateway has no 5XXError or latency alarm (Booking has them). Nothing checks uptime from outside.

## Scope

1. Sentry free-tier project + DSN secret for CIS api/worker: `release` = git SHA, `send_default_pii=False`, scrub bodies and headers.
2. Terraform: 5XXError-rate and IntegrationLatency p95 alarms on the CIS API Gateway, missing data = not breaching (C4.1a), ALARM and OK e-mails (D-20).
3. One free external uptime check for CIS `/health` and Booking `/booking/health/ready`, notifying Nghiệp's phone.
4. Add Sentry to the sub-processor list (input to the legal packet).

## Done when

* A test exception raised on Dev shows in Sentry with the deployed SHA as release and no PII in the event.
* `describe-alarms` lists both alarms; a `set-alarm-state` test delivers an ALARM e-mail and then an OK e-mail.
* The uptime monitor shows green checks for both endpoints.
