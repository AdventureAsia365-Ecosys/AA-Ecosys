## Problem

Live checks that need an owner session cannot be done by the agent: view-as start (owner only), admin writes on synthetic Booking records (sale exception, Generate supplier bookings), the compliance Refresh (relays a staff token to the CRM), inviting staff. The existing E2E identities are deliberately read-only and never owner. Tech lead decision (S288, 23/11): add an admin "like the tech lead" for the agent on Dev.

## Scope

* A new Dev-only WORKFORCE address on the E2E mailbox domain, a code constant (like [AA-816](https://linear.app/aa-ecosys/issue/AA-816/admin-staff-user-management-ui-createdisable-staff-roles) A10b), whose sign-in code mail goes only to the prefix that the MFA admin role can read (never the CI-readable prefix).
* Identity triggers allow it on dev only (exact address, exact groups); refused outside dev.
* CIS and Booking treat it as a normal administrator on Dev (not read-only), with the owner marker, so view-as, Refresh and admin writes work; never the business-owner marker.
* Audit rows name it as the E2E owner; the access review lists it; removal steps documented.

## Done when

* The agent signs in as the E2E owner on Dev (code read from the admin prefix under the MFA session) and: starts view-as in CIS and Booking, presses Refresh evidence, creates a sale exception on a synthetic tour.
* Outside dev the address is refused (test + Terraform precondition).
* Independent security review before merge; CI green; deployed.

+++ Agent notes

Patterns: Infra [AA-816](https://linear.app/aa-ecosys/issue/AA-816/admin-staff-user-management-ui-createdisable-staff-roles) A10b (identity triggers map + SES admin rule + bucket Deny), CIS api/core/e2e_staff.py, Booking app/auth/e2e_staff.py. Session S288.
