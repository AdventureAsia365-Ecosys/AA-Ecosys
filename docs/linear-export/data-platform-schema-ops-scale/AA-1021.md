## Problem

The tech lead wants to publish the platform architecture on a personal account (YouTube, X, LinkedIn, Facebook) in an "engineering notes" framing, without naming the company. The approved plan is in root `docs/audits/2026-11-01-S262-arch-video-plan/` (approved on 01/11/2026).

## Scope

1. **Public label profile**, kept outside the public repo. It maps internal names to generic ones (content platform, trip planner, booking back office, partner CRM, workload / AI / management account, decision / SEO data / geocoding API).
2. **Video pipeline in** `tools/uat/arch/` (code only):
   * scene JSON with a voice per sentence: alternating af_heart (female) and am_michael (male), English only, local TTS at $0;
   * a neutral theme and diagram slides from the refreshed docs, captured as keyframes at 2x;
   * native layouts at 16:9 1920×1080, 1:1, 4:5 and 9:16;
   * burned captions plus SRT/VTT, loudnorm, no metadata.
3. **Public-content gate with 5 layers**; the build fails on any hit:
   * a deny-list and an n-gram check against the public repos;
   * a DOM check before every capture;
   * OCR on the frames;
   * captions, metadata and file names;
   * an independent review agent, then the tech lead watches the final cuts.
     The deny-list is gitignored. Scripts and videos never go into a public repo; they go to Drive.
4. **Series:** 10 episodes. Ep0 trailer; Ep1 big picture; Ep2 lean AWS accounts; Ep3 one gateway for every AI call; Ep4 designing for provider failure (published later, kept generic); Ep5 content pipeline; Ep6 serverless trip planner; Ep7 booking without direct AI; Ep8 multi-tenant CRM; Ep9 security by design.
   Each episode gets 4 cuts: a YouTube master with chapters; a Short of 60 s or less; an X clip of 2:20 or less; a LinkedIn clip of 60–120 s (1:1 or 4:5).
5. **Engineering-notes blog post per episode** (Facebook / LinkedIn article): the same story in text with the public diagrams, through the same gate.
6. **Rules:** AWS service names and icons are allowed. Model vendors and niche vendors are not named. Nothing still planned is shown as live ("designed to"). No cost figures, no weak points, no incidents, no people or company names.

## Order

Builds on the docs refresh issue. Pipeline and gate first, then a pilot of Ep1 in every format, which the tech lead approves (voice, look, wording). Then the remaining episodes, about 2 per session, as a side lane next to code lanes.

## Done when

* A pilot of Ep1 in all 4 formats passes the gate and the tech lead approves it.
* All 10 episodes and their blog posts are built and gated (gate log per video in `docs/audits/<date>-S<nnn>-arch-video/`, without any script text).
* Everything is uploaded to Drive (01 Video), with `rclone check` showing 0 differences. Cost $0.
