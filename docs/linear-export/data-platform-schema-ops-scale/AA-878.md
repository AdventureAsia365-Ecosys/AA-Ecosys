# AA-878 — [Security] Secrets register, orphaned-secret cleanup, read-only E2E account

## Problem

S241 P1-2: 27 secrets have no rotation record, `ADMIN_SECRET` is stored in about six places (one as a plaintext Lambda env value), two GitHub secrets are orphaned, and the E2E UI-smoke account is a full admin.

## Scope

1. `docs/security/secrets-register.md` in the private root repo: name, owner, consumers, last rotation (no values; include vendor TrueIDC).
2. Delete orphans (`ACPCORE_READ_TOKEN`, `VERCEL_DEPLOY_HOOK`) after confirming no consumer.
3. Lambda reads secrets by ARN, no plaintext env values.
4. E2E account becomes read-only staff without PII access (needs the server-side authz issue); then replace `ADMIN_SECRET` in Vercel Preview with a low-privilege credential (underscore env vars: Nghiệp edits by hand).
5. Run the first quarterly access review (DM-8.10, [AA-838](https://linear.app/aa-ecosys/issue/AA-838/dataops-wire-the-capacity-review-monthly-pg-stat-statements-check)).

Out of scope: PAT to GitHub App token (U-25).

## Done when

* Register matches `aws secretsmanager list-secrets` + `gh secret list` (diff = 0, shown in PR).
* Orphans removed; Lambda Terraform passes only ARNs.
* E2E account gets 403 on a write; UI smoke green.
* Access review notes in the session log.
