## Problem

Reports in the ecosystem grew one by one: a weekly platform report on Jira (PR-20), a monthly capacity review (C8), a weekly pg_stat_statements review (C4.3), a quarterly access review (DM-8.10), wave cost reports, session logs, cost pages in the CIS admin, and a planned CRM reports module ([AA-966](https://linear.app/aa-ecosys/issue/AA-966/crm-w7-crm-34-reports-insights)). Nobody has defined the full set the business needs: which reports exist, who reads them, what each contains, how often, from which data, which are automatic and which are on demand. The tech lead asked for a detailed advisory (S258, 29/10/2026).

## Scope

1. Inventory of every report and report-like page that exists today (repo docs, admin pages, Jira, scheduled jobs/workflows), with source data and cadence.
2. Recommended report catalog for the whole ecosystem (CIS, TripPlanner, Booking, CRM/Partner, platform/infra, finance/cost, security/compliance, AI quality, business/executive), each with: audience (by role), purpose/decision it supports, KPIs and sections, data source (tables/views/AWS/Jira), cadence or trigger, delivery channel, automation level, owner, retention.
3. Templates: one per report family (layout, sections, KPI definitions, thresholds, how to read).
4. Automation design: how reports are generated (job kinds, scheduled workflows, admin pages, email/Jira), a single report registry, and the order to build them; cost estimate per item.
5. On-demand reports: what can be requested ad hoc and how.
   Out of scope: building the reports (separate slices after approval); paid BI tools unless approved.
