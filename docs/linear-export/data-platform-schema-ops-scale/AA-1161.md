## Problem

S285 measured the six repos on GitHub:

| Repo | Size | Weight |
| -- | -- | -- |
| Root (AA-Ecosys) | 826 MB | GitHub recommends < 1 GB. `docs/audits` holds 662 MB in 3,744 screenshots (20–45 MB per session); `docs/AAA/figma_AAA` holds Figma exports of 6–15 MB each |
| AA-CIS-Infra | 88 MB | Lambda build zips are committed in several versions (`dist/lambdas/*.zip`, up to 30 MB each) |
| AA-CIS-App | 38 MB | 664 MB of Kiro CLI binaries (`kirocli/bin`) sit on a local branch only, not pushed |
| Booking, Partner, TripPlanner | 4–11 MB | no problem |

At the current rate the root repo passes 1 GB in about 5–10 sessions. History keeps every committed binary. Shrinking it needs a history rewrite and a force push of public repos.

Tech lead decision S285 (19/11/2026): yes to all three points below, applied to every repo, so that each kind of file is stored in its right place.

## Scope

1. **Rule.** Each session commits at most about 5–10 key screenshots, compressed: at most about 500 KB each and about 5–10 MB per PR. Full screenshot sets and videos go to the Google Drive AdventureAsia folder or a private S3 prefix, and the audit file links to them. Build artifacts (Lambda zips, `dist/`), binaries (CLIs) and large data dumps never go into git: CI builds them and S3/ECR/artifacts store them. Write the rule into the aa-session and aa-ship skills and into each repo's agent instructions.
2. **Guards.** A pre-push hook and a CI check in every repo:
   * Refuse an image over 500 KB, and image additions over 10 MB in one PR (root and app repos).
   * Refuse a committed build artifact or binary: `*.zip` under `dist/`, ELF/Mach-O executables, any file over 5 MB unless it is on an explicit allow-list with a reason.
   * Ship a `tools/docs/compress_images.py` (Pillow: PNG quantized to 256 colours, JPEG quality 75, file names kept) that the hook suggests.
3. **GitHub holds only what runs or documents the system (tech lead S285 follow-up).** Keep code, tests, migrations, config and text docs: `docs/` that `/admin/docs` reads, ADRs, runbooks, session logs and audit `.md`. Move out, keeping a link in the repo: audit screenshots, UAT videos, Figma exports, Lambda build zips, binaries. Destinations are the Google Drive AdventureAsia folder or a private S3 prefix, with an index file per folder.
4. **History rewrite (phase 2, tech lead approval on a decision page first).** Run `git filter-repo` on the root repo (images and videos) and on AA-CIS-Infra (`dist/lambdas/*.zip`), then force push. Do it in a planned window with this checklist:
   * merge or close every open PR;
   * keep a full mirror backup (`git clone --mirror`) on private storage;
   * announce the window;
   * force push;
   * re-clone every local checkout and worktree;
   * clear CI caches;
   * check that release-please and the bot branches still work.
     Expected result: the root repo goes from 826 MB to about 100–150 MB.
5. **Clean the current tree first** (before phase 2):
   * Infra: build the Lambda zips in CI or Terraform instead of committing them; remove `dist/lambdas/*.zip` from the tree.
   * CIS: delete the local branch that holds the Kiro binaries.
   * Root: move the Figma exports to Drive/Figma and keep links.

## Done when

* Each repo's pre-push and CI refuse a test image of 600 KB and a test `dist/x.zip`, and accept a compressed screenshot.
* The rule is in the skills. The S286 session close adds at most about 10 MB of images.
* Infra deploys its Lambdas without committed zips (Terraform plan clean, live smoke).
* The root repo size is recorded before and after (`gh api repos/... --jq .size`).
