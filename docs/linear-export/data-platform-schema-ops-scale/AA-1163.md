## Problem

`docs/security/vulnerability-management.md` (SEC-03) triages by severity only. Auditors (ISO 27001 A.8.8, SOC 2 CC7.1) sample whether findings were fixed within an SLA, and severity alone misses what attackers actually exploit.

## Decision (tech lead, S286, D12)

Approved rule:

| Level | Condition | Fix within (Dev) |
| -- | -- | -- |
| P0 | in CISA KEV, or EPSS ≥ 0.10, or CVSS ≥ 9.0 on running, internet-facing code | 7 days (prod 72 h) |
| P1 | CVSS 7.0–8.9, or EPSS percentile ≥ 0.90 | 30 days |
| P2 | CVSS 4.0–6.9 | 90 days |
| P3 | CVSS < 4.0 | next cycle |

## Scope

* Rewrite SEC-03 with this rule, CVSS v4.0, the EPSS API and the KEV feed; the tech lead signs it approved with a date.
* A small free tool (`tools/security/vuln_triage.py`) that reads open Dependabot alerts of the six repos, enriches each with EPSS and KEV, and prints level + due date.
* A monthly triage record (who, date, decisions, exceptions with an end date) stored in the private S3 location chosen in D8.

## Done when

* SEC-03 is approved and dated.
* The tool runs on the six repos and its output is the first monthly triage record.
* Every open P0/P1 has an owner and a due date.
