## Problem

The S278 system audit (`docs/audits/2026-11-12-S278-session/system-audit/`) rates pilot readiness at about 70%. Every link works on Dev, but nobody has taken a newly provisioned agency through the whole chain on the real UI:

CIS → Content studio → WordPress / Facebook → TripPlanner → CRM → Booking → traveller portal.

No issue tracked starting a pilot, so the rule "start prod by pilot week 3" could never start its clock either. The tech lead approved this issue in S278 (decision D13, NEW-A). Order: finish the S278 fixes first, rehearse in S279.

## Scope

* A runbook for onboarding a pilot agency: provision, invite, brand import, modules, AI budget, entering and leaving pilot mode.
* One synthetic tenant `pilot-rehearsal-01` and one AA tour that is sellable in two trip plans.
* The 13-step rehearsal from the audit, section 4:
  * staff steps through the Dev-only write identities;
  * agency and traveller steps by Playwright on the UI, at 1440 and 390, light and dark.
* Cross-app checks in the rehearsal: the AA-cancelled departure (crm-13), tour retirement, and budget fail-closed in three apps.
* Every FAIL becomes a tracked fix.

## Done when

* The runbook is merged in the root docs.
* The rehearsal README in `docs/audits/<date>-S279-pilot-rehearsal/` shows PASS for steps 0–12, or lists each FAIL with the issue that fixes it.
* The tenant leaves pilot mode at the end and the Dev pilot slot is free again.
* Real LLM spend is at most 10 USD (estimate 2–4 USD), reported per stage from the ledger.
