## Problem

Before the first prod, the Ecosystem status page needs the SRE layer: error budgets instead of instant thresholds, a record of incidents, checks from outside the VPC, and a way to see which agency an error or a spend spike comes from (S285 review, `docs/audits/2026-11-19-S285-session/ops-overview-v2-review.md`, items 9–12).

## Scope

1. **SLO + error budget burn** (SRE Workbook): per app "99.6 % / SLO 99.5 % · budget 38 % left · 1 h burn 2.1×"; alert when the 1 h burn > 14.4× or the 6 h burn > 6× (values are settings). Run as a trial on Dev.
2. **Incident record + timeline**: "Declare incident" from an alert (SEV, owner, status), a timeline built from `ops_event`, a "Write lesson" link to the lesson log.
3. **External synthetic checks**: GitHub Actions cron every 5–15 min against the public hosts (DNS, TLS, health), shown as an "external" strip next to the internal one, with a certificate expiry warning. 0 USD (public repo); Route 53 health checks only on an explicit yes (\~0.50–0.75 USD per check per month).
4. **Per-agency drill-down**: a tenant filter; top agencies by AI spend, failed jobs and errors.

## Done when

Each item is live on Dev with screenshots and its thresholds are admin settings; the burn-rate alert is proved by a synthetic error burst on Dev.
