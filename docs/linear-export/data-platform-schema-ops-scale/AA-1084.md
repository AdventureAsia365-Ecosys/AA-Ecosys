## Problem

S277 measured CI/CD over 24/10–11/11 from GitHub Actions (medians):

* CIS CI on PRs went from 4.6–5.4 min (24/10–04/11) to 6.7–7.0 min (08–11/11), and the merge queue from 4.2–4.7 to 6.6–8.2 min. Partner (2.4–3.1) and Booking (1.1–2.8) stayed fast.
* The critical path is the unit shard: 4m00s (06/11) to 5m59s (11/11). The three shards are unbalanced (4m23s / 5m09s / 5m59s). `.github/test-durations/unit.json` was last updated 06/11, so every new test file weighs the median.
* The S273 supply-chain steps (ADR 0021) add about 20–30 s per job, by design.
* PR open to merged on CIS was 106 min on 11/11. The main cause was not CI time:
  * Five code PRs went red on Migration preflight because their branch still carried the migration commit after the migration PR squash-merged (CIS [AdventureAsia365-Ecosys/AA-CIS-App#1436](https://linear.app/aa-ecosys/review/feat-brief-import-fills-brand-context-cta-and-signature-words-998a061f2f29) and [AdventureAsia365-Ecosys/AA-CIS-App#1439](https://linear.app/aa-ecosys/review/feat-hold-masters-that-offer-elephant-riding-until-a-person-approves-ba574bd310b7), Booking #217, Partner #268 and #271). Each cost one more CI round plus a manual merge of main.
  * A latent integration shard bug (`tests/integration/pytest.ini` hiding `pythonpath`) surfaced when new test files shifted the split. It was fixed in CIS [AdventureAsia365-Ecosys/AA-CIS-App#1440](https://linear.app/aa-ecosys/review/fix-integration-pytestini-puts-the-repo-root-on-syspath-2e8a09c26a13).

## Scope

* CIS CI:
  * Refresh the unit (and integration) durations file automatically from the shards' junit reports on main (bot PR or nightly), so the split stays balanced.
  * Raise unit shards from 3 to 4.
* Ship tools (root `tools/github/ship_wave.py`): when a chain's migration PR has squash-merged and been applied, merge origin/main into each `@after` code branch that still carries the migration commit and push it (no force), before gating it.
* Lane template (`tools/workflows/lane.js` COMMON): a lane bases its code branch on origin/main, not on the migration branch; the migration commit is not repeated in the code PR.

## Done when

* CIS CI on main: the longest unit shard is at most 4.5 min, and the median CI wall time over 2 days after the change is at most 5.5 min (from 6.7–8.2).
* A chain shipped with `ship_wave.py` (migration → apply → code) needs no manual merge of main: shown once live.
* The durations refresh has run at least once and its PR or commit is on main.
