## Problem

The Ecosystem status page (core issue) shows the state, but a professional ops page also says what changed, who handles an alert, how fresh each source is, when a limit will be reached, and when spend is abnormal. S285 review of the mockup picked these as P1 (`docs/audits/2026-11-19-S285-session/ops-overview-v2-review.md`).

## Scope (8 features, each 0 USD unless noted)

1. **Change annotations + "What changed"**: markers on every chart by type (deploy, setting change, migration, wave, route control change) and a "What changed" panel filtered by app and type, linking the PR / run / setting history.
2. **Alert ack / snooze / mute with owner**: Ack, Snooze 1 h / 4 h / until tomorrow, Mute with an end time; reason of at least 20 characters; shows "Acked by … at …"; expires by itself.
3. **Data freshness per source**: "as of" chip per section, grey "stale" after 3 × its refresh time; footer lists samplers, schema dump, guards, digest.
4. **Capacity forecast**: days until RDS free storage, AI caps and Actions cache reach their limit.
5. **Cost anomaly by app × provider × route**: banner when an hour's spend is above N × the 7-day median (N is a setting); the grouping works the same when the route moves to Bedrock (tech lead G6). Cost Explorer read once a day is optional (\~0.30 USD/month).
6. **Daily digest + push**: digest from the same verdict function with a link to the right view; push for SEV1/2 not acknowledged after N minutes (push may land in P2).
7. **Saved views + pause auto-refresh**: named views per user; refresh pauses while the tab is hidden, while zoomed or on a custom range.
8. **Accessibility WCAG 2.2 AA**: status never by colour alone, a table view for every chart, keyboard focus, `aria-live` verdict.

## Done when

Each feature is live on Dev on the Ecosystem status page with screenshots; thresholds and N values are admin settings; Linear comment per feature with evidence.
