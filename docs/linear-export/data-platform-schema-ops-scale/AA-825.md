## Problem

No table is partitioned or retained. `shared.decision_log` \~314k, `llm_call_log` \~244k (5× in 10 days), `tenant_api_usage` \~113k (+8.5k/day with 4 tenants). `v_tenant_monthly_usage` filters `date_trunc('month', called_at) = …` twice per tenant (migration 223 :100/:111/:129), so the index is unusable (S237 data review P5).

## Scope (decision E3)

* Rewrite `v_tenant_monthly_usage` with range predicates + index `(tenant_id, called_at)` on `tenant_api_usage`.
* `shared.llm_call_daily` rollup (groups by [AA-804](https://linear.app/aa-ecosys/issue/AA-804/ai-platform-root-adr-0006-ledger-v2-one-gateway-library-for) `app` / `is_shadow` once those columns exist; until then by stage/role/model/tenant).
* TTL job kinds (owner-run, batched DELETE, DRY RUN first, never VACUUM FULL): llm_call_log raw **180 d**; tenant_api_usage **90 d** + monthly rollup; `shared.job` / `booking.job` succeeded 30 d, failed 90 d; outbox/inbox payload PII redacted after 90 d; decision_log after confirming its cache TTL in code; cost_explorer_snapshot latest per day.
* Archive each batch to S3 as Parquet before delete.

## Done when

* Migration applied via D8; admin usage/cost pages return the same numbers as before (spot-check 4 tenants) and faster (EXPLAIN shows index use).
* First TTL run logged with rows archived/deleted per table; S3 objects present.
* Ref: data review §7 N4.
