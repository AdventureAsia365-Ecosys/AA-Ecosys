## Problem

S278 system audit:

* **M29:** the CRM has no handler for `tour.discontinued`. Holds, bookings and TripPlanner drafts on a retired tour were never checked.
* **M31:** the tenant lifecycle and the erasure of client personal data exist only in the CRM. CIS, Booking and TripPlanner keep their data when an agency leaves, which is a GDPR risk.
* **M27:** per-tenant restore exists only for the CRM.

## Scope

1. **Tour retired.** The CRM consumes `tour.discontinued`: flag the trips and options that use the tour, add an owner task, and never change a confirmed booking. Booking and TripPlanner react the same way.
2. **Offboarding.** One saga erases or anonymises the tenant's personal data in every app on the agreed schedule, with an audit row per app. DRY RUN first, following the destructive-ops procedure.
3. **Restore.** A one-tenant restore drill for CIS and TripPlanner, like the CRM's.

## Done when

* A synthetic tenant is offboarded end to end on Dev: each app reports erase done, and a re-read finds no personal data.
* A retired synthetic tour flags the CRM trips that use it.
* The restore drill passes for CIS and TripPlanner.
* Every destructive step went through DRY RUN with the tech lead's approval.
