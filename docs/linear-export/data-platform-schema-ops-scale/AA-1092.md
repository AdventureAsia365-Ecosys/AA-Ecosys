## Problem

The S278 system audit lists security gaps that must close before any real personal data arrives:

* **M19:** TripPlanner signs the tenant assertion with a key derived from the edge key.
* **M24:** the CRM public routes added since the [AA-969](https://linear.app/aa-ecosys/issue/AA-969/crm-w7-crm-37a-security-review-slos-bounded-load-test) review (Book now, the VNPay IPN, the sub-agent intake link) were never reviewed.
* `booking.b2b_partners` has no RLS.
* The new hosts may lack WAF rules.

## Scope

1. A dedicated TripPlanner tenant-assertion signing key: its own secret, rotation, and a verify path that accepts the old key during rotation.
2. An independent review of every public CRM route: rate limits, input validation, signature check on the IPN, replay protection, no data leak in errors. Fix each finding.
3. RLS ENABLE + FORCE on `booking.b2b_partners` with the right policy. The migration goes in its own PR first.
4. A WAF rule check for every public host. Add the missing rules after a cost statement.

## Done when

* Each item has a test and a live check: a forged or old-key assertion is refused, an IPN with a bad signature returns 4xx, cross-tenant reads of `b2b_partners` are refused, and the WAF lists every host.
* The review notes are in the S278+ audit folder with no open high findings.

  - 429 after 160 notices in 15 s; 414 at 16 KiB.

- **RLS:** `booking.b2b_partners` has `relrowsecurity` and `relforcerowsecurity` true, with 2 policies: back office ALL, tenant SELECT.

**Residual items (from the S278 pre-PII review) and the proposed handling:**
1. The TripPlanner web task holds both the edge key and the assertion key, so one BFF compromise yields both. A KMS GenerateMac signer would remove that at a per-call cost. **Proposal:** accept for Dev; revisit before prod.
2. The TripPlanner HTTP API cannot carry a web ACL (AWS limit). Today's controls: edge key, signed assertion, stage throttle, per-IP AI limits. A CloudFront + CLOUDFRONT-scope ACL in front costs ~5 USD/month fixed. **Needs the tech lead's yes on cost.**
3. The CRM CloudFront hosts (partner / agency / client) reach the ALB ACL through `CloudFrontOriginAllow`, so no per-viewer WAF rate limit applies. The app limiters are per task, in memory. A viewer-IP CloudFront function + scoped rate rule costs ~1 USD/month per rule. **Needs the tech lead's yes on cost.**
4. Book now `/price` calls Booking on every request. It is bounded per address (20/min) but not per agency. **Proposal:** a per-agency minute ceiling as an editable setting. Code, $0.
5. Partner-link intake uses the bucket `form:<id>` while the public form uses `<public_key>`, so a form that also has partner links gets double its hourly quota. **Proposal:** one shared bucket per form. Code, $0.
6. `booking.b2b_partners` RLS only fences transactions that bind `app.tenant_id`, and the B2B API handlers do not bind the caller's tenant yet. **Proposal:** bind the tenant in the B2B API handlers and add a cross-tenant refusal test. Code, $0. This is needed for the Done-when "cross-tenant reads refused".

Items 4–6 go into one follow-up lane this session. Items 2–3 wait for a cost decision.
