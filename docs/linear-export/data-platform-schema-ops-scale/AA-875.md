## Problem

S241 P0-8 b5: the WordPress integration validates tenant-entered URLs without resolving DNS and still follows redirects, so outbound calls are not restricted to public hosts (OWASP API7). Specifics stay in the private review.

## Scope

1. One shared client `safe_http`: resolve DNS and reject private, loopback, link-local and metadata ranges for every resolved address; connect to the checked address; `allow_redirects=False` (or re-check each hop); response size cap and timeouts.
2. Replace `_validate_wp_url` and route every tenant-supplied URL fetch through it (inventory by grep in the PR).
3. Unit tests: private IP, redirect to private, multi-record DNS.

## Done when

* Tests above pass in CI.
* Live on Dev: connecting an integration with an internal address returns 4xx and logs the rejection, while the WordPress test site (credentials in Secrets Manager) still connects and publishes.

### 2026-10-20 11:17 — nghiep pham quoc

S245: CIS #880 merged and deployed (6c2e62d3, Deploy Dev success). It adds the `shared/safe_http.py` outbound client with these guards:
- **Resolver:** refuses any address that is not public, including IPv4-in-IPv6 forms. The DNS cache is off.
- **Host checks:** numeric, octal and decimal hosts are normalised and checked. Only https, no userinfo.
- **Redirects:** at most 3 hops, each re-checked; credentials are dropped when a hop changes site.
- **Limits and logging:** 5 MiB cap, `trust_env` off; every rejection logs `safe_http_blocked`.
- **Review:** an independent review found 4 problems, all fixed, including a numeric-host bypass.

**Live on Dev, blocked cases (test tenant trail-pulse, `POST /v1/integrations/wordpress`)**
- `https://10-0-0-1.nip.io`, `https://localtest.me` (127.0.0.1) and `https://a9fea9fe.nip.io` (169.254.169.254) were each refused by the app with **422 "URL cannot point to a private or reserved IP address"**.
- CloudWatch `/ecs/aa-cis-dev` has `safe_http_blocked host=… reason=private_dns stage=dns` for all three.
- Literal private IPs in the body (`https://10.0.0.1.nip.io`, `https://169.254.169.254`, `https://2130706433`, `http://localhost`) are stopped one layer earlier by the API Gateway WAF (403), before the app.
- A public URL (`https://example.com`) is accepted. That probe integration was deleted right after, so trail-pulse is back to not connected.
