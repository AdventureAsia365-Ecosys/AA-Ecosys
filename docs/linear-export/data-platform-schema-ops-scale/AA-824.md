# AA-824 — [Data/Ops] RDS guardrails + connection budget — storage autoscaling, parameter group, pg_stat_statements, log export, alarms, CONNECTION LIMIT per role, Lambda reserved concurrency

## Problem

`aa-cis-dev-db` is db.t3.micro, 20 GB gp3 with no `max_allocated_storage`, no parameter group, no Performance Insights / slow-query log, `skip_final_snapshot = true`. Worst-case pool demand (CIS API 10×15, worker, TP Lambda 5/instance, Booking 5) already exceeds `max_connections`; only the 10-concurrency Lambda quota hides it, and the quota increase to 1000 is pending (S237 data review P4).

## Scope

* `modules/rds`: `max_allocated_storage = 100`, custom parameter group (`log_min_duration_statement=500ms`, `log_lock_waits`, `idle_in_transaction_session_timeout=60s`, `track_io_timing`, `rds.force_ssl=1`, pg_stat_statements preload), `enabled_cloudwatch_logs_exports=["postgresql"]` 14 d, `skip_final_snapshot=false`, `copy_tags_to_snapshot=true`, resize to **t4g.small + Performance Insights** (approved E5).
* Alarms: connections > 60 / 5 min, FreeableMemory < 100 MB, CPU > 80% / 15 min, CPUSurplusCreditsCharged > 0, FreeStorageSpace < 50%.
* Connection budget: `CONNECTION LIMIT` per role via owner migrations (tripplanner 30, booking 10, aa_app_user 15), TP pool max 1/instance, `reserved_concurrent_executions` on browse/assembly, CIS API main pool cap 5 on T-class, `application_name` per pool.
* One maintenance-window reboot while `shared.job` and `booking.job` are idle.

## Done when

* Terraform applied; `SHOW` confirms the parameters; pg_stat_statements has rows; PI visible; alarms in CloudWatch.
* `pg_stat_activity` shows `application_name` per pool; `rolconnlimit` set; Lambda reserved concurrency set — all **before** the Lambda quota case is applied (decision E6).
* Ref: `docs/audits/2026-10-14-S237-lane-backlog/data-architecture/README.md` §5.1/5.2 (N3, X9).
