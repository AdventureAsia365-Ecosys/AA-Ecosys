## Problem

The tech lead asked on 13/11/2026 (S279) for clean-code habits enforced early.

Lint, format, coverage gates, review lanes and CONTEXT.md exist in every app repo. Two kinds of rot still pass CI:

* **Very large files.** A count on 13/11 found 37 files over 1,000 lines in AA-CIS-App, 5 in AA-Partner, 4 in AA-Booking and 3 in AA-TripPlanner-Web. The largest are `api/routers/admin_pipeline.py` (5,813 lines), `services/acp_content_writing/service.py` (3,955) and AA-Partner `web/lib/i18n.ts` (5,517).
* **No complexity lint.** No repo enables C901 / max-complexity (Python) or an eslint complexity rule, so long, branchy functions are never flagged.

Large files and complex functions slow every change, and AI agents edit them less accurately at a higher token cost.

## Scope

1. **Complexity ratchet, per repo.**
   * Python: ruff C901, with a max-complexity chosen from today's distribution.
   * TypeScript: the eslint `complexity` rule on the frontends.
   * Today's offenders go in a committed baseline, so nothing existing fails. A new function over the limit fails. A function in the baseline may not get worse, and the baseline only shrinks.
2. **File-size ratchet, per repo.** A new source file may not exceed about 800 lines. A file already over the limit may not grow; its baseline line count only goes down.
   * Generated files, migrations, fixtures and i18n catalogues are listed exceptions, each with a reason.
3. Both checks run in the repo's pre-push and in CI. Each repo's CONTEXT.md gets one line on the rule.
4. **Split the largest CIS files, starting with** `api/routers/admin_pipeline.py`**.** Split it by route group into modules with the same routes, the same order (literal paths before catch-alls) and the same behaviour. The OpenAPI document must be unchanged. After that, one large file per session whenever work touches it.

## Done when

* All four app repos (AA-CIS-App, AA-Booking, AA-Partner, AA-TripPlanner-Web) have the complexity and file-size ratchets in pre-push and as a CI check. A test shows that a new over-limit function or file fails, and that a baseline entry cannot grow.
* `admin_pipeline.py` is split. The OpenAPI snapshot is unchanged, the integration tests pass, the deploy is live and `/health` returns 200.
* The baseline counts per repo are recorded in the closing comment.
