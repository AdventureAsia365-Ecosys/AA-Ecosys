## Problem

S241 P0-10: staff and tenant login endpoints have no rate limit; the CIS API stage has no throttle and no WAF; Booking API docs are public on `api-booking`; deployed CORS still allows localhost with credentials; CIS and TripPlanner frontends send no CSP/frame/nosniff/referrer headers.

## Scope

1. Per-IP rate limit + per-user backoff on `/auth/admin-login` and `/auth/tenant-login` (no hard lockout).
2. CIS stage throttle 50 rps / burst 100, `/auth/*` about 5 rps (re-measure per second first).
3. WAF on the CIS API stage (`apigateway:SetWebACL`, `waf_protect_rest_api_stages=true`), quote first (D-19).
4. Gate `/booking/docs` + `openapi.json` on `api-booking` ([AA-577](https://linear.app/aa-ecosys/issue/AA-577/security-swagger-ui-docs-cong-khai-o-production-yeu-cau-x-admin-secret) pattern).
5. Empty CORS on deployed envs.
6. Security headers in `next.config` for CIS and TripPlanner (Booking as template).

## Done when

* A burst of logins returns 429; `get-stage` shows the throttle. (WAF: deferred per S241 — turned on when customer sign-up opens; moved to [AA-908](https://linear.app/aa-ecosys/issue/AA-908/identity-traveller-sign-in-on-cognito-external-tripplanner-guest).)
* `curl` to Booking `openapi.json` on the public host returns 403.
* `curl -I` on CIS and TripPlanner pages shows the headers; UI smoke green.
