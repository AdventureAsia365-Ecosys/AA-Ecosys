## Problem

The CIS api, worker and migrations all run as `aa_cis_admin`. This role owns every CIS table and inherits `rds_superuser`, so it bypasses RLS:

* on the 229/237 tables, because it is the owner;
* on the 8 FORCE tables, through the RDS rds_superuser behaviour ([AA-817](https://linear.app/aa-ecosys/issue/AA-817/security-cis-api-runtime-role-aa-cis-admin-is-not-filtered-by-rls) probe).

ADR 0008 decision X1 splits ownership from the runtime role. Design: root `docs/audits/2026-10-16-S239-in-progress-audit/aa817-done-evidence/aa817_remaining_plan.md` §4. Prerequisites and pitfalls: `aa817_plan_critique.md` section D.

## Scope

* New roles `cis_owner` (owns CIS objects, NOLOGIN) and `cis_app` (runtime). Migrations run as a migrator with what they really need:
  * `rds_superuser` for CREATE EXTENSION (041, 234);
  * CREATEROLE for CONNECTION LIMIT (234).
* Before ownership moves, add a `cis_owner` master/platform read policy on the 8 FORCE tables (or drop FORCE there). Otherwise tripplanner and catalog_owner reads and old data migrations silently see 0 rows (D1, D3).
* Ownership transfer only `WHERE owner = 'aa_cis_admin' AND schema IN (<CIS schemas>)`. Exclude objects owned by catalog_owner and the booking / tripplanner schemas (D2).
* Move the schema dump workflow and break-glass ECS exec to the migrator task definition. Scope the ECS task role's `secretsmanager:GetSecretValue` so api/worker cannot read the admin DSN (D4, D5).
* Add a TripPlanner GRANT for photo sync (`services/photos/sync.py`) and cover the s4_trigger Lambda (D6, D7).
* Connection budget for `cis_app` against `max_connections` 181, with tripplanner 30 / booking 15 / aa_app_user 15. Cap autoscale to match (D8).
* CI:
  * conftest and ci.yml create the roles;
  * tests `SET ROLE cis_app`;
  * the 237 guard and conftest change together (D9).

Depends on [AA-807](https://linear.app/aa-ecosys/issue/AA-807/data-phase-1-foundation-per-app-db-owner-roles-migration-ownership) / [AA-826](https://linear.app/aa-ecosys/issue/AA-826/dataadr-new-app-integration-playbook-adr-0008-ownersyaml-registry-role) (owners, db_migrator). Needs Nghiệp for:

* secrets and DSNs (underscore env vars are edited by hand);
* MFA Terraform;
* approvals.

## Done when

* Migrations, the schema dump, TripPlanner/catalog reads, photo sync and the job runner all work (smoke + logs).
* The rollback path is documented and tested once.
