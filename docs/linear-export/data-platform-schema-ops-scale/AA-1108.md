## Problem

The tech lead asked (S282) for an admin page that tracks CI/CD and DevOps per app, to see how long things take and how well delivery works.

Today:

* DEV-01 (monthly DORA report) counts only CIS deploys, read from `shared.job_worker`.
* Lead time, change failure rate, time to restore, CI failure rate on main and CI durations all read "Source not available". The worker reads no GitHub data.
* There is no page that shows any of this.

## Scope

1. **Data, $0, no new secret.** A scheduled root workflow (hourly or nightly) reads the six public repos with `GITHUB_TOKEN` and builds one machine-readable file per run. It holds per app and repo:
   * workflow runs: CI on PRs, merge queue, main, deploy;
   * merged PRs: opened → merged → deployed;
   * deploy runs per service, and post-deploy verify results;
   * reverts and rollbacks.

   The file is published like `catalogue.json` (docs bundle on S3), and the CIS API serves it read-only with a short cache. The alternative is a worker job with an App token; choose with reasons in the implementation notes.
2. **Metrics per app** (CIS, Booking, CRM/Partner, TripPlanner, Infra, root):
   * the four DORA keys: deployment frequency, lead time for changes, change failure rate, time to restore;
   * CI duration p50/p95 per workflow, merge queue wait, failure rate on main, re-runs and flaky signals;
   * Actions minutes, and a trend over 4–12 weeks.

   Thresholds (green/amber/red) are settings on Platform › Settings, never constants.
3. **Admin UI:** Platform › Delivery in the CIS admin (kit components, EN/VI, light/dark, mobile), with one tab per app plus an overview, and links to the GitHub runs.
4. DEV-01 / DEV-03 read the same data, so their "Source not available" lines are replaced.

## Done when

* Merged + CI green + deploy COMPLETED.
* The page shows live numbers for every app, matching a manual spot check of 3 runs in GitHub.
* DEV-01 for the current month renders the DORA keys from real data.
* Screenshots: desktop, mobile, light and dark.

+++ Agent notes

Pattern to reuse: the Docs sync bundle (`catalogue.json`), served by the CIS API. Report registry: root `docs/reports/catalog.yaml` (DEV-01, DEV-03), CIS `services/reports/delivery.py`. Repos are public, so Actions minutes and reads cost $0.
