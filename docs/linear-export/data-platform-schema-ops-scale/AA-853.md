## Problem

Split from [AA-807](https://linear.app/aa-ecosys/issue/AA-807/data-phase-1-foundation-per-app-db-owner-roles-migration-ownership) (Nghiệp decision S239, 16/10). The nightly DB Schema Dump (Infra #122) only dumps the schema. It does not diff against a DB built from all migrations, and nothing checks that a migration writes only to its owner's schemas.

## Scope

* Extend the nightly workflow: build a scratch postgres from all owner migrations, diff it against the live catalog, report unmanaged objects in the root schema-reference PR.
* Copy Guard lint: fail a `db/migrations/<owner>/` file that creates or alters objects outside its owner's schemas (driven by owners.yaml from [AA-826](https://linear.app/aa-ecosys/issue/AA-826/dataadr-new-app-integration-playbook-adr-0008-ownersyaml-registry-role)).

## Done when

* A nightly run reports 0 unmanaged objects (run link), or each remaining one is listed with an owner decision.
* The lint is red on a test migration that touches another owner's schema and green otherwise (run links).
