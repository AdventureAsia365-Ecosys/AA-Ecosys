## Problem

GitGuardian (22/10/2026) flagged a "Generic Password" in public repo AA-CIS-Infra. The source is the DataForSEO API password, committed in plain text in `envs/dev/terraform.tfvars` in April 2026. The file was removed from main on 15/10, but the value is still in git history and became public when Infra went public on 22/10 (ADR 0014 amendment). Gitleaks in Infra scans only the lines a PR adds, so it never saw the history. GitHub secret scanning and push protection were off on Infra and on the root repo, both public.

## Scope

1. GitHub secret scanning + push protection on every public repo of the org. Done S248 for Infra and AA-Ecosys; CIS, Booking and TripPlanner already had it.
2. Infra Secret Scan workflow: add a full-history gitleaks job (schedule + push to main), with a baseline for the known April findings so it is green today and red on any new one.
3. A gitleaks rule for credential-named keys (`*password*`, `*passwd*`, `*secret*`, `*_token`, `*api_key*`) with literal values in `*.tfvars`, `*.tfvars.json`, `.env*` and `*.json`. Allowlist: `REPLACE_ME`, empty strings, test fixtures (`db.example`).
4. Root repo AA-Ecosys: the same gitleaks PR + full-history job (public repo, Actions minutes are free).
5. Docs: baseline row "Secret scanning" in docs/security/baseline.md; a precondition in the repo-visibility runbook/ADR 0014: a full-history scan and rotation BEFORE any private-to-public switch.

## Out of scope (waiting on Nghiệp)

Rotating the DataForSEO password: Nghiệp deferred it in S248. Path: change it in the vendor dashboard → Secrets Manager `aa-cis/dev/dataforseo` → force a new deployment of api + worker → `/admin/dfs-balance` 200 → resolve the GitGuardian incident.

## Done when

* `security_and_analysis` shows secret_scanning + push_protection enabled on all 5 public repos (gh api output in a comment).
* On Infra and root, a draft PR that adds `foo_password = "<random literal>"` in a tfvars file goes red, then is closed without merge (link).
* The full-history job is green on main with the baseline, and goes red on a test branch that has a new historical finding.
* The visibility precondition is written in ADR 0014 / the runbook.
