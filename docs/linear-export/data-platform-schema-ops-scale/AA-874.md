## Problem

S241 P0-8: the CIS Redis cluster has no AUTH, no TLS and no at-rest encryption, and is reachable from a security group shared by several services. Tenant-pool route flags live in Redis; read failures are logged but nothing alerts. With D-12 the code goes fail-closed ([AA-859](https://linear.app/aa-ecosys/issue/AA-859/security-tenant-pool-wave-2-move-tenant-write-and-planning-routes-to)); this issue protects the store and makes failures visible.

## Scope

1. New replication group with AUTH (token in Secrets Manager), in-transit and at-rest encryption, same `cache.t3.micro` (quote first, expected \~0 delta, D-19).
2. Switch CIS api, worker and Booking to the new TLS endpoint; delete the old cluster.
3. Metric filter + alarm on `aa817_tenant_flag_read_failed`, and on `used_tenant_pool=false` only for routes behind a tenant-pool flag; ALARM + OK e-mails (D-20).

## Done when

* `describe-replication-groups` shows AuthTokenEnabled, TransitEncryptionEnabled, AtRestEncryptionEnabled = true.
* An unauthenticated connection from a task (ECS exec Python check) is refused; api, worker and Booking are healthy on TLS.
* A test log event fires the alarm e-mail, then OK.
