## Problem

Platform alert e-mails go to an address hard-coded in Terraform (`var.alert_email`, moved to the work inbox by the S245 Infra PR "send SNS and budget alerts to the work inbox") and in the CIS env var `ALERT_EMAIL_TO` (`cis_ops_alert_email`). Changing or adding a recipient needs a Terraform PR + apply. The owner wants to choose the recipients from the admin page.

Alert paths today:

* SNS topic `aa-cis-dev-acp-alerts`: CloudWatch alarms of CIS, Booking, TripPlanner and shared; the cost anomaly subscription. One e-mail subscription managed by Terraform.
* 5 AWS Budgets (per app + total): e-mail subscribers set directly from `var.alert_email`.
* CIS job `ops_alert_email`: SES to `ALERT_EMAIL_TO` (LLM spend crossings).

## Scope

1. **Data:** a recipients table owned by CIS (per `docs/database/schema-ownership.md`), with email, status (pending / confirmed / removed), SNS subscription ARN, who/when, and an audit trail.
2. **Admin page (CIS staff admin, role admin only):** list recipients with their confirmation status; add (sends the AWS confirmation e-mail); remove; resend confirmation.
3. **SNS:** the CIS api manages the e-mail subscriptions on the alerts topic. The IAM grant is scoped to that topic: Subscribe / Unsubscribe / ListSubscriptionsByTopic / GetSubscriptionAttributes, nothing else.
4. **Budgets:** notify the SNS topic instead of an e-mail address (topic policy lets [budgets.amazonaws.com](<http://budgets.amazonaws.com>) publish), so one recipient list covers everything.
5. `ops_alert_email` **job:** reads the confirmed recipients from the table; falls back to `ALERT_EMAIL_TO` when the table is empty.
6. **Fallback:** Terraform keeps exactly one bootstrap recipient (`var.alert_email`), shown as locked in the UI, so alarms still reach someone if the app or the DB is down.

## Done when

* A recipient added on the admin page receives the AWS confirmation e-mail. After the click, it shows "confirmed" and gets a test alarm and a test budget/ops e-mail.
* A removed recipient receives nothing more.
* The IAM policy is scoped to the alerts topic only (reviewed).
* Deployed and verified live per aa-ship.
