# AA-841 — [Security] Plaintext credentials tracked in AA-CIS-Infra envs/dev/terraform.tfvars (old acc1 RDS DSN with password, DataForSEO login/password) — remove from git, rotate what is still live

## Problem

The S238 lane I review ([AA-828](https://linear.app/aa-ecosys/issue/AA-828/dataops-per-app-cost-allocation-tags-budgets-for-the-data-platform-rds) tags) found that `infra/AA-CIS-Infra/envs/dev/terraform.tfvars` is tracked in git with plaintext credentials:

* `database_url`: a DSN with the master password. Its host is the **old acc1 RDS** (`aa-cis-dev-db.cr2y6824szn3…`, destroyed 09/07/2026, AA-271). The current acc2 RDS is `…ctss2iwwwzfw…`.
* `dataforseo_login` / `dataforseo_password`: DataForSEO is still in use (DFS balance, keyword research).
* Several Secrets Manager ARNs in acc1 (867490540162). These are not secrets themselves, but they are stale.

Last touched in commits 10ff474 / 544aa8d (S16) and 8efe65f. The repo is **private**, but the values live in git history and in every clone and worktree.

It is not yet confirmed whether the old RDS password was reused on acc2, or whether the DFS credentials are the live ones. A direct comparison was blocked by the session's credential-exploration guard (correctly). Nghiệp checks or rotates by hand.

## Scope

1. Confirm `envs/` is the legacy acc1 root (the active root is `accounts/aa365`) and nothing applies from it. Then `git rm` `envs/dev/terraform.tfvars`, keep `terraform.tfvars.example`, and add `envs/**/terraform.tfvars` to `.gitignore`. If `envs/` is entirely dead, remove it with a note in CONTEXT.md.
2. **Rotate** (Nghiệp, by hand):
   * The DataForSEO API password, if it matches the one in use, then update the secret the app reads.
   * The acc2 RDS master password (`aa-cis/dev/rds`, Terraform-managed?) **only if** it equals the old acc1 one. Coordinate with every pool (CIS, TP, Booking, DB Migrate) and follow the [AA-824](https://linear.app/aa-ecosys/issue/AA-824/dataops-rds-guardrails-connection-budget-storage-autoscaling-parameter) connection-budget notes.
3. Decide whether to purge git history (git filter-repo plus a force-push on a private repo; every clone must re-clone). Rotation makes the purge optional. Record the decision.
4. Add a CI secret-scan guard (gitleaks or similar) on AA-CIS-Infra, matching what GitHub push protection already does for some patterns.

## Done when

* `git ls-files | grep tfvars$` in AA-CIS-Infra lists no real tfvars. The `.gitignore` rule is merged.
* Nghiệp confirms the DFS password was rotated, or was already different, and DFS calls still work (balance check green).
* The RDS password status is recorded: different, or rotated with all pools healthy.
