## Problem

The S283 docs audit found 24 pages that say something wrong about what runs live, because facts (accounts, routes, services, migrations, job kinds, required checks) are copied by hand and nothing links a code change to the pages that describe it. Advisory: `docs/audits/2026-11-17-S283-docs-advisory/README.md` sections 2 and 4.2.

## Scope

Slices A1–A9 of the advisory (tech lead choices S283: one central doc map in the root, docs-impact **warn only**, no DVC):

1. A1 page history in the manifest (`last_changed`, `history`) and a "what changed in docs" page.
2. A2 `facts.snapshot.json` + `platform.yaml` + `gen_sections.py` (`--check` / `--write`), first blocks: accounts / LLM route order, ECS services.
3. A3 more generated blocks: latest migration per owner and app versions, job kinds, required checks per repo, backup days.
4. A4 `doc-map.yaml` (seeded from the audit `rows.json`) + `doc_impact.py` + a reusable workflow called from the 5 app repos, warning only.
5. A5 event-based freshness + `doc-owners.yaml` for agent files and `CONTEXT.md`; freshness report in the manifest.
6. A6 agent rules: `aa-ship`, lane briefs, `pre-push` warning, session close step.
7. A7 checks inside backticks (paths, masked Terraform addresses, service / kind / key names, migration numbers, workflow names).
8. A9 (optional) image size gate for new files under `docs/audits/`.
   A8 (make docs-impact a required check) stays out: the tech lead chose warn only.

Cost: under 0.1 USD/month (S3 bundle, public-repo Actions minutes).

## Done when

* Generated blocks render from facts and `gen_sections.py --check` is green in CI.
* A PR that changes mapped code shows a docs-impact warning in all 6 repos.
* The reader shows page history and a "needs review" flag when a dependency changed.
