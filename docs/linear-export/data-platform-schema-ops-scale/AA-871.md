## Problem

S241 P1-6: the three apps log plain text with no request id, so one request cannot be followed across log lines or services. Booking and TripPlanner have no error tracking.

## Scope

1. structlog JSON + request-id middleware in CIS, Booking and TripPlanner; bind `request_id`, `tenant_id`, `job_id` (ids only, never PII, DM-6.4 / C4.2c); return the id in a response header; log `db_ms` (C1.1d).
2. Sentry for Booking and TripPlanner with PII scrubbing, release = git SHA.
3. Test guard: startup fails when the DSN is missing and `ENVIRONMENT != test`.

Depends on the CIS Sentry setup (CIS error visibility issue).

## Done when

* For each app, a CloudWatch Logs Insights query on one `request_id` (taken from a live response header) returns all its log lines as JSON.
* A test exception from Booking and from TripPlanner Dev appears in Sentry with no PII.
* CI shows the missing-DSN guard test passing.
