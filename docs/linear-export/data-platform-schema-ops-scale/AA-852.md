# AA-852 — [Data] Per-app DB owner roles + db_migrator task def (bk_owner / tp_owner, tripplanner role in a migration, revoke legacy grants 179/180)

## Problem

Split from [AA-807](https://linear.app/aa-ecosys/issue/AA-807/data-phase-1-foundation-per-app-db-owner-roles-migration-ownership) (Nghiệp decision S239, 16/10). DB Migrate runs as `aa_cis_admin` for every owner, and the tripplanner role was created out-of-band with IF EXISTS-guarded grants.

## Scope

* Use the owners.yaml registry and bootstrap template from [AA-826](https://linear.app/aa-ecosys/issue/AA-826/dataadr-new-app-integration-playbook-adr-0008-ownersyaml-registry-role); do not re-implement them.
* Role migrations for `bk_owner` / `tp_owner`; transfer ownership of booking.\* and tripplanner.\* objects.
* Capture the tripplanner role in a tp migration and re-issue its grants without guards.
* A separate `db_migrator` ECS task def in Terraform that DB Migrate uses per owner.
* Revoke the legacy grants from migrations 179 (raw_tours) and 180 (tour_atoms) once the catalog views cover the readers.

## Done when

* `SELECT rolname FROM pg_roles WHERE rolname IN ('bk_owner','tp_owner')` returns 2 rows.
* booking.\* and tripplanner.\* tables are owned by those roles (schema reference shows it).
* A DB Migrate run log shows the db_migrator task def.
