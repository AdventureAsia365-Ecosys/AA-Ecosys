## Problem

The Terraform Apply workflow cannot safely apply the whole `accounts/aa365` root, so every S237 apply was a local targeted apply.

CI plan run 38727028673 (15/10) on main shows 0 add / 16 change:

* Hidden-only diffs: secret versions `tripplanner_{api_key,db,mapbox}`, `acp_partner_api`, `acp_webhook_secret`; `random_password.tripplanner_api_key`; `module.rds.aws_db_instance.main`.
* Tag diffs: 2 ACM certs, booking/api_cis API GW domain names, SES identity, TripPlanner zip objects.
* The `dfs_balance_check` zip hash (recurring local vs CI drift since S236, with eventbridge tags).
* One real parameter-group diff: `rds.force_ssl` / `track_io_timing` switch from pending-reboot to immediate.

S239 check (16/10): CI pins Terraform 1.7.5 (`terraform-plan.yml`, `terraform-apply.yml`) while local runs 1.15.5 and `required_version` is a range; `main.tf.bak` and `main.tf.bak2` are still tracked at the repo root; `terraform-apply.yml` has no guard on secrets, passwords or RDS.

Also handed over from [AA-828](https://linear.app/aa-ecosys/issue/AA-828/dataops-per-app-cost-allocation-tags-budgets-for-the-data-platform-rds): the CloudTrail log bucket (`aws_s3_bucket.cloudtrail_logs`, [observability.tf](<http://observability.tf>)) has no `App` tag. `put-bucket-tagging` would replace the whole tag set, so it is added in Terraform once the plan is clean.

Split out of [AA-806](https://linear.app/aa-ecosys/issue/AA-806/infra-split-the-cis-ci-role-app-deploy-vs-terraform-permissions) (scope addition S238), Nghiệp decision S239 (16/10).

## Scope

1. Align the Terraform version between CI and local, then pin it in `required_version` and both workflows.
2. Find the hidden attribute behind each secret / password / RDS diff (`plan` + `show -json`). Fix it with `ignore_changes`, a state refresh or a config change. Never apply a value change to a secret or password.
3. Encode the live parameter-group `apply_method`.
4. Fix the tag drift (ACM, API GW domains, SES, zip objects) and make the zip builds deterministic (`dfs_balance_check`, TripPlanner).
5. Make `terraform-apply.yml` refuse plans that touch `aws_secretsmanager_secret_version`, `random_password` or `aws_db_instance`, unless the run explicitly allows it.
6. `git rm` the tracked leftovers `main.tf.bak` and `main.tf.bak2`.
7. Add the `App` tag to `aws_s3_bucket.cloudtrail_logs` in Terraform (from [AA-828](https://linear.app/aa-ecosys/issue/AA-828/dataops-per-app-cost-allocation-tags-budgets-for-the-data-platform-rds)).

Out of scope: retiring `aa-cis-dev-role`, the boundary flip and WAF enforce (stay in [AA-806](https://linear.app/aa-ecosys/issue/AA-806/infra-split-the-cis-ci-role-app-deploy-vs-terraform-permissions)).

## Done when

* CI plan on main shows "No changes", or only the changes a PR intends.
* One full-root Apply dispatch from CI completes with 0 changes to secrets, passwords and RDS.
* `terraform-apply.yml` rejects a test plan that touches a guarded resource type (run link).
* `aws s3api get-bucket-tagging` on the CloudTrail log bucket returns `App` with its existing tags intact.
