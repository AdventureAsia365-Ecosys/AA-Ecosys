# AA-892 — [Ops] Operations index and runbooks — rollback per component, DB ops index, flag register, incident playbooks

## Problem

Operational knowledge lives in skills, session logs and scattered `docs/*.md`; alarms have no runbook links and there is no single operations index (S243 guide §6.3, proposal OPS-\*).

## Scope

* `docs/ops/README.md`: index of every runbook in all repos + a hand-written CI/CD table.
* `docs/ops/runbooks/rollback-{cis,booking,tp-lambda,vercel,terraform}.md` (CIS and Vercel moved out of `skill/aa-ship` §5 from [AA-869](https://linear.app/aa-ecosys/issue/AA-869/ops-app-rollback-readiness-immutable-cis-ecr-task-def-vercel-rollback), aa-ship keeps a link; TP Lambda documents the current revert-and-redeploy path until [AA-703](https://linear.app/aa-ecosys/issue/AA-703/auth-identity-epic-adr-0006-cognito-workforce-external-pools-email) adds the `live` alias).
* Core how-tos: ECS exec S3-mediated, deploy-gate override, scale, logs, job kill switch, legacy login flag, SES bounce.
* `docs/ops/database-operations.md`, `docs/ops/feature-flags.md`, `docs/ops/playbooks/` (5xx spike, queue stuck, LLM cost spike, Cognito login, SES).
* Per-app `docs/runbooks/deploy.md` (public-safe).

## Done when

Every runbook follows the template, uses single-line AWS CLI with names only, and has `last_tested` + evidence from a Dev run (or `status: draft` with the UNTESTED banner).
