## Problem

[AA-817](https://linear.app/aa-ecosys/issue/AA-817/security-cis-api-runtime-role-aa-cis-admin-is-not-filtered-by-rls) (closed S239) moved the tenant **read** routes and the integration disconnect to the `aa_app_user` tenant pool. Each route is fail-closed and logs `used_tenant_pool`. On the 15 RLS tables, a forged foreign `app.tenant_id` returns 0 rows (probe v2: 75/75 cells pass after migration 239).

The rest of the tenant surface still runs on the owner pool (`aa_cis_admin`). On that pool, RLS is skipped, so isolation depends only on app `WHERE` clauses.

Plan and the critique that corrects it: root `docs/audits/2026-10-16-S239-in-progress-audit/aa817-done-evidence/aa817_remaining_plan.md` (§1–2, waves W2–W9) and `aa817_plan_critique.md` (sections B and C).

## Scope

1. **Tenant writes (W2–W4, W6):**
   * content-writing start / repair / publish writes;
   * angle-gate request and option writes, with RLS on `acp_shared.angle_gate_option` through its parent;
   * T2 version writes.
2. **Atoms, subject and planning reads and writes (W7–W8).** RLS with keep-alive policies for TripPlanner / catalog_owner before the routes move, on:
   * `acp_contract.tour_atoms`, `acp_shared.subject`, `acp_contract.route_pick`;
   * `acp_shared.quarter_plan` / `year_plan` / `tenant_atom_state`;
   * `acp_deliver.tenant_tour_pages` (its tenant_id is text).
3. **Integrations connect / test / publish (W9).** Coordinate with [AA-815](https://linear.app/aa-ecosys/issue/AA-815/portal-facebook-connect-ui-tenant-self-unpublish-wire-existing) / [AA-819](https://linear.app/aa-ecosys/issue/AA-819/aup-2026-11-tenant-ai-notice-at-reviewpublish-t9-guard-against).
4. **Tenant JWT routes outside /v1** (critique B):
   * `/admin/brand-identity` GET/POST, `/upload`, `/parse` (`shared.tenant_brand_rules`, `tenant_seo_config`);
   * `/admin/atoms` GET and PATCH (a tenant write on `tour_atoms`).
5. **Grant hardening** (critique C2 and the probe):
   * `acp_shared.marketplace_portfolios` gives `aa_app_user` INSERT/UPDATE with no RLS;
   * SELECT with no RLS on `shared.tenants` (api_key_hash), `tenant_brand_rules`, `tenant_seo_config`, `tenant_export_config`, `llm_call_log`, `decision_log`, `dfs_call_log`.
   * Revoke these, or add RLS before any route reads them through the tenant pool.
6. **Follow-ups from the** [AA-817](https://linear.app/aa-ecosys/issue/AA-817/security-cis-api-runtime-role-aa-cis-admin-is-not-filtered-by-rls) **PR-A review:**
   * A double-click disconnect returns 503 (`row_mismatch`) instead of 200 `disconnected=false`. Re-check that the row exists before raising.
   * With pool `max_size=1`, a disconnect holds the task's only tenant connection while it waits on Secrets Manager (up to \~16 s). Do the tombstone outside the connection hold, or size the pool against `CONNECTION LIMIT 15` and the api autoscale cap.

One route group per PR, each behind its own Redis flag (report, then confirm), with fail-closed and `used_tenant_pool` logs.
