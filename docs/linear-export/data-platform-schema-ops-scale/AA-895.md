# AA-895 — [Security] Security baseline and vulnerability management policy — Dependabot for Booking and TripPlanner

## Problem

Security controls exist across many issues ([AA-866](https://linear.app/aa-ecosys/issue/AA-866/security-restrict-deployapplymigrate-oidc-trust-to-main-env-policy-ref)…[AA-879](https://linear.app/aa-ecosys/issue/AA-879/ci-ci-gate-parity-across-cis-booking-and-tripplanner)) but there is no single baseline page with status/evidence, no written vulnerability SLA, and Booking/TripPlanner have no Dependabot config (S243 guide §6.5).

## Scope

* `docs/security/baseline.md`: controls with status and evidence link — WAF, MFA, OIDC main-only, CI least privilege, SG per caller, RLS, Redis AUTH/TLS ([AA-874](https://linear.app/aa-ecosys/issue/AA-874/security-redis-authtlsat-rest-encryption-tenant-flag-read-failure)), GuardDuty/CloudTrail/Access Analyzer/S3 BPA ([AA-873](https://linear.app/aa-ecosys/issue/AA-873/security-account-detection-baseline-guardduty-access-analyzer-s3-bpa)), branch protection, secret scanning, agent guardrails.
* `docs/security/vulnerability-management.md`: severity SLA, exception process (`pip-audit-ignore.txt` with expiry), monthly triage; generated open-alerts table.
* `dependabot.yml` in Booking and TripPlanner (CIS and Infra already have one).

## Done when

* Each control links to its evidence or an open issue.
* Dependabot PRs appear in Booking and TripPlanner.
