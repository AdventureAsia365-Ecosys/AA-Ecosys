## Problem

S278 system audit, gap B2: no test identity can **write** on the staff side. The E2E admin of CIS and the E2E staff of Booking are read-only; every POST is 403, including dry runs. So staff steps can be proven only by CI or by admin-secret / M2M scripts, and nothing proves them through the browser.

The tech lead chose (S278) to build write identities before the synthetic pilot rehearsal.

## Scope

* One Dev-only, write-capable E2E staff identity per app: CIS admin, Booking staff, and a maker/checker pair for Booking finance.
* Each identity is limited to synthetic tenants and records (`is_canary` / synthetic marks), and is refused on any real tenant.
* Same managed sign-in as staff today: Cognito WORKFORCE with the E2E mail exception A10. No password sessions.
* Never present in prod: removed at go-live together with the A10 exceptions ([AA-1054](https://linear.app/aa-ecosys/issue/AA-1054/identity-at-go-live-remove-the-e2e-staff-sign-in-exceptions-a10-a10a)).
* An independent security review before merge, because this changes auth and permissions.

## Done when

* A Playwright smoke signs in as each identity and does one write on a synthetic record: CIS review approve, Booking supplier confirm, and a finance maker/checker pair.
* The same identity is refused (403) on a non-synthetic tenant.
* The audit log shows the actor.
* The independent review is clean.
