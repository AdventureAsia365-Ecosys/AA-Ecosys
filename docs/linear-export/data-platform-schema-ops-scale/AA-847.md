## Problem

Split from [AA-712](https://linear.app/aa-ecosys/issue/AA-712/adr-0002-move-the-place-pipeline-itinerary-places-geocoding-tour-graph) (Nghiệp decision S239, 16/10). The TripPlanner browse readers can read the CIS catalog views (TP #78, slice 6b) but still default to `PLACES_SOURCE=legacy`, because the cis path is too slow. S237 Dev parity for Laos (`docs/audits/2026-10-14-S237-lane-backlog/aa712-6b/`):

* routes \~1 s on cis vs \~40 ms on legacy;
* 80 tiles 1,014 ms vs 122 ms;
* destination detail 3.6 s vs 0.85 s (`catalog.v_destination`, security-barrier view with a LATERAL photo count).

Migration 235 (CIS [AdventureAsia365-Ecosys/AA-CIS-App#746](https://linear.app/aa-ecosys/review/perf-catalogv-tour-place-parses-day-text-only-for-the-requested-tours-f44acf672f51)) fixed only per-tour `catalog.v_tour_place` reads. Full-catalog reads (routes, tiles, destination detail) are still open.

The S237 UI verify also found content defects the current CIS build would carry into the flip: the Vietnam "Ho Chi Minh Trail by Bicycle, 14 Days" tour has 12 day entries, Kuang Si appears several times in one Laos tour under different names, and the Ho Chi Minh Trail is drawn as a single pin.

## Scope

1. L4 read model: materialize or tune `catalog.v_destination` and the route and tile reads behind the TP browse readers. New CIS migration (next free number) + Infra byte copy, applied through DB Migrate. Contract columns unchanged, or the change recorded in CONTEXT.md of CIS and TP.
2. Re-run `docs/audits/2026-10-14-S237-lane-backlog/aa712-6b-parity.py` on Dev (read-only, role `tripplanner`) after each change until cis latency is close to legacy.
3. Deterministic content-validity report (no LLM) in `apps/AA-CIS-App/services/places` + a tab on `/admin/places`, per country and catalog-wide: (a) tours where `duration_days` differs from the number of itinerary days; (b) the same real place repeated within one tour; (c) linear or area features (trail, river, road, range, national park) get a "not a pin" kind. This report is a pre-flip gate.
4. Flip the TripPlanner browse Lambda to `PLACES_SOURCE=cis`, then re-run the parity on the live setting.
5. 7-day post-flip window: watch browse Lambda errors and throttle alarms; roll back to `legacy` if a reader regresses.

Out of scope (stay on [AA-712](https://linear.app/aa-ecosys/issue/AA-712/adr-0002-move-the-place-pipeline-itinerary-places-geocoding-tour-graph)): the 142 pending place names, photo sync off the frozen TP tables + TP grant revoke, the `a3_place_days` shadow decision.
