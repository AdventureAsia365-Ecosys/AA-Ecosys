## Problem

CodeQL default setup (turned on by [AA-867](https://linear.app/aa-ecosys/issue/AA-867/security-free-github-security-features-org-2fa-force-push-and-branch)) reports 30 open alerts on AA-CIS-App, and nothing tracks them. As of 20/10/2026:

* 20 × `py/polynomial-redos` + 2 × `py/redos` (high) — mostly `services/acp_content_writing/` (`hygiene.py`, `sentence_repair.py`, `quality_gates.py`, `text_integrity.py`, `trip_facts.py`) and `services/photos/match.py`.
* 5 × `py/stack-trace-exposure` (medium) — e.g. `api/routers/admin_llm_ops.py` returns `str(e)` to the caller.
* 2 × `py/weak-sensitive-data-hashing` — `api/routers/auth.py` (SHA-256 of tenant API keys) and an integration test.
* 1 × `py/incomplete-url-substring-sanitization` in a unit test.

Alert #33 (same rule, `quality_gates.py` `_SENT_SPLIT_RE`) was dismissed in S245 as a false positive after a timing test: `split()` on 1M-character adversarial inputs took 7–31 ms, growing linearly.

## Scope

1. For every regex alert, run the same timing test on adversarial input built from the alert's own message. If the time is linear, dismiss it as a false positive and put the numbers in the dismissal comment. If it is superlinear, rewrite the pattern (possessive quantifiers / atomic groups, Python 3.12) and add a unit test that bounds the runtime.
2. Stack-trace exposure: return a generic error body plus a correlation id; log the detail server-side.
3. API-key hashing: confirm the keys are high-entropy random values (in which case SHA-256 is correct and the alert is dismissed with the reason); otherwise move to HMAC with a server-side pepper.
4. Test-only alerts: fix the test, or dismiss as "used in tests".

## Done when

* 0 open CodeQL alerts on AA-CIS-App main, each one either fixed (PR merged and deployed per aa-ship) or dismissed with a written, measured reason.
* Any regex that was rewritten has a runtime-bound unit test.
