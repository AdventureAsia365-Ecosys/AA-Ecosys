## Problem

S263 spent most of its wall time on the migration loop (CI → queue CI → bot copy → manual DB Migrate → deploy, \~40–50 min per migration, run one by one for 325–331 and crm-036–038) and on extra CI rounds after avoidable failures (preflight class, integration tests that assume Dev grants, gitleaks false positive, a PR merged with a red non-required check). Tech lead (S263, 01/11): do the optimisations now.

## Scope

1. Dev only: Migration Apply also applies contract files automatically when every job table is idle and no wave is open (destructive files stay manual; prod unchanged) — ADR 0017 amendment.
2. GitHub merge queue: group PRs (build several entries together) on AA-CIS-App, AA-Partner, AA-Booking.
3. Faster CI: split the CIS (and Partner if needed) integration suite into parallel shards; Migration preflight becomes a required check.
4. Ship helpers as repo tools: merge (refuses any red check, not only required), stacked-branch train (rebase own commits), copy-and-apply (merged copy PR, tracks its own run id), with docs in skill aa-ship.
5. Lane template: lanes run the same checks as CI before returning (preflight, integration, gitleaks), batch migrations per wave.
6. Session ritual: MFA check at start and a reminder before the 8 h session expires.

## Done-when

* A contract migration on Dev applies without a manual DB Migrate (live run evidence).
* Merge queue shows grouped entries; CIS integration CI time before/after.
* Helpers live in tools/ with tests; skill aa-ship updated.
