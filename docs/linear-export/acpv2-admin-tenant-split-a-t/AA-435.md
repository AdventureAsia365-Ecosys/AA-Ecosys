## Re-verify (03/09/2026)

Confirmed still accurate against the current `origin/main` code (unchanged since 22/08): `/api/auth/login/route.ts`'s admin branch returned the JWT in its JSON body, and `login/page.tsx` duplicated it into a plain, non-httpOnly `cis_api_token` cookie. `cis_admin_token` (the cookie middleware.ts/`requireAdmin()` actually check) has been httpOnly since AA-232 — `cis_api_token` was a pure, XSS-readable duplicate.

**Note on process**: this session's original git checkout was found 8 commits / 5 migrations behind `origin/main` (missing AA-514/AA-519) — exactly the stale-worktree risk AA-520's audit flagged. Built this fix from a fresh `git worktree add ... origin/main` instead of continuing there.

## Fix

Not a literal "make `cis_api_token` httpOnly" — since `cis_admin_token` already does that job (since AA-232), the fix drops `token` from the JSON response entirely (the thing that actually fed `cis_api_token`). Audited every reader of `cis_api_token` across the frontend before touching anything:

- **`(internal)/review/page.tsx`** — the one *real, load-bearing* consumer (3 direct-to-backend `Authorization: Bearer` fetches). Converted to the existing same-origin `/api/tenant/[...path]` proxy (httpOnly-cookie auth, already used elsewhere in the app).
- **`(internal)/upload/page.tsx`** — token was only used as a dead existence-guard that would have silently broken the page once `cis_api_token` stopped being set. Removed.
- **`catalog/page.tsx`** — token fed an `Authorization` header that the receiving proxy (`/api/tour-full/[id]`) already ignores (auths via `requireAdmin()`/httpOnly cookie instead). Confirmed dead, left untouched.
- **`admin/pipeline/s1/page.tsx`** — calls `/acp/s1/*`, which doesn't exist anywhere in the current backend (grepped `api/main.py`'s router list + every router file). Already fully broken/dead regardless of this fix — pre-existing, unrelated, not fixed here.

Content-role login left untouched on purpose (separate, already-accepted risk per AA-253).

## Live-verify

**Pre-merge** (local `next build && next start` against the real backend, temp admin row created+deleted via ECS exec): login response has no `token`, single httpOnly `Set-Cookie` for `cis_admin_token`; wrong password still 401/no-cookie; `/admin/dashboard` still gates correctly (200 with session, 307 without); converted review-queue proxy → 200 real data with session / 401 without; a bogus-id approve → 409 (not 401, proving auth reached the backend without mutating a real row); upload's sources fetch (guard removed) → 200 real data. `next build` clean, no new lint errors (confirmed via stash diff — actually *removed* 3 pre-existing ones as a side effect of deleting dead code).

## Found, not fixed (flagged as follow-up)

Neither admin sidebar's `logout()` can clear `cis_admin_token` — it's httpOnly, so `document.cookie = "...max-age=0"` can't touch it. Clicking "Logout" today only clears the display cookies and redirects to `/login`; the real httpOnly session stays valid until its 24h expiry. This predates AA-435 entirely (httpOnly since AA-232) — not introduced or worsened here. AA-427 built a real server-side `/api/auth/tenant-logout` for the equivalent tenant gap; admin has no equivalent. Worth its own ticket if you want it closed.
