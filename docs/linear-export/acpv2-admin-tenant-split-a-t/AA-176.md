## Bối cảnh (verified 07/06/2026 — repo audit + Linear)

Deploy hiện tại của shared API `api-cis` (ECS Fargate, phục vụ **cả CIS lẫn ACP**) dùng image tag `:latest`. Hệ quả root-cause:

* Không pin được image known-good → **không rollback nhanh được** khi deploy hỏng.
* ECS không đảm bảo pull image mới (cùng tag) → deploy có thể "thành công" mà chạy image cũ.
* Lambda ACP (`acp_s3_campaign_planner`, `brand_brief_parser`, `acp-s4-evaluate`) publish thẳng $LATEST, không alias/version → không canary, không rollback.

→ Đây là gap reliability ở **deployment layer** (app-layer đã chắc: circuit breaker [AA-113](https://linear.app/aa-ecosys/issue/AA-113/hrn-07-s2-expand-keyword-scope-circuit-breaker), checkpoint [AA-107](https://linear.app/aa-ecosys/issue/AA-107/hrn-15-s42-per-tour-checkpoint-resume-on-spot-interruption), crash-recovery [AA-169](https://linear.app/aa-ecosys/issue/AA-169/hrn-s2-auto-crash-recovery-ecs-task-kill-no-auto-resume-hitl-only-gap), idempotency [AA-106](https://linear.app/aa-ecosys/issue/AA-106/hrn-03-eventbridge-source-fix-consumer-idempotency)).

## Áp dụng ACP

Trực tiếp. Shared ECS API serve ACP; S3/S4 là Lambda riêng của ACP. Bắt buộc trước khi có paying B2B tenant.

## Scope (ưu tiên theo leverage)

1. **Immutable tags (cheap, làm trước):** ECS image tag `:latest` → git SHA (`api:<sha>`). GitHub Actions register-task-def với SHA cụ thể. Cho phép rollback = re-deploy task def revision cũ.
2. **ECS deployment circuit breaker + auto-rollback:** bật `deploymentConfiguration.deploymentCircuitBreaker { enable, rollback }` trên service → deploy fail tự rollback về revision trước.
3. **Lambda safe deploy (ACP stages):** alias `live` + version + CodeDeploy canary/linear traffic shift. Đây là nơi blue/green thực sự dùng được cho ACP.
4. **(Optional, Phase 2):** ECS blue/green qua CodeDeploy — đánh giá sau, rolling + circuit breaker đã đủ cho dev/single-tenant.

Vercel frontend: KHÔNG đụng — đã có atomic deploy + instant rollback.

## Quyết định — giữ `:latest`, nhưng cần cách biết đang chạy đúng phiên bản nào (Nghiệp, 04/09/2026)

**Giữ nguyên `:latest`** làm tag chính (không đổi quy ước CI/CD hiện tại trong CLAUDE.md) — không chuyển sang git-SHA làm tag chính.

**Nhưng cần thêm cơ chế truy vết phiên bản** — mục tiêu: bất kỳ lúc nào cũng biết chính xác ECS đang chạy image build từ commit nào, không chỉ biết "đang chạy :latest".

## Việc cần làm — STEP0 trước, đề xuất cụ thể

1. Xác nhận CI hiện tại (`.github/workflows/`) đã có bước nào gắn thêm tag phụ theo git-SHA khi build image chưa (VD: `docker build -t ...:latest -t ...:$GITHUB_SHA`) — nếu chưa, thêm bước này, không đổi tag chính `:latest` được ECS pull, chỉ thêm 1 tag phụ song song trỏ cùng image.
2. Đảm bảo image digest hoặc git-SHA được ghi lại ở nơi có thể tra cứu nhanh — có thể qua: (a) container label (`LABEL git_sha=...` trong Dockerfile) đọc được qua `docker inspect`/`aws ecs describe-task-definition`, hoặc (b) ghi vào 1 file/endpoint health-check trả về version hiện tại (VD `/health` trả thêm field `git_sha`/`build_time`), hoặc (c) cả hai nếu chi phí thấp.
3. Đề xuất phương án nào đơn giản/ít rủi ro nhất trước khi build — đây không phải thay đổi khẩn cấp, làm đúng, không vội.

Không cần Terraform/IAM mới cho việc này (thuần CI + code, có thể có 1 chỗ nhỏ trong app code nếu chọn phương án health-check).
