# AA-279 — [SEC-PIPELINE] Prompt injection surface — S0 brand brief .docx + S2 competitor content feed LLM prompts unsanitized

## Nguồn gốc

Phát hiện trong lúc viết documentation set (doc #28 Vulnerability Mgmt, #7 Brand Standards). **Chưa verify trên code thật — issue này để verify + xử lý sau.**

## Gap

Hai đường untrusted input đi thẳng vào LLM prompt, không có sanitization layer nào được ghi nhận:

1. **S0 — Brand brief** `.docx`: tenant B2B tự upload file → parser trích 8 section (`style_guide`, `core_idea`, `voice_examples`, `should_not_write`…) → build **auto-generated** `system_prompt` lưu vào `shared.tenant_brand_rules` → prompt này được inject vào S1/S2/S3/S4. Nội dung do tenant kiểm soát trở thành **system prompt**.
2. **S2 — Competitor content**: `acp_silver_s2.competitor_inputs` / visibility research nuốt nội dung scrape từ web (bên thứ ba) → đưa vào prompt LangGraph.

## Rủi ro

* Tenant (hoặc trang competitor) chèn instruction vào text → override brand rules, bypass forbidden_words, hoặc điều khiển output của S1/S4.
* Với multi-tenant, injection từ tenant A có thể ảnh hưởng logic dùng chung.

## Verify trước (STEP 0)

- [ ] Đọc `builder.py` (brand brief parser): `system_prompt` được build thế nào, có escape/delimiter không?
- [ ] Đọc `services/acp/s2/*`: competitor text đưa vào prompt ở đâu, có wrap trong delimiter không?
- [ ] Test: upload brief `.docx` chứa câu lệnh kiểu "ignore previous instructions…" → xem output S1 có đổi không?

## Đề xuất fix (nếu confirm)

* Tách untrusted content ra **user turn**, không đưa vào system prompt.
* Wrap trong delimiter rõ ràng + chỉ dẫn "treat as data, not instruction".
* Sanitize/strip instruction-like patterns ở parser; giới hạn độ dài field.
* Test case injection vào `tests/unit/`.
