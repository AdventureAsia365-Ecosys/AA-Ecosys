## Ecosystem alignment decisions to encode

1. **Schema** `booking.*` **in the existing acc2 RDS.** UUID primary keys, like CIS (the ERD uses int).
2. **Golden records, not copies.**
   * `countries`, `areas` and `destinations` reference `shared.destinations` / a new `shared.countries` (owned by CIS).
   * AAA adds only commercial attributes in its own tables keyed by those ids.
3. **Catalog lineage.**
   * `trip_plans` (templates) and `activities` carry `external_ref` (`source_system`, `source_id`) → CIS `published_tours` / atoms, so catalog sync is idempotent.
   * Commercial fields (price, hotels, suppliers) are owned by AAA.
4. **Multi-tour, multi-country.**
   * `trip_case_legs` (`source_tour_id`, `day_from`, `day_to`) from the TripPlanner leg chain;
   * `trip_plan_destinations` and `trip_case_countries` (M:N). Resolves the open "trip_plan → destination" and "multi-country" questions.
5. **Close the handover P0/P1 gaps:**
   * `media_files` (`s3_bucket` + `s3_key`, CDN URL at API time);
   * `supplier_bookings` (item, supplier, price, voucher, status) and `supplier_bills`;
   * `payment_schedule` (deposit / second / final) with invoices linked to `trip_case`;
   * a payment evidence file;
   * enums for the 13 `trip_case` statuses;
   * `created_at` / `updated_at` / `deleted_at` everywhere;
   * `audit_logs`.
6. **Pricing.** Replace `price json` with a `trip_plan_prices` table (season, pax band, currency).
7. **Identity.** Customers are OTP-only (as specified). Staff use the shared staff auth / RBAC (see the staff auth issue).
