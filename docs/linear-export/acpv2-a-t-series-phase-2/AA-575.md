### 2026-09-09 23:31 — nghiep pham quoc

**STEP0**: 01-05 are NOT separate Next.js routes — `atom-curation/page.tsx` is ONE page that implements them as client-side tab state (`SectionKey`). Its 01-06 sub-nav was JSX embedded only in that page's own render tree, never a shared component. Content Trace (`/admin/tenant-activity`) is a genuinely separate route/page with its own independent render tree that never had that markup at all — that's the exact, sole root cause of the sub-nav disappearing.

**Fix**: extracted the sub-nav into a shared `frontend/app/admin/_components/SocialContentSubNav.tsx`, mounted on both pages. 01-05 stay instant same-page tab switches from atom-curation (no reload, preserves AA-554's load-bearing UX); from Content Trace they become real links to `/admin/atom-curation?section=<key>`, read on mount to open the right tab. 06 is always a real link, highlighted correctly on whichever page is active.

**Sort**: extended AA-572's Gate count/Retry count/Created at-only sort to all 7 remaining columns (Topic/Tenant/Tour/Channel/Angle chosen/Status/Published) — same client-side mechanism via a new `sortValue()` switch, Published ranked in pipeline order (No → Not yet → Yes) rather than alphabetically.

Covers: sub-nav visible+highlighted via click-through AND direct URL, tab-switch causes no URL change, `?section=` deep-link opens the real tab, all 7 new columns sort (monotonic asc/desc).
