## Bối cảnh

Phát hiện phụ trong lúc điều tra [AA-544](https://linear.app/aa-ecosys/issue/AA-544/securitygap-seo-context-rls-khong-co-hieu-luc-that-schema-noi-per) (round 3, xác nhận `v1_s0.py`). CloudWatch cho thấy bot quét lỗ hổng tự động đang truy cập được **Swagger UI** (`/docs`, `/v1/api-docs` hoặc tương đương FastAPI mặc định) ở production **công khai, không cần đăng nhập** — bot vào qua `/docs/oauth2-redirect` (public, trả 200), đọc toàn bộ OpenAPI schema, rồi tự động dò từng route khai báo (bao gồm cả `/v1/s0/*` dù route đó đã chết).

Đây là rủi ro bảo mật thật: **Swagger UI công khai = cung cấp sẵn "bản đồ" toàn bộ API cho kẻ tấn công**, giúp bot/hacker biết chính xác có bao nhiêu endpoint, tên gọi, tham số — thay vì phải tự mò mẫm. Không phải lỗ hổng gây thiệt hại trực tiếp ngay, nhưng làm tăng đáng kể hiệu quả trinh sát cho các cuộc tấn công tiếp theo.

## Quyết định (10/09/2026, Nghiệp)

Yêu cầu đăng nhập bằng `X-Admin-Secret` (cơ chế admin auth hiện có) mới được xem Swagger UI ở production — không tắt hẳn, để nhân viên AA vẫn dùng được khi cần debug.

## Việc cần làm

1. STEP0: xác nhận đúng route/cấu hình Swagger hiện tại trong `api/main.py` (FastAPI thường expose qua `/docs`, `/redoc`, `/openapi.json` — xác nhận route thật đang dùng, và route nào đang public thật sự cần chặn, bao gồm cả `/docs/oauth2-redirect` mà bot đã dùng làm cửa vào).
2. Thêm middleware/dependency yêu cầu `X-Admin-Secret` hợp lệ trước khi trả về các route Swagger này — CHỈ áp dụng cho môi trường production (dev vẫn public như hiện tại để tiện code/test, xác nhận cách phân biệt môi trường đang dùng trong codebase — biến env nào).
3. Đảm bảo `/openapi.json` (nguồn dữ liệu Swagger UI đọc) cũng được chặn cùng lúc — chỉ chặn trang UI mà để lộ file JSON nguồn thì vô nghĩa.
4. Live-verify: xác nhận truy cập ẩn danh vào các route Swagger ở production nhận 401/403; xác nhận có `X-Admin-Secret` đúng thì vẫn xem được bình thường; xác nhận dev environment không bị ảnh hưởng.
5. Không tự set Done.

## Built, deployed, live-verified — PR merged

**PR #376 merged to main** (squash), deployed live. All 5 CI checks green, 1956 unit tests passed (10 new).

## STEP0 findings
- Real Swagger routes confirmed in `api/main.py`: FastAPI's defaults were all active — `/docs`, `/redoc`, `/openapi.json`, plus the auto-registered `/docs/oauth2-redirect` (the bot's own entry point per this issue's own report).
- **Important finding on dev/prod detection**: the codebase's existing convention is `ENVIRONMENT` (`os.getenv("ENVIRONMENT", "dev")`, `api/core/sentry.py`) — but Terraform sets `ENVIRONMENT="dev"` on the **one real AWS deployment this app has** (`aws ecs list-clusters` → only `aa-cis-dev-cluster` exists, no separate staging/prod cluster; confirmed live on the running task: `ENVIRONMENT=dev`). Gating on `ENVIRONMENT == "production"` would **never fire** and leave Swagger fully exposed — the opposite of this fix. Used `AWS_EXECUTION_ENV` instead — AWS auto-injects this on every real ECS/Fargate task (confirmed live: `AWS_ECS_FARGATE`), absent on a laptop or GitHub Actions' CI runner. No Terraform change needed.

## What changed
`docs_url`/`redoc_url`/`openapi_url` disabled on the `FastAPI()` constructor; all 4 routes re-registered by hand behind `require_admin_secret_for_docs()`, which reuses the existing `verify_admin_secret()` (`api/routers/admin.py`, same mechanism every `/admin/*` route uses) — but only when `_is_publicly_deployed()`.

## Live-verify (real prod)
Found a real routing nuance worth flagging while verifying: the custom domain `api-cis.lumiguides.it.com` goes through **API Gateway** (`4ylo382khg`), and `/docs`/`/openapi.json` there currently return API Gateway's own `403 MissingAuthenticationTokenException` regardless of my code (pre-existing — `/redoc` and `/docs/oauth2-redirect` have **no API Gateway resource at all**; `/docs`/`/openapi.json` exist in the resource tree with `authorizationType: NONE` but don't reach the backend consistently — looks like the same class of stale-deployment gap AA-432 documented, a separate infra issue, not touched by this PR). The **real, actual bypass path** — confirmed to be the one an internet bot would use, and the one this issue's fix needed to close — is the internet-facing ALB directly (`aa-cis-dev-alb-*.us-west-1.elb.amazonaws.com`, `Scheme: internet-facing`), which skips API Gateway entirely and hits the FastAPI app raw. Tested against that:

**Anonymous (no header):**
| Route | Status | Body |
|---|---|---|
| `/docs` | 403 | `{"detail":"Invalid admin secret"}` |
| `/redoc` | 403 | same |
| `/openapi.json` | 403 | same |
| `/docs/oauth2-redirect` | 403 | same |

**Wrong `X-Admin-Secret`:** `/docs` → 403 (same body — confirms it's a real secret check, not just "header present").

**Correct `X-Admin-Secret`:**
| Route | Status |
|---|---|
| `/docs` | 200 |
| `/redoc` | 200 |
| `/openapi.json` | 200 |
| `/docs/oauth2-redirect` | 200 |

**Dev/local unaffected**: confirmed both ways — (a) real unit tests (`test_aa577_swagger_docs_gate.py`) covering the local/CI no-op branch, (b) direct interpreter check in a local-shaped environment (no `AWS_EXECUTION_ENV` set) — `_is_publicly_deployed()` returns `False`, meaning the dependency is a true no-op regardless of header, exactly matching "dev vẫn public".

Full decisions/tradeoffs: `docs/implementation-notes/AA-577.md`. Not setting status — leaving in Backlog per instructions.

**Worth a look separately** (not this issue's scope, flagging so it isn't lost): the API Gateway custom-domain routing gap for `/docs`/`/redoc`/`/openapi.json`/`/docs/oauth2-redirect` noted above — those 4 paths are currently unreachable through `api-cis.lumiguides.it.com` regardless of auth, which is incidentally safe but not for the reason this issue intended, and the underlying stale-deployment pattern matches AA-432's own documented gotcha.
