## Context

Found while building the country filter for AA_TripPlanner_AI (map-first pin browsing, see PRD on Notion). A STEP 0 query (read-only, S3-mediated ECS exec) grouped `gold_aa_internal.published_tours` joined to `silver_aa_internal.raw_tours.country` for the 31 currently-active tours and returned **8 distinct country string values instead of the expected 6**:

| country (raw value) | active tours |
| -- | -- |
| Laos | 10 |
| Sri Lanka | 9 |
| South Korea | 4 |
| Japan | 3 |
| SRI-LANDKA | 2 |
| OKINAWA | 1 |
| Nepal | 1 |
| India | 1 |

* `SRI-LANDKA` is a misspelled/non-standard variant of `Sri Lanka`.
* `OKINAWA` is a region of Japan, not a country — likely entered where `country` should read `Japan`.

## Scope of this issue

The sample above only covers the 31 tours currently `master_status = 'active'`. This issue is to investigate the full extent of the problem:

1. `silver_aa_internal.raw_tours.country` across all 793 rows (not just the active/published subset)
2. `gold_aa_internal.published_tours` across all 74 rows (all master_status values — active/inactive/trashed) — confirm whether the same non-standard values propagate through to gold, or whether the silver→gold step introduces additional discrepancies

## Why this matters beyond TripPlanner

Any system that groups/filters by `country` is exposed to the same non-normalized values — not just TripPlanner. This is also directly relevant to the Master Data Management gap already flagged in the AA_Ecosys Strategic Analysis (CIO Lens, gap G-D): AA has no single golden record for destination/country data shared across CIS and AAA. Left unfixed at the source, every downstream consumer (CIS tenant portal, dashboards, future `shared.destinations`) has to work around it independently.

TripPlanner is adding a local 2-row hardcoded mapping (`SRI-LANDKA`→`Sri Lanka`, `OKINAWA`→`Japan`) as a stopgap — documented in the AA_TripPlanner_AI PRD (Notion, §4.4) — but that is a band-aid for TripPlanner only, not a fix at the source.

## Suggested next steps (investigate first, not prescriptive)

1. Query full distinct `country` values from `raw_tours` (793 rows) and `published_tours` (74 rows) to find every non-standard variant, not just the 2 surfaced in the active-tour sample.
2. Decide a canonical country list (ISO country names, or AA's own operating-country list — AA_Ecosys docs reference 20 countries across SEA/Asia).
3. Data fix: migration to normalize existing bad values to the canonical list.
4. Prevention: consider a check constraint, enum type, or validation at ingestion (S0) so this can't recur.
