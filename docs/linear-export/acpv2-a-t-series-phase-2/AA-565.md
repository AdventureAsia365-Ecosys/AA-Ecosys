### Key finding that shapes the recommendation

Admin's `TourDetailPanelV2` (its "View" button) is **already a right-side overlay drawer** —
`position:fixed, top:0/right:0/bottom:0, width:70vw` over a dimmed backdrop. This isn't a new UI
concept I'm inventing — it's an existing pattern in this exact codebase, which is why it's the
recommendation below rather than the alternative.

### Recommended: full-width table + right-side overlay drawer (not a squeezed 2-column grid)

Admin's table needs ≥7 columns (checkbox / # / Tour Name / Country / Score / Version / Status /
Actions) to match its fidelity. Today's `CatalogTab` gives the list only 300px once a row is
selected — nowhere near enough for a real table without truncating columns to the point of
losing the parity this issue asks for. So: **table stays full-width always**; opening a row
slides in a drawer over it (reusing `TourDetailPanelV2`'s exact mechanics, at a narrower 700px
fixed width — Tenant's text-heavy content reads better at a fixed width than Admin's 70vw, which
suits its wide before/after compare table).
