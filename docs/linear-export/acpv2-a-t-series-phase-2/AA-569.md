## (d) Export (Blog=text+HTML, other channels=text) — NOT FOUND (real gap)
No export/download button in either frontend surface. No export endpoint for `content_piece` in `api/routers/v1_content_writing.py` or `services/acp_content_writing/`. Grepped all of `api/routers/` for "export" — the only hits (`v1_tours.py`, `v1_pipeline.py`, `admin_pipeline.py`, `admin_atoms.py`) are the admin/tour-pipeline export path, unrelated to tenant content pieces. **Zero channel-conditional export logic exists anywhere for this feature — this isn't a bug in existing code, it's simply unbuilt.**

## (e) Gate/retry/error leakage — MIXED: one surface leaks, one doesn't

Confirmed via `service.py::fetch_review_list` response shape and `ReviewList.tsx` render logic.
- **`t8-angle-gate` end-of-flow card (AngleGateWizard.tsx) — LEAKS, confirmed at the source-string level:**
  - `AngleGateWizard.tsx:641` — `"passed quality review (attempt 2)"` when `attempt_number > 1`.
  - `AngleGateWizard.tsx:650` — `"quality review didn't clear after 2 attempts"`.
  - `AngleGateWizard.tsx:662` — `<strong>Reason:</strong> {piece.held_reason}`, and `held_reason` is built in `service.py:172-173` as **`f"{first_failure['gate']}: {violations joined}"`** — i.e. the tenant would literally see e.g. `Reason: F10_cannibalization_cross_tenant: this content overlaps with...` with the raw internal gate code prefixed onto the string. This is unambiguous from the code (string interpolation), not something that needs a browser to confirm.
